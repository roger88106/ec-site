# 段階 6：E2E と CI

- 前提：段階 4、5
- 完了条件：会員登録から注文までの E2E と、管理者・閲覧者の E2E が CI で通る。CI のすべてのジョブが通る。
- 参照：[plan](../plan.md) 第 4、7 節、`frontend/e2e/`、`.github/workflows/`

## タスク

- [x] **T3601** CI に Keycloak と Mailpit を足し、realm の JSON を取り込む。E2E のジョブのバックエンド・店舗画面・管理画面に、IdP の接続先と secret を渡す（それぞれの既定の値が realm の JSON のローカルと CI 用の値と同じなので、環境変数では渡さない）。
- [x] **T3602** E2E の補助を作る：管理者・閲覧者・会員としてログインする手順と、Mailpit の API で最新のメールを読んで確認のリンクを取り出す手順。E2E で作る会員のメールアドレスには、実行ごとの印を付ける。
- [x] **T3603** 既存の E2E を、管理画面にログインしてから操作する形に直す。店舗での注文は会員として行う。
- [x] **T3604** [テスト] E2E：会員登録 → 確認のメール → ログイン → ログインせずに入れたカートを引き継ぐ → 注文 → 注文の一覧に出る → ログアウトすると、パスワードなしではログインし直せない（AC-108、111〜115、122、125、129）。
- [x] **T3605** [テスト] E2E：閲覧者は注文を見られるが、キャンセルの承認で「権限がない」と示される（AC-136、141）。
- [ ] **T3606** CI ですべてのジョブが通ることを確かめる（push は利用者の許可を得てから）。
