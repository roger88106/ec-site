# Spec 418：店舗画面のセキュリティヘッダー

種類：機能　規模：M　ステータス：草案

## 背景と目的

店舗画面には、セキュリティヘッダーを付ける設定がない。対象は CSP、フレームへの埋め込みの禁止、HSTS、MIME スニッフィングの禁止、参照元の送り方の制限である。公開ネットワークへのデプロイの前に付ける。追跡の issue は #418。issue は管理画面も対象にするが、この spec は店舗画面だけを扱う。関わる文書は、[店舗画面の構成](../../02-設計/apps/store.md)、[バックエンドのアーキテクチャ](../../02-設計/backend-architecture.md)の「公開ネットワークへのデプロイの前提」、[環境変数](../../06-手順書/environment.md)の「店舗画面」。

## スコープ

| 含める | 含めない |
|--------|----------|
| 店舗画面の応答にセキュリティヘッダーを付ける | 管理画面のヘッダー |
| CSP が許すオリジンを、既存の設定と新しい環境変数（画像の配信元）から作る | nonce を使う CSP |
| ヘッダーの値と、主要な画面で CSP の違反がないことの E2E | CSP の違反の報告の送り先 |
| 設計・環境変数・デプロイの前提の文書の更新 | issue に挙げていないヘッダー |

決定：

- CSP は、環境変数から作るオリジンを含むので、リクエストごとに店舗画面の proxy で付ける。値が固定の他のヘッダーは、Next.js の設定ファイルで指定するヘッダーとして、全てのパスに付ける。理由：本番モードの Next.js は、設定ファイルで指定したヘッダーをビルドのときの一覧から読み、起動のときの環境変数を反映しないため ※1。
- CSP は proxy の対象の画面にだけ付ける。Auth.js のエンドポイントと静的なファイルは proxy の対象外なので、CSP は付かない。値が固定の他のヘッダーは付く。
- nonce を使わない（利用者の決定、2026-11-06）。そのため、Next.js が画面に埋め込むインラインのスクリプトとスタイルを許す。
- HSTS は本番モードで付ける。サブドメインへの適用とプリロードの登録は、公開のドメインが決まるまで指定しない。
- CSP のフォームの送信先の許可（form-action）に、IdP と決済サービスのオリジンを入れる。理由：JavaScript が読み込まれる前に送ったフォームの、外部へのリダイレクトを止めないため。
- CSP が許すオリジンは、次の表のとおり作る。

| 用途 | 作り方 |
|------|--------|
| ログインとログアウトの IdP | `AUTH_KEYCLOAK_ISSUER` のオリジン |
| 決済サービスの支払画面（Stripe） | コードの定数 `https://checkout.stripe.com` |
| mock の支払画面 | 新しい任意の環境変数 `STORE_MOCK_PAYMENT_ORIGIN` ※2 |
| 商品の画像 | 新しい環境変数 `STORE_IMAGE_ORIGIN`（既定は `http://localhost:8333`。既定を使うのは開発モードとテストだけ） |

※1：Next.js の本番のサーバーは、設定ファイルのヘッダーを、ビルドで作る `routes-manifest.json` から読む（`next/dist/server/lib/router-utils/filesystem.js` の本番の分岐）。

※2：設定したときだけ許す。本番モードで設定がなくても起動は失敗しない。開発モードとテストの既定は `http://localhost:8080`。mock を使わない環境では設定しない。

## User stories

| US | 誰が | 何をできる | なぜ |
|----|------|------------|------|
| US-418-1 | 消費者 | 他のサイトに埋め込まれず、許可していない場所のスクリプトを実行しない店舗画面で買い物できる | クリックジャッキングとスクリプトインジェクションの被害を防ぐため |

## 受け入れ条件

### US-418-1 他のサイトに埋め込まれず、許可していない場所のスクリプトを実行しない店舗画面で買い物できる（C / P1）

- **AC-418-1** 店舗画面の全ての応答に、後のヘッダーの表のうち「全ての応答」の行のヘッダーが付く。
- **AC-418-2** 画面の応答に CSP が付き、ディレクティブは後のディレクティブの表のとおりである。
- **AC-418-3** 本番モードの応答に、後のヘッダーの表の「本番モードの応答」の行のヘッダーが付く。開発モードでは付かない。
- **AC-418-4** 商品一覧、商品の詳細、カート、注文手続きの画面を開いたとき、CSP の違反が報告されない。
- **AC-418-5** 本番モードで、画像の配信元のオリジンの環境変数がなければ、店舗画面は起動に失敗する。

ヘッダーの表：

| 付く応答 | ヘッダー | 値 |
|----------|----------|----|
| 全ての応答 | `X-Frame-Options` | `DENY` |
| 全ての応答 | `X-Content-Type-Options` | `nosniff` |
| 全ての応答 | `Referrer-Policy` | `strict-origin-when-cross-origin` |
| 本番モードの応答 | `Strict-Transport-Security` | `max-age=31536000` |

ディレクティブの表：

| ディレクティブ | 値 |
|----------------|----|
| `default-src` | `'self'` |
| `script-src` | `'self'` と `'unsafe-inline'`。開発モードだけ `'unsafe-eval'` を加える |
| `style-src` | `'self'` と `'unsafe-inline'` |
| `img-src` | `'self'`、`data:`、画像の配信元のオリジン |
| `font-src` | `'self'` |
| `connect-src` | `'self'` |
| `frame-ancestors` | `'none'` |
| `base-uri` | `'self'` |
| `object-src` | `'none'` |
| `form-action` | `'self'` と、IdP、決済サービスの各オリジン。mock の支払画面のオリジンは、設定したときだけ加える |

## 業務ルール

なし。

## 非機能要件

- **NFR-418-1** ヘッダーを付けた後も、既存の E2E が全て通る（決済、ログイン、画像の表示を含む）。
- **NFR-418-2** この spec で追加する E2E による、E2E の全体の実行時間の増加は 30 秒以内である。

## 依存

| 対象 | 関係 |
|------|------|
| 管理画面のヘッダー | issue #418 で扱い、デプロイ先が決まってから着手する。この spec の完了では issue を閉じない |
| E2E の起動の設定 | 店舗画面を本番モードで起動するので、新しい環境変数を渡す |

## Non-goals

| 項目 | 理由 |
|------|------|
| 管理画面のヘッダー | 配信の方式がデプロイ先によって異なり、ヘッダーを付ける方法を決められないため（利用者の決定、2026-11-06） |
| nonce を使う CSP | 利用者の決定（2026-11-06） |
| 違反の報告の送り先 | 報告を受けて集める仕組みがないため |
| HSTS のサブドメインへの適用とプリロードの登録 | 公開のドメインが決まっていないため |
| issue に挙げていないヘッダー（Permissions-Policy など） | issue の範囲の外のため |
