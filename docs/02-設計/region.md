# 地域の設計

地域モジュールは、都道府県・市区町村・郵便番号のマスターデータを持ち、参照だけを公開する。業務規則は [地域モジュール](../03-機能仕様/region.md) にある。

| 項目 | 内容 |
|------|------|
| レベル | B（参照だけのマスターデータで、業務の状態を変える操作がない） |

## 境界

依存は[全体構成](overview.md)の「モジュールの依存とイベント」。地域は `common` だけに依存し、業務のモジュールに依存せず、イベントを出さない。

### 他のモジュールへの公開

| 種類 | 内容 | 利用者 |
|------|------|--------|
| API | 都道府県の一覧、都道府県をコードで取得する、市区町村をコードで取得する | 注文、レポート |

### 切り出しの前提

別のサービスに切り出せるように、次の前提を守る。

| 前提 | 切り出すとき |
|------|--------------|
| 業務のモジュールに依存せず、イベントを出さない | そのまま移せる |
| 使う側は、地域を呼ぶ腐敗防止層で包む | 腐敗防止層の実装を、HTTP の呼び出しに替える |
| 他のモジュールの表から外部キーを張らない（規則は[地域モジュール](../03-機能仕様/region.md)の「データモデル」） | 表をそのまま移せる |
| API は参照だけで、EC に固有の判断を持たない | 他の用途からも使える |

## 処理の流れ

地域は参照だけを公開し、モジュールをまたぐ処理はない。

### 都道府県と市区町村のキャッシュ

都道府県と市区町村の 4 つの照会（都道府県の一覧、都道府県の取得、都道府県の市区町村の一覧、市区町村の取得）は、メモリのキャッシュから返す。郵便番号の検索は、キャッシュを使わず、毎回 DB から取得する。業務上の扱いは [地域モジュール](../03-機能仕様/region.md) の「参照」。

- 最初に使うときに、1 つの読み取り専用のトランザクションで、都道府県と全ての市区町村を読み、1 つの値として持つ。起動のときは読まない。起動を DB に依存させないため。
- 期限が切れた後の最初の使用で、再読み込みする。
- キャッシュから返す照会は、トランザクションを始めない。
- インスタンスごとに、持つ中身が違ってよい。差が出るのは、データを変えた後に、期限が切れるまでの間だけである。

| 識別子 | 内容 |
|--------|------|
| `ecsite.region.cache.expire-after-write` | 読み込んでから再読み込みするまでの時間（既定値は[環境変数](../06-手順書/environment.md)） |

### 最初のデータの作り方

データの範囲と出典は [地域モジュール](../03-機能仕様/region.md) の「最初のデータ」に書く。

| 項目 | 内容 |
|------|------|
| 変換 | tools（`src/tools/java/com/ecsite/tools/region/`）の `PostalCodeCsv`。本番のコードには入れない。理由：本番で動かさず、tools とテストだけが使うため |
| 郵便番号の一覧 | `src/tools/resources/region/postal-codes.txt`（用途はファイルのコメント） |
| 作り方 | 下の手順。作ったマイグレーションは手動で修正しない |

1. 日本郵便の郵便番号データのページから `utf_ken_all.zip` をダウンロードし、`/.local/masterdata/utf_ken_all/utf_ken_all.csv` に展開する（Git に入れない）。
2. `./gradlew generateRegionMigration` を実行する（置き場所の指定は `build.gradle.kts` のコメント）。一覧の郵便番号がデータになければ失敗する。
3. 郵便番号を追加するときは、一覧に追加する。Gradle のタスク `generateRegionMigration` を、新しいマイグレーションに郵便番号の表を全件置き換える（削除してから入れる）SQL を出力するように修正してから実行する。理由：今のタスクをそのまま実行すると、commit 済みのマイグレーションを上書きし（[CI の検査の script](../06-手順書/ci-checks.md) の `migrations`）、出力先だけを変えると、全件の INSERT で主キーが重なるため。
4. 生成の処理が書く先頭のコメントは変えない。理由は `RegionMigrationGenerator` のコメントに書いてある。

## API

操作の一覧は[ロールと権限の対応表](role-permissions.md)、リクエストとレスポンスの項目は OpenAPI（[店舗 API](../../api/openapi/store.yaml)、[管理 API](../../api/openapi/admin.yaml)）。

管理 API に地域の操作はない。3 つの操作は、地域の presentation が処理する（`storefront` を通さない）。

## パッケージの構成

```
region/
├── api/                    # 他モジュールへの参照の公開
│   └── model/              # API の引数と戻り値の型
├── application/            # 参照のサービス、都道府県と市区町村のキャッシュ
│   └── port/               # リポジトリの port
├── domain/                 # 都道府県、市区町村、住所
├── infrastructure/
│   └── persistence/        # リポジトリの実装
└── presentation/           # 店舗 API の実装
```
