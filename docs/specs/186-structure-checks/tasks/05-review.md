修正した（T186-05-03）：

- 店舗の API の契約が並び順の既定値を持つので、店舗の presentation の `null` の扱いを削除し、既定値を入口の契約の 1 か所にした（plan 第 3.2 節に追記。必須 2）。
- CI の文書に、単体テストが照合する文書を push の CI の対象にしたことを書いた（必須）。
- 図のテストの Javadoc の漏れ（必須）。共通コードが設定に依存しない規則の違反の例（DC-186-7。必須）。
- テストの書き方 第 3.4 節に契約の補助を加え、補助の外の読み込みの文字列の検査の範囲を広げた。補助の可視性、文言の契約のテストの対象の件数、図のテストの名前、単体テストが読む文書の書式の注意、集約の補助の「版」。

残した（推奨。pull request の「推奨の指摘の扱い」に書く）：

| 指摘 | 理由 | 機械の検査に移せるか |
|------|------|----------------------|
| 文書の置き場所の system property の読み方が 2 通り（構成の検査と契約の補助） | 値がないときの失敗の分かりやすさだけの違いで、本 spec の範囲の外 | 移せる（文字列の検査） |
| 生成したコードとモジュールのパッケージの接頭辞が、補助と検査に別々に書かれている | 重複は小さく、補助の判定は 1 か所にある | 移せる（文字列の検査） |
| heap のコメントに測った値がない | 測った値は commit の本文にあり、コメントには経緯を書かない（コメントの書き方） | 移せない |
| 楽観ロックを「版」と書くクラスが本番のコードに残る | 本 spec が変えたクラスだけをそろえた | 移せる（中国語の混入の検査の対象を広げる） |
| spec の番号の正規表現が拾わない形（`AC10`、全角） | 今のコメントに該当する行がない | 移せる（正規表現を広げる） |
| 統合テストが契約と realm を既定の相対パスで読む（`StoreApiTokenContractTest`、`KeycloakIntegrationTest`） | 単体テストの補助の範囲の外 | 起票の案に入れる |
