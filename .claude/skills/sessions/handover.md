# 予備のセッションに担当を渡すメッセージ

issue 担当のセッションが、待機している予備のセッションに spec か issue の担当を渡すときに読む。

メッセージは、セッションの識別子を宛先にして送る（[SKILL.md](SKILL.md)の「セッションの間のメッセージ」）。理由：渡すたびに再読の指示などを手動で書くと、抜けが出るため。

ひな形（`<...>` を埋める）：

```text
<spec の番号または issue の番号> の担当を渡す。次の順に進める。

1. 作業ツリーを作る。`git -C <メインの作業ツリー> worktree add .claude/worktrees/<issue の番号>-<短い名前> -b agent/<issue の番号>-<短い名前> develop` を実行する。以後は、作業ツリーの絶対パスと `git -C` で作業し、メインの作業ツリーを変えない。
2. 作業ツリーの `AGENTS.md` の「最初に読むもの」と、担当の spec（または issue の本文とコメント）を再読する。
3. 返答の言語は、メインの `/.local/agent/environment.md` に従う。Git に入るものは日本語で書く。
4. 文書の本文の書き手は、[文書の書き方](../../../docs/05-開発規則/writing.md)の「本文の書き手」と、skill `docs` の「進め方」のとおり。校閲（検出役、確認役の順）は、skill `review` の docs-review.md の手順 3 に書かれた対象と時点で行う。commit の前に、skill `local-dev` の「CI の検査の script」を実行する。
5. push は段階の最後に行う（規模 S は作業の最後）。pull request は draft で作り、pull request の前のレビューを draft で行う（順は起票と記録の操作の「アーカイブの操作」）。指摘に対応し、本文の「## 危険度」を書いてから ready にする。
6. 資源：利用者が <確認する対象（spec、plan と tasks など）> を承認し、5 時間の使用量が <x>% 未満、週が <y>% 未満なら、問い合わせずに始め、開始を知らせる。特例：<有無>。レビューの profile：<profile>。並行している他のセッション：<セッションと担当>。
7. ready にしたら、issue 担当のセッションに識別子で、pull request の番号、head の commit、危険度を知らせる。
```

- 6 の開始の条件は、[SKILL.md](SKILL.md)の「spec 担当のセッションの起動と実装の開始」の形で書く。x と y も同じ節に従う。
- 予備のセッションの作業ディレクトリは、メインの作業ツリーのままである。作業ツリーを作った後は、絶対パスで作業させる。
- 新しいセッションを手動の作業ツリーで起動するときは、作業ディレクトリ（`cwd`）を作業ツリーのパスで指定する。理由：アプリの「作業ツリーで起動する」の指定は、手動で作った作業ツリーでは反映されない。測定は[毎回読む文書と固定の文脈の大きさ](../../../docs/07-記録/context-size.md)の「固定の文脈」。
