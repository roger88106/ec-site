# セッションの運用

issue 担当のセッションと spec 担当のセッションの運用。役割の表は [エージェントの作業フロー](../../../docs/rules/subagents.md) 第 4 節、作業の形・profile・閾値・使用量を読む頻度は [作業の形と使用量](../../../docs/rules/resources.md)。ツールの名前は末尾の「ツールの注」にだけ書く。

## issue 担当のセッション

- 役割：起票と、spec 担当のセッションの起動。資源の配分。低の変更のマージ。`develop` の CI の見届け。弾の終わりの集計と振り返り。
- 起動：利用者が開く。1 つだけにする。
- 待機：待機中は、通知を受けたときに処理を再開する。定期的な問い合わせはしない。

### 待機と監視の token を抑える

1. CI を待つときは、背景の指令でまとめて待ち、短い間隔で読み直さない。
2. spec 担当のセッションへの返事は短くし、判断に必要な事実だけを書く。
3. 弾の区切りで文脈を圧縮するか、新しいセッションにする（利用者が行う）。
4. 汎用の区分で動かす（[エージェントの作業フロー](../../../docs/rules/subagents.md) 第 3 節）。
5. spec 担当のセッションの終わりを待つときは、ターンを使わない待ち方（終わったら知らせる指定）を使い、問い合わせを繰り返さない。

## 資源の配分

- 作業の形、profile、並行の数は、issue 担当のセッションが [作業の形と使用量](../../../docs/rules/resources.md) 第 1 節の表で決める。並行の数の上限は、マシンの環境の文書（`/.local/agent/environment.md`）の値。
- 利用者が特例の配分を指定したときは、利用者の決定が最終。issue 担当のセッションは、そのための配分（他の spec を区切りで停止するなど）を決めて実行し、利用者に報告する。

## spec 担当のセッションの起動と実装の開始

起動のメッセージに、開始の条件を書く。形：

> 利用者が確認対象を承認し、5 時間の使用量が x% 未満、週が y% 未満なら、問い合わせずに始め、開始を知らせる。

- x と y は、issue 担当のセッションが資源の配分から決める。
- 条件を満たさないとき、または渡されていないときは、spec 担当のセッションは issue 担当のセッションに問い合わせてターンを終える。待つ間は token を使わない。
- 返事がないときは、次に利用者か issue 担当のセッションから指示が来るまで始めない。
- 利用者が確認対象を承認したこと（通常の承認）は、開始の条件の材料である。開始を決めるのは issue 担当のセッション。
- 利用者が「今すぐ始めて」などと特例を明示したときは、利用者の決定が最終。issue 担当のセッションは、そのための配分を決めて実行する。
- spec 担当のセッションが直接その特例を受けたときは、issue 担当のセッションに知らせてから始める。許可は待たない。
- 始めたら、[開発の進め方](../../../docs/rules/workflow.md) 第 5.6 節の実装を始める前の照合に進む。

## セッションの間のメッセージ

名前でなく、セッションの識別子で送る。名前は重なったり変わったりして、別のセッションに届くことがある。

## 遠隔操作

利用者が外にいてセッションを操作できないときに入れる。待機中のセッションには、入れる前に短いメッセージ（「何もせず、待機中と返して終わる」）を送り、次のターンを開始する状態にしてから入れる。待機中のままでは入れられない。

## 単線のときの兼務

単線のときは、1 つのセッションが issue 担当と spec 担当を兼ねる。区分は spec 担当の区分（高性能）。理由：資源の調整がほぼ要らず、2 つのセッションが固定で持つ文脈と通知の token を省けるため。兼ねるときも、起票と spec の作業の規則は変えない。

## ツールの注

使うサービスに固有の名前と手順。サービスを替えるときは、この節だけを修正する（Claude Code のデスクトップアプリ）。

- セッションへのメッセージ：`mcp__ccd_session_mgmt__send_message`（引数に識別子を渡す。一覧は `list_sessions`）。子のセッションへは `SendMessage` も使える。
- 遠隔操作：`mcp__ccd_session_mgmt__set_remote_control`。待機中のセッションに入れると「Remote Control requires an active session」で失敗するので、先に短いメッセージを送ってから入れる（6 つで成功を確認した）。
- 終わったら知らせる指定：背景の実行（`run_in_background`）か、起動したセッションの終了の通知。通知でターンが再開する。
- 使用量：`mcp__ccd_session_mgmt__get_usage`（5 時間と週の使用率、戻る時刻）。
