## タスク

実装は実装役のサブエージェントに任せる。`[リスク]` のタスクは高性能の区分のモデルで行う。

- 組：`[テスト]` のタスクと、その次の実装のタスクは組である。同じ実装役が続けて行い、同じ commit にする（[開発の進め方](../../../05-開発規則/workflow.md) 第 2.1 節）。

- [ ] **T283-01-01** 表のセルごとに、文の字数の合計を測る。`--stats` に、その合計の分布（40、60、80 字以上）を加え、アーカイブの外の文書で測る。直近の 5 つの pull request で、追加行のうち警告が出る見込みの数も測る（字数 100、読点 5、セルの閾値の案）。差分の測定は、スクラッチパッドの script で行う。結果を書き、セルの閾値を決める（DC-283-22、24）。
  - 依存：なし
  - 範囲：`scripts/ci/ja-text.mjs`（`--stats` だけ）、`scripts/ci/ja-text.test.mjs`
  - 確認方法：結果の数。1 つの pull request で警告が 10 を超えるなら、利用者に閾値を確認する。
- [ ] **T283-01-02** [テスト] インラインコードの扱いのテストを書き、レッドを確認する。語の検査は、インラインコードの中の語を数えない。読点の数は、インラインコードかリンクだけの項目を区切る読点を数えない。許容用語の照合も、インラインコードを除いた文で行う。テストの例に、tasks の範囲の行と参照の行の形を入れる（DC-283-18、21）。
  - 依存：T283-01-01
  - 範囲：`scripts/ci/ja-text.test.mjs`
  - 確認方法：テストが失敗する（レッド）。commit の本文に、レッドを確認したことを書く。
- [ ] **T283-01-03** T283-01-02 のテストが通る実装を書く。script の冒頭の説明も修正する（DC-283-18、21、24）。
  - 依存：T283-01-02
  - 範囲：`scripts/ci/ja-text.mjs`
  - 確認方法：テストが通る。`node scripts/ci/ja-text.mjs` の error が 0。
- [ ] **T283-01-04** [テスト] [リスク] 差分の追加行の検査のテストを書き、レッドを確認する。項目は次のとおり（DC-283-21〜23）。
  - マージベースからの追加行の文で、字数か読点の数が閾値以上なら、注釈の形の警告を出す。閾値以上の表のセルも同じ。終了コードは 0 である。
  - 既存の行には警告を出さない。
  - `develop` への push では、1 つ目の親との差分を見る。shallow clone では、差分を求められないので失敗にする。
  - 表の区切り行、コードブロック、インラインコード、URL は数えない。
  - 依存：T283-01-03
  - 範囲：`scripts/ci/ja-text.test.mjs`、`scripts/ci/lib/` のマージベースの関数のテスト
  - 確認方法：テストが失敗する（レッド）。
- [ ] **T283-01-05** [リスク] T283-01-04 のテストが通る実装を書く。`ja-text.mjs` に `--changed` を加える。マージベースを求める関数を `scripts/ci/lib/` に切り出し、マイグレーションの検査もそれを使う。セルの閾値を `ja-text.json` に書く。script の冒頭の説明に、閾値と対象を書く（DC-283-21〜24）。
