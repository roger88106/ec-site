# 機能仕様の雛形

## この雛形の使い方

モジュールごとに 1 つ、`docs/03-機能仕様/<モジュール>.md` として置く。読むのは主にエージェントで、モジュールの規則の正本として読む。

| 置くもの | 置かないもの（置き場所） |
|----------|--------------------------|
| 業務規則 | 依存、公開（API、イベント）、パッケージの構成、処理の流れの図（[モジュールの設計の雛形](../02-設計/template.md)で書く `docs/02-設計/<モジュール>.md`） |
| 状態の遷移 | 決定の理由（`docs/04-決定記録/`。本文は決定記録を指す） |
| データモデル | API の項目とエラーコードの一覧（OpenAPI） |
| 今有効な AC | |

- 節の名前と順は固定で、構造の検査の script が確認する。
- 当てはまらない節は消さずに「なし」と書く。
- 1 つの事実の正本は 1 つ。他の文書にある内容は転記せず、その文書を指す。

## 写して使う骨組み

````markdown
# <モジュールの論理名>モジュール

<モジュールが管理するものを 1〜2 文で書く。モジュールの境界、処理の流れ、API の一覧、パッケージの構成は [<モジュール>の設計](../02-設計/<モジュール>.md) を指す。>

| 項目 | 内容 |
|------|------|
| レベル | <A、B または C>（<理由>） |

## 業務規則

<モジュールが守る規則を、小見出し（`###`）ごとに、表と短い箇条で書く。決まりと対応は表にする。長い理由は注にする。決定の理由は決定記録を指す。>

## 状態の遷移

<状態を持つ集約の遷移を、図と表で書く。表は、操作、すでにその状態のときの扱い、できない状態。状態を持たないときは「なし」。図の矢印のラベルに条件を添えるときは、括弧の前に `<br/>` を入れて改行する。画面に今できる操作のフラグを返すときは、小見出し「状態ごとにできる操作」に、状態を行、画面を列にした表を置き、各欄に「`フラグ`：操作」を 1 行ずつ書く。>

## データモデル

<schema、テーブルの関係（Mermaid の erDiagram）、列の規則を書く。列の正本は Flyway のマイグレーション。>

## 今有効な AC

<選んだ基準を 1 文で書き、表にする。列は AC、今の内容、元の spec。>
````

- レベルの行は `| レベル | A（理由） |` の形にする。記号は[文書の記号と番号](../05-開発規則/notation.md)の「モジュールの設計書の記号」。
- `## 今有効な AC` の「今の内容」は、有効なら spec の AC の本文（長ければ要点）、変更なら今の規則の内容を短く書き、根拠の `業務規則` の小見出しを「業務規則の「<小見出し>」」と書く。
