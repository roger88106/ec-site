# 段階 4：トランザクションの外での外部の呼び出し

- 前提：段階 3（画像のサービスのエラーの分類）
- 完了条件：US-65 のテストが通る。画像の変換と保存をトランザクションの外で行い、保存に失敗したら配信のファイルを消す。返金・取消のリスナーが、トランザクションの外で決済サービスを呼ぶ。既存のテストがすべて通る（`./gradlew check`、`e2e.sh`）。
- 参照：[plan](../plan.md) 第 5 節、spec の US-65、BR-40、[メディアモジュール](../../../backend/modules/media.md)、[商品カタログモジュール](../../../backend/modules/catalog.md)、[決済モジュール](../../../backend/modules/payment.md)、[通知モジュール](../../../backend/modules/notification.md)、[バックエンドの書き方](../../../backend/coding.md) 第 1.1、4.1 節

## タスク

- [x] **T017-04-01** [テスト] メディアの API の統合テストを書く。レッドを確かめる。
  - 用意は、トランザクションの外で受付のファイルを確かめ、変換し、配信のバケットに置き、アセットを記録しない。
  - 登録は、呼んだ側のトランザクションの中でアセットを記録する。トランザクションがなければ失敗する。
  - 破棄は、用意で置いたファイルを消す。消すのに失敗しても例外を投げず、warn のログに保存先のキーを出す（AC-305）。
  - 受付がない・大きさが範囲の外・中身が対象の画像でないときは、今の確定と同じエラーを返す。
  - 用意・登録・破棄の型は、メディアの API の `PreparedImage`（アセット ID だけを持つ）にした（2026-10-20 利用者）。レッドは、まだない操作のコンパイルの失敗で確かめた。
- [x] **T017-04-02** メディアの API と service の確定を、用意・登録・破棄に分ける。T017-04-01 を通す。今の確定は、使う所がなくなれば消す。
  - 用意はトランザクションの有無を問わない（トランザクションの中で呼ぶと失敗させると、テストのトランザクションで画像を足す既存のテストが通らないため。トランザクションの外で呼ぶことは T017-04-03 で確かめる。2026-10-20 利用者）。登録はトランザクションがなければ失敗させる（`MANDATORY`）。今の確定は商品の画像の追加が使っているので、T017-04-04 で消す。
- [x] **T017-04-03** [テスト] 商品の画像の追加の統合テストを書く。レッドを確かめる。
  - 画像の変換の間、データベースのトランザクションがない（変換の実装を差し替えて、呼ばれた時点のトランザクションの有無を記録する）（AC-304）。
  - 商品の版の不一致など、保存のトランザクションが失敗したら、配信のファイルが消え、アセットの記録がなく、元のエラー（409 など）を返す（AC-305）。
  - 成功したときは、今どおり画像が商品の最後に加わる。
  - 保存の失敗は、変換の間にほかの操作が商品の版を上げた形で起こす。レッドは、変換の時点にトランザクションがあることと、配信のファイルが残ることで確かめた。
- [x] **T017-04-04** 商品の画像の追加を、トランザクションの外の流れ（読み取り → 用意 → 保存 → 失敗なら破棄）と、保存の service（商品への追加と登録を 1 つのトランザクション）に分ける。T017-04-03 を通す。
  - 流れは `ProductImageService.addImage`（トランザクションなし）に残し、加えられることの確かめと保存を `ProductImageCommandService` に移した（2026-10-20 利用者）。メディアの今の確定は使う所がなくなったので消した。
