# Spec 416：全角の郵便番号と電話番号を受け付ける

種類：機能　規模：M　ステータス：確定

## 背景と目的

注文手続きの画面で、日本語入力をオンのまま郵便番号に全角（例：`１００－０００１`）を入れると、住所の補完が実行されず、エラーも表示されない。そのまま注文すると、郵便番号または電話番号の欄に形式の誤りが表示される。入力は消えず、誤りの欄へフォーカスが移るので、直せば注文できる。影響は軽いが、日本語入力を切り替える手間がかかる。

原因は 3 つある。郵便番号の形式の確認が、半角の数字 7 桁と半角のハイフン 1 つだけを受け付ける。注文のサーバーアクションが、入力のまま API に送る。API の契約が、郵便番号と電話番号に半角だけの形式を定めている。この spec は、店舗画面で全角の数字とハイフンの類を半角に変換し、補完と注文ができるようにする。

追跡の issue は #416。関わる文書は、[店舗モジュール](../../03-機能仕様/storefront.md)、[店舗画面の構成](../../02-設計/apps/store.md)。

## スコープ

| 含める | 含めない |
|--------|----------|
| 郵便番号と電話番号の、全角の数字とハイフンの類の変換 | 氏名と住所の変換 |
| 住所の補完の前の変換 | API の契約とバックエンドの変更 |
| 注文の送信の前の変換 | 入力欄の値の書き換え（入力欄を離れたときの表示を含む） |
| テストの追加、AC 一覧・店舗モジュール・店舗画面の構成の更新 | E2E の追加 |


決定：

1. 規模は M にする。理由：AC を追加・変更するが、API の契約と DB の構造を変えず、店舗画面だけを変えるため。
2. 変換は、画面に依存しない 1 つの関数にまとめ、住所の補完と注文の送信の両方で使う。変換の規則は BR-416-1。
3. 住所の補完では、郵便番号の形式の確認の中で、最初に変換する。郵便番号を検索するサーバーアクションも形式の確認を通るので、同じく変換される。注文のフォームと検索のサーバーアクションは変えない。
4. 注文の送信では、注文のサーバーアクションの中で、API に送る前に郵便番号と電話番号を変換する。理由：JavaScript の読み込み前の送信（フォームの action）も同じ処理を通るため（前提は依存の #441）。
5. 入力欄の値は変えない（利用者の決定。issue #416 のコメント、2026-11-06）。理由：入力中に欄の値を書き換えると、日本語入力の変換中の文字が乱れるおそれがあるため。このおそれは issue の注意点で、実機では確認していない。
6. 変換の後に形式が違う入力（ハイフンが 2 つ以上、桁数が違う、など）は、今と同じく形式の誤りとして扱う。
7. NFKC で `-` にならないハイフンの類も `-` に置き換える（利用者の決定。issue #416 のコメント）。
8. 既存の AC-255 の「7 桁を入れると」に、全角の入力を含める（利用者の決定。issue #416 のコメント）。AC 一覧では AC-255 の状態を「変更」にし、「変えた spec」の列に 416 を書く。AC-86 はバックエンドの形式なので変えない。
9. E2E は加えない。理由：変換は単体テストとサーバーアクションのテストで確認でき、補完と送信の流れは既存の E2E が確認しているため。

   | 論理名 | 識別子 |
   |--------|--------|
   | 郵便番号の形式の確認 | `normalizePostalCode`（`lib/postalCode.ts`） |
   | 注文のサーバーアクション | `placeOrder`（`actions/checkout.ts`） |
   | 注文のフォーム | `OrderForm` |
   | 変換の関数 | 新しく `lib/` に置く（名前は実装で決める） |

## 受け入れ条件

### US-416-1 全角の入力でも補完と注文ができる（C / P1）

- **AC-416-1** 注文手続きの画面で、郵便番号を全角の数字とハイフンの類で入れても、変換して 7 桁になれば、半角の 7 桁を入れたときと同じく住所を補完する。
- **AC-416-2** 注文するとき、郵便番号と電話番号の全角の数字とハイフンの類を、半角に変換して送る。
- **AC-416-3** 変換しても、郵便番号と電話番号の欄の値は、入力したまま変えない。
- **AC-416-4** 変換の後も形式が違う郵便番号（ハイフンが 2 つ以上ある、など）は、住所を補完しない。

## 業務ルール

- **BR-416-1** ハイフンの類は、全角のハイフンマイナス（U+FF0D）と ※1 の 8 つの文字をいう。郵便番号と電話番号は、Unicode の NFKC で正規化し、続けて NFKC で `-` にならないハイフンの類（※1 の文字）を `-` に置き換える。氏名と住所は変換しない。理由：氏名と住所は入力のまま保存するため。

※1：NFKC で `-` にならないハイフンの類。

| 文字 | 符号位置 |
|------|----------|
| 長音符 | U+30FC |
| 半角の長音符 | U+FF70 |
| マイナス記号 | U+2212 |
| ハイフン | U+2010 |
| 非改行ハイフン | U+2011 |
| エヌダッシュ | U+2013 |
| エムダッシュ | U+2014 |
| 水平線 | U+2015 |

## 非機能要件

- **NFR-416-1** API の契約とバックエンドを変えない。
- **NFR-416-2** 半角の入力の振る舞い（補完、送信、エラーの表示、誤りの欄へのフォーカス）を、今のまま保つ。
