# Spec 349：書き方の規則の文書の節の形を検査する

種類：整理　規模：M　ステータス：確定

## 背景と目的

書き方の規則の文書で、各節に `確認方法：` と `理由：` の行があるかを調べる検査はない。節の形の規則は、[書き方の規則とレビュー](../../05-開発規則/review.md)の「規則の書き方」にある。レビュー用の script は `確認方法：` の行の形を読むが、節に行がないことは見ない。この script は CI で実行しない。CI で実行するのは、そのテストだけである。

追跡の issue は #349。issue は `理由：` の行がない節を 2 つ（テストの書き方の「テストの種類」、バックエンドのテストの書き方の「テストの置き場所」）と書いている。今の文書を調べると、他に 2 つある（バックエンドの書き方の「パッケージの大きさ」「名前の形」）。合わせて 4 つの節になり、issue の記述と数が合わない。

消費者・運営者に見える振る舞いは変えない。

## スコープ

| 含める | 含めない |
|--------|----------|
| 節ごとの行の有無と、行の途中の `確認方法：` を調べる検査の追加 | 適用済みのマイグレーションのコメントが、見出しを「第 N 節」で指す問題 |
| 4 つの節への `理由：` の行の追加 | `確認方法：` の行の直後が空行か見出しであることと、箇条の細かな形 |
| | 節の形の規則の対象外の文書 |
| | `理由：` の内容の妥当性 |

決定：

- 対象の文書は、[書き方の規則とレビュー](../../05-開発規則/review.md)の冒頭の文にあるリンクから読む。今は 6 つの文書である。理由：対象の一覧の正本を 1 か所にするため。リンクが 1 つも読めないときは失敗にする。
- 節の単位は、`##` から `######` の見出しのうち、次の見出しまでに本文（空行以外の行。コードブロックを含む）があるもの。本文のない親の見出しは節に数えない。最初の `##` の前（文書の冒頭）は節にしない。
- 判定の区分は誤りの防止とする。誤って書いたものを拒否し、意図して作った回避は対象にしない。
- 判定は許可する形の一覧で書く。`確認方法：` の行は、字下げのない行頭から始まる形だけを許す。
- 検査は `scripts/ci/` の直下に置くので、`check-all.sh` が実行する。skill の script には依存しない。理由：CI の検査から skill の script を import している前例がないため。
- 節の形から外れる節は、除外の一覧に書く。一覧の形は他の検査と同じ {キー: 理由} とし、共通のモジュールで読み込む。キーは `<ファイル>「<番号を除いた見出し>」`。今は次の 2 件。
  - テストの書き方の「カバレッジと mutation score の基準」：テストの実行方法を指すだけの節で、規則を持たないため。
  - コメントの書き方の「関連する文書」：文書への案内で、規則を持たないため。
- `理由：` の行を加える位置は、規則の本文の後、`確認方法：` の行の前。

加える `理由：` の行を、次の表に示す。

| 節 | 理由の行の案 | 出典 |
|----|--------------|------|
| テストの書き方の「テストの種類」 | 理由：テストの種類ごとに確認する対象を決め、どのテストでも確認されない AC や振る舞いを残さないため。 | [constitution](../../constitution.md)の「テスト」（全ての AC にテストを対応させる）。[テストの書き方](../../05-開発規則/test-writing.md)の箇条（テストに出ない AC は CI が失敗にする） |
| バックエンドのテストの書き方の「テストの置き場所」 | 理由：テストのために本番のクラスの可視性を広げず（同じパッケージ）、Docker のない環境でも単体テストを実行できるようにする（ソースセット）ため。 | [バックエンドのテストの書き方](../../05-開発規則/test-writing-backend.md)の記述（テストのために可視性を広げない）。[テストの実行方法](../../06-手順書/running-tests.md)の「バックエンド」の表（`./gradlew test` は Docker が不要） |
| バックエンドの書き方の「パッケージの大きさ」 | 理由：直下のクラスが増えたら、クラスのまとまりで分け、パッケージから役割を読み取れるようにするため。 | 一部だけ。アーカイブした spec 155 の DC-155-41（まとまりで分けられるなら分ける）。「役割を読み取れる」は推定 ※1 |
| バックエンドの書き方の「名前の形」 | 理由：クラスの名前から、役割（port、実装、用途）と置き場所が分かるようにするため。 | なし。全体が推定 ※1 |

※1：文書にもコミットメッセージにもないため、推定である。

「テストの種類」と「テストの置き場所」の案も、事実の出典はあるが、それを規則の目的とすることは文書に書かれておらず、推定である。

4 つの節の全てに、この案で行を加える。推定を含むので、pull request の本文で利用者の review の対象として示す。

## 目的と完了条件

### DS-349-1 書き方の規則の文書で、確認方法と理由の行の抜けを CI で見つけられるようにする（D / P1）

- **DC-349-1** 対象の文書を、書き方の規則とレビューの冒頭の文にあるリンクから読む。リンクが 1 つも読めないとき、リンク先のファイルがないとき、対象の文書のコードブロックが閉じていないときは失敗にする。
- **DC-349-2** 節に `確認方法：` の行がなければ失敗にする。
- **DC-349-3** 節に `確認方法：` の行が 2 つ以上あれば失敗にする。
- **DC-349-4** 節に `理由：` の行（字下げのない行頭から始まり、内容のある行）がなければ失敗にする。
- **DC-349-5** `確認方法：` が、字下げのない行頭以外（行の途中、箇条、表のセル、字下げ）にあれば失敗にする。半角のコロン、コロンの前の空白も同じく失敗にする。コードブロック、インラインコード、HTML のコメントの中は見ない。節の外（最初の `##` より前）の行頭の `確認方法：` も失敗にする。
- **DC-349-6** 内容のない `確認方法：` の行の後で、最初の空行でない行が箇条でなければ失敗にする。
- **DC-349-7** 除外の一覧の節は DC-349-2〜4 の対象にしない。理由のない除外と、今の文書にない節の除外は失敗にする。
- **DC-349-8** 判定の区分（誤りの防止）を script の先頭のコメントに書く。「失敗したとき：」「除外：」「使い方：」の行も書く。
- **DC-349-9** 「検出すべき例」の全てでテストが失敗を確認し、「検出してはいけない例」の全てでテストが成功を確認する。
- **DC-349-10** 今の文書に対して検査が成功する。

### DS-349-2 検査が見つける節に理由の行を加え、検査の一覧を更新する（D / P1）

- **DC-349-11** 「加える `理由：` の行」の 4 つの節に `理由：` の行がある。
- **DC-349-12** CI の検査の script の「検査の一覧」の表に、この検査の行がある。
- **DC-349-13** `scripts/ci/check-all.sh` が成功する。
- **DC-349-14** `ModuleStructureTest` が通る。このテストがパッケージの大きさの節を読むためである。

## Non-goals

| 項目 | 理由 |
|------|------|
| 適用済みのマイグレーションのコメントが、見出しを「第 N 節」で指す問題 | issue の範囲外で、#289 に記録するため |
| `確認方法：` の行の直後が空行か見出しであること、箇条の細かな形、形 1 の後の箇条、列名が確認方法の表の検査 | レビュー用の script が読むときに失敗にするため |
| 他の規則の文書（開発の進め方など）の検査 | 形の規則（書き方の規則とレビューの「規則の書き方」）の対象でないため |
| `理由：` の内容の妥当性の検査 | 文の形では判定できないので、レビューで読むため |
