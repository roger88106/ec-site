# Spec 010：売上の簡易レポート

ステータス：確定

## 1. 背景と目的

B 側の「データ収集と簡易レポート」を作る。運営者（営業と管理職）が、管理画面で売上の推移と、何がどこで誰に売れているかを、グラフと表で確認できる状態にする。MVP の最後の機能とする。

- 今は、注文・支払・出荷のデータはあるが、まとめて見る手段がない。注文は今の状態だけを持ち、途中の出来事（キャンセル申請の後の却下、返送など）は残らない。
- 買い手の属性は、注文のお届け先の都道府県しかない。年齢層と性別で見るために、会員の生年月日と性別を集める。
- **データは広く集め、どう数えるかはレポートごとに決める**。集めるときに絞ると、後で別の見方（返送の率、受け取られにくい地域など）をしたくなっても、過去の分を作れないため。
- レポートは 3 つに絞り、見るための仕組み（期間、粒度、売上の数え方、権限）をそろえる。分析の機能を広げるのは MVP の後とする。

AC・US・BR・NFR の番号は、spec 009 から続けて振る。

## 2. 用語

[用語集](../../reference/glossary.md)の「注文の状態」「支払の状態」「売上確定」「お届け先」を参照。レポート、集計の粒度、売上の数え方、年齢層は plan で用語集に追加する。

## 4. User stories と受け入れ条件

### US-41 売上の推移を見る（B / P1）

- **AC-197** 運営者は、期間と集計の粒度（週、月、四半期、年）を選び、粒度ごとの売上額と販売数量の推移を折れ線グラフで見られる。
- **AC-198** 同じ数字を、粒度ごとの行の表でも見られる。
- **AC-199** 商品を 1 つ選ぶと、その商品だけの推移を見られる。選ばなければ全商品の合計。
- **AC-200** 売上の数え方（BR-25）を画面で切り替えられる。
- **AC-201** 売れなかった区切りも、0 の行として示す。理由：線が途切れて読み違えないため。

### US-42 商品のバリエーションごとの売れ行きを見る（B / P1）

- **AC-202** 運営者は、商品を 1 つと期間を選び、バリエーション（軸の値の組み合わせ）ごとの販売数量と売上額を棒グラフで見られる。
- **AC-203** 同じ数字を表でも見られる。表は販売数量の多い順に並べる。
- **AC-204** 期間に売れなかったバリエーションも、0 として示す。

### US-43 買い手の地域・年齢層・性別を見る（B / P1）

- **AC-205** 運営者は、期間を選び、お届け先の都道府県ごとの売上額と注文件数を、グラフと表で見られる。
- **AC-206** 同じ期間の、年齢層（BR-27）ごとの売上額と注文件数を、グラフと表で見られる。
- **AC-207** 商品を 1 つ選ぶと、その商品を含む注文だけを数える。売上額はその商品の明細の分だけを数える。
- **AC-208** 生年月日の分からない会員の注文は、年齢層「不明」として数える。
- **AC-219** 同じ期間の、性別（BR-29）ごとの売上額と注文件数を、グラフと表で見られる。性別の分からない会員の注文は「不明」として数える。
- **AC-220** 都道府県は、全国地方公共団体コードの順（北海道から沖縄県）に並べる。

### US-44 会員の生年月日と性別を集める（C / P1）

- **AC-209** IdP の会員登録の画面で、生年月日を入れられる。
- **AC-210** 生年月日は任意とする。入れなくても登録でき、注文できる。理由：属性の収集のために購入を妨げないため。
- **AC-211** 会員は、IdP のアカウントの画面で、後から生年月日を入れる・修正することができる。
- **AC-212** 注文の成立のときに、その時点の年齢を注文に記録する。後で生年月日を修正しても、成立済みの注文の年齢は変えない。
- **AC-213** 未来の日付と、明らかにありえない日付（120 年より前など）は受け付けない。
- **AC-221** IdP の会員登録の画面で性別（BR-29）を選べる。任意とし、後から IdP のアカウントの画面で修正できる。
- **AC-222** 注文の成立のときに、その時点の性別を注文に記録する。後で修正しても、成立済みの注文の性別は変えない。

### US-45 見てよいレポートだけを見る（B / P1）

- **AC-214** 運営者は、権限を持つレポートだけを、管理画面のメニューで見て開ける。
- **AC-215** 権限のないレポートの API を呼ぶと 403 になる。
- **AC-216** 権限はレポートごとに分ける。レポートの中の選択肢（粒度、商品など）ごとの権限は作らない。
- **AC-217** 役割ごとの権限は BR-28 のとおり。

### US-46 レポートを表計算で使う（B / P1）

- **AC-218** 運営者は、表示しているレポートの表を CSV で取り出せる。文字コードは表計算ソフトで文字化けしないもの（plan で決める）。

### US-47 注文のデータを集める（B / P1）

- **AC-223** 状態によらず、全ての注文をレポートのデータに集める（支払待ち、支払の期限切れ、キャンセル、返送を含む）。
- **AC-224** 注文の状態と配送状態が変わるたびに、何が・いつ・どの状態からどの状態に変わったかを、履歴として集める。
- **AC-225** 集めたデータのうち、どの注文を数えるかは、レポートごとに決める（BR-25 など）。集めるときには絞らない。

## 5. 業務ルール

spec 002 の BR-6〜11、spec 003 の BR-12、13、spec 007 の BR-14〜17、spec 009 の BR-18〜23 に加える。

- **BR-24 期間と区切り**：日の区切りは日本時間とする（注文一覧の絞り込みと同じ）。期間の始まりと終わりは日で指定する。

  | レポート | 区切り |
  |----------|--------|
  | 売上の推移 | 週は月曜から日曜、月は暦の月。四半期と年は会計年度で区切る ※1 |
  | バリエーションの売れ行き、地域・年齢層・性別 | 区切らない（期間の合計）。期間の指定で月・年を選ぶときは暦の月・年 |

  - 期間が区切りの途中で切れたら、その区切りは期間の中の日だけを数える。

  ※1：会計年度の始まりの月は設定で持つ。既定は 4 月（四半期は 4〜6 月、7〜9 月、10〜12 月、1〜3 月）。年の表示は、始まりの月の年で呼ぶ（2026 年 4 月〜2027 年 3 月は「2026 年度」）。

- **BR-25 売上の数え方**：次の 2 つから選ぶ。既定は「注文基準」。

  | 数え方 | 数える注文 | 数える日 |
  |--------|------------|----------|
  | 注文基準 | 与信が成功した注文（「受付」になった注文）。後でキャンセルになった注文は除く | 注文日 |
  | 出荷基準 | 売上を確定した注文。返金待ち・返金済みの注文は除く | 出荷日 |

  - 支払待ちのまま期限切れになった注文は、どちらの数え方でも数えない（データには集める。AC-223）。

- **BR-26 売上額**：既定は、消費税と送料を含む額（注文の総額）。画面で、消費税を除く・送料を除くを選べる。

  - 商品を選んだとき（AC-199、207）と、バリエーションの売れ行き（US-42）は、送料を含められない（明細に送料を分けられないため）。送料を除くを選んだものとして数え、画面にその旨を表示する。
  - 注文件数は、条件に合う明細を 1 つ以上含む注文の数。

- **BR-27 年齢層**：注文に記録した年齢（AC-212）で、10 代以下、20 代、30 代、40 代、50 代、60 代以上、不明に分ける。

- **BR-28 レポートの権限**：

  | 役割 | 売上の推移 | バリエーションの売れ行き | 地域・年齢層・性別 |
  |------|-----------|--------------------------|-------------|
  | 管理者 | 見られる | 見られる | 見られる |
  | 管理職（新設） | 見られる | 見られる | 見られる |
  | 営業（新設） | 見られない | 見られる | 見られる |
  | 閲覧者 | 見られない | 見られない | 見られない |

  - 管理職と営業は、レポート以外の管理画面の操作を、閲覧者と同じく参照だけできる。

- **BR-29 性別**：男性、女性、その他、回答しない、から選ぶ。入れていない会員と「回答しない」は、レポートでは「不明」として数える。

## 6. 非機能要件

- **NFR-12** レポートの集計は、注文・出荷などの業務の処理を遅らせない。
- **NFR-13** 1 年分の注文（plan で件数を決める。数万件を想定）で、どのレポートも 3 秒以内に表示する。
- **NFR-14** レポートに出す数字は、業務の処理から遅延してよい。遅延の上限は plan で決める（数分を想定）。理由：集計の方式（問い合わせのたびに集計するか、集計を持つか）を選べるようにするため。
- **NFR-15** ローカルの seed に、レポートで分析できる量と分布の注文（1 年以上、複数の都道府県と年齢層、出荷済み・キャンセル・返金済みを含む）を入れる。seed の注文は、支払・出荷の状態と食い違わない。お届け先は、実在する郵便番号・都道府県・市区町村の組み合わせにする。理由：都道府県のコード化と市区町村の補完（第 7 節）を、seed にもそのまま適用できるようにするため。
- **NFR-16** レポートに個人を特定できる情報（氏名、住所、メールアドレス、生年月日）を出さない。

## 7. Non-goals

| 項目 | 扱う場所 |
|------|----------|
| 3 つ以外のレポート（在庫の回転、カートの離脱、会員の継続など） | MVP の後の spec |
| 閲覧履歴・検索語など、注文以外の行動のデータの収集 | MVP の後の spec |
| レポートの中の選択肢ごとの権限 | 行わない（AC-216） |
| 運営者がレポートの権限を画面で設定する | 行わない（IdP の役割で設定する） |
| 年齢層・性別以外の会員の属性の収集 | MVP の後の spec |
| お届け先の都道府県を、全国地方公共団体コードと名前で持つ形に修正する | 郵便番号と住所を結び付ける spec。本 spec のレポートは、都道府県の名前をコードに読み替えて集計する |
| 市区町村ごとの集計 | 郵便番号と住所を結び付ける spec の後。成立済みの注文も、記録した郵便番号から市区町村を補える |
| 年齢層と性別のクロス集計（30 代の女性など） | MVP の後の spec |
| 前年同期との比較、目標との比較 | MVP の後の spec |
| レポートの定期のメール送信 | MVP の後の spec |
| 店舗画面での売れ筋の表示 | MVP の後の spec |
