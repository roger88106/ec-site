# カートモジュール

消費者のカートと、その品目（バリアントと数量）を管理する。

- レベル：B（品目の上限と合算だけで、状態遷移を持たない）
- 依存：商品カタログモジュール（API）、在庫モジュール（API）、会員モジュール（API。presentation 層だけ）
- 関連 spec：002（US-14、15）、003（US-25）
- 用語と識別子：[用語集](../glossary.md)

## カート

- カートは、品目の一覧、バージョン、最終更新日時を持つ。品目は、バリアント、数量、入れた日時を持つ。
- 価格は持たない。表示のたびに注文モジュールの見積もりで現在の価格を求める（AC-79）。
- カート ID は推測できない UUID。ログインせずに作ったカート（会員を持たない）は、カート ID を知っていることが使える条件になる（[plan 002](../specs/002-cart-and-order/plan.md) 第 3 節、AC-120）。
- 変更（品目の追加・数量の変更・削除・空にする）のたびにバージョンを上げる。注文モジュールが、注文手続きを始めた後の変更を見つけるため。

### 会員のカート

- 会員のカートは、会員 ID を持つ。会員ごとに 1 つ（AC-121）。会員が初めて使うとき（`/me/cart`）に作る。ログインせずに作ったカートは会員を持たず、後から会員を持つこともない。
- 会員のカートは、持ち主の会員だけが読み書きできる。ほかの会員とログインしていない人には、カートがないときと同じく 404 にする（存在を推測させない。[plan 003](../specs/003-auth/plan.md) 第 3.4 節）。店舗のカートの表示も同じ。
- 持ち主の確認は、カートと、要求した会員 ID（ログインしていなければなし）で行う。会員を持たないカートは、だれでも使える。

### カートを移す（AC-122、123）

ログインせずに使っていたカートの品目を、会員のカートへ移す。店舗画面のサーバーが、ログインの直後に 1 回呼ぶ。

- 移すカートの品目を、入れた順に、会員のカートへ入れる。同じバリアントは数量を合算し、10 を超えたら 10 に切り詰める。品目が 30 に達したら、残りの品目は移さない（移すカートの並びの後ろの品目から移さない）。
- 結果として、切り詰めた品目と、移せなかった品目（バリアントと数量）を返す。画面が一度だけ知らせる。
- 商品カタログ・在庫は確かめない（AC-123）。買えない品目は、カートの表示（AC-80）と注文（AC-88）で扱う。
- 移し終えたら、移すカートを空にする。同じカートを 2 回移しても、2 回目は空なので何も起きない（ログインの処理の二重の呼び出しに備える）。
- 移す元に指定できるのは、会員を持たないカートだけ。会員のカートを指定したら 404。
- 期限の切れたカートは空として扱う（AC-81）。
- 会員のカートが変わったら、カート変更のイベントを出す（その会員の注文手続きの引当を解く。AC-84）。移すカートも空になるので、変わっていればイベントを出す。

### 品目の追加と変更

- 同じバリアントを入れたら数量を合算する（AC-74）。品目は入れた順に並べる。
- 数量は 1〜10、品目は 30 まで（AC-75）。合算の結果で判定する。
- 入れるとき・数量を増やすときは、商品カタログで「C 側に表示される商品の、販売停止でないバリアント」かを（AC-72）、在庫で販売可能数が数量以上かを（AC-76）確かめる。数量を減らす・削除するときは確かめない。
- 確かめるのは追加・変更の時点だけ。その後に買えなくなった品目は、表示（AC-80）と注文（AC-88）で扱う。

### 期限

- 最終更新から 30 日たったカートは、読むときに空として扱う（AC-81）。次に書くときに、品目を消してから書く。
- 期限切れのカートの削除は、定期ジョブの方式が決まってから（spec 002 の Non-goals）。

## 構成

```
cart/
├── catalogdir/      # 商品カタログの API を自分の型に変換する腐敗防止層（選べるバリアントか）
├── stockdir/        # 在庫の API を自分の型に変換する腐敗防止層（販売可能数）
├── service/         # カート、リポジトリの port、エラー
├── infrastructure/  # リポジトリの実装
├── controller/      # OpenAPI（store.yaml）から生成したインターフェースを実装
├── api/             # 店舗・注文に公開する API
└── event/           # カート変更のイベント
```

- 入れるときの販売可能数は、自分の引当も数える（カートは注文手続きを知らないため）。注文手続きの途中でカートに戻って同じ品目を増やすと、自分の引当の分だけ少なく判定されることがある。引当はカートのほかの変更や 15 分の期限で解かれるので、実害は小さいとして受け入れる。

## 他モジュールへの公開

| 種類 | 内容 | 利用者 |
|------|------|--------|
| API | カートの品目・バージョン・会員 ID（期限切れは品目が空）、カートを空にする（注文の成立と同じトランザクション） | 店舗、注文 |
| イベント | カート変更（カート ID） | 注文（引当を解く） |

## データモデル

[V202610111100__cart_create_cart.sql](../../backend/ecsite/src/main/resources/db/migration/V202610111100__cart_create_cart.sql)、[V202610121100__cart_add_member_id.sql](../../backend/ecsite/src/main/resources/db/migration/V202610121100__cart_add_member_id.sql)

- バリアントは商品カタログモジュールの ID なので、外部キーは張らない（constitution 6）。
- 品目は入れた順の連番を持つ。保存では品目を入れ直すので、連番は入れた順に振り直される。
- 変更の保存は、バージョンが 1 つ前のときだけ行う。同じカートへの同時の変更は 409 になる。
- 会員 ID は会員モジュールの ID なので、外部キーは張らない。会員ごとに 1 つを一意制約で守る（同じ会員の初回の要求が同時に来ても、会員のカートは 1 つ）。
