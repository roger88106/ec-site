# Spec 455：エージェントの作業の流れの小さい問題を修正する

種類：整理　規模：M　ステータス：確定

危険度：高

## 背景と目的

担当のセッションの振り返り約 75 件を集計すると、エージェントの作業の流れの問題が多数あった。多くは skill・文書・script の数行の誤りや不足で、同じ問題が繰り返し出ている。例は 2 つある。検査の script に拒否され、同じコマンドを書き換えた（47 件）。skill `local-dev` の、作業ツリーのスロットで画面を起動する手順が失敗する（8 件）。

この spec は、issue の「整える」の項目を、skill・規則・script・雛形に入れる。消費者・運営者に見える振る舞いと、製品のコードは変えない。追跡の issue は #455。

## スコープ

| 含める | 含めない |
|--------|----------|
| 利用者と決めた 3 つ（「決定：」の最初の 4 つの箇条） | Claude Code の側の仕様に関わる 3 つ（組み込みの `/code-review` の level、auto mode によるマージの許可の拒否、文脈の圧縮の後に規則から外れること） |
| skill `local-dev` の手順と、`scripts/dev/` の script（書き換えの script、サーバーの停止） | 校閲の手順（skill `review` の docs-review.md）、文書の書き方の skill、各 template.md（#454 で扱う） |
| サブエージェント（実装役）の定義と、skill `sessions`・`review`・`agent-retro` の手順、pull request の雛形 | hook（`scripts/dev/hooks/`）の判定の変更 |

決定：

- push：最初の push を、draft の pull request を作る直前にする。段階の途中で push してよい場合（CI でしか確認できないこと、バックアップ、引き継ぎの前）は今のまま残す。
- コミットメッセージの書き換え：push していない commit のメッセージを、非対話の rebase で書き換える script を `scripts/dev/` に置く。入力は対応表で、commit と新しいメッセージのファイルの組を並べたものである。
  - 書き換えの前に、作業ツリーに未 commit の変更がないことを確認する。対応表に push 済みの commit があるときは、状態を変えずに失敗する。
  - 途中で失敗したら、rebase を中止して元の状態に戻し、0 以外の終了コードで終わる。
  - 書き換えるのはメッセージだけで、各 commit の内容（tree）が変わらないことを確認する。各 commit の書き換えは commit の hook を通す。
- 規模 S と危険度：実装の前に、危険度の script を手元で実行し、危険度を確認する。規模 S で危険度が高いときは、規模 M と同じレビュー（spec の最後のレビューに当たるもの）を行う。レビューの記録は pull request の本文の節に書く（節は雛形に既にある）。
- 推定で判定する検査：検出すべき例と検出してはいけない例の表を plan（規模 M は spec）に置く既存の規則（文書の構成の「形を判定する検査」）を、hook にも当てる。plan の雛形に、その表の節を置く。レビュー役はその表と照合する。表にない書き方のうち、検査を意図的に回避するものは既知の制限とし、重要度「高」にしない。同じ種類の指摘が 2 回続いたら前提を替える（既存の規則）。
- サーバーの停止：スロットの script に停止のコマンドを追加する（対象を選べる。スロット 0 でも動く）。ポートで待ち受けるプロセスを探して停止する、既存の処理を使う。
- 起動の指示の雛形：skill `sessions` にある、予備のセッションに引き継ぐための雛形を書き換える。新しく起動するときも、予備に渡すときも、同じ 1 つの雛形を使う。
- 実装役に守らせる項目は、実装役の定義に書く（実装役への指示の雛形が今はないため）。
- 危険度が低い pull request のマージは、今の規則（issue 担当のセッションがマージする）のまま。起動の指示の雛形に書く。
- 既存の指摘の一覧（#252）へのコメント：spec 担当のセッションは pull request の本文の節に書き、issue 担当のセッションがマージの後に #252 へ転記する。権限の設定は変えない。

## 目的と完了条件

### DS-455-1 commit のメッセージを校閲の後で書き換えられる（D / P1）

- **DC-455-1** 開発の進め方の「push のタイミング」が、最初の push を、draft の pull request を作る直前としている。AGENTS.md の Git の表と skill `sessions` の雛形は、それと食い違わない。
- **DC-455-2** 書き換えの script が、push していない commit のメッセージを対応表のとおりに書き換え、内容（tree）を変えない。テストで確認する。
- **DC-455-3** 書き換えの script は、対応表に push 済みの commit か誤りがあるとき、または作業ツリーに未 commit の変更があるとき、状態を変えずに失敗する。テストで確認する。
- **DC-455-4** 書き換えの script が、書き換えの途中で失敗したとき、rebase を中止して元の状態に戻し、0 以外の終了コードで終わる。一時のリポジトリで動かすテストで確認する。
- **DC-455-5** skill `local-dev` に、書き換えの script の使い方がある。

### DS-455-2 規模 S でも危険度に合ったレビューをする（D / P1）

- **DC-455-6** エージェントの作業フローの「レビューの時点と profile」に、実装の前に危険度の script を実行する規則がある。
- **DC-455-7** 同じ節に、規模 S で危険度が高いときに規模 M と同じレビューをする規則がある。
- **DC-455-8** pull request の雛形の「レビューの記録」の節の説明が、規模 S（危険度が高いときを含む）の書き方と合う。

### DS-455-3 推定で判定する検査のレビューが収束する（D / P1）

- **DC-455-9** 例の表（検出すべき例・検出してはいけない例）を置く規則の対象に hook が含まれ、plan の雛形にその表の節がある。
- **DC-455-10** レビュー役の指示の雛形に、例の表と照合する規則と、表の外の意図的な回避を既知の制限として重要度「高」にしない規則がある。

### DS-455-4 skill `local-dev` の手順で、拒否と失敗の往復がなくなる（D / P1）

- **DC-455-11** 作業ツリーのスロットの画面は、スロットの script をバックグラウンドで実行してから、プレビューのツールに URL を渡して開く手順になっている。
- **DC-455-12** 検査に拒否されない書き方が、skill の始めの近くにある。バックスラッシュを含む置き換えは、Edit か Write した script で行う。コミットメッセージは、ファイルに書いて検査してから渡す。避ける語の一覧を、先に読む。
- **DC-455-13** commit の失敗を見逃さない書き方がある。commit の出力を `tail`・`grep` に通さない。`;` でつながない。commit の後に最新の commit を確認する。
- **DC-455-14** issue を本文とコメントの JSON で読む書き方が、skill `local-dev` と skill `sessions` の全ての箇所で使われている。
- **DC-455-15** スロットの script の停止のコマンドが、スロットのポートで待ち受けるプロセスを停止する。テストで確認し、skill の停止の手順がそれを使う。
- **DC-455-16** commit の hook が実行する検査を、commit の前に手動で重ねて実行しない、という手順がある。
- **DC-455-17** CI の待ち方がある。バックグラウンドで待つ。ワークフローの名前で絞る。ready の後に、危険度のワークフローの再実行を確認する。
- **DC-455-18** 環境の準備が、次の 3 つある。JAVA_HOME がないときの対処。Docker のエンジンが応答しないときの確認と、復旧した後に Gradle のデーモンを停止すること。新しい作業ツリーでの API の型の生成。
- **DC-455-19** Git Bash と Windows の挙動の違い（`cat >` の入力待ち、バックグラウンドの処理とパイプ、`MSYS_NO_PATHCONV`、`grep -P`、Grep のブレース）がある。
- **DC-455-20** Browser での画面の確認（localhost の Cookie が蓄積する、CSP の違反の読み方、バックグラウンドのタブで描画が停止する）がある。
- **DC-455-21** `claude -p` での動作の確認（プロンプトは標準入力で渡す、失敗したらログインの状態を確認する）が、skill `sessions` の「ツールの補足」にある。

### DS-455-5 サブエージェントとセッションの指示が雛形で揃う（D / P1）

- **DC-455-22** 実装役の定義に、次の 5 つがある。
  - 作業ツリーの絶対パスを確認する。
  - レビューの指摘の修正でも、テストと実装を分けてレッドを確認する。
  - テストの失敗を確認するために壊したコードは、Edit で元に戻す。
  - 作業ツリーでは IDE の MCP を使えない。
  - ツールの呼び出しが多くなったら、区切りのよい時点で結果を返す。
- **DC-455-23** skill `sessions` に、担当のセッションを起動する指示の雛形がある。雛形は、確認の宛先、作業ツリーの作り方、並行している作業の状況、マージの許可と後片付けを含む。雛形にマシン固有のパス、セッションの識別子、手元の呼び名を書かない。
- **DC-455-24** skill `review` に、レビュー役を起動したら、結果がそろうまで対象を変えない、という手順がある。
- **DC-455-25** 作業ツリーのセッションが書く振り返りとレビューの結果の置き場が、skill `agent-retro` と skill `review` で同じ書き方になっている。
- **DC-455-26** 件数は結果のファイルの行を数えて書く、という手順が skill `review` にある。
- **DC-455-27** 危険度が低い pull request のマージの担当が、起動の指示の雛形に書かれている。
- **DC-455-28** 既存の指摘の一覧への転記の担当が、書き方の規則とレビューの「レビューの収束」と、pull request の雛形に書かれている。

### DS-455-6 検査が通る（D / P1）

- **DC-455-29** `scripts/ci/check-all.sh`（CI と同じ条件）が通る。

## 非機能要件

- **DN-455-1** 消費者・運営者に見える振る舞いと、製品のコードを変えない。
- **DN-455-2** #454 が変えるファイルを変えない。対象は、skill `docs`、skill `review` の docs-review.md、文書の書き方と構成の規則、各 template.md、校閲役の定義、`scripts/ci/` の文書の検査である。ただし、文書の構成の「形を判定する検査」の 1 文は、この spec が変える。両方の issue が変えるファイル（エージェントの作業フロー、開発の進め方、skill `review`）は、この spec の行だけを変える。
- **DN-455-3** アーカイブした spec を変えない。
- **DN-455-4** hook の判定を変えない。
