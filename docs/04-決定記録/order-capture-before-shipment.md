# 出荷の登録で、注文を出荷済みにする前に売上を確定する

## 背景

出荷の登録は、次の 2 つからなる。

- 決済サービスでの売上確定
- 注文を出荷済みにして、出荷を作る DB の更新

決済サービスはトランザクションの外で呼ぶ（[注文モジュール](../03-機能仕様/order.md)の「支払」）。外部の呼び出しは DB のロールバックで取り消せないため、2 つは 1 つのトランザクションにできず、どちらかが先になる。2 つの間で失敗すると、片方だけが残る。

## 選択肢

| 選択肢 | 良い点 | 悪い点 |
|--------|--------|--------|
| A：売上確定を先にする | 失敗の後に残るのは「売上確定済みで出荷なし」である。売上が確定していない注文は、出荷済みにならない。「売上確定済みで出荷なし」は、再登録かキャンセルで解消する | 確定の後に注文が受付でなくなると、売上確定済みのまま残る |
| B：出荷済みを先にする | — | 失敗の後に残るのは「売上が確定していないのに出荷済み」 |

選択肢 B の出典は、書き換え前の注文モジュールの理由の文（commit d0029132 の `docs/03-機能仕様/order.md`）である。

## 結論

A を選ぶ。

- 売上が確定していないのに出荷済みになる注文を作らないため。
- 逆向きの「確定済みで出荷なし」は、再登録かキャンセル（返金）で解消されるため許す。

受け入れた結果が起きたときの扱い（確定の後に注文が受付から変わった、与信期限切れ、決済サービスへの接続の失敗）は、[注文モジュール](../03-機能仕様/order.md)の「出荷の登録」に書く。
