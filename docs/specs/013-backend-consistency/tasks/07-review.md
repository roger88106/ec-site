## レビューの結果

### 修正したこと

- 生成したモデルを、引数なしのコンストラクターと項目名のメソッドで組み立てた（plan の調べで 7 モジュール 50 か所）。作成の応答（201、Location、作成した ID）を共通の補助にした。
- 版の比べ方と、集約を戻すときの失敗の扱いを、共通の補助 1 か所にした。明細の小計の掛け算を `Money` の操作にした。
- order：注文の詳細を view で返し、presentation が集約を受け取らない形にした。注文手続きの参照を参照の service に分けた。値の型を `vo/` に移した。
- payment：更新の service の読み取りのメソッドを参照の service に移した。与信期限・支払えるかの判定を支払の集約に任せ、期限切れにする処理を 1 か所にした（DC-138）。
- 定期の処理の間隔を設定の型で受け、起動の時に検証する。設定の型を有効にする宣言を設定のクラスに置いた。
- mock の画面の HTML を、モジュールごとに 1 つの補助にまとめた。使われないコードを削除し、テストだけが使うコードにテスト用と書いた。
- ArchUnit の規則を 3 つ追加した（レベル A の presentation が集約に依存しない、生成したモデルの組み立て方、`@EnableConfigurationProperties` の置き場所）。
- レビューで、catalog の商品の詳細の view の価格が整数だったので `Money` にした。

### 修正せずに残したこと

| 項目 | 理由 |
|------|------|
| AC-154 のテストの、間隔の文字列の解決方法を変えた | 間隔を設定の型から SpEL で取ると、`${}` だけで解決するテストが通らない。利用者と決めて DN-15 の特例にした（spec 第 6 節）。確認する中身は変えていない |
| catalog の商品のバリアントと画像の追加の応答に Location がない | spec の Non-goals。作成の応答の補助を使わず、状態と本文だけを返す |
| `@Scheduled` の SpEL が、設定の型の Bean の長い名前を書く | `@EnableConfigurationProperties` で登録した Bean の名前は「接頭辞-完全修飾名」に決まっている。コメントに書いた |

既存のテストを広げると DN-15 を超えるので、テストを変えてよい spec で扱う。

- `ModuleStructureTest` のレベル A の一覧に payment がない（`ModuleRoleTest` にはある）。
- 金額の型の ArchUnit（`MoneyTypeTest`）が `application/model/view/` を見ていない。今回の catalog の view の価格は、レビューの grep で検出した。
