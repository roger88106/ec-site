# Spec 381：AC-108、110、111、112 の文を、パスワードを確認メールのリンク先の画面で設定する流れに合わせる

種類：整理　規模：M　ステータス：確定

## 背景と目的

AC-108 の今の文「店舗から会員登録の画面に遷移し、メールアドレス、パスワード、氏名で登録できる。」は、会員登録の画面でパスワードを入力すると解釈できる。実際の画面にはパスワードの欄がなく、確認メールのリンク先の画面で設定する。AC-110〜112 の文も、パスワードを設定する時点を反映していない（下の照合の表）。

AC の文を今の振る舞いに合わせる。消費者・運営者に見える振る舞いは変えない。追跡の issue は #381。出典は #252 のコメント（spec 345 で見つけた、重要度「必須」の既存の問題）。

### 元の意図（MVP-003 の記録）

- MVP-003 の spec（`docs/08-spec/archive/mvp/003-auth/spec.md:40`）の AC-108 の定義は、パスワードを含む今の文のまま。
- MVP-003 の plan（`docs/08-spec/archive/mvp/003-auth/plan.md:85`）の行「会員登録の流れ」は、対応する AC を 108、110〜112 とし、流れを次のように決めている。「メールアドレスと氏名を入れる → 確認メール → リンクを開く → パスワードを設定する（Keycloak 26.8 は、メールアドレスの確認が必須のとき、登録の画面にパスワードを表示しない）。確認の前はパスワードがないので、ログインできない。」
- したがって、今の流れは MVP-003 の plan で決めた設計で、不具合ではない。AC の文だけが更新されずに残った。コードが正しく文書が古いので文書を修正する（[開発の進め方](../../05-開発規則/workflow.md)の「コードと文書の食い違い」）。issue に書かれた「この判断は推測である」は、この記録で確認できた。

### 確認の方法の限界

- 読んだのは E2E、realm の設定、テーマの設定（`docker/keycloak/themes/ec-site/login/theme.properties`。テーマは色と書体だけを上書きするので、入力欄を変えない）、MVP-003 の記録である。この照合のために E2E や Keycloak を実行していない。
- 次の 3 つは自動のテストで確認していない。
  - AC-110：テスト（`RealmSettingsContractTest.java:48`）は realm の設定の値だけを確認する。条件を満たさないパスワードを画面で入力し、拒否されることを確認する E2E はない。
  - AC-111：パスワードを設定する前にログインできないことを確認する E2E はない（根拠は MVP-003 の plan の記述）。
  - AC-112：別のブラウザーで開く場合の E2E はない（根拠は MVP-003 の plan の ※1 と、`docs/01-概要/member.md`、`docs/02-設計/backend-architecture.md:201`）。

決定：

1. 規模は M にする。理由：[開発の進め方](../../05-開発規則/workflow.md)の「規模」の表で、AC を変える変更は M 以上であるため。AC 一覧の列「変えた spec」に番号を書くには spec のディレクトリが必要である（`scripts/ci/ac-check.mjs` の検査）。
2. 振る舞いを変えない文の修正なので、整理の spec で行う。[開発の進め方](../../05-開発規則/workflow.md)の「コードと文書の食い違い」の、コードが正しく文書が古いときの扱いに当たる。元の意図は MVP-003 の plan と一致している（上の根拠）。
3. AC-110、111、112 も同じ spec で修正する。理由：照合で、いずれもパスワードを設定する時点と差があったため（照合の表）。
4. 根拠の文書は、4 つの AC とも `docs/01-概要/member.md` の「業務の流れ」にする。理由：[起票と記録の操作](../../05-開発規則/issues.md)の「AC 一覧の操作」に、状態が「変更」の AC の今の内容に根拠を添える規則があり、会員登録の流れを書いているのはこの節であるため。`docs/03-機能仕様/member.md` に流れの節はない。この spec では追加しない。
5. AC-111 は「メールアドレスの確認」の語を残す。理由：`verifyEmail` の設定が確認を必須にしており、テスト名（`RealmSettingsContractTest.java:56`）もその語を使っているため。

```
店舗から会員登録の画面に遷移し、メールアドレスと氏名で登録できる。パスワードは、会員登録の画面でなく、確認メールのリンク先の画面で設定する。これらの画面とログインの画面は IdP が表示する。根拠は[会員登録とログインの流れ](../01-概要/member.md)の「業務の流れ」。

```

AC-111：

```
登録すると確認メールが届く。メールのリンクでメールアドレスを確認し、パスワードを設定するまでは、ログインできない。根拠は[会員登録とログインの流れ](../01-概要/member.md)の「業務の流れ」。

```
