# Spec 415：ログインの直後にカートを移せなかったときに、カートを残して、カートの画面で再試行する

種類：機能　規模：M　ステータス：確定

## 背景と目的

ログインの直後に、ログインせずに使っていたカート（以下、Cookie のカート）の品目を、会員のカートへ移す。移せなかったときは、警告のログを書くだけで利用者に知らせず、Cookie のカートの ID を必ず削除する。Cookie のカートは DB に残るが、利用者は ID を失うので、そのカートを再び使えない。移す前のカートの取得が例外になったときも、移さずに ID を削除する。

この動きは、[店舗画面の構成](../../02-設計/apps/store.md)の「使うカートの選び方」のとおりである（移せなくても削除する）。この spec は、移せなくても削除する設計を誤りとして扱う。設計が削除する理由は、ログインしている間は Cookie のカートを使わず、残すとログアウトの後に古いカートが見えるためである。ログアウトで Cookie のカートの ID を削除する処理が追加されたので、この理由はログアウトについては当てはまらない。

[カートモジュール](../../03-機能仕様/cart.md)の「カートを移す」は、移し終えたら移すカートを空にするので、2 回呼ばれても 2 回目は品目を移さない。そのため、タイムアウトで実際には移っていても、もう一度呼んでよい。

ログインの直後に移す処理のテストのうち、名前に AC-124 を付けたテストは、移せなかったときの動きを確認している。AC-124 はログアウトの AC で、テストの内容と食い違う。

追跡の issue は #415。利用者の決定（issue のコメント、2026-11-06）は、次の 3 つ。

- カートの画面を開いたときに、カートを移す処理を再試行する。
- Cookie のカートの ID を残すのは一時的な失敗（5xx、例外）のときだけにし、404 と 400 では削除する。
- 知らせの文言と Cookie の形式は担当のセッションが決める。

2 つ目の決定は、401 についてこの spec で変える。401 でも Cookie のカートの ID を残す（決定 2）。利用者が 2026-11-09 に承認した。

## スコープ

| 含める | 含めない |
|--------|----------|
| ログインの直後に移せなかったときの扱い | ログアウトの処理 |
| カートの画面での再試行と、その結果の表示 | ログインの直後のタイムアウトの長さ |
| テスト | カート以外の画面での再試行 |
| AC 一覧と店舗画面の構成の更新 | E2E のテスト |

含めないものの理由は Non-goals に書く。

決定：

1. 規模は M にする。理由：AC を追加するが、API の契約と DB の構造を変えず、店舗画面だけを変えるため。
2. カートを移した結果を、次の 4 つに分ける。分ける判定は関数にして、単体テストを書く。
   - 移せた（200）：Cookie のカートの ID を削除する。
   - 移すカートがない、または ID が不正（404、400）：Cookie のカートの ID を削除し、何も表示しない。理由：再試行しても結果が変わらず、移す品目もないため。
   - 一時的な失敗（5xx、例外）：Cookie のカートの ID を残す。
   - ログインが切れている（401）：Cookie のカートの ID を残す。カートの画面での再試行では、ログインの画面へリダイレクトする。理由：ログインの直後に、もう一度移すため。
3. 移す前のカートの取得（品目の商品名を知らせに使う）が例外になったときも、一時的な失敗として扱う。
4. カートの画面を開いたとき、ログインしていて Cookie のカートの ID があれば、再試行する。理由：ログインしている間に ID が残るのは、移せていないときだけであるため（移せたとき、移すカートがないときは削除する）。
5. 再試行は、カートの画面のクライアントコンポーネントが、表示の後にサーバーアクションを呼んで行う。再試行している間は、カートを移していることを読み上げの領域に表示する。再試行の後は、カートの画面を再表示する。理由：サーバーコンポーネントは Cookie を書けないため（[店舗画面の構成](../../02-設計/apps/store.md)の「カート ID の Cookie」）。
6. 再試行の結果は、サーバーアクションの結果としてコンポーネントに返し、コンポーネントが表示する。知らせの Cookie は使わず、その形式も変えない。理由：知らせの表示のコンポーネントは、最初に受け取った知らせを保持するので、表示の後に書いた知らせの Cookie は表示されないため。
   - 移せた：切り詰めた品目と移せなかった品目があれば、ログインの直後と同じ形（AC-123）で表示する。
   - 一時的な失敗：移せなかったことと、カートの画面をもう一度開くと再試行することを表示する。文言は実装のタスクで決める。
   - 移すカートがない、または ID が不正：何も表示しない。
7. ログインの直後に移せなかったときは、知らせの Cookie を書かない。理由：知らせを表示するのはカートの画面だけで、カートの画面を開くと再試行するので、再試行の結果を表示すれば足りるため。
8. 移す API の呼び出しと結果の区分を 1 か所に置き、ログインの直後の処理とカートの画面の再試行で共有する。違いは token の渡し方だけで、ログインの直後はログインで得た token、再試行はセッションの token を渡す。

   | 論理名 | 識別子 |
   |--------|--------|
   | ログインの直後の処理 | `mergeCartAfterLogin`（`frontend/store/src/api/cart.ts`） |
   | 移す API | `POST /me/cart/merge` |
   | 知らせの Cookie | `cart_merge_notice` |
   | 知らせの表示のコンポーネント | `CartMergeNoticeView` |

9. 店舗画面の構成の「使うカートの選び方」の、移す処理の箇条と注を、この spec の動きに合わせて書き換える。追記でなく、節の全体を読んで書き換える。

## 受け入れ条件

### US-415-1 移せなかったカートを後で移せる（C / P1）

- **AC-415-1** ログインの直後に一時的な失敗（5xx、例外）でカートを移せなかったときは、Cookie のカートの ID を残す。
- **AC-415-2** ログインしていて Cookie のカートの ID があるときにカートの画面を開くと、カートを移す処理を再試行する。
- **AC-415-3** 再試行で移せたときは、移した品目を含む会員のカートを表示する。
- **AC-415-4** 再試行で移した結果が上限を超えたときは、ログインの直後と同じく、切り詰めた品目と移せなかった品目を表示する（AC-123）。
- **AC-415-5** 再試行も一時的な失敗のときは、カートを移せなかったことを表示し、Cookie のカートの ID を残す。
- **AC-415-6** 移すカートがない、または ID が不正（404、400）のときは、Cookie のカートの ID を削除し、何も表示しない。
- **AC-415-7** 再試行している間は、カートを移していることを表示する。
- **AC-415-8** 再試行のときにログインが切れていれば、Cookie のカートの ID を残して、ログインの画面へリダイレクトする。

## 非機能要件

- **NFR-415-1** API の契約とバックエンドを変えない。
- **NFR-415-2** 移せなかったときの警告のログに、カートの ID（Cookie の値）を出力しない。ログインの直後の処理と同じ扱いを、再試行にも当てはめる。理由：ID を知った人は、ログインせずにそのカートを操作できるため（[カートモジュール](../../03-機能仕様/cart.md)の「カート」）。

## Non-goals

| 項目 | 理由 |
|------|------|
| ログアウトで Cookie のカートの ID を削除する処理 | 変えると AC-124（ログアウトするとブラウザーのカートは空に見える）が変わるため ※1 |
| ログインの直後のタイムアウトの長さ（30 秒） | 店舗 API の全体の設定で、カートを移す処理だけの問題ではないため |
| カート以外の画面での再試行 | 利用者の決定がカートの画面を開いたときで、注文手続きはカートの画面から始めるため |
| E2E のテスト | 移す API だけを失敗させる手段が E2E の環境にないため。手動の確認（T415-01-10）で代える |

※1：移せないままログアウトしたときは、Cookie のカートの ID が削除されるので、そのカートは再び使えない。
