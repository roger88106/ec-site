# Spec 369：AC-78 の文を、減量と削除に販売可能数の確認が適用されない形に書き換える

種類：整理　規模：M　ステータス：確定

## 背景と目的

AC-78 の文は「品目の数量を変更（AC-75、76 の範囲で）・削除できる。」で、字義どおりに読むと、減量にも AC-76（入れた後の数量が販売可能数を超えると拒否）が適用される。実際の振る舞いは、数量を増やすときだけ販売可能数を確認し、減らす操作と削除は確認しない。例：数量 5、販売可能数 2 の品目を 4 に減らす操作は受け付ける。

文とコードが食い違うので、AC の文をコードの振る舞いに合わせる。消費者・運営者に見える振る舞いは変えない。追跡の issue は #369。出典は #346 のレビュー。

## スコープ

| 含める | 含めない |
|--------|----------|

| | 「変更」の操作で数量 0 を拒否するテストの追加 |

決定：

- 規模は M にする。理由：[開発の進め方](../../../../05-開発規則/workflow.md)の「規模」の表で、AC を変える変更は M 以上であるため。AC 一覧の列「変えた spec」に番号を書くには、spec のディレクトリが必要である（`scripts/ci/ac-check.mjs` の検査）。
- 振る舞いを変えない文の修正なので、整理の spec で行う。[開発の進め方](../../../../05-開発規則/workflow.md)の「コードと文書の食い違い」にある、コードが正しく文書が古いときの扱い（文書を修正する）に当たる。同じ節の「完了した spec の AC を変える振る舞いの変更（上限の値を変える、など）は、新しい機能の spec で行い、AC 一覧の行で示す。」と、続く整理の spec の制限（整理の spec で行うのは、レビューで見つけた不具合の修正だけ）は、振る舞いの変更についての規則なので当たらない。
- 元の意図もコードの振る舞いと一致しているため、文を修正してよい。根拠は次の表のとおり。

  | 根拠 | 場所 | 内容 |
  |------|------|------|
  | MVP-002 の tasks | `docs/08-spec/archive/mvp/002-cart-and-order/tasks/02-cart.md:18` | 「数量の変更・削除（AC-78）。減らすときは販売可能数を確認しない」 |
  | 統合テスト | `backend/ecsite/src/integrationTest/java/com/ecsite/module/cart/presentation/CartApiTest.java:197` | 「AC-78 数量を変更できる。増やすときは販売可能数を超えると 400、減らすときは確認しない」 |
  | カートの機能仕様 | [カートモジュール](../../../../03-機能仕様/cart.md)の「品目の追加と変更」 | 増量の確認と、「減量・削除：確認しない」の行 |

- AC-75（数量は 1〜10）は、増減によらず変更の操作に適用される。コードは数量を変えるたびに範囲を確認し、統合テストと単体テストが、数量 11 が拒否されることを確認している（`CartApiTest.java:220`、`backend/ecsite/src/test/java/com/ecsite/module/cart/domain/CartTest.java:123`）。そのため、新しい文にも AC-75 の範囲を残す。
