# seed

開発と E2E で使うデータ。`db/seed/` の下に、使う profile ごとに分けて置く（`application-local.yml` と `application-e2e.yml` の `spring.flyway.locations`）。
本番相当の環境と統合テストには適用されない（バックエンドのアーキテクチャ 第 6.2 節）。

| 置き場所 | 中身 | 使う profile |
|----------|------|--------------|
| `db/seed/base/` | ローカルと E2E の両方に必要なデータ：税区分と税率（送料の税区分の固定の ID を含む） | local、e2e |
| `db/seed/local/` | 画面で見るためのサンプルデータ：カテゴリ、商品、在庫、注文と支払など | local |
| `db/seed/e2e/` | E2E だけに必要なデータ。今は無いので置いていない。必要なものが出たら作る | e2e |

- E2E は、テストのたびに必要なデータを API で作る（`e2e/src/data.ts`）。`db/seed/local/` のデータに頼らない。
- 新しいデータは、まず `local` に置く。E2E も必要なら `base` に、E2E だけが必要なら `e2e` に置く。
- 注文には、状態に合う支払を必ず入れる（`R__payment_seed.sql`）。支払のない注文は、出荷の売上確定で支払が見つからない。与信の参照は mock の形にするので、売上確定は mock でだけ通る（[開発環境の起動](../../../../../../../../docs/dev/setup.md)「Stripe で動かす」）。

## 書き方

- Flyway の繰り返し実行のマイグレーション（`R__<モジュール>_seed.sql`）にする。
  - 繰り返し実行のマイグレーションは、すべてのバージョン付きのマイグレーションの後に実行されるので、テーブルが必ず先にある。
  - 内容を変えると、次の起動時に再実行される。各段階では、モジュールのファイルに追記する。
  - ファイル名は、`base`・`local`・`e2e` を通して重ねない（Flyway は名前で繰り返し実行のマイグレーションを見分けるため）。
- 何度実行しても同じ結果になるように書く（`INSERT ... ON CONFLICT (id) DO UPDATE` など）。
- ID は固定の UUID にする。画面や `.http` から同じデータを指せるようにするため。
- データ（名称など）は日本語で書く（開発の進め方 第 3 節）。

例：

```sql
INSERT INTO tax.tax_category (id, name, version, created_at, updated_at)
VALUES ('00000000-0000-0000-0000-000000000001', '標準', 0, now(), now())
ON CONFLICT (id) DO UPDATE SET name = EXCLUDED.name;
```

## レポート用の注文

レポートの画面で意味のある数字を見るため、2024-10-01〜2026-09-30 の 2 万件の注文を、SQL で作る。空の DB から流すと 15 秒ほどかかる。
期間は固定の日付なので、時が経つと「今月」「今年度」の数字は出ない（2024-10-01〜2026-09-30 を選ぶ）。

| ファイル | 中身 |
|----------|------|
| `R__member_seed.sql` | レポート用の会員 300 人（IdP のアカウントはなく、ログインできない） |
| `R__ordering_seed.sql` | 注文と明細と消費税。日時の筋と状態の割合は、このファイルの冒頭に書く |
| `R__payment_seed.sql` | 注文の状態に合う支払（与信済み、売上確定済み、支払なし、与信の取消済み、返金済み） |
| `R__shipping_seed.sql` | 出荷済みと返送の出荷。seed の「今」（2026-10-01 0 時）より後に進むはずの配送状態は、そこで止める |
| `R__zz_reporting_seed.sql` | 今の 4 件を含むすべての注文の、レポートの写しと状態の履歴 |

- 注文の日時の筋（受付、申請、出荷、返送など）は注文の seed だけに書き、支払・出荷・写しの seed は注文の行から作る。返送でのキャンセルは、キャンセルの理由で見分ける。
- 乱数は、番号と用途の文字列の md5 から作る（固定の種）。何度再作成しても同じ注文になる。
- Flyway は繰り返し実行のマイグレーションを名前の順に流す（`base` と `local` を通して）。後の名前の seed は読めないので、税率は税区分の固定の ID から決め、写しの seed は名前を `zz` で始める。
- 在庫は、この注文の分を出庫していない。

### お届け先

実在する郵便番号・都道府県・市区町村の組み合わせ 55 件から選ぶ。

- 出典：日本郵便「郵便番号データダウンロード」の住所の郵便番号。55 件すべてを、郵便番号から住所を引いて確認した（2026-10-15）。
- 選び方：25 の都道府県の、県庁所在地や大きな駅の周り。人口の多い都道府県ほど選ばれやすいよう、都道府県の人口（2020 年の国勢調査、10 万人単位）を、その都道府県の件数で割った重みを付ける。
- 番地より後（`1-2-3` など）は架空の値。
- 都道府県と市区町村のコードは、地域のマスターデータ（`region` の表）を名前で引く。名前を変えて引けなくなると、注文の seed が NOT NULL の制約で失敗する。
