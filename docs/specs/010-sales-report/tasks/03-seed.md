## 測った結果（T0306、T0307）

段階 6 のレビューの結果に書くため、ここに残す。2026-10-15、開発マシン（Windows 11、Docker の PostgreSQL）で、ローカルの DB を再作成した直後に測った。

| 測ったもの | 結果 |
|------------|------|
| マイグレーションと seed（空の DB から） | 14.9 秒（注文 7.3 秒、写しと履歴 5.3 秒）。起動まで 21 秒 |
| 売上の推移（2 年、週、全商品） | 初回 0.42 秒、2 回目から 0.10 秒 |
| 売上の推移（2 年、月、出荷基準、消費税を除く） | 0.09 秒 |
| 売上の推移（2 年、四半期、商品を選ぶ） | 0.02〜0.04 秒 |
| バリエーションの売れ行き（2 年） | 0.04〜0.08 秒 |
| 地域・年齢層・性別（2 年、全商品） | 0.02〜0.05 秒 |
| 地域・年齢層・性別（2 年、商品を選ぶ、出荷基準） | 0.02 秒 |

- どれも plan 第 9 節の API 1 秒以内を満たし、索引は追加していない。
- seed の直後、表の統計を取る前に集計すると、商品を選んだ売上の推移が 2.7 秒かかった（統計がないため、非効率な実行計画が選ばれた）。写しの seed の最後で統計を再取得するようにした。本番相当の環境では、写しはイベントで少しずつ増えるので起きない。
