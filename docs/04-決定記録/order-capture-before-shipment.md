# 出荷の登録で、注文を出荷済みにする前に売上を確定する

## 背景

出荷の登録は、次の 2 つからなる。

- 決済サービスでの売上確定
- 注文を出荷済みにして、出荷を作る DB の更新

決済サービスはトランザクションの外で呼ぶ（[注文モジュール](../03-機能仕様/order.md)の「支払」）。このため 2 つは 1 つのトランザクションにできず、どちらかが先になる。2 つの間で失敗すると、片方だけが残る。

## 選択肢

| 選択肢 | 良い点 | 悪い点 |
|--------|--------|--------|
| A：売上確定を先にする | 失敗の後に残るのは「売上確定済みで出荷なし」で、売上が確定していない注文が出荷済みにならない。再登録かキャンセルで解消される | 確定の後に注文が受付でなくなると、売上確定済みのまま残る |
| B：出荷済みを先にする | — | 失敗の後に残るのは「売上が確定していないのに出荷済み」 |

## 結論

A を選ぶ。

- 売上が確定していないのに出荷済みになる注文を作らないため（以前は[注文モジュール](../03-機能仕様/order.md)の「出荷の登録」の本文に書いていた理由を、ここに移した）。
- 逆向きの「確定済みで出荷なし」は、再登録かキャンセル（返金）で解消されるため許す。再登録は、決済の API が売上確定済みなら決済サービスを呼ばずに成功を返すので、確定が重ならない。

受け入れた結果は次のとおり。

| 場面 | 結果 |
|------|------|
| 確定の後に注文が受付でなくなっていた（キャンセル申請など） | 409 にする。売上確定済みのまま残り、再登録すると決済サービスを呼ばずに進む。キャンセルになったら返金される |
| 与信期限切れ | 409 にし、出荷は作らない |
| 決済サービスに接続できない | 502 にし、出荷は作らない |
