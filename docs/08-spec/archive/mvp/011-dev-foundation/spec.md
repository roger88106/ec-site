# Spec 011：開発の基盤の整理

ステータス：確定

## 1. 背景と目的

spec 010 で MVP の機能がそろった。MVP を完成させる前に、プロジェクト全体をレビュー、残りの整理を spec 011〜018 に分けた（一覧は plan で文書にする）。本 spec はその最初で、後の spec が全て頼る道具と手順を整える。

- tasks のタスク番号は spec の番号の下 1 桁を使うので、spec 011 から spec 001 の番号と重なる。段階の途中に追加したタスクは、番号の順に並ばない。
- CI の検査をローカルで一度に実行するコマンドがなく、CI で初めて失敗することがある。E2E の lint・型チェックはどの検査にも入っていない。AC とテストの対応の検査に、テストのまとまりの名前を対応とみなす漏れがある。CI の検査の script は、エージェントの skill にしか書かれていない。
- ローカルの DB を再作成する手順が複数のコマンドで、自動のモードでは止められる。DB の seed・画像・IdP の設定の 3 つの正本が、いっしょに再作成される保証がない。E2E の script は、前提のコンテナが止まっていても確認しない。
- CI が 13 分あまりかかり、10 分の目安を超えている。バックエンドのジョブ（約 7 分）が終わってから E2E（約 6 分）が始まる。
- Javadoc の書き漏れと、インスタンスを作らないクラスの書き方を、人手でしか確認できない。表示の文言の検査が、正規表現の中の引用符を文言の始まりと読む。
- 文書の一部が、会話の言語に固有の問題（中国語の混入）を扱っている。Git の文書では、日本語で書くことだけを求めればよい。
- Windows のポートの予約（WinNAT）で、ローカルの環境のポートが使えなくなることがある。対処の手順と script が、ローカルにしかない。

本 spec は整理の spec（[文書の記号と番号](../../../../rules/notation.md)）。消費者・運営者に見える振る舞いを変えない。

本 spec で新しく使う用語（MVP の完成までの一覧など）は、plan で用語集に追加する。

## 4. 目的と完了の条件

### DS-21 spec と tasks の番号が、spec が増えても重ならず、順に並ぶ（D / P1）

- **DC-73** spec 011 以降のタスク番号は、spec の番号をそのまま（桁を固定せず）含み、ほかの spec のタスク番号と重ならない。形式は文書の記号と番号にある。
- **DC-74** 段階の途中で追加するタスクは、その段階のファイルの末尾に、続きの番号で追加する。タスク番号の順と、ファイルの中の並びの順が同じになる。この規則が文書にある。
- **DC-75** spec 001〜010 の文書とコミットメッセージは変えない。番号を扱う検査の script は、古い形式と新しい形式の両方を読む。
- **DC-76** MVP の完成までの spec（011〜018）の一覧（目的、順序、状態）と、MVP の後に回した決定の一覧が 1 つの文書にあり、README の進捗の表から辿れる。

### DS-22 CI と同じ検査を手元で一度に実行し、commit の前に CI の結果が分かる（D / P1）

- **DC-77** CI の検査の script を全て実行するコマンドが 1 つある。検査の script を追加しても、このコマンドを修正する必要がない。
- **DC-78** E2E のコードの lint・型チェックが、ローカルの検査と CI の両方で実行される。
- **DC-79** AC とテストの対応の検査は、テストのまとまりの名前（入れ子のクラス、`describe`）だけにある AC を、対応とみなさない。
- **DC-80** 表示の文言の検査は、正規表現のリテラルの中の文字を文言とみなさない。その例が検査の script のテストにある。
- **DC-81** CI の検査の script の一覧と、それぞれが何を確認するかが、開発者向けの文書にある。エージェントの skill は、その文書を指す。
- **DC-94** commit の前の hook が、DC-77 の検査の script を実行する（テストは流さない）。hook を置く手順が、開発環境の起動の文書にある。

### DS-23 ローカルの環境を 1 つのコマンドで再作成でき、テストのデータの正本が Git にある（D / P1）

- **DC-82** ローカルの DB を 1 つのコマンドで再作成できる。再作成するのはローカルの DB だけで、E2E の DB と IdP には触れない。
- **DC-83** DB の seed、画像、IdP の設定の正本が全て Git にあり、ローカルの環境を全て再作成すると、3 つがそろった状態に戻る。手順が開発環境の起動の文書にある。
- **DC-84** E2E の script は、始める前に前提のコンテナ（DB、IdP、メール、画像のストレージと変換）が動いているかを確認し、停止していれば名前を示して終了する。

### DS-24 CI が 10 分以内に終わる（D / P1）

- **DC-85** CI の全体（push から全ジョブの完了まで）が、通常の commit で 10 分以内に終わる。spec の最後に、直近 3 回の時間を記録する。
- **DC-86** CI の各ジョブの時間の内訳（バックエンドのコンパイル・生成・テスト、E2E の準備とテスト）を測った結果と、選んだ短縮の方法が、plan にある。
- **DC-95** E2E のジョブは、バックエンドと画面のジョブの完了を待たずに始まる。理由：E2E が最も長いジョブで、待つと全体の時間が 2 つのジョブの時間の和になるため。

### DS-25 コードの書き方の規則を、機械で確認する範囲を広げる（D / P1）

- **DC-87** 公開のメソッドの Javadoc の書き漏れが、`check` で検出される。既存のコードの書き漏れは、本 spec で修正する。
- **DC-88** インスタンスを作らないクラスの書き方が、バックエンドの書き方の文書にあり、テストで確認する。

### DS-26 Git の文書が、日本語で書くことだけを求める（D / P1）

- **DC-89** Git の中の現行の文書と skill に、特定の言語の混入の検査を求める記述がない。日本語で書く規則は残す。完了した spec の記録は変えない。

### DS-27 環境に固有の問題（ポートの予約）の対処が、Git にある（D / P1）

- **DC-90** ローカルの環境が使うポートを、Windows のポートの予約から外す script と、予約の範囲に入ったときの対処の手順が Git にある。script は管理者の権限で動くことを明示し、何を変えるかを先に示す。
- **DC-96** Mailpit の SMTP の既定のポートは、Windows がよく使う 1025 でなく、誰の環境でも同じ設定で動く番号にする。

### DS-28 手元の作業の待ち時間と手間を減らす（D / P2）

- **DC-91** ローカルのビルドとテストの時間を測り、短縮の方法を選んだ結果が plan にある。効果が測れたものだけを入れる。候補には、起動中のバックエンドを再起動せずに、修正したコードを反映する仕組み（開発のときだけの依存）を含める。
- **DC-92** 機能紹介のページの数字（AC、テスト、spec の数）を、script で出せる。
- **DC-93** 開発のサーバーが自動で作るファイルが、Git の作業ツリーに残らない。

## 5. 業務ルール

なし（本 spec は業務の規則を変えない）。

## 6. 非機能要件

- **DN-10** API の応答、画面、データベースの構造とデータを変えない。既存のテストは、変えずに全て通る。例外：DC-79 の検査の修正で対応がないと分かった AC は、一覧にして spec 012 に回す（本 spec ではテストを追加しない）。
- **DN-11** CI を速くするために、検査を減らさない。同じ検査を、並列で実行するか、早くする。
