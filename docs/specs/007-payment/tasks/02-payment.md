## 支払

- [x] **T7202** [テスト] 支払の単体テスト（BR-15）：
  - 未払い → 与信済み → 与信の取消待ち → 与信の取消済み
  - 未払い → 支払なし
  - 支払なしで与信の成功を受けると、与信の取消待ちになる（AC-157）
  - 同じ遷移を重ねても変わらない。遷移できない通知は無視する（BR-17）
- [x] **T7203** 支払（集約）と状態を実装する。T7202 を通す。
- [x] **T7204** 支払のテーブルをマイグレーションで作り、リポジトリを実装する（注文 ID で一意）。

## API とジョブ

- [ ] **T7207** [テスト] 決済の API の統合テスト：
  - 注文 ID と総額と期限で支払（未払い）を作れる。同じ注文で 2 回作っても 1 つ
  - 支払の画面の URL を求めると、開いている画面があれば同じ URL を返す（AC-152）
  - 与信の成功の通知で与信済みになり、与信の成功のイベントが出る（AC-146）
  - 支払の状態を注文 ID でまとめて読める
- [ ] **T7208** 決済の API と、通知を処理するサービスを実装する。T7207 を通す。
- [ ] **T7209** [テスト] 期限切れのジョブの統合テスト：
  - 期限を過ぎた未払いの支払は、支払の画面を閉じて支払なしになり、期限切れのイベントが出る
  - 支払の画面を閉じられなかった（支払が済んでいた）ら、何もしない（AC-156）
  - 2 回流しても、イベントは 1 回だけ（NFR-7）
- [ ] **T7210** 期限切れのジョブを実装する（1 分ごと、分散ロック付き）。T7209 を通す。
- [ ] **T7211** [テスト] 与信の取消の統合テスト：
  - 与信済みの支払を取り消すと、与信の取消待ちになり、コミットの後に決済サービスで取り消して取消済みになる
  - 決済サービスが失敗したら取消待ちのまま残り、再発行で取り消される（AC-164）
  - 取消済みの支払を重ねて取り消しても、成功し、変わらない（AC-166）
- [ ] **T7212** 与信の取消を実装する（plan 第 3.3 節）。T7211 を通す。
