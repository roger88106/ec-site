# カートモジュール

消費者のカートと、その品目（バリアントと数量）を管理する。

- レベル：B（品目の上限と合算だけで、状態遷移を持たない）
- 依存：商品カタログモジュール（API）、在庫モジュール（API）
- 関連 spec：002（US-14、15）
- 用語と識別子：[用語集](../glossary.md)

## カート

- カートは、品目の一覧、バージョン、最終更新日時を持つ。品目は、バリアント、数量、入れた日時を持つ。
- 価格は持たない。表示のたびに注文モジュールの見積もりで現在の価格を求める（AC-79）。
- カート ID は推測できない UUID で、それを知っていることがカートを使える条件になる（[plan 002](../specs/002-cart-and-order/plan.md) 第 3 節）。
- 変更（品目の追加・数量の変更・削除・空にする）のたびにバージョンを上げる。注文モジュールが、注文手続きを始めた後の変更を見つけるため。

### 品目の追加と変更

- 同じバリアントを入れたら数量を合算する（AC-74）。品目は入れた順に並べる。
- 数量は 1〜10、品目は 30 まで（AC-75）。合算の結果で判定する。
- 入れるとき・数量を増やすときは、商品カタログで「C 側に表示される商品の、販売停止でないバリアント」かを（AC-72）、在庫で販売可能数が数量以上かを（AC-76）確かめる。数量を減らす・削除するときは確かめない。
- 確かめるのは追加・変更の時点だけ。その後に買えなくなった品目は、表示（AC-80）と注文（AC-88）で扱う。

### 期限

- 最終更新から 30 日たったカートは、読むときに空として扱う（AC-81）。次に書くときに、品目を消してから書く。
- 期限切れのカートの削除は、定期ジョブの方式が決まってから（spec 002 の Non-goals）。

## 他モジュールへの公開

| 種類 | 内容 | 利用者 |
|------|------|--------|
| API | カートの品目とバージョン（期限切れは空）、カートを空にする（注文の成立と同じトランザクション） | 店舗、注文 |
| イベント | カート変更（カート ID） | 注文（引当を解く） |

## データモデル（草案）

マイグレーションができたら、リンクに置き換える。

| テーブル | 論理名 | カラム |
|----------|--------|--------|
| `cart.cart` | カート | カート ID、バージョン、作成日時、更新日時 |
| `cart.cart_item` | カートの品目 | カート ID、バリアント ID、数量（1〜10）、入れた日時。主キーはカート ID とバリアント ID |

- バリアントは商品カタログモジュールの ID なので、外部キーは張らない（constitution 6）。
