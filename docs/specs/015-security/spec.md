# Spec 015：セキュリティ

ステータス：確定

## 1. 背景と目的

spec 010 の後の全体のレビューで、設定の漏れや新しいエンドポイントの追加し忘れで、起動が止まらず、アクセスを制限しないまま動く箇所が見つかった。**設定が足りなければ動き出さず、許すエンドポイントは明示したものだけ**にする。

- 決済と物流は、設定がなければ外部サービスの代わり（mock）を使う。本番で決済の設定を忘れると、mock の支払画面から、支払わずに注文を受付にできる。mock の画面と通知のエンドポイントには認証がない。
- 店舗 API の会員の操作は、認可の設定にパスを手動で並べ、並べていない操作は誰でも使える。管理 API は契約から権限を作り、宣言がなければ起動に失敗する。
- 店舗 API・管理 API 以外の URL は、全て認証なしで使える。メトリクスのエンドポイントは、業務の API と同じポートにある。
- 管理画面は、IdP の接続先の設定がなければ、ローカルの IdP につなぐままビルドできる。店舗画面は、リクエストヘッダーのホストを検証せずに使って、ログアウトの後の戻り先を作る。
- ローカル環境（compose）のサービスは、全てのネットワークからつながる。ローカル・E2E 用の設定ファイルが、バックエンドの本番の jarに入る。

MVP はデプロイしない（[MVP の完成までの一覧](../mvp.md) 第 3 節）が、デプロイの前に修正が必要な箇所を、統一した設定の書き方（spec 013、014）に従って先に修正する。

AC・US・BR・NFR の番号は、spec 010 から続けて振る。

## 2. 用語

| 用語 | 意味 |
|------|------|
| 本番の実装 | 外部サービス（決済、物流）に実際につなぐ実装。決済は Stripe。物流はまだない |
| mock | 外部サービスの代わりに、バックエンドの中で動く実装。開発・E2E・検証サーバーで使う |
| mock フラグ | 外部サービスごとに、mock を使うことを示す設定。立てなければ本番の実装を使う |
| 業務ポート | 店舗 API・管理 API・通知のエンドポイントを公開するポート |
| 運用ポート | 死活監視とメトリクス（運用のエンドポイント）を公開するポート。業務ポートと分ける |

用語集には plan で追加する。

## 4. User stories と受け入れ条件

### US-48 設定の漏れで mock を使わない（B / P1）

運営者は、設定を忘れても、気づかないまま mock で注文を受けない。

- **AC-226** 決済と物流に、それぞれ mock フラグがある。フラグを立てたサービスだけが mock を使い、立てなければ本番の実装を使う。
- **AC-227** 決済のフラグを立てず、Stripe の設定（鍵）が足りなければ、バックエンドは起動に失敗し、足りない設定の名前をログに出力する。
- **AC-228** 物流のフラグを立てなければ、バックエンドは起動に失敗する。理由：物流の本番の実装がまだないため（第 7 節）。
- **AC-229** mock の支払画面と、mock の配送業者の画面（通知の操作を含む）は、そのサービスのフラグを立てたときだけ使える。フラグがなければ、その URL は見つからない（404）。
- **AC-230** 決済・物流のサービスを選ぶ今の設定（mock か Stripe かの選択）をなくす。フラグだけで選ぶ。
- **AC-231** ローカルの設定は、決済と物流のフラグを立てる。Stripe の sandbox で動かす設定は、決済のフラグを下ろす。E2E の設定は、ローカルの設定のフラグを受け継ぐ。

### US-49 会員の操作を、token なしで使わせない（C / P1）

消費者の会員の情報と注文は、本人の token がなければ、店舗 API から読めず変えられない。

- **AC-232** 店舗 API の契約で会員の token が必要な操作は、全て token なしで 401 を返す。
- **AC-233** 契約で token が必要ない操作（商品の閲覧、匿名のカートなど）は、token なしで今までどおり使える。
- **AC-234** 契約と認可の設定が食い違う（契約で token が必要なのに、token なしで通る操作がある、またはその逆）と、CI で失敗する。

### US-50 決めていない URL と運用のエンドポイントを、業務ポートで出さない（B / P1）

運営者は、新しいエンドポイントを追加するときに認可を決め忘れても、そのエンドポイントを誰でも使える状態にしない。

- **AC-235** 業務ポートは、店舗 API・管理 API・決済と物流の通知のエンドポイント・mock のエンドポイント（フラグを立てたとき）だけを出す。それ以外の URL は拒む。ステータスコードは plan で決める。
- **AC-236** 死活監視とメトリクスは、運用ポートだけで出す。業務ポートでは出さない。
- **AC-237** 運用ポートの番号は設定で変更でき、ローカルの既定は業務ポートと競合しない。

### US-51 画面の設定の漏れで、ローカルの値やリクエストヘッダーに頼らない（B / P1）

運営者は、画面の設定を忘れたとき、ローカル向けの値で動く画面を公開しない。

- **AC-238** 管理画面を本番モードでビルドするとき、IdP の接続先と client ID がなければ、ビルドに失敗し、足りない設定の名前を出力する。
- **AC-239** 管理画面の開発モードとテストは、今までどおりローカルの IdP の既定値で動く。
- **AC-240** 店舗画面は、公開する URL（origin）を環境変数で受け取る。本番モードで値がなければ、起動に失敗する（今の必須の設定と同じ）。
- **AC-241** 店舗画面のログインの戻り先と、ログアウトの後の戻り先は、公開する URL から作り、リクエストヘッダー（ホスト、転送元のプロトコル）を使わない。
- **AC-242** 店舗画面の任意の設定（API の応答を再取得する間隔など）も、必須の設定と同じ 1 か所で読む（[フロントの書き方](../../frontend/coding.md) 第 8.1 節）。

### US-52 ローカル環境と設定を、外から使わせない（B / P1）

運営者と開発者は、ローカル環境と、Git にあるローカル用の秘密情報を、既定では手元のマシンの外から使わせない。

- **AC-243** ローカル環境（compose）のサービスのポートは、既定では手元のマシン（127.0.0.1）からだけつながる。
- **AC-247** 1 つの設定を変えるだけで、compose の全てのサービスのポートを、同じネットワークの他のマシンからもつなげるようにできる。理由：他のマシン（スマートフォンなど）から確認する場面があるため。
- **AC-244** バックエンドの本番の jarに、ローカル・E2E・Stripe の sandbox の設定ファイルが入らない。
- **AC-245** 本番の jarを、ローカルの profile を指定して起動しても、mock フラグとローカル用の秘密情報は読まれない。物流のフラグがないので、起動に失敗する。

### US-53 mock のテスト用の操作を、本番の jarに入れない（B / P2）

- **AC-246** mock の決済の、テストだけで使う操作（次の操作を失敗させる、状態を削除するなど）は、本番の jarに入らない。テストは今までどおりその操作を使える。

## 5. 業務ルール

- **BR-30** 外部サービスの mock は、mock フラグで明示したときだけ使う。フラグがなければ本番の実装を使い、本番の実装の設定が足りなければ、動き出さずに失敗する。
- **BR-31** 設定が足りないときは、ローカル向けの値で動き出さず、起動かビルドに失敗する。ローカル向けの既定値は、開発モードとテストでだけ使う。
- **BR-32** 認可は既定で拒み、許すエンドポイントを明示する。店舗 API と管理 API は、契約を正とする。

## 6. 非機能要件

- **NFR-17** ローカルの起動、E2E、CI は、今と同じコマンドで動く。理由：mock フラグはローカルの設定に書き、起動のたびに環境変数を追加しないため。
- **NFR-18** 本 spec の AC に関わらない既存のテスト（バックエンド、フロント、E2E）は、期待値を変えずに通る。テストの設定（mock フラグ、ポート）は変えてよい。
- **NFR-19** 起動・ビルドのエラーメッセージは、足りない設定の名前を出力し、秘密情報を出力しない。

## 7. Non-goals

| 項目 | 扱う場所 |
|------|----------|
| 物流の本番の実装（配送業者との接続）。それまでは物流のフラグを立てないと起動できない | 1 → 10 |
| デプロイ、IdP の本番の構成、秘密情報の管理（[バックエンドのアーキテクチャ](../../backend/architecture.md) 第 7.3 節） | 1 → 10。本 spec では第 7.3 節の前提に、mock フラグと運用ポートを追加する |
| 2 つの mock の画面の HTML の重複をまとめる | 行わない（セキュリティに関わらない整理） |
| mock の配送業者の画面が、リクエストのホストから自分の URL を作る | 行わない（フラグを立てた環境にだけあり、本番に出ない） |
| ローカル環境の既定のユーザーとパスワード（IdP の管理、DB） | 行わない（AC-243 で手元のマシンからだけつながる） |
| IdP の画面・権限の整理 | 1 → 10 |
