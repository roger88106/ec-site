# Spec 406：支払待ちの注文があるときに、新しい注文の前に確認する

種類：機能　規模：L　ステータス：確定

危険度：高

## 背景と目的

同じカートから、先の注文の与信の通知が届く前に、2 件目の注文を成立させられる。カートは注文の成立で変わらない（AC-144）。重複の防止は注文手続きごとである（AC-91）。このため、注文手続きを再作成すると 2 件目の注文が成立する。

この spec の目的は、消費者が気づかずに同じ内容を二重に注文し、二重に支払うことを防ぐことである。意図して続けて注文する消費者は止めない。そこで、支払待ちの注文があるときは、注文手続きの開始で確認の画面を表示する。消費者が確認の画面で「新しく注文する」を選んだときだけ、2 件目の注文を作れるようにする。

追跡の issue は #406。関わる文書は、[注文モジュール](../../03-機能仕様/order.md)、[カートモジュール](../../03-機能仕様/cart.md)、[注文の設計](../../02-設計/order.md)。

### 確認した範囲と限界

issue #406 の統合テストで、次を確認した。店舗画面は操作していない。

| 操作 | 結果 |
|------|------|
| 順に 2 回注文する | 別の注文が 2 件できる。在庫は 10 から 6 になる。両方を支払うと両方が受付になり、両方を出荷すると売上の確定が 2 件になる |
| 2 つのタブで注文手続き A、B を始め、A、B の順に注文する | 両方が成立する。在庫は 10 から 6 になる |
| 先の注文の与信の後に、先に始めていた注文手続きと新しい注文手続きから注文する | 先に始めていた手続きは 409、新しい手続きは 400（カートが空）になり、二重にならない |
| 支払の期限切れの後に、同じカートで注文する | 再び注文できる。これは意図した仕様である（[カートモジュール](../../03-機能仕様/cart.md)の「カート」） |

利用者は 2026-11-06 に、issue 担当のセッションを通じて次を決めた（2 件目を常に作らせないとした最初の決定を置き換える）。消費者は確認の画面で「支払へ進む」「新しく注文する」「戻る」を選べる。判定では品目を比べない。注文の時点でも、サーバーが判定する。支払待ちの注文のキャンセルは入れない。

## スコープ

| 含める | 含めない |
|--------|----------|
| 開始のときの確認の画面 | 会員ごとの支払待ちの上限（#411） |
| 3 つの選択（支払へ進む、新しく注文する、戻る） | 支払待ちの注文のキャンセル |
| 確認した注文手続きからの注文 | 品目の比較 |
| 確認なしの注文の拒否と、確認の画面への案内 | 拒否だけで 2 件目を作らせない案 |
| 同時に注文した場合の二重の成立の防止 | 注文の成立でカートの品目を削除すること |
| 機能仕様と設計の文書の更新 | |

## User stories

| US | 誰が | 何をできる | なぜ |
|----|------|------------|------|
| US-406-1 | 消費者 | 支払待ちの注文があるときに注文手続きを始めると、その注文を確認して、支払うか、新しく注文するか、やめるかを選べる | 気づかずに二重に注文することを防ぐため |
| US-406-2 | 消費者 | 確認していない注文手続きから注文しようとしたときも、確認の画面へ案内される | 別のタブや先に始めていた注文手続きから、気づかずに二重に注文することを防ぐため |

## 受け入れ条件

### US-406-1 支払待ちの注文の確認（C / P1）

- **AC-406-1** 会員に支払待ちの注文があるとき、注文手続きの開始は確認を求める応答を返し、注文手続きを作らない。
- **AC-406-2** AC-406-1 の応答では、在庫の引当を変えない。前の注文手続きの引当も解かない。
- **AC-406-3** AC-406-1 の判定では品目を比べない。カートの内容によらず、購入の可否の判定より先に行う。
- **AC-406-4** 店舗画面は、AC-406-1 の応答を受けたら確認の画面を表示する。確認の画面は、支払待ちの注文ごとに、注文番号、注文日時、明細、総額、支払の期限を示す。複数あれば全てを示す。
- **AC-406-5** 確認の画面で「支払へ進む」を選ぶと、選んだ注文の支払画面へ遷移する。新しい注文は作らない。
- **AC-406-6** 支払の期限を過ぎた注文には「支払へ進む」を表示しない。
- **AC-406-7** 確認の画面で「新しく注文する」を選ぶと、新しい注文手続きを始め、注文手続きの画面へ遷移する。引当と購入の可否の判定は、通常の開始と同じ。
- **AC-406-8** 確認の画面で「戻る」を選ぶと、カートの画面へ遷移する。注文手続きを作らず、既存の注文とカートを変えない。

### US-406-2 確認していない注文手続きからの注文（C / P1）

- **AC-406-9** AC-406-7 で始めた注文手続きからは、支払待ちの注文があっても注文できる。2 件目の注文が成立し、在庫も減る。
- **AC-406-10** 確認は、その注文手続きにだけ有効である。次に注文手続きを開始するときは、再び確認する。
- **AC-406-11** 確認していない注文手続きから注文するとき、会員に支払待ちの注文があれば、拒否する。注文を作らず、在庫を減らさない。
- **AC-406-12** 確認した後に、会員の別の注文が新たに支払待ちになったときは、その注文手続きからの注文も AC-406-11 と同じく拒否する。
- **AC-406-13** 店舗画面は、AC-406-11、AC-406-12 の拒否を受けたら、確認の画面を表示する。入力したお届け先は保存しない。
- **AC-406-14** 同じ会員の注文手続きから同時に注文しても、AC-406-11、AC-406-12 の判定を経ずに成立することはない。他方は、先に成立した注文の後に判定され、拒否される。
  - Given：支払待ちの注文が 0 件で、確認していない注文手続きが 2 つある。
  - When：同時に注文する。
  - Then：一方だけ成立し、在庫が 1 件分だけ減り、他方は拒否される。
- **AC-406-15** 同じ注文手続きの再送は、従来どおり作成済みの注文を返す（AC-91 を変えない）。注文が支払待ちかによらない。
- **AC-406-16** 会員に支払待ちの注文がなくなった後は、確認なしで注文手続きを開始し、注文できる。なくなるのは、支払の期限切れによるキャンセルと、与信の成功による受付のときである。
- **AC-406-17** 他の会員のカートの開始と、他の会員の注文手続きからの注文は、従来どおり 404 で、注文を示さない。
- **AC-406-18** 変更を適用した時点で既に支払待ちの注文も、判定の対象にする。

## 業務ルール

- **BR-406-1** 「支払待ちの注文がある」は、注文の状態で判定する。支払の期限を過ぎ、期限切れのキャンセルの前の注文も、支払待ちとして扱う。理由：キャンセルまで状態は支払待ちのままで、在庫も戻らないため。
- **BR-406-2** 判定の対象は、その会員の支払待ちの注文である。会員のカートは会員ごとに 1 つなので、会員ごとに判定する（[カートモジュール](../../03-機能仕様/cart.md)の「会員のカート」）。
- **BR-406-3** 「戻る」は新しい注文をやめるだけで、既存の注文を変えない。支払待ちの注文は、支払うか、期限切れになる（AC-158 を変えない）。

## 非機能要件

- **NFR-406-1** 確認の判定はサーバーで行い、画面の判定に頼らない。同時の注文の判定は DB で保証し、複数のインスタンスで動かしても判定が一致するように、JVM 内のロックを使わない（constitution の「水平スケール」）。
- **NFR-406-2** 変更を適用する時点で支払待ちの注文が複数あっても、DB のマイグレーションを失敗させず、既存の注文を変えない。

## Non-goals

| 項目 | 理由 |
|------|------|
| 会員ごとの支払待ちの注文の上限 | 別の問題（在庫の確保）で、#411 で扱う |
| 2 件目の注文を常に拒否する案、カートの内容で分ける案 | 利用者が確認の画面を表示する方針に決めた（2026-11-06） |
| 品目の比較 | 利用者の決定（2026-11-06）。支払待ちの注文があれば、品目によらず確認の画面を表示する |
| 注文の成立でカートの品目を削除する | AC-144 とカートの規則を変えることになり、期限切れの後に再び注文できなくなる |
| 支払待ちの注文のキャンセル | AC-158 を変えない（利用者の決定） |
