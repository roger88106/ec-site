# Spec 517：業務のエラーのない操作にも x-error-codes を書き、全ての操作に必須にする

種類：整理　規模：M　ステータス：確定

## 背景と目的

店舗 API と管理 API の契約では、操作ごとに、その操作の実装が投げうる業務のエラーのコードを `x-error-codes` に書く（[API の規約](../../05-開発規則/api-conventions.md)の「エラーの本文」）。今は、業務のエラーのない操作に `x-error-codes` を書いていない。書いていない操作は、管理 API の 44 操作のうち 17、店舗 API の 23 操作のうち 17 である。書いていない操作が、業務のエラーのない操作か、書き漏れかを、契約から区別できない。書き漏れのまま実装にエラーを追加すると、画面の側で扱いを決める機会がなくなる。

この spec では、業務のエラーのない全ての操作について、`x-error-codes` に空の配列を書き、全ての操作に `x-error-codes` があることを契約のテストで確認する。消費者・運営者に見える振る舞いも、API の応答も変えない。追跡の issue は #517 で、並行して進める整理の全体の issue は #544 である。

## スコープ

| 含める | 含めない |
|--------|----------|
| 業務のエラーのない全ての操作に、空の配列の `x-error-codes` を書く | 値を作れないときに、共通のエラーでなく業務のエラーのコードを返す 3 か所の修正（内訳は Non-goals） |
| 全ての操作に `x-error-codes` があることを、契約のテストで確認する | 統合テストのエラーのコードの確認（応答の `errorCode` を操作の一覧と照合する仕組み）の変更 |
| API の規約の「エラーの本文」にある表の行「操作ごとの一覧」の修正 | |
| バックエンドのコードの生成と、画面の型の生成が、空の配列で失敗しないことの確認 | |

決定：

- `x-error-codes` のない 34 操作に、空の配列を書く。理由：34 操作の実装を読み（2026-11-18）、入力や業務の状態から業務のエラーのコードを投げる操作がないことを確認したため。34 操作が返すのは、共通のエラー（全ての操作が返しうるエラー）だけである。
- 業務のエラーのない操作は、`x-error-codes` に空の配列を書く。
- 全ての操作に `x-error-codes` があることは、契約のテストで API ごとに確認する。失敗のときは、ない操作（`GET /products` の形）を並べて示す。理由：今の契約のテスト（エラーのコードの契約テスト）は、`x-error-codes` のない操作を空の一覧として扱うので、書き漏れを見つけられないため。
- AC は変えない。AC-274（契約は、操作ごとに、返しうるエラーのコードの一覧を示す）の確認を強めるもので、加えるテストの名前は AC-274 で始める。
- 規模は M にする。[開発の進め方](../../05-開発規則/workflow.md)の「規模」の判定の表では、API の契約を変えるので L になる。ただし、plan に書くモジュールをまたぐ決定も、API と AC の対応の変更もないので、同じ節の特例で M にする。issue 担当のセッションが、利用者に代わって承認した（2026-11-18）。
- 画面の型を作る openapi-typescript は、拡張の項目から型を作らない（[API の規約](../../05-開発規則/api-conventions.md)の「エラーの本文」）。API ごとのエラーのコードの全体の列挙も変わらないので、画面の生成した型は変わらない見込みである（DC-517-5 で確認する）。

## 目的と完了条件

### DS-517-1 契約から、業務のエラーのない操作と書き漏れを区別できるようにする（D / P1）

- **DC-517-1** 両方の契約の全ての操作に `x-error-codes` がある。業務のエラーのない操作は空の配列である。
- **DC-517-2** 1 つの操作から `x-error-codes` を外すと、契約のテストが失敗し、その操作を示す。
- **DC-517-3** API の規約の表の行「操作ごとの一覧」が、「全ての操作に書く。業務のエラーがなければ空の配列」の規則になっている。

### DS-517-2 コードの生成と検査が通る（D / P1）

- **DC-517-4** バックエンドのコードの生成と `./gradlew check` が通る。
- **DC-517-5** 画面の型の生成が通り、生成した型に差分がない。フロントの lint が通る。

## Non-goals

| 項目 | 理由 |
|------|------|
| DB の値が不正なときの復元で、業務のエラーのコードを返す 2 か所（商品の集約の読み込み、税区分の参照）の修正 | 契約でなく実装の不具合で、#555 が復元の全体を共通の仕組みで修正するときに扱う |
| 税込価格の計算で、業務のエラーのコードを返す箇所の修正 | 契約の変更と関係がない。引数から値を作る処理で、#555 が扱う DB からの復元ではない。起票するかは、issue 担当のセッションが利用者に確認する |
| 統合テストにある、エラーのコードの確認の変更 | 全ての操作に一覧があれば、今の確認のままで足りるため |
