# Spec 008：機能紹介のページ

ステータス：草案

## 1. 背景と目的

このリポジトリを、営業の場でエンジニアでない人（顧客になりうる相手）に見せる機会がある。今の README と docs/ は開発者とエージェント向けで、何ができるか、どう作ったかを短く伝えられない。

- 機能（店舗画面・管理画面でできること）を、画面のスクリーンショットと一緒に 1 枚のページで見せる。
- 作り方（spec から作る進め方、自動のテスト、AI エージェントとの分担）を、専門用語に頼らずに見せる。
- ページは GitHub から辿れ、ブラウザーで直接開ける。

原稿（HTML、明暗の両テーマ）は `/.local/sales/` に下書きがある。スクリーンショットは決済より前のもの。

本 spec は**整理の spec**（[文書の記号と番号](../../process/notation.md)）。店舗画面・管理画面の振る舞いは変えない。決済の画面をスクリーンショットに入れるため、spec 007 の完了を前提にする。

## 2. 用語

新しい業務の用語はない。

## 3. スコープ

| # | 目的 | 対象 | 優先度 |
|---|------|------|--------|
| DS-19 | 営業の相手（エンジニアでない人）が、機能と作り方を 1 枚のページで知ることができる | D | P1 |
| DS-20 | ページを GitHub から辿って、ブラウザーで開ける | D | P1 |

## 4. 目的と完了の条件

### DS-19 機能と作り方を 1 枚のページで知る（D / P1）

- **DC-67** ページに、店舗画面と管理画面の主な機能（カタログ、カート、注文、決済、在庫、税率など）が、今の画面のスクリーンショットと一緒にある。「開発中」の表記が、実際の進捗と合っている。
- **DC-68** ページに載せる数字（自動のテストの数、受け入れ条件の数など）は、数え方を決めて数え直したものにする。
- **DC-69** ページは明暗の両テーマで読め、スマートフォンの幅で横に崩れない。

### DS-20 GitHub から辿って開ける（D / P1）

- **DC-70** ページはリポジトリに置き、`develop` の変更で自動で公開される。
- **DC-71** README の先頭から、ページへのリンクで辿れる。

## 5. 非機能要件

- **DN-9** 個人の連絡先や、秘密の値（鍵など）をページに載せない（載せる個人の情報は Open questions で決める）。

## 6. Non-goals

- 店舗画面・管理画面のデモの公開（動く環境を外に出すこと）。
- docs/ の開発者向けの文書の書き直し。

## 7. Open questions

- ページの言語：日本語のみか、中国語・英語も作るか。
- 名前・GitHub のリンク・連絡先・開発の期間を載せるか。
- 置き場所と公開の方法：案は、リポジトリの根の `showcase/` に置き、GitHub Actions で `develop` から GitHub Pages に出す。利用者の手作業（Settings の Pages と Environments）が要る。
- README の先頭に店舗のトップのスクリーンショットを足すか。
