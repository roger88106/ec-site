# 段階 1：税（US-1）

- 前提：段階 0
- 完了条件：US-1 の AC（AC-1〜7）のテストがすべて通る。CI が通る。
- 参照：spec US-1、[tax.md](../../../modules/tax.md)、`admin.yaml`（tag: tax）

## タスク

- [x] **T101** マイグレーション：税区分と税率のテーブル（[tax.md](../../../modules/tax.md) の草案）。
- [x] **T102** [テスト] 値オブジェクトの単体テスト。
  - 率：0 以上 100 未満、小数第 2 位まで（AC-7）
  - 適用期間：開始は終了より前、空白は無限、ある時点を含むかの判定（AC-2）
- [x] **T103** 率と適用期間を実装する。T102 を通す。
- [x] **T104** [テスト] 税区分の単体テスト（現在時刻は引数で固定する。AC-4 の日時は日本時間なので、`2027-04-01 00:00` は `2027-03-31T15:00Z` として書く）。
  - 期間の重複、途切れ、最後が空白でない一覧は拒否される（AC-3）
  - AC-4 のシナリオ（基本の税率に終了を入れ、期間限定の税率と戻りの税率を足す）が通り、各時点の税率が正しい
  - 過去の日時を新たに設定できない。開始済みの税率は率と開始を変えられず、削除できない。終了は未来へ変更できる。終了済みは変更できない。未開始は変更・削除できる（AC-5）
  - 指定時点の税率（AC-4）
- [x] **T105** 税区分（集約）、ファクトリ、エラーコードを実装する。T104 を通す。
- [x] **T106** [テスト] リポジトリの統合テスト：保存・再構築・置き換え、バージョン不一致の検出、排他制約による重複の拒否。
  - 置き換えの途中で一時的に期間が重なっても、結果に重なりがなければ成功する（排他制約の検査は書き込みの最後。[tax.md](../../../modules/tax.md)）
  - 書き込みの最後に検出された排他制約の違反が、業務のエラーに変換される（500 にならない）
- [x] **T107** リポジトリを jOOQ で実装する。T106 を通す。
- [x] **T108** [テスト] 税込価格の計算の単体テスト（BR-1）。端数の境界値（例：1,234 円・8% → 1,332 円）を含める。
- [x] **T109** 税込価格の計算を実装する。T108 を通す。
- [x] **T110** [テスト] 受け入れテスト（MockMvc、固定の `Clock`。AC-4 の日時は日本時間のオフセット付きで送る）。
  - 税区分の登録と、名称の重複で 409（AC-1）
  - 税率の一覧の置き換え：AC-3〜5 の拒否が 400、AC-4 のシナリオが通る、バージョン不一致で 409
  - 一覧の取得で、現時点の率が返る
  - 登録の `Location` の URL で、その税区分を取得できる。存在しない ID は 404
- [x] **T111** アプリケーション層（コマンド・クエリ）と、生成インターフェースを実装する Controller を作る。T110 を通す。
- [ ] **T112** 商品カタログ向けの API を作る：税区分ごとの税率の一覧（予定を含む）、指定時点の税率、税込価格の計算。
- [ ] **T113** seed：税区分「標準」（10%）、「軽減」（8%）。
- [ ] **T114** [tax.md](../../../modules/tax.md) のデータモデルを、マイグレーションへのリンクに置き換える。用語集に新しい用語があれば足す。
