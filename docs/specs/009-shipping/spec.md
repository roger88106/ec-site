# Spec 009：出荷と配送状況

ステータス：確定

## 1. 背景と目的

コアフローの「決済 → 出荷 → 配送状況」を作る。運営者が支払済みの注文を出荷し、消費者と運営者が配送状況を確認できる状態にする。届けられずに返ってきた注文は、キャンセルして返金できるようにする。

- 今は、与信が成功した注文は「受付」のままで、出荷を記録する手段も、売上を確定する手段もない。
- spec 007 で、売上確定と与信期限切れは出荷の spec で扱うと決めた。

外部の物流サービス（配送業者）は、内部の mock だけで再現する。理由：日本の配送業者の API は契約が必要で、決済サービスのようなテスト環境（sandbox）がないため。物流サービスとのやり取りは腐敗防止層の中に限定し、実在のサービスに接続するときは実装を追加するだけで対応できるようにする。

AC・US・BR・NFR の番号は、spec 007 から続けて振る。

## 2. 用語

[用語集](../../reference/glossary.md)の「注文の状態」「与信」を参照。出荷、配送業者、送り状番号、配送状態、売上確定、与信期限は plan で用語集に追加する。

## 4. User stories と受け入れ条件

### US-35 注文を出荷し、売上を確定する（B / P1）

- **AC-167** 運営者は、「受付」の注文詳細で、配送業者と送り状番号を入力して出荷を登録できる。
- **AC-168** 出荷を登録すると、総額で売上を確定し、注文は「出荷済み」になる。
- **AC-169** 売上確定に失敗したら、出荷は登録されず、注文は「受付」のまま。管理画面に失敗の理由（与信期限切れ、決済サービスに接続できない、など）を表示する。
- **AC-170** 「受付」以外の注文は出荷を登録できない。「キャンセル申請中」の注文は、申請を承認か却下してから出荷する。
- **AC-171** 「出荷済み」の注文は、消費者はキャンセルを申請できない。運営者は、配送状態が「返送」のときだけキャンセルできる（US-40）。
- **AC-172** 同じ注文に出荷を重複して登録しても、売上確定は 1 回だけ実行する。
- **AC-173** 配送業者は決まった一覧（plan で決める）から選ぶ。送り状番号は必須。

### US-36 配送状況を受け取る（B / P1）

- **AC-174** 配送状態（BR-19）は、物流サービスからの通知で遷移する。
- **AC-175** 同じ通知が重複して届いても、1 回だけ反映する。
- **AC-176** 通知の順序が入れ替わっても、配送状態は戻らない（例：「配達完了」の後に「配送中」が届いても「配達完了」のまま）。
- **AC-177** 途中の状態の通知が届かなくても、後の状態に遷移する（例：「出荷済み」から「配達完了」）。
- **AC-178** 署名を確認できない通知と、登録済みのどの出荷にも一致しない通知は、処理しない。

### US-37 配送状況を確認する（C・B / P1）

- **AC-179** 店舗の注文詳細に、配送状態、配送業者、送り状番号を表示する。出荷後は、注文状態の代わりに配送状態を表示する。理由：注文状態と配送状態の「出荷済み」が並ばないようにするため。
- **AC-180** 店舗の注文一覧で、出荷後の注文は、注文状態の代わりに配送状態を表示する。
- **AC-181** 管理画面の注文詳細に、配送状態、配送業者、送り状番号、出荷日時を表示する。
- **AC-182** 管理画面の注文一覧で、状態「出荷済み」で絞り込める。「受付」で絞り込むと、出荷待ちの注文が表示される。

### US-38 出荷通知メールを受け取る（C / P1）

- **AC-183** 出荷を登録すると、注文のメールアドレスに、注文番号、配送業者、送り状番号を書いた出荷通知メールを送る。
- **AC-184** 出荷登録は、メール送信の結果を待たない。送信に失敗したら、送れるまで再試行する。理由：メールサーバーが応答しないときも、出荷を止めないため。
- **AC-185** 再試行しても、1 つの出荷につき出荷通知メールは 1 通だけ届く。

### US-39 与信期限に気づく（B / P1）

- **AC-186** 管理画面の注文一覧と注文詳細で、与信期限（BR-20）が近い「受付」の注文に、期限が近いことを表示する。
- **AC-187** 管理画面の注文一覧で、与信期限が近い注文を絞り込める。
- **AC-188** 与信期限を過ぎた注文を出荷すると、売上確定に失敗する（AC-169）。運営者はその注文をキャンセルできる。

### US-40 返送された注文をキャンセルし、返金する（B / P1）

- **AC-189** 管理画面の注文一覧で、配送状態「返送」の注文を絞り込める。
- **AC-190** 運営者は、配送状態が「返送」の注文を、理由を入力してキャンセルできる。
- **AC-191** 返送された注文をキャンセルするとき、運営者は在庫に戻すかを選ぶ。戻すときは明細の数量だけ在庫数を増やし、戻さないときは在庫数を変えない。理由：返ってきた商品が売れる状態とは限らないため。
- **AC-192** 返送された注文をキャンセルすると、総額（送料を含む）を返金する。
- **AC-193** キャンセルは、返金の結果を待たずに成立する。返金に失敗したら、返金できるまで再試行する。理由：決済サービスが応答しないときも、キャンセルを止めないため。
- **AC-194** 返金が済むまで、管理画面の注文詳細に「返金待ち」と表示する。
- **AC-195** 同じ注文の返金が重複して実行されても、返金は 1 回だけ。
- **AC-196** キャンセルの後、店舗の注文一覧と注文詳細は「キャンセル」を表示する。消費者にメールは送らない。

## 5. 業務ルール

spec 002 の BR-6〜11、spec 003 の BR-12、13、spec 007 の BR-14〜17 に加える。

- **BR-18 注文状態**：BR-14 に次を加える。
  - 「受付」→「出荷済み」（出荷登録と売上確定）
  - 「出荷済み」→「キャンセル」（配送状態が「返送」のときの、運営者のキャンセル）
  - 配送状態は注文状態と別に持つ（BR-19）。

- **BR-19 配送状態**：出荷ごとに持つ。業務の判断に使う区切り（出荷した、届いた、返ってきた）だけを状態にする。

  | 配送状態 | 意味 | 次の状態 |
  |----------|------|----------|
  | 出荷済み | 運営者が出荷を登録した。物流サービスはまだ荷物を受け取っていない | 配送中、配達完了、返送 |
  | 配送中 | 物流サービスが荷物を受け取り、届けるまでの間 ※1 | 配達完了、返送 |
  | 配達完了 | 荷物を届けた | なし |
  | 返送 | 届けられず、荷物が送り主に戻った | なし |

  ※1：物流サービスの途中の表示（ヤマト運輸の「荷物受付」「発送」「作業店通過」「配達中」「持戻」「保管中」など）は、全て「配送中」にまとめる。配送業者の表示との対応は、plan で用語集に書く。

- **BR-20 与信期限**：与信の成功から一定の日数（決済サービスによる。plan で決める）を過ぎると、売上を確定できない。「期限が近い」とする日数も plan で決める。

- **BR-21 支払状態**：BR-15 に次を加える。

  | 支払状態 | 意味 |
  |----------|------|
  | 売上確定済み | 総額で売上を確定した |
  | 与信期限切れ | 与信期限を過ぎ、売上を確定できなかった |
  | 返金待ち | 売上確定済みの注文がキャンセルになり、返金が済んでいない |
  | 返金済み | 総額を返金した |

  - 「与信期限切れ」の注文をキャンセルしても、与信を取り消さない。

- **BR-22 物流サービスからの通知**：BR-17（決済サービスからの通知）と同じく、署名を確認し、重複して届いても 1 回だけ反映し、処理に失敗した通知は物流サービスの再送で再処理する。

- **BR-23 出荷の単位**：1 つの注文に出荷は 1 つ。注文の全ての明細を 1 回で出荷する。

## 6. 非機能要件

- **NFR-9** 物流サービスは設定で切り替える。自動テストと CI は外部の物流サービスに接続せず、内部の mock で、配送状態の通知と、通知の遅れ・重複・順序の入れ替わり・途中の欠けを再現する。
- **NFR-10** 決済サービスの応答が遅れても、売上を 2 回確定しない。また、売上未確定のまま「出荷済み」になった注文を残さない。
- **NFR-11** 自動テストとローカルでは、メールを外に送らず、compose の Mailpit で受ける。

## 7. Non-goals

| 項目 | 扱う場所 |
|------|----------|
| 分割出荷（明細ごと・数量ごとの出荷） | 将来の spec。出荷ごとに売上を分けて確定するので、決済サービスの複数回の売上確定と合わせてレビューする（BR-23） |
| 実在の物流サービスへの接続 | 将来の spec（本 spec は腐敗防止層と mock まで） |
| 配送業者の追跡ページへのリンク | 実在の物流サービスへの接続と同時 |
| 送り状の発行、集荷の依頼 | 将来の spec |
| 配送中の細かな状態（荷物受付、持戻、保管中など）の表示 | 将来の spec（BR-19 の ※1） |
| 出荷登録の取消、送り状番号の訂正 | 将来の spec |
| 返送以外での、出荷後のキャンセル（紛失、届いた後の取消） | 将来の spec |
| 返品（届いた後に消費者が返す）、一部の返金 | 返品の spec |
| 与信期限切れの注文の自動キャンセル | 行わない（運営者が判断する。AC-188） |
| 与信を再取得して、期限切れの注文を出荷する | 将来の spec |
| 出荷による在庫の変更 | 行わない。在庫数は注文の成立で減らしている（spec 002 の Non-goals にある「出荷による在庫の確定」は不要になる） |
| 出荷通知以外のメール（注文確認、配達完了、キャンセル、返金） | 将来の spec |
| 公開ネットワークでの、物流サービスの通知のエンドポイント | 公開ネットワークへのデプロイの前提と同時（constitution 16） |
| 期限切れのカートと引当の削除（spec 002、007 の Non-goals） | 別の spec |
