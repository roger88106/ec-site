# Spec 417：店舗画面のヘッダーを、幅 375px でもはみ出さずに使えるようにする

種類：機能　規模：M　ステータス：確定

## 背景と目的

店舗画面のヘッダーは、幅によらず、全ての項目を 1 行に並べる。項目は、店名、商品一覧、検索、カート、ログイン状態の項目である。全ての画面が同じヘッダーを使う。

幅 375px で開くと、ヘッダーの内容の幅は 547px になり（ログイン中）、全ての画面に横スクロールが出る。項目の文字は、1 文字ごとに縦に折り返す。1 行で折り返さずに並べるには、ログインなしで約 682px、ログイン中で約 892px が必要である。幅 768px のタブレットの縦でも、ログイン中は崩れる。

対応する最小の画面幅は、どの文書にも定められていなかった。利用者が 375px と決めた。E2E はデスクトップの幅だけで実行していて、狭い幅を確認するテストがない。

この spec は、幅 1024px 未満のヘッダーを、メニューを使う配置にして、幅 375px でも横スクロールなしに全ての項目を使えるようにする。

追跡の issue は #417。関わる文書は、[店舗画面の構成](../../02-設計/apps/store.md)、[店舗モジュール](../../03-機能仕様/storefront.md)。

### 確認した範囲と限界

| 確認した内容 | 方法と出典 |
|--------------|------------|
| 幅 375px のヘッダーの内容の幅は 547px（ログイン中） | 開発サーバーで測定（2026-11-09） |
| ヘッダーの外の内容は、表の下の画面で、画面の幅に収まっていた（ログイン中） | 同上 |
| 1 行で並べるのに必要な幅は、ログインなしで約 682px、ログイン中で約 892px | issue #417 の計算 |
| 対応する最小の画面幅は 375px | issue #417 のコメント（2026-11-06）の、利用者の決定 |

幅に収まっていた画面は、トップ、商品一覧、商品の詳細、検索の結果、カート（商品あり）、注文手続き、注文履歴、注文の詳細である。

支払待ちの注文の確認の画面、ログインしていない状態の各画面の内容、IdP の画面は、測っていない。

## スコープ

| 含める | 含めない |
|--------|----------|
| 店舗画面のヘッダーの、狭い幅の配置 | ヘッダーの外の各画面の配置 |
| E2E に、幅 375px で確認するテストを追加する | 管理画面 |
| 店舗画面の構成の文書と AC 一覧の更新 | IdP（Keycloak）の画面 |
| | 375px より狭い幅 |

含めないものの理由は Non-goals に書く。

決定：

1. 規模は M にする。理由：AC を追加するが、API の契約と DB の構造を変えず、店舗画面のヘッダーだけを変えるため。
2. 対応する最小の画面幅は 375px にする。利用者が決めた。
3. 1 行に並べる今の配置は、幅が 1024px 以上のときだけ使う。幅 1024px 未満は、狭い幅の配置にする。理由：ログイン中に 1 行で並べるには約 892px が必要である。Tailwind の既定のブレークポイントのうち、892px 以上で最小のものが 1024px（`lg`）のため。
4. 狭い幅の配置は、次の 3 つの部分からなる。
   - 1 行目：店名、カート、メニューを開くボタン。
   - 2 行目：検索欄を、ヘッダーの幅いっぱいに置く。
   - メニューの中：商品一覧と、ログイン状態の項目。ログインなしは「ログイン」「会員登録」、ログイン中は氏名、「ご注文履歴」「アカウント」「ログアウト」。
5. メニューは、ボタンで開閉する。メニューの中のリンクで画面を遷移したら、メニューを閉じる。理由：ヘッダーは全ての画面に共通のレイアウトにあり、画面を遷移しても再作成されないため、閉じる処理がないと開いたまま残るため。
6. 項目は、狭い幅の配置と 1 行の配置で 2 組描画せず、1 組だけ描画して、幅で並べ方と表示を切り替える。理由：同じリンクが 2 つあると、支援技術で 2 回読み上げられ、ロールと名前で要素を取得するテストでも 1 つに決まらないため。
7. 項目の文字は、1 文字ごとに折り返さない。
8. E2E に、幅 375px のブラウザーの設定を追加し、狭い幅のテストだけをその設定で実行する。既存のテストは、デスクトップの幅だけで実行する。理由：全てのテストを 2 つの幅で実行すると、E2E の実行時間がほぼ倍になるため。
9. 店舗画面の構成の「表示の決まり」の表に、対応する最小の画面幅（375px）の行と、ヘッダーの狭い幅の配置（1024px 未満）の行を加える。

| 論理名 | 識別子 |
|--------|--------|
| ヘッダー | `SiteHeader` |
| Playwright のブラウザーの設定 | `projects`（`e2e/playwright.config.ts`） |

## User stories

| US | 誰が | 何をできる | なぜ |
|----|------|------------|------|
| US-417-1 | 消費者 | スマートフォン（幅 375px）でも、横にスクロールせずに、ヘッダーの全ての項目を使える | スマートフォンで買い物をするため |

## 受け入れ条件

### US-417-1 狭い幅でもヘッダーを使える（C / P1）

- **AC-417-1** 幅 375px で、ログインしていない消費者が店舗画面を開くと、横スクロールが出ない。
- **AC-417-2** 幅 375px で、ログインしている会員が店舗画面を開くと、横スクロールが出ない。
- **AC-417-3** 幅 1024px 未満でメニューを開くと、商品一覧と、ログイン状態の項目が表示される。項目は、ログインなしは「ログイン」「会員登録」、ログイン中は氏名、「ご注文履歴」「アカウント」「ログアウト」である。
- **AC-417-4** 幅 1024px 未満では、検索欄とカートへのリンクは、メニューを開かずに使える。
- **AC-417-5** メニューの中のリンクで画面を遷移すると、メニューが閉じる。
- **AC-417-6** 幅 1024px 以上では、今と同じく、全ての項目を 1 行に並べ、メニューを開くボタンを出さない。

## 業務ルール

なし。

## 非機能要件

- **NFR-417-1** API の契約とバックエンドを変えない。
- **NFR-417-2** E2E の全体の実行時間を大きく増やさない。追加するのは、幅 375px のテストのファイル 1 つだけにする。
- **NFR-417-3** メニューを開くボタンは、キーボードで操作でき、開閉の状態を支援技術に伝える。
- **NFR-417-4** 開いたメニューは Esc キーで閉じ、フォーカスをメニューを開くボタンに戻す。

## Non-goals

| 項目 | 理由 |
|------|------|
| ヘッダーの外の各画面の配置 | 幅 375px で測った画面の内容は、幅に収まっていたため。測っていない画面で崩れが見つかれば、別の issue に起票する |
| 375px より狭い幅 | 利用者が、対応する最小の幅を 375px と決めたため |
| 管理画面 | 今回の issue の対象（店舗画面のヘッダー）の外のため |
| IdP の画面 | Keycloak のテーマで、店舗画面のコードの外にあるため |
