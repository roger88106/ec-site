## 出荷の登録

- [x] **T9303** [テスト] 注文の単体テスト：受付 → 出荷済み。受付以外は出荷できない（AC-170）。出荷済みは、返送のときだけ運営者がキャンセルできる（AC-171）。できる操作のフラグ。
- [x] **T9304** 注文に出荷済みを追加する。T9303 を通す。マイグレーションで状態の制約を修正する。
- [x] **T9305** [テスト] 出荷の登録の統合テスト（管理 API）：
  - 受付の注文に登録すると、売上確定済み・出荷済みになり、出荷ができる（AC-167、168）
  - 売上確定に失敗したら、出荷は作られず受付のまま。期限切れは 409、接続の失敗は 502（AC-169、188）
  - キャンセル申請中は 409（AC-170）
  - 重ねて登録しても、売上確定は 1 回（AC-172）
  - 配送業者は一覧から、送り状番号は必須（AC-173）
  - 確定の後に注文が受付でなくなっていたら 409。再登録すると確定せずに進む
- [x] **T9306** 出荷の登録を実装する（plan 第 2 節）。イベント「注文の出荷」を登録する。T9305 を通す。

## 返送のキャンセル

- [x] **T9307** [テスト] 返送のキャンセルの統合テスト：

  - 在庫に戻すときは在庫数が増え、戻さないときは変わらない（AC-191）
  - 返送以外の出荷済みは 409（AC-171）
  - 返金の結果を待たずに成立する（AC-193）
