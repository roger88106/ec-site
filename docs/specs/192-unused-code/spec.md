# Spec 192：使われていないコードを削除し、静的解析の検査を広げる

ステータス：草案

## 1. 背景と目的

MVP 019 の全体のレビューで、使われていないコードの指摘（8 件）が残った。spec 18 で Error Prone と NullAway を入れたときに範囲を絞った検査と、バックエンドの書き方の null の基準の補いも残っている。spec 155 では、パッケージの移動を伴わない DC と、使われていないコードと範囲の近い DC を、本 spec に移した。どれもバックエンドの `src/main` を変え、削除の対象と静的解析の設定が重なるので、1 つの spec で扱う。

追跡の issue は [#192](https://github.com/roger88106/ec-site/issues/192) で、扱う issue は #85、#148 である。作業ブランチは `192-unused-code` である。規模は L を提案する。理由：注文、地域、商品カタログ、媒体、出荷、支払、共通のコード、店舗画面、管理画面にまたがるため。

本 spec は整理の spec である（[文書の記号と番号](../../rules/notation.md)）。

### 1.1 使われていないコードの再調査

#85 の「ほか 4 件」は、MVP 019 のレビューの結果のファイルが残っていない。そこで 2026-10-26 に、今の `develop`（f8f2b29a）を同じ観点で再調査した。観点は、本番から呼ばれずテストか tools だけが使う操作、どこからも使われない型・export・ファイル・依存、使われていない import と並びの乱れた import である。汎用のモデルで 1 回実行し、spec 担当のセッションが主な指摘をコードで確認した。

- #85 で名前を挙げた項目は、全て今のコードに残っていた。`cn` は、依存そのものは使われていて、使われていないのは管理画面の `cn` を再び export するファイルだった。
- 「ほか 4 件」に当たるものとして、商品の代表画像の操作、地域のモジュールの公開の API の郵便番号の検索、税率のキャッシュの破棄、ファイル保存の設定の値の型を複製する操作が見つかった。後の 2 つは spec 155 から移した DC-155-27 と同じである。
- spec 155 から移した DC の項目は、全て今のコードに残っていた。例外は DC-155-32（レベル A のモジュールの一覧の複製）で、spec 186 の DC-186-10 が同じ内容を済ませ、一覧は構成の検査の補助の 1 か所にある（2026-10-26 に spec 186 のマージの後の `develop` で確認した）。そこで本 spec の範囲から外す。
- spec 181 と spec 186 のマージの後の `develop`（821af1a5）で、上の項目が残っていることを確認し直した。
- 使われていない import は `src/main` と統合テストに 1 件ずつ、並びの乱れた import は全体で約 50 ファイルある。

## 2. 用語

| 用語 | 意味 |
|------|------|
| テスト専用の操作 | 本番のコードから呼ばれず、テスト（`src/test`、`src/integrationTest`、`src/testFixtures`）か tools だけが呼ぶ、`src/main` の操作 |
| 使われていない export | 定義したファイルの外から import されない、フロントの export |

用語集に追加する語は、plan で決める。

## 4. 目的と完了条件

### DS-192-1 テスト専用の操作をなくす（D / P1）

- **DC-192-1** 次の操作が、本番のコードにない。テストは、本番のコードと同じ公開の操作で確認する形にする。#85 の項目である。

| 操作 | 今の呼び出し元 |
|------|----------------|
| 注文がキャンセル済みかを返す操作 | 注文の単体テストだけ |
| レポートの集計の基準が注文の状態を数えるかを返す操作 | 基準の単体テストだけ |
| 商品の代表画像を返す操作 | 商品の単体テストだけ |
| 地域のモジュールの公開の API の、郵便番号で住所を引く操作 | 地域の API の統合テストだけ。店舗の API は、地域のモジュールの中から直接引く |

- **DC-192-2** 郵便番号の CSV を読む処理（対象の郵便番号を絞る処理を含む）は、`src/main` になく、マイグレーションを作る tools の側にある。理由：本番で動かず、tools とテストだけが使うため。#85 の項目である。
- **DC-192-3** 次のテスト専用の操作が、本番のコードにない。DC-155-27 の項目である。
  - 税率のキャッシュを破棄する操作と、そのために広げたクラスの public
  - ファイル保存の設定の値の型を複製する操作（アップロードの URL の期限と接続先を替える 2 つ）
  - ファイル保存のクライアントを作る static の操作。テストのために切り出した、決済のクライアントの組み立ての static の操作も同じに扱う。
  - mock の画面だけが使う、最近の出荷の一覧の問い合わせ。出荷の Repository の port から外し、mock の側に置く。
- **DC-192-4** テストのために可視性を広げた本番のクラスがない。例は、決済の期限切れのジョブの public である。他のパッケージのテストが呼ぶ必要があるときは、公開の API か、テストの補助を通す。DC-155-28 の項目である。

※1：DC-192-1 で削除する操作の AC のテスト（郵便番号の検索の AC-253、AC-254）は、店舗の API のテストで同じ条件を確認していることを plan で確認し、足りなければ店舗の API のテストに移す。

### DS-192-2 同じ処理を 1 か所に（D / P1）

- **DC-192-5** 出荷の mock の画面は、通知のモジュールの文言のキーを使わない。DC-155-20 の項目である。
- **DC-192-6** 画像の変換の処理は、ファイル保存の設定の値の型に依存しない。理由：外部のサービスの知識を 1 か所に限るため。DC-155-24 の項目である。
- **DC-192-7** イベントの記録の表を読み書きする処理は、本番のコードの 1 つのクラスにある。片付けのジョブも、そのクラスを使う。DC-155-30 の項目である。
- **DC-192-8** 認証の情報から token を取り出し、なければ未認証のエラーにする処理は、1 か所にある。今は会員、運営者、ログイン中の利用者の情報の API の 3 か所にある。DC-155-31 の項目である。

### DS-192-3 フロントの使われていないもの（D / P1）

- **DC-192-9** 店舗画面と管理画面の API の型の別名のうち、どこからも使われないものがない。テストだけが使う別名は、plan で残すか決める。#85 の項目である。
- **DC-192-10** 管理画面に、`cn` を再び export するだけで、どこからも import されないファイルがない。店舗画面と管理画面の `cn` の import 元は 1 通りにそろえる。#85 の項目である。
- **DC-192-11** 店舗画面、管理画面、共有のパッケージ、E2E に、使われていない export とファイルがない。定義したファイルの中だけで使うものは、export を外す。
- **DC-192-12** 使われていない export、ファイル、依存を、CI の検査が見つける。生成したコードと、外から取り込んだ画面の部品（shadcn/ui）は、理由を付けて対象外にできる。#85 のコメント（spec 135 第 8 節）の項目である。

### DS-192-4 Java の import（D / P1）

- **DC-192-13** 全てのソースセットの Java のファイルに、使われていない import がない。
- **DC-192-14** 全てのソースセットの Java のファイルの import は、決めた順に並ぶ。順は plan で決め、[バックエンドの書き方](../../rules/backend-coding.md)に書く。
- **DC-192-15** DC-192-13、14 の違反を、CI の検査が見つける。

### DS-192-5 NullAway と規則の検査（D / P1）

- **DC-192-16** NullAway の `AcknowledgeRestrictiveAnnotations` が有効で、`./gradlew check` が通る。生成した interface の `@Nullable` の引数を、上書きで注釈なしにした所を検出するためである。#148 の項目である。
- **DC-192-17** 要求の省略できる部分（必須でない要求のヘッダー・パラメータ）を受ける引数に `@Nullable` がある。今は、決済と配送業者の通知を受ける 2 つの Controller にある。#148 の項目である。
- **DC-192-18** 全てのソースセットの `@SuppressWarnings` の直前に、理由のコメントがある。今は `unchecked` の 12 か所に理由がない。理由のない `@SuppressWarnings` を、規則の検査が見つける。#148 の項目である。
- **DC-192-19** JSpecify 以外の `Nullable` のワイルドカードの import（`import javax.annotation.*;` など）を、規則の検査が見つける。#148 の項目である。
- **DC-192-20** [バックエンドの書き方](../../rules/backend-coding.md) 第 7 節に、次がある。#148 の項目である。
  - getter を `Optional` で返すか `@Nullable` で返すかの基準
  - `Objects.requireNonNull` の理由の文の形と、今のコードがその形にそろうこと（今は「〜がある」の形と「〜がない」の形などが混ざる）
  - [テストの実行方法](../../guides/running-tests.md)のコンパイルの失敗の読み方から、バックエンドの書き方 第 7.2 節への導線

## 6. 非機能要件

- **DN-192-1** 消費者・運営者に見える振る舞いを変えない。
- **DN-192-2** API の契約とデータベースの構造を変えない。地域のマイグレーションを作る tools の出力も変えない。
- **DN-192-3** AC を追加・変更しない。削除する操作の AC のテストは、同じ条件を別の公開の操作で確認する形に移し、テストを弱めない。
- **DN-192-4** 追加した検査は、違反する例で違反を検出できることを確認する。
- **DN-192-5** カバレッジと mutation score が基準を下回らず、`./gradlew check` と `check-all.sh` が通る。

## 9. Open questions

1. 外から取り込んだ画面の部品（管理画面の shadcn/ui の部品の、使われていない小部品。約 50）を削除するか。
   - 推奨：削除しない。検査の対象外にし、理由を除外の一覧に書く。理由：生成したコードで、部品を追加するときに取り込み直すと戻り、差分が増えるため。
   - 別案：削除する。使われていない export が 0 件になる。
2. 規模を L にするか（第 1 節）。
   - 推奨：L。理由：開発の進め方 第 4.2 節の「2 つ以上のモジュールにまたがる」に当たるため。
