# 作業ツリーのセッションが読むもの

セッションの起動の形ごとに、設定・定義・skill を読む場所と、変更が反映される時点を示す。作業ツリーを作るとき、定義・skill・hook を変える spec を確認するときに読む。

作業ツリーの置き場所は `.claude/worktrees/<issue の番号>-<短い名前>`（`.gitignore` で無視され、検索の対象にならない。デスクトップアプリが作るものも同じ）。手動で作るときは、メインの作業ツリーで `git worktree add .claude/worktrees/<issue の番号>-<短い名前> -b agent/<issue の番号>-<短い名前> develop`。`reformat_file` の注意は [開発環境の起動](../../../docs/06-手順書/setup.md)の「IDE の設定」。

測定の方法、確認していない項目、公式の文書との比較は[エージェントの作業フローの調べた仕組みと実績](../../../docs/07-記録/subagents-results.md)の「作業ツリーのセッションが読む設定の測定」。アプリのセッションは、作業ツリーで動くときも、メインの作業ツリーの、commit していない変更を含む内容を読む。

| 起動の形 | `.claude/settings.json` | `.claude/settings.local.json` | `.claude/agents/` | `.claude/skills/` |
|----------|-------------------------|-------------------------------|-------------------|-------------------|
| アプリの作業ツリーのセッション | メインの作業ツリーのもの | メインの作業ツリーのもの。作業ツリーにあっても読まない。hook の変更は 10 秒ほどで反映される | メインの作業ツリーのもの。作業ツリーに足した定義は読まれない | メインの作業ツリーのもの。作業ツリーに足した skill は読まれない |
| アプリのメインの作業ツリーのセッション | メインの作業ツリーのもの | メインの作業ツリーのもの。hook の変更は 10 秒ほどで反映される | メインの作業ツリーのもの。足した定義は、10 秒後は読まれず、40 秒後には読まれた | メインの作業ツリーのもの。足した skill は 10 秒ほどで読まれる |
| 作業ツリーで起動した `claude -p` | 作業ツリーのもの。hook の変更は、動いているセッションにすぐ反映される | 作業ツリーのもの。メインの作業ツリーのものは、作業ツリーにないときも読まない。変更は、動いているセッションに反映されない | 作業ツリーのもの。起動の後に足した定義は、新しいセッションまで読まれない | 作業ツリーのもの。起動の後に足した skill は、数秒で読まれる（足した直後の最初の呼び出しは失敗しうる） |

メインの作業ツリーで起動した `claude -p` は、メインの作業ツリーの 4 つを読む。作業ツリーで起動した `claude -p` は、その作業ブランチに commit された `settings.json` を読む。そのため、`develop` を取り込んでいない作業ブランチには、`develop` の `settings.json` の変更（hook と permissions）が反映されない。アプリの作業ツリーのセッションでも、`$CLAUDE_PROJECT_DIR` はメインの作業ツリーを指す。

定義・skill・hook を変える spec は、マージの前に、変更を入れた作業ツリーで次を確認する。アプリの作業ツリーのセッションは、作業ツリーの変更を読まないので、確認に使えない。

1. その作業ツリーのディレクトリで `claude -p` を起動する（起動の形は、[SKILL.md](SKILL.md)の「ツールの補足」にある `claude -p` の起動）。`claude -p` はメインの作業ツリーの `settings.local.json` を読まないので、`settings.local.json` の hook は、作業ツリーの `.claude/settings.local.json` に置いて確認する。
2. 変更が読まれることを確認する（hook は出力か拒否、定義は Agent のツールが示す名前、skill は Skill のツールが示す名前）。
3. 読まれない起動の形があれば、spec に書き、マージの後の動きを利用者に伝える。
4. 反映が確認できないときは、新しいセッションを起動して確認する。
