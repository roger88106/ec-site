# 商品カタログモジュール

商品、バリアント、カテゴリ、公開状態、商品検索を管理する。

| 項目 | 内容 |
|------|------|
| レベル | A（軸の組み合わせの一意性、公開の条件など、不変条件が多い） |
| 依存 | 税（API）、メディア（API。商品画像のファイル） |
| 関連 spec | [001](../../specs/001-catalog-and-inventory)、[002](../../specs/002-cart-and-order) |

## 商品（集約）

- 商品は、商品品番、名称、説明、税区分、税抜価格、所属カテゴリ、バリアント軸（最大 3 つ）、公開状態、初回表示日時、公開期間、バリアント、画像を持つ。
- バリアントは、バリアント品番、軸の値、表示順、販売停止、画像を持つ。価格は持たず、商品の価格を使う（バリアントごとの価格は将来）。
- 商品とバリアントは 1 つの集約（軸の値の組み合わせが商品内で一意であることは、商品単位の不変条件のため）。
- 品番は属性で、他のデータからの参照には使わない。
- バージョンは商品に 1 つ。バリアントの登録・削除・並び替えも、商品のバージョンを上げる。

### 登録と編集

| 項目 | 決まり |
|------|--------|
| 税区分 | 登録時と変えたときに、今有効な税率があるかを税モジュールに確かめる（`TaxDirectory`）。存在しない税区分も、有効な税率がないのと同じく 400 |
| 所属カテゴリ | 存在しないカテゴリは 400（削除と同時に起きた外部キーの違反も 400） |
| バリアント軸 | 名前は 1〜30 文字で商品内で重複しない。値は 1〜50 文字 |
| 販売終了の商品 | 編集とバリアントの登録はできる（C 側には出ない） |

### バリアント

- 登録は並びの最後に加える。軸の値の数は商品の軸の数と同じ。
- 軸キーは、軸の値を U+001F（単位区切り文字）でつないだ値。軸のない商品では空になるので、軸キーの一意制約でバリアントが 1 つに限られることも DB で守れる。
- 軸の値の組み合わせの重複は 409、軸のない商品への 2 つ目のバリアントは 400。
- 並び替えは、商品のすべてのバリアントを送る（過不足は 400）。
- 公開中の商品の最後のバリアントは削除できない。

### 初回表示日時

C 側に最初に表示された（される予定の）日時。新着順の基準で、商品・バリアントを削除できるかの判定にも使う。定期ジョブを使わず、操作時点の現在時刻と比べて判定する。

- 公開したとき、または公開中に公開期間を変えたときに、「公開した時刻と公開開始日時の遅いほう」を入れる。それが公開終了日時以降なら空にする。
- 過去になったら確定し、以後は変わらない（再公開しても新着順は上がらない）。
- 未来の間はまだ表示されていない。非公開・販売終了にしたら空に戻し、公開期間を変えたら計算し直す。
- 削除できるのは、初回表示日時が空か未来の商品（C 側に一度も表示されていない）。

### 状態の切り替え

公開・非公開・販売終了、販売停止・解除は冪等にする（すでにその状態なら成功して何もしない）。バージョンは受け取らず、保存時に他の更新と衝突したときだけ 409。販売終了からは、公開にも非公開にも戻せない。

### 公開期間

- 基本情報と同じくバージョンを受け取って変える（他の人の変更を黙って上書きしないため）。どの状態の商品にも設定できる。
- 期間の外かどうかは表示時点の現在時刻で判定し、運営者の操作なしにその時刻で切り替わる。

### 商品画像

画像は商品集約の一部で、メディアモジュールのアセット ID と並び順を持つ。ファイルの受け付け・検証・配信・削除はメディアモジュール（[media.md](media.md)）が行い、`MediaDirectory` を通して呼ぶ。

- 1 商品 20 枚まで。先頭が代表画像。並び替えは商品のすべての画像を送る。
- バリアントには、その商品の画像を 1 枚指定できる（任意。なければ代表画像）。画像を削除すると、その指定は外れる。
- 画像の登録・削除・並び替え、バリアントの画像の指定は、バージョンを受け取る。
- 登録では、同じトランザクションでアセットを確定させる（受付の範囲は商品 ID）。画像・商品を削除したら、同じトランザクションでアセットを手放す。
- C 側・B 側に返す画像の URL は、メディアモジュールからまとめて取る。

### できる操作の旗

商品の詳細の応答（`admin.yaml` の `ProductActions`）に、今できる操作の旗を返す。値はドメインの `ProductActions` から作り、画面は同じ判定を持たない。

| 旗 | できるとき |
|----|------------|
| 公開・非公開・販売終了 | その状態でないとき |
| 商品の削除、バリアントの削除 | C 側に表示されたことがないとき |
| バリアントの追加 | 軸があるか、バリアントがないとき |

集約が別の理由で拒む操作（バリアントのない商品の公開、公開中の最後のバリアントの削除）は旗で止めず、操作したときのエラーで知らせる。

## カテゴリ（集約）

- カテゴリは、親、名称、深さ（1〜3）、表示順を持つ。商品とは ID でだけつながる。
- 深さは親の深さ ＋ 1。親を変える操作はないので、登録後に変わらない。
- 登録したカテゴリは兄弟の最後に並べる（表示順は兄弟の最大 ＋ 1。同じになったら登録日時と ID の順）。

### 並び替え

兄弟の全体を送って変える。

- 送る ID は、その親の今の子と過不足なく一致しなければ 400（画面を開いた後に増減していたら並べ直してもらう）。
- `version` は送らない。兄弟の行を ID の順にロックするので、同時の変更は直列になり、後の変更が残る。
- 表示順が変わったカテゴリはバージョンを上げる（並べ替えの前に開いた画面で名称を変えると 409）。

### 削除

子カテゴリを持つカテゴリは削除できない。削除と子の登録が同時に起きた外部キーの違反も業務のエラーに変える（削除は 400、登録は親がない 404）。

## C 側の表示と検索

### 表示される条件

公開状態が「公開」で、公開期間内。この条件はドメインと参照用の SQL の 2 か所にある ※1。

※1：SQL は 1 か所にまとめて一覧と検索で使い（検索だけに非公開の商品が出る事故を防ぐ）、ドメインと一致することを統合テストで確かめる。

### 税込価格での並べ替え・絞り込み

税区分ごとに税率が違うので、税抜の順と税込の順は一致しない（1,000 円・8% は 1,080 円、990 円・10% は 1,089 円）。そこで一覧の SQL で税込価格を計算する。

1. 税モジュールから、税区分ごとの税率の一覧（予定を含む）を取る（インスタンス内で 30 秒キャッシュ）。
2. 表示時刻で有効な税率を決め、税区分ごとの率を SQL に埋め込む。
3. 税込価格を計算し、価格帯の絞り込み（下限・上限ともその値を含む）と並べ替えに使う。

- キャッシュの影響は、税率の登録・変更の反映が最大 30 秒遅れることだけ（切り替えの時刻ちょうどに切り替わる）。
- 有効な税率のない税区分の商品は、税込価格を出せないので表示しない（最後の税率は無期限なので、通常は起きない）。
- 税込価格の計算は税モジュール（Java）とここ（SQL）の 2 か所にあり、端数の境界値を含めて一致を統合テストで確かめる。

### キーワード検索

- 専用の窓口（商品検索）の後ろに置き、通常の商品照会（カテゴリ・価格帯・並べ替え）とはコードもクエリも分ける。
- MVP は商品名と説明の部分一致。精度は求めない（チューニングや形態素解析なし）。ワイルドカード文字はエスケープし、並びは新着順で固定、専用のインデックスは作らない。
- 検索エンジンを入れるときは商品検索の実装を差し替え、商品のイベントでインデックスを同期する。C 側 API は変えない。

## B 側の商品一覧

状態に関係なくすべての商品が対象。並びは登録日時の新しい順、同じなら ID の順。

| 絞り込み | 決まり |
|----------|--------|
| 品番 | 商品品番かバリアント品番の前方一致。英小文字は大文字として扱う |
| 商品名 | 部分一致。英字の大文字・小文字を区別しない |
| カテゴリ | 子孫のカテゴリの商品も含む（C 側と同じ） |

絞り込みの文字列中のワイルドカード文字（`%`、`_`）は、ただの文字として扱う。

## 他のモジュールへの公開

| 種類 | 内容 | 利用者 |
|------|------|--------|
| API | C 側向けの商品一覧・検索・詳細（税込価格を含む）、カテゴリの木 | 店舗 |
| API | 複数のバリアントの、注文に使う情報 ※2 | カート、注文 |
| API | 複数のバリアントの商品 ID | レポート |
| イベント | バリアント登録、バリアント削除、商品削除 | 在庫 |
| イベント | 商品公開、商品非公開、商品販売終了、商品価格変更 | なし（将来の検索インデックスの同期用） |

※2：商品 ID、商品品番、バリアント品番、商品名、軸の値、税抜価格、税区分、画像の URL、C 側に表示されるか、販売停止か。存在しないバリアントは含めない。

イベントはどれも、イベント ID、発生時刻、商品 ID を持つ。バリアント登録・削除はバリアント ID も、商品価格変更は変更後の税抜価格も持つ。品番は持たない。状態の切り替えで状態が変わらなかったときは登録しない。
