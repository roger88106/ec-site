# 段階 4：Stripe の実装

- 前提：段階 3。利用者が Stripe のアカウントを作り、テストモードの鍵を `/.local/` に置いている
- 完了条件：署名の検証と応答の変換の単体テストが通る。sandbox で、注文から与信、期限切れ、キャンセルから与信の取消までを手動で確認し、結果を報告している。
- 参照：[plan](../plan.md) 第 3.1 節、第 3.4 節、spec の BR-17、NFR-5、8、[開発環境の起動](../../../guides/setup.md)、[環境変数](../../../guides/environment.md)

## 着手の前

- [x] **T7401** sandbox で、与信だけを取る Checkout の通知の種類と中身（与信の成功、画面の期限切れ、画面を閉じたとき、取り消したとき）を確認し、payment.md の「通知のエンドポイント」に書く。plan と合わなければ、止めて報告する。

## 実装

- [x] **T7402** `stripe-java` を依存に追加し、依存とライセンスに書く。
- [x] **T7403** [テスト] Stripe の実装の単体テスト：
  - テストの鍵で署名した通知を受け付け、署名が合わない・古い通知を拒否する（BR-17）
  - 記録した通知の中身を、与信の成功・期限切れに変換する。知らない種類は無視する
- [x] **T7404** Stripe の実装（支払画面を作る・閉じる、与信を取り消す）と、通知のエンドポイント `POST /api/webhooks/stripe` を実装する。T7403 を通す。エンドポイントは認証なしで通す。
- [x] **T7405** compose に `stripe-cli`（profile `stripe`）を追加し、開発環境の起動と環境変数の文書、skill `local-dev` に Stripe で動かす手順を書く。
- [x] **T7406** sandbox で手動で確認する：注文 → 支払 → 受付、カードの拒否 → 再試行、期限切れ、キャンセル → 与信の取消。テストのカード番号は Stripe の文書のものを使う。

## T7406 で見つけた不具合

- [x] **T7407** [テスト] 品目が複数の注文で、与信の成功の後に注文した品目をカートから除けない（カートの保存の楽観ロックで失敗し、注文が支払待ちのまま）。品目を一度に除くテスト（カートの単体、2 品目の注文の統合）を追加し、修正する（AC-147）。
