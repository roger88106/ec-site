# Spec 283：文書の書き方の規則と用語を、書き換えの前に決める

ステータス：草案

危険度：高

## 1. 背景と目的

整理の段階の第 2 段（文書）の最初の spec である。第 2 段では、大半の文書を書き換える。古い規則と用語で書き換えると、後で全てを修正することになる。そこで、書き換えの前に、文書の書き方の規則と用語を決める。日本語の整理の全体（第 4 段）のうち文書の部分は、本 spec の規則を使い、第 2 段の各 spec の完了の条件に含めて行う（利用者の決定、2026-10-29）。

追跡の issue は [#283](https://github.com/roger88106/ec-site/issues/283) で、扱う issue（sub-issue）は #267（再検討する語）と #100（1 文の長さと読点の数の検査）である。参照の書き方と、skill `docs` の存在しない文書への参照も扱う（issue 担当のセッションとの分担、2026-10-29）。作業ブランチは `283-writing-rules` である。

本 spec は整理の spec である（[文書の記号と番号](../../05-開発規則/notation.md)）。規則の文書、skill、CI の検査の script を変えるので、危険度は高とする（[エージェントの作業フロー](../../05-開発規則/subagents.md) 第 4 節）。

## 4. 目的と完了条件

### DS-283-1 書き方の規則の正本を 1 つにする（D / P1）

- **DC-283-1** 文書の書き方の規則が、1 つの文書にある。対象は、第 1.1 節 ※1 の 4 か所の規則の全てである。
- **DC-283-2** 他の文書は、書き方の規則を転記せず、その文書を指す。対象は、skill `docs` と開発の進め方、レビューの手順と校閲役の定義、`ja-text` の説明である。
- **DC-283-3** skill `docs` には、手順だけが残る。手順は、進め方、確認のコマンド、参照の修正、語の一括の置き換えである。
- **DC-283-4** 規則の出典（`japanese-tech-writing`、Unlicense）の表示が、移した後の文書にある。
- **DC-283-5** constitution の文書の地図と、AGENTS.md の最初に読むものに、正本の文書がある。
- **DC-283-6** 存在しない文書（`coding.md`）への参照がない。

### DS-283-2 語を選ぶ規則を改める（D / P1）

- **DC-283-7** 正本に、語を選ぶ基準が書いてある。基準は、一般の日本語の技術文書の読者に通じることである。
- **DC-283-8** 正本に、造語を作らない規則と、どうしても必要なときの手順がある。手順は、用語集に定義を加え、校閲役に読ませることである。
- **DC-283-9** 正本に、英語の語を直訳しない規則がある。分野で定着したカタカナ語（ボックス、コマンドなど）があれば、それを使う。
- **DC-283-10** 「和語より技術文書の語」の今の規則と、口頭の語を避ける規則が、DC-283-7〜9 と矛盾しない形で残る。

### DS-283-3 参照を「文書の名前と節の見出し」で書く（D / P1）

- **DC-283-11** 正本に、参照の書き方の規則がある。参照は、文書の名前と、節の見出し（番号を除く）で書く。
- **DC-283-12** 文書の参照の検査（`doc-refs`）が、見出しで書いた参照の先に、その見出しがあることを確認する。同じ文書に同じ見出しが 2 つ以上あって先が決まらないときは、失敗にする。
- **DC-283-13** アーカイブの外の参照（コードのコメントを含む）が、見出しの形に置き換えてある。
- **DC-283-14** アーカイブの外で、節の番号の参照（`第 N 節`）を書くと、検査が失敗する。対象は、Markdown の全ての `第 N 節`（インラインコードの外）と、コードのコメントで文書の名前の直後にある `第 N 節` である。
- **DC-283-15** skill `docs` の参照の修正の手順が、見出しの形に合っている。

### DS-283-4 再検討する語を置き換える（D / P1）

- **DC-283-16** 第 2 節の各語の新しい語が、利用者が決めた語として用語集にある。用語集に置かない語（一般の語の言い換え）は、言い換えの一覧にある。
- **DC-283-17** アーカイブの外に、第 2 節の元の語（第 2 節の意味のもの）が残っていない。対象は、文書と skill、サブエージェントの定義、コードのコメントとテスト名、script の出力の文である。
- **DC-283-18** 誤検出のない元の語は、言い換えの一覧の error にある。文脈で決まる元の語（`段`、単独の `高`・`低`、`動かして確認する`）は warning にあり、その分け方が plan にある。
- **DC-283-19** 中国語の用語と形が近い元の語（`無記憶`、`指令`）は、言い換えの一覧（層 1）の error に置き、中国語の混入の検査の一覧（層 2）には置かない。理由：誰が書いても通じにくい語で、同じ語を両方に置かない規則（skill `zh-mixing`）があるため。
- **DC-283-20** 識別子（`--round` などの script の引数、label「見逃し」、ファイル名）は変えない。変えないものの一覧が plan にある。

### DS-283-5 1 文の長さ、読点の数、表のセルの長さを CI で検査する（D / P1）

#100 の項目である。

- **DC-283-21** pull request で追加・変更した行に、字数か読点の数が閾値以上の文があれば、CI が失敗する。
- **DC-283-22** 表のセルごとに文の字数の合計を測り、閾値以上のセルを示す。閾値は測定で決め、tasks の結果に書く。CI を失敗にするかは plan で決める。
- **DC-283-23** DC-283-21 の検査は、追加・変更していない既存の行では失敗にしない。
- **DC-283-24** DC-283-21・22 の閾値と、対象のファイルの範囲が、検査の script の説明にある。
- **DC-283-25** commit の前の hook が、ステージした追加行で、DC-283-21 と同じ判定を示す。判定は CI と同じ関数で行う。

### DS-283-6 本 spec の文書の完了の条件（D / P1）

第 2 段の各 spec が共通で満たす完了の条件である（第 1 節）。

- **DC-283-26** 本 spec で書き換えた所の `ja-text` の warning が 0 である。対象は、正本の全体、skill `docs` の全体、開発の進め方の移した後の 2 つの節である。語と参照の置き換えだけで変えた所は対象にしない ※3。
- **DC-283-27** spec・plan・tasks と、書き換えた文書を、利用者の確認の前に文書のレビュー（skill `review` の手順 8）と校閲役（同 手順 9）が読んでいる。

※3：置き換えは数百のファイルに及び、そのファイルの既存の warning を全て修正すると、第 2 段の後の spec の書き換えと重なるため。
