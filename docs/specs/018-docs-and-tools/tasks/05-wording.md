# 段階 5：言い回し

- 前提：段階 4（新しい文書も対象に含めるため）。段階 2 の T018-02-03 で決めた方法を使う。
- 完了条件：すべての対象の文書で候補を提示し、利用者が判断し、採ったものを直した。言い換えの一覧と skill `docs` 第 2 節が直っている。番号と節の見出しが変わっていない（DN-22）。`check-all.sh` が通る。
- 参照：[plan](../plan.md) 第 6 節、spec の DS-51、[開発の進め方](../../../process/workflow.md) 第 1.4 節、skill `docs`（[SKILL.md](../../../../.claude/skills/docs/SKILL.md)）

## 方針

- 候補は、skill `review` の文書のレビューの手順で挙げる（日本語だけの文脈のサブエージェントに見本を渡す）。
- 候補は表（ファイル、行、今の書き方、修正案、理由）で示す。利用者が採否を決め、採ったものだけを直す。
- 意味、番号、節の番号と構成、表の構成は変えない（DC-193）。
- tasks には、範囲ごとに、直したファイルと内容の要約だけを書く。手順は書かない。
- 1 回の提示は、目安として 1,000 行以内にする。
