# 毎回読む文書と固定の文脈の大きさ

毎回読む文書の大きさと、セッションの固定の文脈の大きさを置く。文書を整理した後に、効果を比べるときに読む。

## 1. 測り方

- 文書の大きさは、`wc -c` のバイト数で測る。
- 固定の文脈は、新しいメインのセッションを起動した直後に、デスクトップアプリの使用量の表示（文脈の内訳）で読む。
- spec 309 が変えた文書のうち、固定の文脈に自動で入るのは `AGENTS.md` だけである。内訳の「Memory files」に含まれる。
- `/.local/agent/environment.md` は、メインのセッションでは SessionStart の hook で最初のメッセージに入る。サブエージェントには入らない。
- constitution や開発の進め方などは、セッションが読んだときに文脈に入る。会話の中のファイルの読み取りとして数える。
- 基準の記録は、日本語の文書を約 2.5 文字で 1 token、英字の混ざる文書をおよそ 5 バイトで 1 token と概算した。正確な数は数えていない。

### 基準との比較

- Memory files は 3,278 から 3,006 に、272 token 減った。`AGENTS.md` の減った 2,233 バイトに当たり、約 8 バイトで 1 token である。Memory files には、`AGENTS.md` のほかに、全てのプロジェクトに共通の、利用者の規則の文書と MEMORY.md が入る。
- spec 309 の変更が固定の文脈に毎回入るのは `AGENTS.md` だけである（「測り方」）。constitution や開発の進め方などは、セッションが読んだときに文脈に入るので、上の表には現れない。
- Messages の差（3,295 と 1,045）は、spec 309 の変更によるものではない。最初の指示の長さと、SessionStart の hook が文脈に加えるもの（`/.local/agent/environment.md`）の違いと見られるが、確認していない。
- 基準（整理の前、約 10 万 token）と比べると、今の固定の文脈は約 8.3〜8.5 万 token である。基準の最初のメッセージ（2 万 token）は環境の文書と指示を含み、今回の測定は短い指示なので、合計はそのまま比べられない。
- System tools は 3.9 万、MCP tools は 2 万、System prompt は約 1.2 万、Skills は 0.7 万で、どれも基準と同じである。Memory files は基準の 0.25 万から 0.30〜0.33 万に増えている。基準の後に `AGENTS.md` と MEMORY.md が増えたためと見られ、spec 309 で一部を減らした。
- issue #265 の測定（token の合計、レビューの割合、CI の秒数）は、固定の文脈を含まないので、この表とは比べない。
- 最も大きいのは、ツールの定義（System tools と MCP tools で約 6 万 token）で、文書の整理では減らない。
