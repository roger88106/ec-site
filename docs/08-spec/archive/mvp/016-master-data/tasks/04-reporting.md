- 前提：段階 2
- 完了条件：売上レポートは注文の写しの都道府県のコードで集計し、都道府県別の売上に名前を返す。管理画面は名前を応答から表示する。都道府県・市区町村・郵便番号の表が、地域モジュールのほかにない（テストのデータを除く）。AC-262、263 のテストが通る。`./gradlew check`、`check-frontend.sh` が通る。
- 参照：[plan](../plan.md) 第 2.4 節、spec の US-56、[レポートモジュール](../../../../../design/modules/reporting.md)、[管理画面の構成](../../../../../design/apps/admin.md)

- [x] **T016-04-04** [テスト] 管理画面の顧客別のレポートの結合テストを修正する：都道府県の名前を応答から表示する（AC-262）。レッドを確認する。

- [x] **T016-04-07** 都道府県・市区町村・郵便番号の表が、地域モジュールのほかにないことを確認する（AC-263）。都道府県名（「北海道」など）で `git grep` し、地域の最初のデータとテストのデータのほかに出ないことを確認する。確認方法をこのタスクの下に書き、`ac-exclusions.json` に書く。
  - 確認方法：お届け先の seed にない都道府県名（鳥取県、徳島県、佐賀県、山梨県）で `git grep -l` し、地域の最初のデータ（`V202610200910__region_seed_master.sql`）だけに出ることを見る。47 の一覧はどこかにあれば必ずこれらを含むので、ほかに表がないと分かる。お届け先の seed にある都道府県名（沖縄県）は、ほかに注文の seed（55 件の住所）、地域のテスト、文書の例（設計書、用語集、spec 010）に出るが、どれも表ではない。
