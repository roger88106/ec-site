# Spec 284：CI の検査の説明を各 script のコメントに寄せ、文書の写しを守るだけの検査をやめる

ステータス：確定
危険度：高

## 1. 背景と目的

milestone「整理の段階」の第 2 フェーズ（文書）の 2 つ目の spec である。追跡の issue は [#284](https://github.com/roger88106/ec-site/issues/284) で、作業ブランチは `284-ci-docs` である。[#266](https://github.com/roger88106/ec-site/issues/266) を sub-issue として扱う。整理の spec なので、AC、API、データベースは変えない。規模は M で、2026-10-29 に利用者が承認した。

[CI の検査](../../06-手順書/ci.md)の「CI の検査の script」の検査の表の各行と、対応する script の先頭のコメントは、ほぼ同じ内容である。検査を変えるたびに、両方を修正する必要がある。

CI の検査の文書は 71,667 バイトあり、そのうち検査の表（34 行。`scripts/ci/` の直下の検査 33 本と、`ja-text` の `--changed` の行）が 45,539 バイトを占める。`lib/` の一覧もある。`lib/` には 18 のファイル（テストを除く）があり、一覧にないのは `comment-text.mjs`・`added-diff.mjs`・`merge-base.mjs` の 3 つである。

また、設計書の「関連 spec」の行とマイグレーションの一覧は写しで、その一致だけを確認する検査がある。方針は 2026-10-29 に利用者が決めた（記録は Git にない）。

- 検査の表は「名前と 1 文の目的」に縮め、詳しい説明は各 script の先頭のコメントを正本にする。
- 設計書の「関連 spec」の行とマイグレーションの一覧は、検査による強制をやめ、行と一覧も削る。

危険度を高にする理由：検査の script（`scripts/ci/`）、git の hook（`scripts/dev/hooks/`、`scripts/dev/lib/`）、`.claude/`、規則の文書（`docs/05-開発規則/`）を変えるため。

### 本 spec の用語

| 用語 | 意味 |
|------|------|
| 検査の表 | [CI の検査](../../06-手順書/ci.md)の「CI の検査の script」の最初の表。1 行が `scripts/ci/` の直下の 1 つの検査に当たる |
| 先頭のコメント | script の 1 行目から続く `//` の行。script が何を確認するかを書く |
| 写し | 正本（コード、設定、他の文書）にある事実を、別の文書にも書いたもの |
| 写しを守る検査 | 写しと正本が一致することだけを確認する検査。写しを削れば不要になる |
| 経緯 | 過去に試した結果と、決めた時点の事情。今の規則と設定値の根拠にならないもの |

### 写しを守る検査の候補

`scripts/ci/` の直下の検査と、文書を読むバックエンドのテストのうち、写しを守るものを挙げる（2026-11-01 の `develop`、6dd83e14）。扱いは「決めたこと 1」で決めた。第 2 フェーズの spec 4・5 は、issue 担当のセッションの計画にあり、まだ起票していない。

| 検査 | 写し | 正本 | 写しを守る以外の役割 | 推奨 |
|------|------|------|----------------------|------|
| `related-specs` | 設計書 15 ファイルの概要の表の「関連 spec」の行 | Git の履歴 | なし | 削る（利用者の決定） |
| `design-migrations` | 設計書 12 ファイルの「データモデル」の節のマイグレーションの一覧 | `db/migration/` のファイル | なし | 削る（利用者の決定） |
| `ci-docs` | 検査の表の名前 | `scripts/ci/` の直下のファイル | 検査を追加したときに説明の書き漏れを防ぐ | 残し、DC-284-10〜12 の形に修正する |
| `progress` | MVP の README の進捗の表と、MVP の完成までの一覧 | 各 spec の tasks のチェックボックス | アーカイブした 1→10 の spec の tasks が全て済んでいることの確認 | 残す。MVP の部分は第 2 フェーズの spec 5 で扱う |

| `role-permissions` | [ロールと権限の対応表](../../02-設計/role-permissions.md) | API の契約と realm | 契約に権限の漏れがないことの確認 | 残す。生成物を Git に置くかは、第 2 フェーズの spec 5 の AC 一覧と一緒に決める |

## 3. 目的と完了条件

### DS-284-1 検査の説明の正本を、script の先頭のコメントにする（D / P1）

- **DC-284-1** 検査の表は、検査の名前と目的の 2 列である。
- **DC-284-2** 目的の文は、1 行 120 字以内である。
- **DC-284-3** 表の行から削った内容（確認すること、失敗したときの修正の手順、除外の書き方）は、対応する script の先頭のコメントにある。
- **DC-284-4** DC-284-3 の例外として、コードから直接読める事実と経緯は、コメントに移さずに削ってよい。移さずに削ったものは、「作業の記録」に検査ごとに 1 行で書く。
- **DC-284-5** `lib/` の各ファイル（テストを除く）の役割が、そのファイルの先頭のコメントにある。今の一覧にない `comment-text.mjs`・`added-diff.mjs`・`merge-base.mjs` も含む。
- **DC-284-6** CI の検査の文書に `lib/` の一覧がない。代わりに「複数の検査が使う関数は `lib/` に置き、役割は各ファイルの先頭のコメントに書く」の 1 文がある。
- **DC-284-7** CI の検査の文書に、実測値（時間、カバレッジのばらつき）と経緯がない。
- **DC-284-8** 設定の値の根拠になる実測値（統合テストのフォークの数、カバレッジの許容の幅、PIT とジョブの時間）は、`docs/07-記録/ci-results.md` に移す（「決めたこと 2」）。
- **DC-284-9** CI の検査の文書が 26,000 バイト以下である。理由：表で約 41,000 バイト、`lib/` の一覧で約 6,000 バイト、実測値と経緯で約 2,000 バイトが減り、約 23,000 バイトになる見込みのため。上限には 3,000 バイトの余裕を見る。
- **DC-284-10** `ci-docs` は、表の名前と `scripts/ci/` の直下の検査が 1 対 1 に対応しないとき、失敗する（今と同じ）。
- **DC-284-11** `ci-docs` は、検査の表が 2 列でないとき、失敗する。理由：表に詳しい説明を再び追加するのを防ぐため。
- **DC-284-12** `ci-docs` は、`scripts/ci/` の直下の検査と `lib/` の各ファイル（テストを除く）のうち、1 行目がコメント（`//`）でないものがあるとき、失敗する。理由：先頭のコメントがない script を残さないため。
- **DC-284-13** `ci-docs` のテストが、DC-284-10〜12 の違反の例（表にない検査、3 列の表、先頭のコメントのない script）と、通る例を確認する。

### DS-284-2 写しを守るだけの検査と、その写しを削る（D / P1）

- **DC-284-14** `related-specs` の script、テスト、除外の一覧（`related-specs-exclusions.json`）がない。
- **DC-284-15** `design-migrations` の script とテストがない。

### DS-284-3 規則の本文に、AI のサービス固有の名前がないことを検査する（D / P1）

#266 の 2 つの項目は、サービス固有の名前の検査（本節）と、`.gitignore` と文書の `.claude/` の列挙の照合（「決めたこと 3」）である。

- **DC-284-20** 新しい検査の script が `scripts/ci/` の直下にある。
- **DC-284-21** 対象のファイル（「決めたこと 4」）の本文に、一覧にある名前があれば、新しい検査はファイル:行を出力して失敗する。
- **DC-284-22** 名前の一覧は、script の中の 1 か所に置く。
- **DC-284-23** 判定は誤りの防止とする（[文書の書き方](../../05-開発規則/writing.md)の「spec と plan の書き方」）。誤って書いた名前を見つけ、意図して作った回避（字を分ける、全角にする）は対象にしない。
- **DC-284-24** 名前を書いてよい場所を、許可する形の一覧で決める。一覧に当たらない場所の名前は全て失敗にする。許可する場所は次のとおりである。
  - パスと識別子のコードスパン（`` `.claude/` `` など）、Markdown のリンク先（`.claude/skills/...` などのパス）。
- **DC-284-25** 検査のテストが、名前を書いた本文の行で失敗し、許可する形（コードスパンのパス、リンク先のパス）で通ることを確認する。
- **DC-284-26** 対象のファイルに違反がなく、検査が通る。
- **DC-284-27** 次の 2 か所が、`.claude/` の下のファイルとフォルダーを列挙せず、`.gitignore` の許可の行を指す。
  - [constitution](../../constitution.md)の「リポジトリ構成」
  - [ブランチとリリース](../../06-手順書/branches.md)の「切り方と pull request」
