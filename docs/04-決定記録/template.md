# 決定記録の雛形

## この雛形の使い方

| 項目 | 内容 |
|------|------|
| 読者 | 設計の理由を知りたいエンジニアとエージェント |
| 置くもの | 選択肢のある決定の背景・選択肢・結論 |
| 置かないもの（置き場所） | 選択肢のない規則は[機能仕様](../03-機能仕様/)（本文には規則だけを書き、理由はこの決定記録に置いてリンクで指す）、処理の流れは[設計](../02-設計/)、API の項目は OpenAPI |
| いつ書くか | 設計上の選択肢があり、選んだ理由を残す決定をしたとき |
| ファイル名 | 英語の短い名前（例：`order-capture-before-shipment.md`）。1 つの決定に 1 ファイル |
| 決定を変えたとき | 新しいファイルを書き、古いファイルの「関連」に新しいファイルを書く。古い決定の本文は書き換えない |

## 骨組み

次の骨組みを写して使う。各見出しの下の説明は、書いたら削除する。

```markdown
# <決定の要約>

## 背景

何を決める必要があったか。決定を制約する条件（外部サービスの仕様、既存の規則など）を、出典とともに書く。

## 選択肢

| 選択肢 | 良い点 | 悪い点 |
|--------|--------|--------|
| A：… | … | … |
| B：… | … | … |

出典で確認できる選択肢だけを挙げる。

## 結論

選んだものと、選んだ理由。受け入れた欠点（選ばなかった選択肢の良い点を捨てたことを含む）も書く。

## 日付

決定した日（YYYY-MM-DD）。日付が分からないときは、分からないと書く。

## 関連

- spec・plan：決定を書いた spec の文書
- 機能仕様・設計：この決定に基づく規則や処理の流れを書いた文書
- 置き換えた決定・置き換えられた決定：あればファイルへのリンク
```
