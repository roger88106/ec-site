## 起票のまとめの案

spec の最後のレビューの推奨のうち、本 spec で直さなかったものと、実装の中で見つけた後回しの作業を、既存の issue と重複しないようにまとめた。利用者が承認したら、issue 担当のセッションが起票する。

| 案 | 起票の方法 | 内容 |
|----|------------|------|
| A | 新しい整理の issue（milestone `1→10`） | 静的解析とモジュールの境界の補い：(1) Checkstyle の `AvoidStarImport` で、全てのワイルドカード import を禁じる（今は `Nullable` を含む 3 つのパッケージだけを規則の検査が見る）。(2) 認証情報から token を取り出す共通の操作を、presentation の外から呼ばない規則（ArchUnit）。(3) 通知モジュールが出荷モジュールの文言のキーの形を文字列で組み立てる所を、出荷モジュールの公開 API に表示名のキーを返す操作を置く形にする。(4) mock の出荷の問い合わせが `persistence/` の外で jOOQ を使う所を、書き方の例外として書くか、`persistence/` に置く。(5) IdP の環境変数の既定値が、`knip.ts`、`check-frontend.sh`、CI の 3 か所にあるのを 1 か所にする。(6) 地域のマイグレーションを再生成すると、先頭のコメントの文書のパスだけが、コミット済みのマイグレーション（古い `docs/backend/`）と違う。生成の script の出力とコミット済みのものを一致させる方法を決める |
| B | #202 へのコメント | spec の番号の検査の対象に、リポジトリのルートの設定のファイル（`knip.ts` など）を加える。#202 の「対象の外の `build.gradle.kts` のコメント」と同じ種類 |

- 構成の検査のテストが `System.getProperty` を直接読む指摘は、#202 の「文書の置き場所の system property の読み方をそろえる」と同じなので、起票しない。
