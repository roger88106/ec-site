# フロントの書き方

原則は [constitution](../constitution.md) 第 2・12 節。アプリごとの構成（ディレクトリ、API の呼び出し、表示の決まり、画面の追加手順）は [管理画面の構成](../frontend/admin.md) と [店舗画面の構成](../frontend/store.md) にあり、本書は両方に共通する書き方と、構成の文書から引くべき規則だけを書く。部品の共有と i18n の決まりは spec 006 で足す。

## 1. 置き場所

### 1.1 画面に依存しない処理は `lib/` の関数にする

- **規則**：判定、変換、表示の整形、列挙の表示名は、`lib/` の関数（React に依存しない）にし、横に単体テストを置く。画面の部品は、その関数を呼ぶだけにする。
- **理由**：規則を描画なしの速いテストで確かめ、画面を作り直しても規則が残るようにするため（constitution 12.2）。
- **確かめ方**：人手（見直し）。

### 1.2 機能ごとに `features/<機能>/`

- **規則**：画面と、その画面だけで使う部品・処理は `features/<機能>/` に置く。複数の機能で使う部品は `components/`、shadcn/ui の生成物は `components/ui/`（手で直さない）。
- **理由**：機能を足す・消すときに触るファイルを 1 か所にまとめるため。
- **確かめ方**：人手（見直し）。shadcn/ui の生成物は Biome の対象から外してある（各プロジェクトの `biome.jsonc`）。

## 2. API

### 2.1 生成した型で呼ぶ

- **規則**：API は `openapi-fetch`（管理画面は `openapi-react-query` の `$api`）で、OpenAPI から生成した型を使って呼ぶ。パスや応答の型を手で書かない。
- **理由**：契約が変わったときに、型チェックで食い違いが分かるようにするため（constitution 9）。
- **確かめ方**：自動（型チェック）。

### 2.2 エラーの文は API の `message` を出す

- **規則**：業務のエラーと入力のエラーは、API のエラーの応答の `message`（項目ごとは `errors`）をそのまま出す。画面で文を作るのは、通信の失敗など API の応答がないときだけ。
- **理由**：メッセージの正本をバックエンドの 1 か所にするため（constitution 9）。
- **確かめ方**：人手（見直し）。

## 3. 店舗画面のサーバーアクション

### 3.1 `catch` では `unstable_rethrow` を先に呼ぶ

- **規則**：サーバーアクションで例外を `catch` するときは、最初に `unstable_rethrow(error)` を呼ぶ。`redirect` は try の外で呼ぶ。
- **理由**：Next.js の `redirect`・`notFound` は例外で移動を知らせるので、`catch` で飲み込むと、ログインの画面への移動などが通信の失敗として扱われてしまうため。
- **確かめ方**：人手（見直し）。サーバーの処理のテストは段階 3 で足す（spec 004 の DC-14）。

### 3.2 結果は `ActionResult` で返す

- **規則**：サーバーアクションは失敗を例外にせず、`ActionResult`（`lib/actionResult.ts`）で返す。ただし 401 はログインの画面へ移す。
- **理由**：操作した部品の近くに結果を出し、入力を消さないため（[店舗画面の構成](../frontend/store.md) 第 4.1・6 節）。
- **確かめ方**：人手（見直し）。

## 4. 整形と lint

- **規則**：Biome の設定（`biome.jsonc`）に従う。インデントは 2 文字、行の長さは 120、文字列は単一引用符、文末のセミコロンは要るところだけ。Tailwind のクラスの並びは Biome が揃える。
- **理由**：書き方の揺れを道具で無くし、見直しで扱わないため。
- **確かめ方**：自動（`pnpm lint`。CI）。
