- 前提：段階 2
- 完了条件：管理者で全操作ができ、閲覧者は更新で「権限がない」と示される。下記の手動確認が通る。管理画面の lint・型チェック・テスト・ビルドが通る。
- 参照：[plan](../plan.md) 第 1、4、6 節、[管理画面の構成](../../../frontend/admin.md)、skill `new-screen`

## タスク

- [ ] **T3501** 管理画面の構成を直す：ログインの状態の取り方、token をメモリーにだけ持つこと、API に token を付ける場所、401・403 の扱い、テストでのログインの扱い。
- [ ] **T3502** ログインを組み込む（`oidc-client-ts` + `react-oidc-context`）。
  - 起動したらログインを求める（AC-132）
  - token はメモリーに持ち、期限が近ければ更新する。token がないとき（新しいタブ、再読み込み）は、画面ごとの移動で IdP から取り直す
  - ログアウトは IdP のログアウトに移る（AC-135）
  - 接続先は環境変数にする
- [ ] **T3503** API の呼び出しに token を付ける（`openapi-fetch` の middleware）。401 ならログインし直す。403 は「この操作を行う権限がありません。」と示す（AC-141）。
- [ ] **T3504** ヘッダーに運営者の氏名とログアウトを置く（AC-135）。
- [ ] **T3505** [テスト] 結合テスト：403 の応答で「権限がない」と示す（AC-141）。既存の結合テストが、ログインした状態として動くようにする（テストではログインを置き換える）。
- [ ] **T3506** 手動確認：管理者で商品・在庫・注文の操作ができる。閲覧者で一覧・詳細は見られ、更新で「権限がない」と示される。新しいタブ・再読み込みでパスワードを求められない。ブラウザーを閉じて開き直すとログインを求められる。会員のアカウントではログインできない。
