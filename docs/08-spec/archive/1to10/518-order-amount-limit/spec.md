# Spec 518：注文の総額を、決済サービスが受け付ける範囲に限る

種類：機能　規模：L　ステータス：確定

## 背景と目的

注文の総額にも支払の金額にも、上限と下限の検査がない（追跡の issue：#518）。総額は 1 円になりうる（商品の税抜の価格は 1 円から、送料は設定で 0 円にできるため）。総額は 1 億円を超えることもある（税抜 9,999,999 円の商品 10 個で、税込の総額は約 1 億 1 千万円。カートには 30 品目まで追加できるので、さらに大きくなる）。

決済サービス（Stripe）の sandbox（日本のアカウント）で、日本円の金額ごとに支払画面の作成と与信の取得を確認した（2026-11-19）。決済サービスの文書（通貨ごとの「最小および最大請求金額」）では、日本円の最小は 50 円である。日本のアカウントの JCB、Diners Club、Discover は 8 桁（99,999,999 円）までである。

| 確認したこと | 結果 |
|--------------|------|
| 支払画面を作る（総額 49 円） | 拒否（50 円未満） |
| 支払画面を作る（総額 50 円） | 成功 |
| 支払画面を作る（総額 1 億円〜999,999,999,999 円） | 成功（13 桁は拒否） |
| JCB のカードで与信を取得する | 99,999,999 円まで成功、1 億円は拒否 |
| American Express のカードで与信を取得する | 999,999,999 円まで成功、10 億円は拒否 |
| Visa のカードで与信を取得する | 10 億円で成功 |

今は、50 円未満の注文を作れる。支払画面を開くと決済サービスに拒否されてエラーになり、注文は支払待ちのまま、支払の期限を過ぎてキャンセルされる。99,999,999 円を超える注文は、JCB などのカードでは決済サービスの画面で拒否され、支払えない。

決済サービスが受け付けない総額の注文を、注文手続きの開始と注文の時点で、業務のエラーとして拒否する。支払画面で失敗して、支払えない注文が残らないようにする。関わる文書は、[注文モジュール](../../../../03-機能仕様/order.md)と[決済モジュール](../../../../03-機能仕様/payment.md)。

## スコープ

| 含める | 含めない |
|--------|----------|
| 決済の業務規則に、1 回の支払の金額の範囲（下限と上限）を定める | 範囲を設定で変えること |
| 注文手続きの開始と注文で、総額が範囲の中かを判定する | カートの画面で、注文手続きの前に範囲を示すこと |
| 拒否のエラーコードと文言 | 管理画面 |
| 店舗画面で、拒否の文言とカートへの導線を示す | 変更前に作られた、範囲外の支払待ちの注文の扱い |

## 受け入れ条件

### US-518-1 支払えない総額であることを、注文の前に知る（C / P1）

- **AC-518-1** 注文手続きの開始で、総額が下限より小さければ拒否する。注文手続きを作らず、引当もしない。
- **AC-518-2** 注文手続きの開始で、総額が上限より大きければ拒否する。注文手続きを作らず、引当もしない。
- **AC-518-3** 注文で、総額が範囲の外なら拒否する。注文と支払を作らず、在庫を減らさない。例：注文手続きの開始の後に価格が変わり、範囲の外になったとき。
- **AC-518-4** 総額が下限ちょうど、または上限ちょうどなら、注文手続きを開始でき、注文できる。
- **AC-518-5** 拒否の応答は業務のエラーで、文言に下限と上限の値を差し込む。理由：文言の値は正本から差し込む規則（[注文モジュール](../../../../03-機能仕様/order.md)の「今有効な AC」の AC-266）があるため。
- **AC-518-6** 店舗画面は、注文手続きの開始が拒否されたら、カートの画面に拒否の文言を表示する。
- **AC-518-7** 店舗画面は、注文が拒否されたら、注文手続きの画面に拒否の文言とカートへの導線を表示する。導線は、カートの変更や在庫不足のときと同じ。
- **AC-518-8** 上限ちょうどの総額の注文で、支払画面を開ける。

## 業務ルール

- **BR-518-1** 1 回の支払の金額の範囲は、50 円以上 99,999,999 円以下とする。範囲は決済モジュールが定め、注文モジュールは決済モジュールの公開の API から範囲を取得する。理由：決済サービスの制約で、決済の規則であるため。
- **BR-518-2** 注文での範囲の判定は、確認した総額との比較（総額が変わったかの判定）の後にする。理由：総額が変わったときは、まず変わったことを示して再度確認してもらうため。

## 依存

| 対象 | 関係 |
|------|------|
| 決済モジュール | 範囲を公開の API で示す |
| 注文モジュール | 注文手続きの開始と注文で判定する |
| #570（並行） | 注文と決済の公開の API の列挙を変える。同じファイルを変えるときは、変える行を重ねない |
| #556（並行） | 支払の期限切れのジョブを変える。この spec は変えない見込み |
| #423 | 本 spec の後に始める（同じ支払と注文の修正の順で、本 spec の次） |

## Non-goals

| 項目 | 理由 |
|------|------|
| 範囲を設定で変える | 決済サービスの制約で、運用で変える値でないため |
| カートの画面で範囲を事前に示す | 注文手続きの開始の拒否で足りるため |
| 決済サービスごとに範囲を変える | 決済サービスは 1 つで、内部の mock も同じ範囲で動けば足りるため |
| 範囲外の既存の支払待ちの注文 | 支払の期限を過ぎるとキャンセルされるため |
