# 店舗モジュール

C 側 API の商品の一覧・検索・詳細、カートの表示、店舗の情報を、複数のモジュールの結果を組み合わせて返す。ドメインもテーブルも持たない。モジュールのレベルと境界、処理の流れ、API の案内、パッケージの構成は、[店舗の設計](../02-設計/storefront.md)に書く。

## 業務規則

### 在庫の有無

- 商品の一覧・検索は、1 ページ分の商品に、バリアントの在庫の有無を付ける。販売できるバリアントのいずれかに在庫があれば「在庫あり」、全バリアントが在庫なしなら「在庫なし」とする。
- 在庫がまだないバリアントは「在庫なし」（[在庫モジュール](inventory.md)）。
- 商品・価格・公開状態・在庫はキャッシュしない。

### 商品の詳細

- 商品の全バリアントに在庫の有無を付ける。表示されない商品は、存在しない商品と同じく見つからない（404）。
- 軸ごとの値の一覧は、バリアントの表示順で最初に現れた順に、重複を除いて求める。在庫なしや販売停止で選べない値も含める。

### 価格の表示

- 商品の一覧・詳細の価格は、税込と税抜の組で返す。店舗画面は、税込価格を主に、税抜価格を括弧で併記して表示する（BR-4）。

### カートの表示

- 金額と購入できるかの判定は、注文モジュールの見積もりに任せる。品目の取得から判定までを任せ、店舗は結果を表示の型に変える ※1。
- 会員のカートは持ち主だけに表示し、他の人には 404 を返す。持ち主かどうかは、注文モジュールが、要求した会員の ID（ログインしていなければなし）とカートの持ち主を照合して判断する。

※1：注文手続き中なら、注文モジュールがその引当を販売可能数から除いて見積もる（[注文モジュール](order.md)の「見積もり」）。

### お届け先の入力

- ハイフンの類は、※2 の表の 9 つの文字をいう。このうち全角のハイフンマイナスだけが、NFKC の正規化で `-` になる。
- 店舗画面は、郵便番号と電話番号を Unicode の NFKC で正規化し、残ったハイフンの類を `-` に置き換えてから、住所の補完と注文に使う。氏名と住所は変換しない（BR-416-1）。
- 変換しても、入力欄の値は変えない。
- 変換の後も形式が違う郵便番号（ハイフンが 2 つ以上ある、など）は、住所を補完せず、注文では形式の誤りになる。

※2：半角の長音符は、NFKC の正規化で長音符になる。

| 文字 | 符号位置 |
|------|----------|
| 全角のハイフンマイナス | U+FF0D |
| 半角の長音符 | U+FF70 |
| 長音符 | U+30FC |
| マイナス記号 | U+2212 |
| ハイフン | U+2010 |
| 非改行ハイフン | U+2011 |
| エヌダッシュ | U+2013 |
| エムダッシュ | U+2014 |
| 水平線 | U+2015 |

### 店舗の情報

- 問い合わせ先のメールアドレスを設定に持ち、店舗 API で返す。店舗画面は、キャンセルの申請が却下された注文の画面にこのメールアドレスを表示する。
- 問い合わせ先は必須。なければ起動しない。環境変数は[環境変数](../06-手順書/environment.md)にある。
