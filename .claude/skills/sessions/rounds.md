# ステップとフェーズの終わり

ステップとフェーズの終わりに、issue 担当のセッションが行うことの詳細。ステップの終わりは、「定期の全体のレビュー」を除く次の節を上から順に行う（フェーズの終わりは「振り返り」と「定期の全体のレビュー」）。

## 集計と profile の再検討

- `node .claude/skills/review/stats.cjs --round <ステップ> --profile <profile> <spec の番号...>` を、ステップの終わりに実行する。
- profile ごとに、その profile で動いた spec だけを渡して実行する。1 つのステップに複数の profile があれば、実行を分ける。理由：profile は spec の起動ごとに決まるため（[作業の形と使用量](../../../docs/05-開発規則/resources.md)）。
- 結果（profile・時点ごとの指摘の数と採用の割合）を読み、profile の再検討を利用者に提案する。レビューを減らすときは、見逃しの一覧で確認してから決める（[エージェントの作業フロー](../../../docs/05-開発規則/subagents.md)の「モデルや設定を替えるとき」）。

## 効果の測定

- 整理の第 2 フェーズの最初のステップだけ、閾値・並行の上限・spec の最後のレビューの量を測り直す。第 1 フェーズの測定の結果は[エージェントの作業フローの調べた仕組みと実績](../../../docs/07-記録/subagents-results.md)の「値を今は変えない理由」にある。測る作業そのものは、後回しの作業の起票の案に入れる。
- 方法は、整理の前の基準と同じ script に、レビューの記録の集計（`node .claude/skills/review/stats.cjs`。使い方は [review](../review/SKILL.md) 手順 6 と stats.cjs の冒頭）を加える。方法に使うのは、セッションの記録（jsonl）から spec ごとの token と時間を集計する `/.local/refactor/baseline/tokens.cjs`（`node tokens.cjs sessions|specs`）と、結果の `report.md` である。これらは Git に入らないので、新しい clone にはない。ないときは、利用者に所在を聞く。
- 比べる項目：レビューの費用の割合、段階ごとの重要度「高」の指摘の件数、待機の token、固定の文脈の大きさ。

## 見逃しの一覧

- ステップの終わりに、見逃しの一覧（label「見逃し」の issue）を読む（`gh issue list --label 見逃し`）。
- 本文の「関連」に、エージェントがマージしたと書いたものが 1 件でもあれば、危険度が高い経路の一覧と、危険度が低い変更のマージの条件の再検討を利用者に提案する。見逃しの一覧の書き方は [エージェントの作業フロー](../../../docs/05-開発規則/subagents.md)の「モデルや設定を替えるとき」。

## 振り返り

- ステップとフェーズの終わりに、skill `agent-retro` で行う。ファイルは `/.local/retro/` に置く。
- ステップの終わりに、ファイルの問題の短い名前を数え、別のセッションで 2 回以上出た問題を整理の issue の案にして利用者に示す。案にした問題には、ファイルに印を付ける。

## 危険度が低い変更の推奨と起票の案

- ステップの終わりに、このステップでマージした危険度が低い変更の pull request から、本文の「推奨の指摘の扱い」と起票の案を集めて利用者に示す。利用者が承認したものだけを起票する。理由：危険度が低い変更は利用者が pull request を確認しないため。

## 校閲の見逃しと誤検出の集め先（#294）

- ステップの終わりに、issue #294 の新しいコメント（返信のないもの）を読む（`gh issue view 294 --json comments`）。
- 読んだコメントを、[校閲役の評価の一覧](../review/evals/ja-proofread.md)にある例の表へ加える。見逃しは見逃しの例、誤検出は誤検出の例とする。例文は、コメントの出典の文をそのまま使い、利用者の中国語の言葉を転記しない。例の選び方と、例を替えてよい条件は、評価の一覧に従う。
- 移したコメントに、移した先（評価の一覧と例の番号）を書いた返信を付ける。返信の本文は、投稿の前に校閲役に読ませる（skill `review` の docs-review.md の手順 3）。
- 例を加えたら、次に校閲役を替えるときに、前の設定も再採点する。手順は、[校閲役の評価の一覧](../review/evals/ja-proofread.md)の「校閲役を替えるときの手順」。

## 定期の全体のレビュー

- フェーズ（または milestone）の終わりに、提案だけを出す全体のレビューとして行う。skill `review` の全体のレビューの手順を使う。
- 材料に、既存の指摘の一覧（issue「既存のレビューの指摘の一覧」）と、振り返りの集計を加える。
- 定期の自動の実行は使わない。無人で動かすと使用量の配分に従わなくなるため。
