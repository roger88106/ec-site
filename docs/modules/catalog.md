# 商品カタログモジュール

商品、バリアント、カテゴリ、公開状態、商品検索を管理する。

- レベル：A（軸の組み合わせの一意性、公開の条件など、不変条件が多い）
- 依存：税モジュール（API）
- 関連 spec：001（US-2〜7、9、11、13）
- 用語と識別子：[用語集](../glossary.md)

## 商品（集約）

- 商品は、商品品番、名称、説明、税区分、税抜価格、所属カテゴリ、バリアント軸（最大 3 つ）、公開状態、初回表示日時、公開期間、バリアント、画像を持つ。
- バリアントは、バリアント品番、軸の値、表示順、販売停止、画像を持つ。価格は持たず、商品の価格を使う（MVP。バリアントごとの価格は将来の spec）。
- 商品とバリアントは 1 つの集約にする。軸の値の組み合わせが商品内で一意であることは、商品単位の不変条件のため。
- 品番は属性であり、他のデータからの参照には使わない（constitution 7.1）。

### 商品の登録・編集

- 税区分は、登録時と、税区分を変えたときに、現時点で有効な税率があるかを税モジュールに確かめる（AC-6）。税モジュールの API は腐敗防止層（`TaxDirectory`）で包む。存在しない税区分も、有効な税率がない税区分と同じく 400。
- 所属カテゴリに存在しないカテゴリを指定したら 400。割り当てとカテゴリの削除が同時に起きて外部キーの違反になった場合も 400。
- バリアント軸の名前は 1〜30 文字で、商品の中で重複できない。軸の値は 1〜50 文字。
- バージョンは商品に 1 つ。バリアントの登録・削除・並び順の変更も、商品のバージョンを上げる。
- 販売終了の商品も、編集とバリアントの登録はできる（C 側には表示されない）。

### バリアント

- バリアントの登録は、並びの最後に加える。軸の値の数は商品の軸の数と同じでなければならない（AC-22）。
- 軸キーは、軸の値を U+001F（単位区切り文字）で連結した値。軸のない商品では空文字になるので、軸キーの一意制約で、バリアントが 1 つに限られることも DB で守れる（AC-24）。
- 軸の値の組み合わせの重複（AC-23）は、一意性の違反として 409。軸のない商品への 2 つ目のバリアント（AC-24）は 400。
- 並び順の変更は、カテゴリと同じく、商品のすべてのバリアントを送る。過不足があれば 400。
- 公開中の商品の最後のバリアントは削除できない（AC-31 と同じエラー）。

### 初回表示日時

初回表示日時は、C 側に最初に表示された（または表示される予定の）日時。新着順の基準であり、商品・バリアントを削除できるかの判定にも使う。

- 公開したとき、または公開中に公開期間を変えたときに、「公開した時刻と公開開始日時の遅いほう」を入れる。その日時が公開終了日時以降なら、表示されないので空にする。
- 値が過去になったら確定し、以後は変わらない（再公開しても新着順の順位は上がらない。AC-54）。
- 値が未来の間は、まだ表示されていない。非公開にしたら空に戻し、公開期間を変えたら計算し直す。
- 削除できるのは、初回表示日時が空か未来の商品（C 側に一度も表示されていない。AC-33、71）。

定期ジョブを使わず、操作の時点の現在時刻と比べて判定する（constitution 5-5）。

### 状態の切り替え

公開・非公開・販売終了、販売停止・解除は冪等にする（constitution 9）。すでにその状態なら何もせず成功とする。運営者からバージョンは受け取らず、保存時に他の更新と衝突した場合だけ競合として返す。

- 販売終了からは、公開にも非公開にも戻せない（AC-32）。
- 販売終了にしたときも、非公開と同じく、未来の初回表示日時は空に戻す。

### 公開期間

公開期間（AC-34〜36）は、基本情報と同じくバージョンを受け取って変える。入力して保存する値で、他の人の変更を黙って上書きしないため。

- どの状態の商品にも設定できる。初回表示日時を計算し直すのは、公開中に変えたときだけ（上の「初回表示日時」）。
- 期間の外かどうかは、表示の時点の現在時刻で判定する。運営者の操作なしに、その時刻で切り替わる（AC-35）。

### 商品画像

画像は商品集約の一部で、ファイルの置き場所とアップロードの流れは [plan 001](../specs/001-catalog-and-inventory/plan.md) 第 7 節。

- 1 商品あたり 20 枚まで（AC-40）。並びの先頭が代表画像（AC-37）。並び替えは、バリアントと同じく商品のすべての画像を送る。
- バリアントには、その商品の画像を 1 枚だけ指定できる（任意。AC-38）。指定がなければ代表画像を使う。
- 画像を削除すると、その画像を指定していたバリアントの指定を外す（代表画像に戻る）。C 側に表示されたことのある商品の画像も削除できる。
- 画像の登録・削除・並び替えと、バリアントの画像の指定は、基本情報と同じくバージョンを受け取る。
- 配信のバケットのファイルは、商品画像削除・商品削除のイベントを商品カタログ自身が購読して消す。削除は何度行っても同じ結果になるので、イベントが重ねて届いてもよい（constitution 5-7）。商品の削除では、その商品のキーの接頭辞（`products/{productId}/`）のファイルをまとめて消す。

## B 側の商品一覧

状態に関係なく、すべての商品が対象（AC-47）。並びは登録日時の新しい順で、同じなら ID の順。

- 品番の絞り込みは、商品品番またはバリアント品番の前方一致。英小文字は大文字として扱う。
- 商品名の絞り込みは部分一致で、英字の大文字・小文字を区別しない。
- カテゴリの絞り込みは、C 側（AC-52）と同じく、子孫のカテゴリに所属する商品も含む。
- 絞り込みの文字列中のワイルドカード文字（`%`、`_`）は、ただの文字として扱う。

## カテゴリ（集約）

- カテゴリは、親カテゴリ、名称、階層の深さ（1〜3）、表示順を持つ。
- 商品とは ID でだけつながる。
- 深さは親の深さ＋1。親を変える操作はないので、登録後に深さは変わらない。
- 登録したカテゴリは、兄弟の最後に並べる（表示順は兄弟の最大＋1）。同時に登録されて表示順が同じになったら、登録日時と ID の順に並べる。

### 並び順の変更

兄弟の並び順は、1 件ずつではなく兄弟の全体を送って変える（AC-11）。

- 送る ID は、その親の今の子カテゴリと過不足なく一致しなければならない。足りない・余分・別の親のカテゴリが入っていれば 400。画面を開いた後に兄弟が増減していたら、並べ直してもらう。
- `version` は送らない。兄弟の行を ID の順にロックしてから変えるので、同時に変えても直列になり、後の変更が残る。
- 表示順はカテゴリの一部なので、表示順が変わったカテゴリはバージョンを上げる。並べ替えの前に開いた画面で名称を変えると 409 になる。

### 削除

子カテゴリを持つカテゴリは削除できない（AC-12）。削除と子カテゴリの登録が同時に起きて外部キーの違反になった場合も、業務のエラーに変換する（削除は 400、登録は親が見つからない 404）。

## C 側に表示される条件

公開状態が「公開」で、公開期間内であること。

この条件は、ドメインと参照用の SQL の 2 か所にある。SQL 側は 1 つの部品にまとめて一覧と検索の両方で使い、検索だけに非公開の商品が出る事故を防ぐ。両者が一致することは統合テストで確認する。

## 税込価格での並べ替え・絞り込み

税区分ごとに税率が違うため、税抜の順と税込の順は一致しない（例：1,000 円・8% は 1,080 円、990 円・10% は 1,089 円）。そのため、一覧の SQL で税込価格を計算する。

1. 税モジュールから、税区分ごとの税率の一覧（予定を含む）を取得する。インスタンス内で 30 秒キャッシュする。
2. 表示時刻で有効な税率を決め、税区分ごとの率を SQL に埋め込む。
3. 商品の税込価格を計算し、価格帯の絞り込みと並べ替えに使う。

- 有効な税率は表示時刻で判定するので、切り替えの時刻ちょうどに切り替わる。キャッシュの影響は、税率の登録・変更の反映が最大 30 秒遅れることだけ。
- 表示時刻で有効な税率のない税区分の商品は、税込価格を出せないので C 側に表示しない。割り当て時に有効な税率を確かめ（AC-6）、最後の税率は無期限なので、通常は起きない。
- 税込価格の範囲の絞り込みは、下限・上限ともその値を含む。
- 税込価格の計算が、税モジュール（Java）とここ（SQL）の 2 か所にある。端数の境界値を含めて、結果の一致を統合テストで確認する。

## キーワード検索

- キーワード検索は専用の窓口（商品検索）の後ろに置き、通常の商品照会とはコードを分ける（constitution 4.4）。
- MVP では、商品名と説明に対する部分一致で探す。キーワード中のワイルドカード文字はエスケープする。並びは新着順で固定し、専用のインデックスは作らない。
- 検索エンジンを入れるときは、商品検索の実装を差し替え、下記のイベントでインデックスを同期する。

## 他モジュールへの公開

| 種類 | 内容 | 利用者 |
|------|------|--------|
| API | C 側向けの商品一覧・検索・詳細（税込価格を含む）、カテゴリの木 | 店舗 |
| イベント | バリアント登録、バリアント削除、商品削除 | 在庫。商品削除は商品カタログ自身も購読する（画像のファイルの削除） |
| イベント | 商品公開、商品非公開、商品販売終了、商品価格変更 | なし（将来の検索インデックス同期用） |
| イベント | 商品画像削除 | 商品カタログ自身（配信のファイルの削除） |

イベントはどれも、イベント ID と発生時刻に加えて、商品 ID を持つ。バリアント登録・バリアント削除はバリアント ID も持ち、商品価格変更は変更後の税抜価格を持つ。商品画像削除は、画像 ID と配信のファイルのキーを持つ。品番は持たない（constitution 7.1）。状態の切り替えで状態が変わらなかったときは、イベントを登録しない。

## データモデル

- カテゴリ：[V202610091200__catalog_create_category.sql](../../backend/src/main/resources/db/migration/V202610091200__catalog_create_category.sql)
  - 同じ親の下での名称の一意性は、最上位（親が null）同士も含める（`UNIQUE NULLS NOT DISTINCT`）。
- 商品・バリアント：[V202610091400__catalog_create_product.sql](../../backend/src/main/resources/db/migration/V202610091400__catalog_create_product.sql)
  - 商品の一部（軸、所属カテゴリ、バリアント、軸の値）は、商品の削除で一緒に消える（`ON DELETE CASCADE`）。
  - 所属カテゴリからカテゴリへの外部キーは CASCADE にしない。商品が所属しているカテゴリの削除を拒否するため（AC-12）。
  - 税区分は税モジュールの ID なので、外部キーは張らない（constitution 6）。
- 商品画像：[V202610101000__catalog_create_product_image.sql](../../backend/src/main/resources/db/migration/V202610101000__catalog_create_product_image.sql)
  - バリアントの画像は、同じ商品の画像だけを指せる（商品 ID と画像 ID の組で外部キーを張る）。画像を削除すると、バリアントの指定だけが外れる（`ON DELETE SET NULL (image_id)`）。
