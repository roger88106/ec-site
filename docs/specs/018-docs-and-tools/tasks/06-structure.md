## タスク

- [ ] **T018-06-01** 文書を `docs/rules/`、`docs/design/`、`docs/guides/` に移す（DC-196）。
  - リンクを直す script で、文書の中のリンクを直す。
  - コード、skill、AGENTS.md、README、CI の workflow のパスも直す。
  - `doc-refs.mjs` が通る。
- [ ] **T018-06-02** constitution の文書の地図とリポジトリ構成の図を、新しい構成に合わせて書き直す。アーカイブの置き場所（`docs/specs/archive/mvp/`）を書く（DC-196）。
- [x] **T018-06-03** spec 001〜017 の AC を抜き出す script で、AC 一覧の雛形を作り、テストの所在を埋める（DC-197）。
  - 結果：[AC 一覧](../../../design/acceptance-criteria.md)（312 件）。抜き出しと表の作成は、別の script を作らず `ac-check` の `--write` にした（T018-06-06）。要約・元の spec・テストの列は作り直す列、状態・変えた spec・今の内容は手で書く列で、作り直しても残る。テストの列は、AC をテスト名に持つテストのファイル（3 つまで）、除外、なし。今は 302 件にテストがあり、10 件が除外。状態はすべて有効で、T018-06-04 で決める。
  - 利用者の確認待ち：テストの列を `ac-check` が比べるので、テストを足す・名前を変えると、AC 一覧の作り直しが要る（hook と CI で止まる）。文書が古くならない代わりに、手間が増える。
  - 段階 5 の後に行うと決めた文書の移動（T018-06-01・02）より前に行った（利用者と決めた）。
- [x] **T018-06-04** 後の spec にある前の AC 番号の参照を候補にして、各 AC の状態を決める。利用者が確認する（DC-197）。
  - 結果：後の spec の spec・plan にある前の AC 番号の参照（77 か所、45 個の AC）と、各 spec の変更の表を、サブエージェント（Opus）が読んで候補を出し、利用者が確認した。14 件を「変更」にした（AC-70、73、81、84〜87、90、93〜95、101、103、131）。廃止はない。参照されたが有効のままの 35 件は、テストを足しただけなどで振る舞いを変えていない。
  - 番号で参照せずに変えた AC は、spec 015〜017 の AC の見出しで照らしただけで、すべては調べていない。気づいたら、AC 一覧の行を直す（開発の進め方 第 1.5 節）。
- [x] **T018-06-05** [テスト] `ac-check` が AC 一覧を読む検査のテストを書く（DC-198）。次のそれぞれで失敗すること。
  - 有効・変更の AC に、テストも除外もない。
  - 廃止の AC を、テストが参照している。
  - spec にあって AC 一覧にない AC がある。
  - 結果：`ac-check.test.mjs` に、廃止の AC と、AC 一覧の作り方・読み方・照らし方のテストを足した。手元でレッド（関数がない）を確かめ、T018-06-06 と同じ commit にした。
- [x] **T018-06-06** `ac-check` を直して、T018-06-05 を通す。
  - 結果：`ac-check` が AC 一覧を読み、廃止の AC をテストの要る AC から外し、テストが参照すると手元でも失敗にする。spec と一覧の AC の食い違い、有効・変更・廃止でない状態、古い表（作り直した表と違う）も失敗にする。`--write` で表を書き直す。テストのファイルは、探す順が OS で違うので、名前の順にした。CI の検査の文書の行を直した。
- [x] **T018-06-07** 開発の進め方に、コードを唯一の正とすること、食い違いの扱い、AC 一覧の更新の手順を書く（DC-199）。
  - 結果：[開発の進め方](../../../process/workflow.md)第 1.5 節「コードと文書の食い違い」を足し、第 1.3 節の置き場所の表に AC 一覧を足した。
- [ ] **T018-06-08** 段階の完了の確認：`./gradlew check`、`check-frontend.sh`、`e2e.sh`、`check-all.sh` が通る（パスを直したため）。
