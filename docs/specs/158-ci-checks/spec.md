# Spec 158：CI の検査の script を強め、推奨の指摘を修正する

ステータス：確定

## 1. 背景と目的

CI の検査の script（`scripts/ci/`）と workflow（`.github/`）に、検査の見逃しと誤検出、推奨の指摘、追加したい検査が溜まっている。同じ script を変えるので、1 つの spec にまとめる。

- 扱う issue のうち、#15、#92、#108 は MVP 018・019 と spec 7 のレビューの指摘で、#110、#154、#149 は追加したい検査である。
- #92 の「ほか 3 件」は、MVP 019 のレビューの結果のファイルが残っていない。そこで、spec の始めに、同じ観点（script と CI の一貫性、不要なもの、後の開発への備え）で `develop`（3faaf8db）を再びレビューした。汎用のモデルで 2 回実行し、和集合を取った。
- あわせて、issue の 21 項目が今も残っているかを照合した。17 項目が残り、3 項目は一部だけ修正済みで、1 項目は修正済みだった。修正済みの 1 項目は `actions/cache` の版で、今は他の action の版の範囲に入っている。
- 再レビューでは、issue にない指摘が、高 5 件、必須 4 件、推奨 27 件見つかった。件数は 2 回の重複を除いた数である。高の 5 件は、どれも検査が違反を見逃すか、誤って通すもので、DS-158-2 で扱う。

追跡の issue は [#158](https://github.com/roger88106/ec-site/issues/158)、扱う issue は [#15](https://github.com/roger88106/ec-site/issues/15)、[#92](https://github.com/roger88106/ec-site/issues/92)、[#108](https://github.com/roger88106/ec-site/issues/108)、[#110](https://github.com/roger88106/ec-site/issues/110)、[#154](https://github.com/roger88106/ec-site/issues/154) と、[#149](https://github.com/roger88106/ec-site/issues/149) のうち機械の検査の部分である。作業ブランチは `158-ci-checks`。本 spec は整理の spec で、規模は M である（[開発の進め方](../../rules/workflow.md) 第 4.2 節）。API の契約とデータベースを変えず、AC を変えないため。

## 6. 決めたこと

spec の確認で、利用者が 4 つとも案 A に決めた（2026-10-23）。規模 M も同じ時に承認した。Open questions はない。

### 6.1 E2E の実行中の印と PID の再利用（DC-158-8）

今は、E2E のロックの PID が別のプロセスに再利用されて印が残ることがある、と案内の文で知らせるだけである。案内の文は、スロットのロックの script（`scripts/dev/lib/slot-lock.mjs`）にある。

- 案 A（推奨。採用）：案内のままにし、#15 のこの項目は「案内で足りる」として閉じる。理由：起きるのは、E2E が異常終了し、同じ PID を別のプロセスが使ったときに限られる。プロセスの開始時刻の取り方は Windows と Linux で違い、script の量が増える。
- 案 B：ロックの開始の時刻とプロセスの開始時刻を照合し、再利用を判定する。

### 6.2 新しい検査で今のコードに出る違反の扱い（DC-158-26）

| 検査 | 件数 | 場所 |
|------|------|------|
| 文言のコメント（DC-158-17、18） | 10 件以上 | 管理画面と共有のパッケージの `translate('…')` |
| クエリ付きの URL（DC-158-21） | 1 件 | 店舗画面の注文の一覧の URL |
| 共有のパッケージと同じ名前（DC-158-25） | 2 件 | 両方の画面の `translate`。各画面の文言を渡すので、正しい定義 |
| 使わない語（DC-158-19） | 2 件 | `ci.yml` のコメント |
| コンポーネントの内部の属性（DC-158-50） | 5 か所 | 管理画面の注文の詳細と商品の登録の画面のテスト |
| 空白で区切った AC（DC-158-51） | 4 か所 | 管理画面の注文のテスト |

DC-158-50・51 の違反は、spec 157 が修正する。そこで、案 A・B のどちらでも、DC-158-50・51 の検査を加えるタスクは、spec 157 のマージの後に `develop` を取り込んでから行う。spec 157 のマージが本 spec の最後のタスクより遅れるときは、spec の確認とは別に、利用者に扱いを相談する。

- 案 A（推奨。採用）：正しい定義（`translate` の 2 件）だけを、理由付きで除外の一覧に置く。他は本 spec で修正する。理由：修正はコメントの追加と URL の組み立ての置き換えで小さく、除外を残すと検査を入れた意味が薄れるため。管理画面と共有のパッケージのファイルは spec 157 と重なるが、DN-158-5 のとおりに解消する。
- 案 B：検査だけを本 spec で入れ、違反を除外の一覧に置く。修正は spec 157 と、店舗画面の次の spec に任せる。
