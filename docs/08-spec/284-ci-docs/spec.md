# Spec 284：CI の検査の説明を各 script のコメントに寄せ、文書の写しを守るだけの検査をやめる

ステータス：草案
危険度：高

## 1. 背景と目的

milestone「整理の段階」の第 2 段（文書）の 2 つ目の spec である。追跡の issue は [#284](https://github.com/roger88106/ec-site/issues/284) で、作業ブランチは `284-ci-docs` である。[#266](https://github.com/roger88106/ec-site/issues/266) を sub-issue として扱う。整理の spec なので、AC、API、データベースは変えない。規模は M で、2026-10-29 に利用者が承認した。

[CI の検査](../../06-手順書/ci.md)は 68,727 バイトあり、そのうち第 3 節の検査の表（33 行）が 43,960 バイト、`lib/` の一覧が 5,476 バイトを占める。表の各行は、対応する script の先頭のコメントとほぼ同じ内容を書いている。検査ごとに、説明が 2 か所（script の先頭のコメントと表の行）にあり、検査を変えるたびに両方を修正する必要がある。

また、設計書の「関連 spec」の行とマイグレーションの一覧は写しで、その一致だけを確認する検査がある。方針は 2026-10-29 に利用者が決めた（issue 担当のセッションの棚卸しの備忘録。Git に入らない）。

- 検査の表は「名前と 1 文の目的」に縮め、詳しい説明は各 script の先頭のコメントを正本にする。
- 設計書の「関連 spec」の行とマイグレーションの一覧は、検査による強制をやめ、行と一覧も削る（利用者の決定、2026-10-29）。

危険度を高にする理由：検査の script（`scripts/ci/`）、git の hook（`scripts/dev/hooks/`、`scripts/dev/lib/`）、`.claude/`、規則の文書（`docs/05-開発規則/`）を変えるため。

### 本 spec の用語

| 用語 | 意味 |
|------|------|
| 検査の表 | [CI の検査](../../06-手順書/ci.md) 第 3 節の最初の表。1 行が `scripts/ci/` の直下の 1 つの検査に当たる |
| 先頭のコメント | script の 1 行目から続く `//` の行。script が何を確認するかを書く |
| 写し | 正本（コード、設定、他の文書）にある事実を、別の文書にも書いたもの |
| 写しを守る検査 | 写しと正本が一致することだけを確認する検査。写しを削れば不要になる |
| 経緯 | 過去に試した結果と、決めた時点の事情。今の規則と設定値の根拠にならないもの |

### 写しを守る検査の候補

|------|------|------|----------------------|------|

## 3. 目的と完了条件

### DS-284-1 検査の説明の正本を、script の先頭のコメントにする（D / P1）

- **DC-284-1** 検査の表は、検査の名前と目的の 2 列である。
- **DC-284-2** 目的の文は、1 行 120 字以内である。
- **DC-284-3** 表の行から削った内容（確認すること、失敗したときの修正の手順、除外の書き方）は、対応する script の先頭のコメントにある。
- **DC-284-4** DC-284-3 の例外として、コードから直接読める事実と経緯は、コメントに移さずに削ってよい。移さずに削ったものは、第 10 節に検査ごとに 1 行で書く。
- **DC-284-5** `lib/` の各ファイル（テストを除く）の役割が、そのファイルの先頭のコメントにある。今の一覧にない `comment-text.mjs` も含む。
- **DC-284-6** CI の検査の文書に `lib/` の一覧がない。代わりに「複数の検査が使う関数は `lib/` に置き、役割は各ファイルの先頭のコメントに書く」の 1 文がある。
- **DC-284-7** CI の検査の文書に、実測値（時間、カバレッジのばらつき）と経緯がない。設定の値の根拠になる実測値（統合テストのフォークの数、カバレッジの許容の幅、PIT の位置）は、第 6 節の決めること 2 で決めた案に従って移すか削る。
- **DC-284-8** CI の検査の文書が 25,000 バイト以下である。理由：棚卸しの見込み（約 40,000 バイトの削減）を確認するため。
- **DC-284-9** `ci-docs` は、表の名前と `scripts/ci/` の直下の検査が 1 対 1 に対応しないとき、失敗する（今と同じ）。
- **DC-284-10** `ci-docs` が、検査の表が 2 列でないとき、失敗する。理由：表に詳しい説明を再び追加するのを防ぐため。
- **DC-284-11** `ci-docs` が、`scripts/ci/` の直下の検査と `lib/` の各ファイル（テストを除く）のうち、1 行目がコメント（`//`）でないものがあるとき、失敗する。理由：正本の説明がない script を防ぐため。
- **DC-284-12** `ci-docs` のテストが、DC-284-9〜11 の違反の例（表にない検査、3 列の表、先頭のコメントのない script）と、通る例を確認する。

### DS-284-3 規則の本文に、AI のサービス固有の名前がないことを検査する（D / P1）

#266 の 2 つの項目は、サービス固有の名前の検査（本節）と、`.gitignore` と文書の `.claude/` の列挙の照合（第 6 節の決めること 3）である。

- **DC-284-19** 新しい検査の script が `scripts/ci/` の直下にある。対象のファイル（第 6 節の決めること 4）の本文に、一覧にある名前があれば、ファイル:行を出力して失敗する。
- **DC-284-20** 名前の一覧は、script の中の 1 か所に置く。
- **DC-284-21** 判定は誤りの防止とする（[開発の進め方](../../05-開発規則/workflow.md) 第 1.4 節）。誤って書いた名前を見つけ、意図して作った回避（字を分ける、全角にする）は対象にしない。
- **DC-284-22** 名前を書いてよい場所を、許可する形の一覧で決める。一覧は、パスと識別子のコードスパン（`` `.claude/` `` など）、AGENTS.md のモデルの区分の表、skill `sessions` の「ツールの注」の節である。一覧に当たらない場所の名前は全て失敗にする。
- **DC-284-23** 検査のテストが、名前を書いた本文の行で失敗し、許可する形（コードスパンのパス、モデルの区分の表の行）で通ることを確認する。
- **DC-284-24** 今の対象のファイルにある名前（例：[エージェントの作業フロー](../../05-開発規則/subagents.md) の「Claude Code など」）を修正し、検査が通る。修正は、サービスに依存しない言葉に替えるか、ツールの注に移す。

## 4. 守る制約

- **DN-284-1** 振る舞い、API、データベース、AC を変えない。
- **DN-284-2** 残す検査の判定を変えない。変えるのは、`ci-docs`（DC-284-9〜11）と、DC-284-19 の新しい検査だけである。script の先頭のコメントの変更は、コメントだけにする。
- **DN-284-3** アーカイブのファイルを変えない。
- **DN-284-4** 変えたファイルの `node scripts/ci/ja-text.mjs --warning` の警告が 0 である。
- **DN-284-5** `bash scripts/ci/check-all.sh` と、文書を読むバックエンドの単体テスト（`./gradlew test`）を含む CI が通る。
- **DN-284-6** 新しく作った検査と変えた検査は、違反の例を与えて、失敗することを確認する。
