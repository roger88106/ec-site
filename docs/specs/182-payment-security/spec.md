# Spec 182：決済の設定の検証、セキュリティと設定の指摘、出荷の読み取りを整える

ステータス：確定

## 1. 背景と目的

MVP 019 の全体のレビューと spec 155 の最後のレビューで、決済の設定の検証、セキュリティと設定の推奨の指摘、出荷の登録の読み取りの置き場所の指摘が、未対応のまま残った。本 spec はこれらを直す。

追跡の issue は [#182](https://github.com/roger88106/ec-site/issues/182) で、扱う issue は #79、#90、#175 である。作業ブランチは `182-payment-security` である。規模は L で、利用者が 2026-10-24 に承認した。理由：決済、注文、画像、共通コード、認可の設定の 5 か所にまたがり、[開発の進め方](../../rules/workflow.md) 第 4.2 節の「2 つ以上のモジュールにまたがる」に当たるため。

2026-10-24 に、今の `develop`（spec 155 のマージの後）で、各項目が残っているかをコードで確認した。全て残っていた。

| issue | 項目 | 今のコード |
|-------|------|------------|
| #79 | 支払画面の期限と設定 `ecsite.payment.deadline` を対応づける検証がない | 支払画面の期限は Stripe の実装の定数（31 分）で、支払の期限の設定（既定 30 分）に上限の検証がない |
| #90 | `security` を書き忘れた店舗の操作が公開になる | 店舗の操作の token の要否は、`store.yaml` の操作に `security` がなければ「不要」とする。今は公開の操作（商品、カテゴリ、カートの作成、店舗の情報、住所の補助）が `security` を書かない |
| #90 | 秘密の値を持つ設定の record の `toString` が値を伏せない | Stripe の設定は伏せる。画像の保存先（S3 の秘密の鍵）と画像の変換（imgproxy の鍵と salt）の設定は伏せない |
| #90 | 復元の失敗で集約の内容を `error` のログに出す | 集約を戻す共通の補助が、保存した状態の全体をデバッグ用のメッセージに入れ、システムのエラーとして `error` のログに出る |
| #90 | `zipkin` の接続先の既定値が共通の設定にある | 共通の設定（`application.yml`）に `http://localhost:9411` があり、local 以外の環境でも送信を試みる |
| #90 | `Location` が `forward-headers-strategy` に依存 | 作成の応答の `Location` は、今のリクエストの URI から絶対 URL を作る。`server.forward-headers-strategy` を設定していないので、プロキシの後ろでは内部のホストを指す |
| #175 | 出荷の登録が、決済を呼ぶ前に集約を Repository から直接読む | 出荷の登録の service が、売上確定の前に注文を Repository から読み、出荷できるかを確認する（バックエンドの書き方 第 1.1 節の「外部の呼び出しの前の読み取り」に反する） |

本 spec は整理の spec である（[文書の記号と番号](../../rules/notation.md)）。消費者・運営者の画面の振る舞いは変えない。運用と開発（起動の条件、トレースの送信、HTTP の応答のヘッダー）に見える変化は、第 5 節に挙げる。

## 2. 用語

| 用語 | 意味 |
|------|------|
| 支払画面の期限 | 決済サービス（Stripe Checkout）の支払画面が開ける期限。Stripe は作ってから 30 分以上 24 時間以下を求める |
| 支払の期限 | 注文日時に設定 `ecsite.payment.deadline` を加えた時刻。過ぎると期限切れのジョブが支払を「支払なし」にする |
| 公開の操作 | 店舗 API のうち、会員の token なしで使える操作 |
| 秘密の値 | 鍵、パスワード、署名の鍵など、ログに出してはいけない設定の値 |

用語集に追加する語はない（plan 第 6 節）。

## 4. 目的と完了条件

### DS-182-1 支払の期限と支払画面の期限（#79 / P1）

- **DC-182-1** 支払の期限の設定が 30 分を超えると、アプリは起動に失敗する。支払画面の期限は今の定数（31 分）のままにする。理由：支払画面は注文の後に作るので、支払の期限が 30 分以下なら、支払画面が支払の期限より前に閉じないため（利用者の決定、2026-10-24）。
- **DC-182-2** 決済のモジュールの設計書の「支払の期限」の節に、支払の期限の上限（30 分）と理由がある。
- **DC-182-3** 上限を、設定の検証の単体テストで確認する（30 分は起動でき、30 分を超えると失敗する）。

### DS-182-2 店舗の操作の公開（#90 / P1）

- **DC-182-4** `store.yaml` の全ての操作が `security` を書く。公開の操作は、空の一覧（`security: []`）で公開であることを明示する。
- **DC-182-5** `security` を書かない操作が `store.yaml` にあると、アプリは起動に失敗する。失敗のメッセージは、その操作のメソッドとパスを含む。理由：書き忘れた契約が、検出されないまま本番で動くことを防ぐため（利用者の決定、2026-10-24）。
- **DC-182-6** DC-182-5 を、`security` のない操作を含む契約を読み込む単体テストで確認する。

### DS-182-3 ログに出さない値（#90 / P1）

- **DC-182-7** 秘密の値を持つ設定の record（画像の保存先、画像の変換）の `toString` は、秘密の値を伏せる。単体テストで確認する。
- **DC-182-8** バックエンドの書き方に、秘密の値を持つ設定の record の `toString` を伏せる規則と、その確認方法がある。
- **DC-182-9** 集約を戻すのに失敗したときのメッセージは、集約の名前を含み、保存した状態の内容を含まない。理由：保存した状態は購入者の氏名・住所・メールアドレスなどの個人情報を含み、ログに個人情報を出さないため。原因の例外は残す。
- **DC-182-10** DC-182-9 を、共通の補助の単体テストで確認する。

### DS-182-4 環境に依存する値（#90 / P1）

- **DC-182-11** 共通の設定は、トレースの送信を無効にし、送信先を持たない。local の profile（E2E は local に重ねるので E2E も）が、ローカルの Zipkin への送信を有効にする。他の環境は、環境変数で送信を有効にしたときだけ送る。
- **DC-182-12** [環境変数](../../guides/environment.md) の一覧と共通コードの設計書のトレースの節が、送信を有効にする環境変数と、DC-182-11 の後の既定値を書く。
- **DC-182-13** 作成の応答の `Location` は、ホストを含まない相対の URL（`/api/...`）である。理由：デプロイ先のプロキシが `X-Forwarded-*` ヘッダーをどう扱うか（`server.forward-headers-strategy`）によらず、同じ値になるため。店舗画面と管理画面は `Location` を使わない（利用者の決定、2026-10-24）。
- **DC-182-14** DC-182-13 を、作成の応答の補助の単体テストで確認する。作成の応答の `Location` の URL で、作成したリソースを取得する既存の API のテストが通る。

### DS-182-5 出荷の登録の読み取り（#175 / P1）

- **DC-182-15** 出荷の登録で、売上確定の前に注文が出荷できるかを確認する読み取りは、注文の参照の service にある。出荷の登録の service は、注文の Repository に依存しない。
- **DC-182-16** 出荷の登録の振る舞い（注文がない、受付でない、与信の期限切れ、決済サービスに接続できない、のエラー）は変わらず、既存の出荷の登録のテストが通る。

## 5. 振る舞いと文書への影響

| 変化 | 誰に見えるか | 変える文書 |
|------|--------------|------------|
| 支払の期限の設定が 30 分を超えると、起動に失敗する | 運用（設定）。既定値（30 分）では変わらない | 決済のモジュールの設計書（「支払の期限」の節） |
| `security` を書かない店舗の操作があると、起動に失敗する | 開発者 | `store.yaml`（公開の操作に `security: []` を追加）、店舗 API の認可を書く設計書と規則（plan 第 6 節） |
| トレースが、local と E2E 以外では既定で送られない | 運用 | 環境変数の一覧、共通コードの設計書 |
| `Location` が相対の URL になる | API のクライアント。店舗画面と管理画面は `Location` を使わない（作成した ID を本文から読む） | `store.yaml`・`admin.yaml` の `Location` の説明、バックエンドの書き方 第 2.2 節 |

- AC は追加・変更しない。AC-233（契約で token が必要ない操作は token なしで使える）の文は変えない。そのテストの名前の「security のない操作」だけを変える。
- データベースの構造は変えない。

## 6. 非機能要件

- **DN-182-1** 消費者・運営者の画面の振る舞い（API の応答の本文、画面、メールの文面）を変えない。
- **DN-182-2** データベースの構造を変えない。API の契約は、第 5 節の変化だけを変える。
- **DN-182-3** AC を追加・変更しない。
- **DN-182-4** 起動の検証は、違反を直した後に有効にし、違反を含む入力で失敗することをテストで確認する。
- **DN-182-5** `./gradlew check` と CI が通る。

## 8. Non-goals

| 項目 | 扱う場所 |
|------|----------|
| 支払の期限を 30 分より長くする（支払画面の期限を支払の期限から求める） | 起票しない（必要になったときに機能の spec で扱う） |
| 管理 API の操作の権限の書き忘れ | 扱わない。管理 API は全ての操作が token を要し、権限の対応にない操作は拒否する |
| 他の外部の呼び出しの前の読み取り（注文の取消など） | 本 spec で見つけたら、起票のまとめの案（T182-02-06）に入れる |
| トレースの送信先を Zipkin 以外にする、ログの形の変更 | 起票しない |

## 9. Open questions

なし。草案の 3 つの問い（支払の期限と支払画面の期限の対応のさせ方、`security` の書き忘れの検査の置き場所、`Location` の形）は、利用者が推奨の案を選んだ（2026-10-24）。決定は DC-182-1、DC-182-5、DC-182-13 にある。選ばなかった案は、支払画面の期限を支払の期限から求める案、検査を単体テストか CI の script に置く案、プロキシのヘッダーを信頼する設定か文書だけで扱う案である。
