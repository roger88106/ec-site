# テストの書き方

テストの種類と、今のテストで守っている書き方。流し方は [テストの流し方](running.md)、テスト先行の進め方は [開発の進め方](../process/workflow.md) 第 2 節。

## 規則の一覧

| 節 | 規則 | 確かめ方 |
|----|------|----------|
| 2.1 | テスト名に AC 番号を入れる | 自動（`ac-check.mjs`） |
| 2.2 | テスト名は振る舞いを書く | 人手（`@DisplayName` があることは自動。`scripts/ci/test-names.mjs`） |
| 3.1 | 統合テストの土台を使う | 人手 |
| 3.2 | テストデータは補助のクラスで作る | 人手 |
| 3.3 | テストは main と同じパッケージ | 自動（ソースセット） |
| 4.1 | 画面に見えるもので探す | 人手 |
| 4.2 | API の差し替えは型付きの MSW | 自動（型チェック） |
| 4.3 | E2E のデータに実行ごとの印 | 人手 |
| 5 | 時間で待たない | 自動（`scripts/ci/time-waits.mjs`） |

人手のものは、各 spec の [見直し](../process/review.md) で読む。

## 1. テストの種類

| 種類 | 対象 | ツール | 置き場所 |
|------|------|------|----------|
| バックエンドの単体テスト | Spring を起動しないもの | JUnit、AssertJ | `src/test` |
| バックエンドの統合テスト | Spring と DB などをつないだもの | `@SpringBootTest`、Testcontainers | `src/integrationTest` |
| フロントの単体テスト | 画面に依存しない関数（判定、変換、表示の整形） | Vitest | 対象の横（`*.test.ts`） |
| フロントの結合テスト | コンポーネントを描画し、利用者の操作で振る舞いを確かめる（API は MSW） | Vitest、React Testing Library | 対象の横（`*.test.tsx`） |
| E2E | 管理画面・店舗画面・バックエンドをつないだ、コアフローの少数のシナリオ | Playwright | `e2e/` |

- 必須の統合テスト：Modulith の境界、Repository（永続化・再構築・差分更新・イベント発行）、並行性（並行の不変条件を持つモジュール）、外部連携の port（mock と実装の挙動の一致）。
- 店舗画面には結合テストを置かない ※1。表示のコンポーネントは HTML に描画して、サーバーの処理（サーバーアクション、ログインのコールバックなど）は Node の上で直接呼んで確かめ、画面をつないだ流れは E2E で確かめる。
- E2E は専用の DB・IdP・画像のバケットで、毎回作り直した状態から流す（ローカルの開発のデータを変えない）。
- 見た目（配置、色、余白）は手で確かめる。
- テストに出ない AC は CI が失敗にする。テストで確かめられない AC は、理由と一緒に除外の一覧に書く。
- カバレッジ（行・分岐）は CI で報告を作るが、基準の値で CI を失敗させない。薄い所を見つけるために使う。

※1：操作がサーバーアクションを通り、ブラウザーの中だけでは再現できないため。

## 2. テスト名

### 2.1 AC 番号を入れる

AC を確かめるテストは、名前（Java は `@DisplayName`、Vitest・Playwright は `test`・`it` の第 1 引数）の先頭に AC 番号を入れ、続けて振る舞いを日本語で書く（`AC-43 調整後に負になる調整は拒否される`）。複数の AC は 1 つずつ並べ（`AC-8、9、10`）、範囲（`AC-8〜10`）でまとめない。

理由：AC からテストを、テストから AC を引けるようにするため。

### 2.2 名前は振る舞いを書く

「〜すると〜になる」の形で、画面や API に起きることを書く。メソッド名やクラス名を写さない。Java のテストは、すべての `@Test`・`@ParameterizedTest` に `@DisplayName` を付ける。

理由：失敗したときに、どの振る舞いが壊れたかが名前だけで分かるようにするため。

## 3. バックエンド

### 3.1 統合テストの土台

- 統合テストは `@IntegrationTest` を付ける。Spring と、Testcontainers の PostgreSQL・SeaweedFS・imgproxy が起動する ※2。
- API のテストは `@AutoConfigureMockMvc` の MockMvc で呼び、時刻は `TestClockConfig` で固定する。
- データを残さないテストは `@Transactional` で巻き戻す。

※2：IdP は起動せず、`TestSecurityConfig` が署名の鍵を `TestTokens` の鍵に差し替える。Keycloak は、それを確かめるテストだけが自分で起動する。

理由：テストごとにコンテナを起動し直さず、データが他のテストに漏れないようにするため。

### 3.2 テストデータは補助のクラスで作る

複数のテストで使うデータは `CatalogTestData`・`OrderTestData` などの補助で作る。token は `TestTokens`、画像は `TestImages` から取る。

理由：テストの本文に、確かめる項目だけを残すため。

### 3.3 テストの置き場所

main と同じパッケージに置く。Spring を起動しないものは `src/test`、起動するものは `src/integrationTest`。

## 4. フロント

### 4.1 画面に見えるもので探す

結合テストと E2E は、役割と名前で要素を探す（`getByRole('button', { name: '保存' })`、`getByLabel('名称')`）。CSS のクラス、`data-testid`、内部の状態は使わない。

理由：作り直しても、振る舞いが同じならテストが壊れないようにするため。

### 4.2 API の差し替えは型付きの MSW

管理画面の結合テストは、`src/test/` の `http`（openapi-msw）で OpenAPI の型に合ったハンドラーを作る。既定のハンドラーは置かず、テストごとに `server.use(...)` で渡す。

理由：契約にない応答をテストで作らないため。

### 4.3 E2E のデータに実行ごとの印

E2E で作るデータの品番・名称に、実行ごとの印（`E2E-<印>-…`）を付ける（`e2e/src/data.ts`）。

理由：前の実行や手で作ったデータと混ざらないようにするため。

## 5. 待ち方

時間で待たない（`Thread.sleep`、`waitForTimeout`）。条件で待つ（Playwright の `expect(...).toBeVisible()` などの自動の再試行、状態を直接確かめる）。

理由：遅い環境で失敗し、速い環境で時間を無駄にするため。
