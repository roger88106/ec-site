# 会員モジュール

IdP（Keycloak）のアカウントと、EC の会員 ID の対応を管理する。

| 項目 | 内容 |
|------|------|
| レベル | B（不変条件は「1 つのアカウントに 1 人の会員」だけ） |
| 依存 | なし（カート・注文・店舗の presentation から API で呼ばれる） |
| 関連 spec | [003](../../specs/003-auth) |

## 会員

- 会員は、会員 ID（UUID）、IdP のアカウント ID（token の subject）、登録日時を持つ。
- カート・注文手続き・注文が持つのは会員 ID。IdP を替える・アカウントを移すときは、この対応だけを直す。
- メールアドレスと氏名は持たない（IdP が正本で、必要なときに token から読む）。注文には注文時点のメールアドレスを写す。
- 届け先などの会員の情報は、将来ここに足す。

## 会員を求める

- 会員の token で初めて API を呼んだときに作る。IdP の登録を EC に知らせる仕組みは作らない。
- 「IdP のアカウント ID から会員 ID を求める（なければ作る）」を API で公開する。
- 同じアカウントの初回の要求が同時に来ても、会員は 1 人だけ作る ※1。

※1：アカウント ID の一意制約で守り、作れなければ（先に作られた）読み直す。作る処理は、呼び出し元のトランザクションを壊さない挿入で行う。

## token から会員を取り出す

presentation が token から会員の情報（アカウント ID、メールアドレス、確認済みか、姓、名）を取り出す部品は `common/security` に置く（Spring Security の型をモジュールに出さないため）。

| 店舗 API の操作 | token がないとき |
|-----------------|------------------|
| 会員の操作 | filter で 401 |
| 任意の操作（カート） | ログインしていない人として扱う |

## 構成

```
member/
├── api/                    # 会員 ID を求める
├── application/            # アカウントから会員 ID を求める（初めてなら作る）
│   └── port/               # リポジトリの口
├── domain/                 # 会員
└── infrastructure/
    └── persistence/        # リポジトリの実装
```
