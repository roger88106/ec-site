## 店舗画面

- [x] **T015-04-03** [テスト] 店舗画面の設定の単体テストを、新しいファイルに書く。レッドを確認する。
  - 本番モードで `AUTH_URL` がなければ起動に失敗する。開発モードとテストではローカルの値になる（AC-240）。
  - ログアウトの戻り先は公開する URL から作り、別のホストと `x-forwarded-proto` のリクエストヘッダーでも変わらない（AC-241）。
  - API の応答を再取得する間隔は、設定の 1 か所から読む（AC-242）。
- [x] **T015-04-04** `AUTH_URL` を必須の環境変数に追加し、ログアウトの戻り先と再取得する間隔を設定から読む。E2E の店舗画面に `AUTH_URL` を渡す。T015-04-03 を通す。
- [x] **T015-04-05** [テスト] ログインの戻り先の結合テスト：Auth.js のリクエストの処理に、別のホストのリクエストヘッダーで要求し、IdP への移動の戻り先が公開する URL になる（AC-241）。レッドを確認する。結合テストで作れなければ止めて報告する（plan 第 4 節 ※9）。
  - 結果：Vitest の上で、本物の Auth.js の処理（csrf と signin のエンドポイント）を呼んで作った。Auth.js は `AUTH_URL` があればリクエストの URL をそれに置き換えるので、T015-04-04 で `AUTH_URL` を必須にした後のテストは初めから通る。`AUTH_URL` を空にすると、偽装したホストが戻り先に含まれて失敗することを確認した（レッドの代わり）。
- [x] **T015-04-06** `trustHost: true` を削除する。T015-04-05 を通す。
