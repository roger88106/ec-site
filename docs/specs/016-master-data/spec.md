# Spec 016：マスターデータ

ステータス：確定

## 1. 背景と目的

spec 010 の後の全体のレビューで、同じ値の一覧・上限・規則が、バックエンド・画面・SQL・文言に別々に書かれている所が多く見つかった。**値ごとに正となる 1 か所を決め、他はそこから得る**。

- 都道府県の一覧が 5 か所（注文の検証、店舗画面の選択肢、売上レポートのコードの表、レポートの seed、管理画面の文言）にある。注文は都道府県を名前で持ち、売上レポートは名前からコードを再度引く。
- 市区町村は住所の自由入力に含まれ、コードを持たない。郵便番号は形を確認するだけで、住所の入力を助けない。
- 同じ列挙（注文の状態、配送業者、配送状態など）を、モジュールの間で名前の一致だけを頼りに写している。売上レポートは注文の状態を文字列で比べる。
- 上限（分類の深さ、画像の形式・大きさ・枚数）と、エラーのコードが API の契約になく、画面が同じ値を手動で書く。エラーの文言に数字を直接書いた所がある。
- 画面が業務の規則から操作の可否を推し量る所が残る（キャンセルの申請が却下されたか、キャンセルの時に在庫を戻すか聞くか など）。
- 日本時間、時点の税率の判定が、バックエンドの複数の所に別々に書かれている。

都道府県・市区町村・郵便番号は、マスターデータ（コードと名前の表）にする。外部（国の API、日本郵便）から取り込んで更新する仕組みは 1 → 10 で作る（[MVP の完成までの一覧](../mvp.md) 第 3 節）。本 spec では、マスターデータの構造と最初のデータを作り、取り込みの仕組みを後から追加できる形にする。

spec 013 と 014 で、振る舞いを変えるために回した所（[spec 013](../013-backend-consistency/spec.md) 第 7 節、[spec 014](../014-frontend-consistency/spec.md) 第 7 節）も本 spec で行う。

AC・US・BR・NFR の番号は、spec 015 から続けて振る。

## 2. 用語

| 用語 | 意味 |
|------|------|
| マスターデータ | 業務で共通に使う、コードと名前の表。本 spec では都道府県、市区町村、郵便番号 |
| 地方公共団体コード | 総務省が都道府県と市区町村に振るコード（全国地方公共団体コード）。都道府県は先頭の 2 桁 |
| 市区町村 | 地方公共団体コードを持つ市・町・村と東京都の特別区。政令指定都市は区を 1 つの市区町村として扱い、市そのものは選べない |
| 町域 | 郵便番号に対応する、市区町村より下の地名（郵便番号のデータの「町域名」） |
| 正となる所 | ある値を決める、ただ 1 つの所。他はそこから得るか、一致をテストで確認する |

用語集には plan で追加する。

## 4. User stories と受け入れ条件

### US-54 お届け先の都道府県と市区町村を、一覧から選ぶ（C / P1）

消費者は、お届け先の都道府県と市区町村を一覧から選び、残りの住所を入力する。

- **AC-248** 注文手続きの画面のお届け先は、都道府県・市区町村・それより下の住所を、別の欄で入力する。都道府県と市区町村は一覧から選ぶ。
- **AC-249** 市区町村の一覧は、選んだ都道府県の市区町村だけを表示する。都道府県を選択し直すと、選んだ市区町村は外れる。
- **AC-250** 都道府県と市区町村の一覧は、店舗 API のマスターデータから得る。画面は都道府県・市区町村の表を持たない。
- **AC-251** 注文の確定は、選んだ都道府県に属さない市区町村、またはマスターデータにないコードを、入力の誤り（400）で拒む。
- **AC-252** 注文の詳細（店舗画面・管理画面）は、お届け先を、都道府県名・市区町村名・それより下の住所の順に表示する。

### US-55 郵便番号から、お届け先の住所を補う（C / P1）

消費者は、郵便番号を入れると、都道府県・市区町村・町域を入力しなくてよくなる。

- **AC-253** 店舗 API は、郵便番号から、都道府県・市区町村・町域を返す。
- **AC-254** 1 つの郵便番号に複数の町域があるときは、すべてを返す。
- **AC-255** 注文手続きの画面で郵便番号（7 桁）を入れると、都道府県と市区町村を選んだ状態にする。町域が 1 つで、住所の欄が空のときは、町域を住所の欄に入れる。
- **AC-256** マスターデータにない郵便番号は、何も補わず、消費者がそのまま入力を続けられる。郵便番号は、マスターデータにないことを理由に拒まない。理由：最初のデータは一部だけのため（第 7 節）。
- **AC-257** 補った後も、消費者は都道府県・市区町村・住所を変えられる。
- **AC-283** 郵便番号のデータの町域名にある、住所でない注記（「以下に掲載がない場合」、括弧の中の補足など）は、町域として返さない。町域名が注記だけの郵便番号は、都道府県と市区町村だけを返す。

### US-56 都道府県と市区町村を、コードとマスターデータで扱う（B / P1）

運営者は、都道府県と市区町村を、名前の書き方の違いによらず、コードで集計し表示する。

- **AC-258** 注文は、お届け先の都道府県と市区町村をコードで持つ。
- **AC-259** 都道府県と市区町村のマスターデータは、全国の都道府県（47）と市区町村を、最初のデータとして持つ。
- **AC-260** 郵便番号のマスターデータは、構造と、開発とテストに使う一部の郵便番号だけを、最初のデータとして持つ。
- **AC-261** 既にある注文は、都道府県名をコードに変換し、住所の先頭をマスターデータの市区町村名と照合して、市区町村を分ける。照合できない注文があれば、データベースの移行を失敗させる。
- **AC-262** 売上レポートの都道府県別の集計は、注文の都道府県のコードを使い、都道府県名から再度引かない。管理画面は、都道府県名を API の応答から表示し、画面の文言に都道府県の表を持たない。
- **AC-263** 都道府県・市区町村・郵便番号の表は、マスターデータのほかに持たない（バックエンドの検証、画面、レポート、seed）。テストのデータは除く。

### US-57 入力の誤りを、API の文で知る（C / P1）

消費者は、注文手続きの入力の誤りを、API が決めた文で知る。

- **AC-264** 注文手続きの画面は、入力の誤り（400）の欄ごとの文を、API の応答の文のまま表示する。画面で文を作るのは、応答がないときだけ。
- **AC-265** 店舗 API の入力の誤りの文は、消費者が読んで修正できる文にする。形の誤りに、正規表現などの検証の部品の既定の文を表示しない。
- **AC-266** エラーの文に上限・桁数などの値を入れるときは、数字を文に書かず、正となる所から差し込む。バックエンドのエラーの文と、画面の文言の両方に当てる。

### US-58 操作できるかとその理由を、API から受け取る（C、B / P1）

消費者と運営者の画面は、業務の規則から操作の可否を推し量らず、API の応答で表示を切り替える。

- **AC-267** 店舗 API の注文の応答は、キャンセルの申請の結果（申請していない、申請中、承認、却下）を返す。店舗画面は、申請が却下されたかを、この結果だけで決める。
- **AC-268** 管理 API の注文の応答は、キャンセルの時に在庫を戻すかを運営者に聞くかを返す。管理画面のキャンセルの確認は、これで表示を切り替える。
- **AC-269** 管理 API の商品の応答は、商品を削除できないときの理由を返す。管理画面は、削除できない理由をこれで表示する。
- **AC-270** 管理 API の分類の応答は、子の分類を追加できるかを返す。管理画面は、子の分類を追加する操作の表示をこれで切り替え、分類の深さを持たない。
- **AC-271** 店舗画面と管理画面は、API の応答の操作の可否と理由のほかに、注文の状態や商品の状態から操作の可否を決める判定を持たない。

### US-59 上限・形式・エラーのコードを、API の契約から得る（B / P1）

運営者は、上限やエラーのコードを変えたとき、画面が古い値のまま動く状態を残さない。

- **AC-272** 管理 API の契約は、商品の画像の形式・大きさの上限・枚数の上限を、型の制約で示す（説明の文だけにしない）。管理画面は、この値を契約から得る。
- **AC-273** 管理 API の契約は、分類の深さの上限を示し、バックエンドの上限と一致する。
- **AC-274** 店舗 API と管理 API の契約は、操作ごとに、返しうるエラーのコードの一覧を示す。画面は、エラーのコードで分けるとき、契約から作った型を使う。
- **AC-275** バックエンドのエラーのコードと、契約のエラーのコードの一覧が食い違うと、CI で失敗する。
- **AC-276** 管理 API の商品のバリアントの追加は、作ったバリアントの URL を応答の Location に入れる（[API の規約](../../api/conventions.md) 第 2 節）。

### US-60 列挙・日本時間・税の規則を、1 か所で決める（B / P1）

運営者は、列挙の値や業務の時刻・税の規則を変えたとき、一部だけが古いまま動く状態を残さない。

- **AC-277** モジュールの間で列挙を写すときは、すべての値の対応を、コンパイルかテストで確認する。値を追加して対応を書き忘れると、コンパイルかテストで失敗する。
- **AC-278** 売上レポートは、注文の状態を文字列で比べず、列挙で比べる。
- **AC-279** 列挙を文字列で持つデータベースの列は、すべて取りうる値を制約で限る。制約の値と列挙の値が食い違うと、テストで失敗する。
- **AC-280** 業務の日付を切る時間帯（日本時間）は、バックエンドの 1 か所で決める。注文番号の日付、年齢の基準日、注文の一覧の日付の範囲、売上レポートの日は、そこから得る。
- **AC-281** 時点の税率の判定は 1 か所で決める。税込価格の端数の規則を SQL でも計算する所は、Java と同じ結果になることをテストで確認する。
- **AC-282** 分類の深さの上限は、バックエンドの 1 か所で決める。上限を変えたとき、データベースの制約と分類の絞り込みが追従しなければ、テストで失敗する。

## 5. 業務ルール

- **BR-33** 値の置き場所は、誰が・いつ変えるかで決める。

  | 値 | 置き場所 | 例 |
  |----|----------|-----|
  | デプロイせずに運営者や外部のデータで変わる業務のデータ | データベース（マスターデータなど） | 税率、都道府県、市区町村、郵便番号 |
  | 環境ごとに違う、デプロイに関わる値 | 環境変数（設定） | 接続先、鍵、mock フラグ、ポート |
  | 変えるとコードも変わる業務の規則 | バックエンドの domain の定数 | 分類の深さ、画像の枚数、氏名の文字数 |

  どの値も正となる所は 1 つで、画面は API の契約か応答から得る。置き場所の規則は、plan で設計の文書に書く。
- **BR-34** 都道府県と市区町村は、地方公共団体コードで識別する。名前は表示にだけ使う。
- **BR-35** 注文は、お届け先の都道府県と市区町村を、注文の時点のコードと名前で持つ。マスターデータの名前が後で変わっても、注文の表示は変わらない。※1
- **BR-36** 郵便番号は、入力を補うためだけに使い、注文を受けるかの判断には使わない。
- **BR-37** 郵便番号のマスターデータは、他のデータから参照しない。注文は、補った町域を住所の文字として持つ。郵便番号のデータを更新するときは、表をまるごと入れ替える。※2

※1：注文の明細が注文の時点の商品名と価格を写すのと同じ考え方（AC-92）。市区町村の合併などで名前やコードが変わっても、送った先の記録を変えない。

※2：郵便番号のデータには、町域を識別するコードがなく、更新で町域の行が分かれる・まとまることがある。参照されなければ、差分を追わずに入れ替えられる。郵便番号のデータの各行は地方公共団体コードを持つので、市区町村のマスターデータとはコードでつながる。

## 6. 非機能要件

- **NFR-20** マスターデータを外部（国の API、日本郵便）から取り込む仕組みを後から追加するとき、マスターデータを使う側（注文、レポート、画面）を変えずに済む。
- **NFR-21** 最初のマスターデータは、公開されたデータからスクリプトで作り、手動で 1 行ずつ書かない。郵便番号のデータの変換（注記を除く、複数の行に分かれた町域をまとめるなど）は、後で取り込みの仕組みからも使える形で作る。出典と利用の条件を [依存とライセンス](../../reference/licenses.md) に書く。
- **NFR-22** 本 spec の AC に関わらない既存のテスト（バックエンド、フロント、E2E）は、期待値を変えずに通る。お届け先の形、操作の可否と理由、エラーの文とコードに関わるテストは、新しい振る舞いに合わせて変えてよい。
- **NFR-23** CI の全体が 10 分以内のまま終わる（spec 011 の DC-85）。理由：郵便番号の全国のデータを入れないのは、テストのデータベースを作るたびに読み込むと CI が遅くなるため。

## 7. Non-goals

| 項目 | 扱う場所 |
|------|----------|
| マスターデータを外部（国の API、日本郵便）から取り込み、更新する仕組み | 1 → 10 |
| 郵便番号の全国のデータ。郵便番号と都道府県・市区町村の食い違いの検査 | 1 → 10（取り込みの仕組みと同時） |
| 市区町村の合併・廃止の扱い（廃止した市区町村を一覧から外す、古いコードの読み替え） | 1 → 10（取り込みの仕組みと同時） |
| 市区町村別の売上の集計 | 行わない（今のレポートにない） |
| 配送業者の状態の対応の表をデータにする、ヤマト運輸以外の表 | 1 → 10（物流の本番の実装と同時。今は mock だけ） |
| 会員の住所録（お届け先を保存して選ぶ） | 1 → 10 |
