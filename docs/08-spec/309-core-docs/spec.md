# Spec 309：毎回読む文書の、同じ規則の正本を 1 つにする

ステータス：草案

危険度：高

## 1. 背景と目的

整理の段階の第 2 フェーズの spec 3 である。spec 3 であることの出典は、issue 担当の棚卸しである。棚卸しは Git の管理外にある。毎回読む文書（`AGENTS.md`・constitution・開発の進め方・エージェントの作業フロー・作業の形と使用量）に、同じ規則が 2 か所以上に書いてある。経緯と調べた記録も本文にある。`AGENTS.md` とエージェントの作業フローは、整理の前より大きく増えた。そこで、規則ごとに正本を 1 つにし、経緯と記録を決定記録と記録の文書に移し、固定の文脈の大きさを測る。

追跡の issue は [#309](https://github.com/roger88106/ec-site/issues/309) で、種類は整理、領域は docs である。関連する issue は、#252（既存のレビューの指摘の一覧。閉じない）、#265（閉じた測定）、#279・#283・#284（第 2 フェーズの spec 0〜2、マージ済み）である。起票と着手は利用者が承認した（2026-11-01）。作業ブランチは `309-core-docs`（`develop` の 84c2ff3e から作った）で、アーカイブ先は `docs/08-spec/archive/1to10/309-core-docs/` である。

本 spec は整理の spec である（[文書の記号と番号](../../05-開発規則/notation.md)）。`AGENTS.md`、constitution、`docs/05-開発規則/`、`.claude/` を変える。`scripts/ci/risk.json` の「エージェントの規則と設定」の経路に当たるので、危険度は高とする。マージは利用者が許可する。

hook、CI の検査の script、認証・支払・権限の経路は変えない。そのため、pull request の前の文脈を持たない高性能のレビュー役は加えず、セキュリティのレビューも行わない。

## 3. 目的と完了条件

### DS-309-1 毎回読む文書の、同じ規則の正本を 1 つにする（D / P1）

- **DC-309-1** [plan](plan.md)の「正本を 1 つにする」の一覧の各規則が、一覧に挙げた正本の節に書いてある。
- **DC-309-2** 一覧の「指す側」の文書は、その規則を言い換えず、正本を指す。skill `sessions`・`review` は、正本を移したことで切れる参照だけを修正する（DN-309-5）。
- **DC-309-3** `AGENTS.md` の「モデルの区分」の表の列は、区分、モデル、ID、既定の effort だけである。使う場面は、エージェントの作業フローを指す。組み込みのコードレビューとセキュリティのレビューの行は、ツールの名前と level の指定だけを残す。
- **DC-309-4** マージの許可と変更の危険度の正本は、確認 4 の決定のとおりである。
- **DC-309-5** `AGENTS.md` の Git の表の「マージ・tag」の行は、許可と担当は正本を指し、`gh pr merge --match-head-commit <SHA>` と、hook が確認の画面を表示することだけを書く。
- **DC-309-6** `AGENTS.md` の「作業の進め方」と「完了の基準」は、確認 3 の決定のとおりである。
- **DC-309-7** constitution の「リポジトリ構成」の木の `docs/` の下に、フォルダーの説明のコメントがない。フォルダーの説明の正本は「文書の地図」である。
- **DC-309-8** 開発の進め方の「文書の置き場所」の表には、spec と issue に関わる行だけが残る。
- **DC-309-9** 開発の進め方の「文書の書き方」の節がない。文書の書き方への案内は「spec と plan の書き方」だけにあり、指す側は修正してある。
- **DC-309-10** レビューの重要な観点の列挙が、エージェントの作業フローの「レビューの時点と profile」の 1 か所にある。「任せる作業とモデル」のレビューの行は、それを指す。

### DS-309-2 経緯と記録を、規則の文書から移す（D / P1）

- **DC-309-11** 任せ方の決定とその理由は、確認 1 の決定のとおりの 1 か所にある。エージェントの作業フローと実績の文書に、同じ理由の二重の記述がない。
- **DC-309-12** エージェントの作業フローに、「調べた仕組み」の節がない。
- **DC-309-13** エージェントの作業フローの「取り入れるもの・取り入れないもの」は、理由のない規則の箇条（サブエージェントへの任せ方）になっている。
- **DC-309-14** spec 246 の経緯は、エージェントの作業フローでは、1 文の規則と記録へのリンクだけになっている。
- **DC-309-15** 「整理の第 1 フェーズの測定では値を変えない」の文は、確認 2 の決定のとおりである。

### DS-309-3 規則と skill の置き場所を修正する（D / P1）

- **DC-309-16** 作業ツリーの置き場所と設定の読まれ方が、skill `sessions` の「作業ツリーのセッションが読むもの」に 1 つだけある。エージェントの作業フローの箇条は、skill を指す 1 文である。

- **DC-309-19** `AGENTS.md` の「環境」の最後の箇条は、書き先の 2 つの区分と script の置き場所だけを書く。作業ツリーのセッションが読むものは、skill `sessions` を指す。
- **DC-309-20** レビューの重要度の定義と収束の上限（skill `review` の `prompts.md`、`convergence.md`）の扱いは、確認 5 の決定のとおりである。

### DS-309-6 固定の文脈を測る（D / P1）

### DS-309-7 本 spec の文書の完了の条件（D / P1）

第 2 フェーズの各 spec が共通で満たす完了の条件である。
