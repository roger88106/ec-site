# 通知モジュール

消費者へのメールを送る。今は出荷通知メールだけ。

| 項目 | 内容 |
|------|------|
| レベル | B（業務の規則は「同じ注文に同じ種類のメールは 1 通」だけで、集約に守らせる不変条件がない） |
| 依存 | 注文（イベントだけ。注文の API は呼ばない ※1） |
| 関連 spec | [009](../../specs/009-shipping) |

※1：メールに要る値（宛先、注文番号、配送業者、送り状番号）は、イベント「注文の出荷」に載っている。

## 出荷通知メール

- イベント「注文の出荷」をコミットの後に受け、注文のメールアドレスへ送る。
- 件名と本文は日本語のテキスト。雛形はメッセージのファイル（`messages.properties` の `ecsite.notification.*`）に置き、注文番号、配送業者の表示名、送り状番号を差し込む。
- 送信元は設定 `ecsite.notification.from`。
- 消費者が配送業者のサイトで追跡できるよう、送り状番号はそのまま（ハイフンを除いた数字）載せる。

### 1 通だけ送る

| 項目 | 内容 |
|------|------|
| 記録 | 送ったメールを、注文 ID とメールの種類の組で記録する（一意制約） |
| 順序 | 同じトランザクションで、記録を挿入（すでにあれば何もしない）→ 挿入できたときだけ送る |
| 失敗 | 送信に失敗したら例外で終わり、記録も巻き戻る。未完了のイベントの再発行（[バックエンドのアーキテクチャ](../architecture.md) 第 5 節）で送り直す |
| 重ねて届いた | 記録があるので送らない。同時に届いたら、後の挿入は先のコミットを待ってから何もしない |

- 送信が済んでからコミットに失敗したときだけ、2 通になりうる。DB のコミットの失敗はまれなので許す。

## メールの送信

| 項目 | 内容 |
|------|------|
| port | 「メールを送る」の 1 つ（宛先、件名、本文）。SMTP の型とエラーを `infrastructure` の外に出さない |
| 実装 | Spring Boot のメール（`spring-boot-starter-mail`）で SMTP に送る。接続先は Spring Boot の設定 `spring.mail.*` |
| ローカル・テスト・E2E | compose の Mailpit（SMTP は `localhost:1025`、届いたメールは `http://localhost:8025` で見る）。統合テストは Testcontainers の Mailpit |

## 他のモジュールへの公開

なし。

## 構成

```
notification/
├── application/            # 注文の出荷のリスナー、出荷通知メールの組み立て
│   └── port/               # メールを送る、送ったメールの記録
└── infrastructure/
    ├── mail/               # SMTP での送信
    └── persistence/        # 送ったメールの記録の実装
```

## データモデル

- schema は `notification`。注文は他のモジュールの ID なので、外部キーは張らない。
- 送ったメールは、注文 ID、メールの種類（`SHIPMENT`）、宛先、送った日時を持つ。注文 ID とメールの種類の組で一意。
