# 校閲役の評価の一覧

校閲役（検出役・確認役）を採点するための、例の一覧である。見逃しの例は、校閲を通った後に通じにくい語が見つかった文である。誤検出の例は、挙げてはいけない文（正しい日本語）である。

- 使う時点：校閲役の定義やモデルを替えるとき。手順は「校閲役を替えるときの手順」。
- この一覧は、`ja-text` と `zh-mixing` の検査から除かれている。例文に、使わない語と中国語の混入を例として書くため。
- 校閲役は、この一覧を読まない。例を読むと、採点の結果が実際の校閲より良くなるため。
- 例文に、利用者の中国語の言葉を転記しない。

## 例の表

出典は、文書のパスと commit である。例文は、出典の文書の文をそのまま使う。出典に該当する文がない例だけ、出典に「作った例」と書く（今は 0 件）。

「ja-text の扱い」の列は、その語が今の言い換えの一覧（`scripts/ci/ja-text.json`）にあるかを示す（2026-11-01 の状態）。

## 入力の作り方

全ての例文を 1 つの入力にまとめる。

- 入力は、校閲の手順と同じく、差分の追加行（各行の先頭に `+`）とファイルの名前で渡す。ファイルの名前は `docs/eval-ja-proofread.md` とする。
- 1 つの例文を 1 行にし、番号の順に並べる。
- 入力に、番号・種類・挙げるべき語句・出典を入れない（例文だけ）。理由：答えが入力にあると、採点にならないため。
- 入力のファイルは `/.local/review/` の下に置く。

## 数え方

指摘の表は、校閲役が返す表である。列は、ファイル・行・今の書き方・修正案・理由である。

- 2 つの役割に分けた校閲では、確認役の表で「判定」が「挙げる」の行を、指摘の表とする。
- 見つけた数：見逃しの例ごとに、挙げるべき語句を指摘の表の「今の書き方」の列に含む行があれば「見つけた」と数える。
- 誤検出の数：誤検出の例に当たる指摘の表の行を、1 行ずつ誤検出に数える。1 つの例に 2 行あれば 2 件である。
- 見逃しの例の文に、別の例の挙げるべき語句がある場合は、その語句を含む行も、その例を見つけたと数える。
- 誤検出の例の文は、見逃しの例の語句を含む場合がある（F-06 の `主の` など）。その語句だけを挙げた行は、誤検出に数える。

## 実行の回数

同じ設定を 2 回実行し、2 回の合計で比べる。

## 採用の基準

新しい設定の結果を、前の設定と比べて、次の表で扱いを決める。

| 新しい設定の結果（前の設定と比べて） | 扱い |
|---|---|
| 見つけた数が同じか多く、誤検出の数が同じか少なく、少なくとも一方が良い | 採用する |
| 見つけた数も誤検出の数も同じ | 採用しない |
| 一方が良く、他方が悪い | 利用者に判断を求める |
| 両方が悪い、または一方が悪く他方が同じ | 採用しない |

## 校閲役を替えるときの手順

校閲役の定義やモデルを替えるときは、次の順で行う。

1. 比べる 2 つの設定（今の設定と新しい設定）を、同じ commit の評価の一覧で採点する。
2. 各設定を、「入力の作り方」の入力で 2 回実行し、「数え方」で見つけた数と誤検出の数を数える。token と時間も記録する。
3. 「採用の基準」の表で、扱いを決める。
4. 結果を、[調べた仕組みと実績](../../../../docs/07-記録/subagents-results.md)の節「校閲の評価の結果」に書く。

例を加えた後は、前の設定も再採点する。理由：例が変わると、前の結果と比べられないため。
