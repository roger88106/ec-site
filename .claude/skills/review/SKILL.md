# レビュー

実装を見ていないサブエージェントにレビューを任せ、spec 担当のセッションがまとめる。規則の置き場所と書き方は [書き方の規則とレビュー](../../../docs/rules/review.md)、サブエージェントへの任せ方は [エージェントの作業フロー](../../../docs/rules/subagents.md) にある。

## 使う場面

| 場面 | 対象 | 手順 |
|------|------|------|
| `[リスク]` のタスクの後 | そのタスクの差分 | 手順 1〜6（観点は、タスクに関わるもの：金額、セキュリティなど） |
| 段階の最後のレビュー | 差分（段階の最初の commit の 1 つ前から HEAD まで） | 手順 1〜6。中国語で指示する環境では手順 9 も行う |
| spec の最後のレビュー | 差分（spec の最初の commit の 1 つ前から HEAD まで） | 手順 1〜6。観点は、段階をまたぐ影響、ファイルをまたぐ影響、spec との一致の 3 つ。中国語で指示する環境では手順 9 も行う |
| plan・tasks の照合 | spec と plan、spec・plan と tasks | 手順 7 |
| 文書のレビュー | 新しく書いた、または変えた文書 | 手順 8 |
| pull request の前 | pull request の差分 | 完了の定義を確認し、draft で先に作った pull request に組み込みのコードレビューを使う（level は毎回明示する。順は [開発の進め方](../../../docs/rules/workflow.md) 第 4.2 節）。認証・支払・権限の経路を変えるなら、セキュリティのレビューも行う。hook・判定器・認証・支払・権限の経路を変える spec は、無記憶の高性能のレビュー役（`reviewer`）も 1 回加える（[エージェントの作業フロー](../../../docs/rules/subagents.md) 第 4 節）。中国語で指示する環境では手順 9 も行う |
| リリースの前 | リリースに入る差分 | マイグレーション、設定、互換性、リリースの説明の案を見る |
| 全体のレビュー（受け入れ確認） | リポジトリ全体 | 手順 1〜6。材料に、既存の指摘の一覧（issue「既存のレビューの指摘の一覧」）と振り返りの集計を加える。対象を観点ごとに、さらに範囲（モジュール、アプリ、E2E、文書、script と CI）で分ける |

時点ごとのモデルとレビューの回数は、[エージェントの作業フロー](../../../docs/rules/subagents.md) の profile の表で選ぶ。profile は issue 担当のセッションが渡す（[作業の形と使用量](../../../docs/rules/resources.md)）。

## 手順

1. 対象を決める。差分なら、変えたファイルを [書き方の規則とレビュー](../../../docs/rules/review.md) 第 2 節 ※1 のコマンドで一覧にする。結果の置き場所 `/.local/review/<yyyyMMddHHmm>-<名前>/` を作り、差分を `diff.txt` に書く（レビュー役はコマンドを実行できないため）。2 回目以降は [convergence.md](convergence.md) のとおり対象を絞り、レビューした commit を置き場所に記録する。
   完了の条件：対象のファイルの一覧が置き場所にある。
2. チェックリストを作る。`node .claude/skills/review/checklist.cjs` の出力を置き場所に保存する。対象に関係しない文書の節は除く。
   完了の条件：チェックリストのファイルがある。
3. 観点を選ぶ。観点の一覧とサブエージェントへの指示のひな形は [prompts.md](prompts.md)。差分のレビューでは、対象に関係する観点だけを選ぶ。
   完了の条件：観点ごとに、読むファイルの範囲が決まっている。
4. 観点ごとに、レビュー役の定義（`reviewer`）でサブエージェントを立てる。並列で実行してよい。モデルは上の profile の表で選ぶ。指示は [prompts.md](prompts.md) のひな形を使い、日本語だけで書く。渡すのは対象のファイルの一覧と差分のファイル、spec と plan のパス、チェックリスト（関係する部分）、観点、同じ spec のそれまでの `rejected.md`、結果の書き先だけ。サブエージェントは結果をファイルに書き、件数だけを返す。
   完了の条件：全ての観点の結果のファイルがそろった。
5. 全ての結果がそろってから、まとめる。重複を除いて指摘を「高」「必須」「推奨」に分ける（定義は [prompts.md](prompts.md) の「重要度」）。各指摘に、由来（今回・既存）、根拠（規則の文書と節、または spec の DC・AC）、場所、修正案、機械の検査に移せるか（移せる検査の名前、または移さない理由）を付ける。指摘が事実かは、spec 担当が確認する。
   完了の条件：まとめの表があり、全ての指摘に根拠と「機械の検査に移せるか」がある。
6. 結果を利用者に示し、レビューの記録を次の表で書く。全てのレビュー（段階、spec の最後、pull request の前の `reviewer` と組み込みのコードレビュー、`[リスク]` のタスクの後）を、文章でなくこの表で記録する。書き先は、規模 L は tasks のレビューのタスクの「結果」、規模 M は spec.md の結果、規模 S は pull request の本文（規模 S は `stats.cjs` の集計の対象外）。レビュー役ごとに 1 行で、集計の script が読むので、列の名前と順序を変えない。理由：整理の第 1 段で表の形がそろわず、集計できたのが 1 つの spec だけだったため（issue #265）。

   ```markdown
   | 時点 | 観点 | モデル | 回数 | token | 時間 | 高 | 必須 | 推奨 | 採用 |
   |------|------|--------|------|-------|------|----|------|------|------|
   | 段階 1 | 網羅性 | 汎用 | 1 | 52000 | 3m20s | 1 | 2 | 1 | 2 |
   | 段階 1 | 規則 | 汎用 | 1 | 41000 | 2m50s | 1 | 1 | 0 | 1 |
   | 段階 1 | 重複を除く | — | 1 | — | — | 1 | 2 | 1 | 3 |
   | pull request の前 | 組み込み | 組み込み | 1 | — | — | 0 | 1 | 2 | 1 |
   ```

   同じ時点の同じ回で複数のレビュー役が動いたとき（和集合のレビュー、複数の観点）は、その後に観点を `重複を除く` とした 1 行を加え、高・必須・推奨・採用に重複を除いた数を書く。その行のモデル・token・時間は `—`、回数は対象の回（例：`1`）。2 回目以降のレビュー（[convergence.md](convergence.md)）は、回ごとにこの行を加える。`stats.cjs` は、表・時点・回数が同じ行をまとめ、その中にこの行があれば、高・必須・推奨・採用にその行の値を使い、他の行の値を合計しない（token は他の行を合計する）。その行がない組で行が 2 つ以上あるときは、行の値を合計する。重複して数えているおそれがあるので、そのような組の数を出す。同じ組にこの行が 2 つ以上あるとき、またこの行の回数が数で読めないときは、書き誤りの疑いとして標準エラーに警告する。同じ指摘を複数のレビュー役が挙げたとき、この行がないと重複して数える。

   時点は、段階 n、spec の最後、pull request の前、`[リスク]` のタスクの後。モデルは区分（最上位・高性能・汎用・軽量）。組み込みのコードレビューは、モデルを `組み込み` とし、高・必須・推奨の別が出ないときは、指摘を重要度の定義（[prompts.md](prompts.md)）で分けて書く。回数は、同じ対象の何回目か。token と時間は、サブエージェントの結果の値を使い、出ないときは `—`。セッションの記録から集計する方法は、弾の終わりの測定だけで使う。高・必須・推奨は指摘の数、採用は修正した数。表の下に、修正したもの、残したものと理由、機械の検査に移したものを書く。「高」と「必須」は修正する。「推奨」は spec 担当が判定する。推奨は spec の最後にまとめ、pull request の「推奨の指摘の扱い」に書く（低の変更は弾の終わりに確認する。skill `sessions`）。機械の検査に移せる指摘は、検査を追加するタスクを提案する。
   2 回目以降のレビュー、上限、既存の指摘、採らなかった指摘は [convergence.md](convergence.md)。
   完了の条件：全ての指摘の扱いが決まっている。
7. plan と tasks を照合する。手順とひな形は [docs-review.md](docs-review.md)。
8. 文書をレビューする。手順とひな形は [docs-review.md](docs-review.md)。
9. 中国語で指示する環境では、校閲役 `ja-proofreader`（[定義](../../agents/ja-proofreader.md)）に変えた日本語を読ませる。環境の決め方と手順は [docs-review.md](docs-review.md)。
10. 校閲役や他のレビューが見つけ、利用者が確認した型を、機械の検査に加える。手順は [docs-review.md](docs-review.md)。
