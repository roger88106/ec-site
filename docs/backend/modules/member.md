# 会員モジュール

IdP（Keycloak）のアカウントと、EC の会員 ID の対応を管理する。

| 項目 | 内容 |
|------|------|
| レベル | B（不変条件は「1 つのアカウントに 1 人の会員」だけ） |
| 依存 | なし（カート・注文・店舗の presentation から API で呼ばれる） |
| 関連 spec | [003](../../specs/003-auth)、[017](../../specs/017-stability) |

## 会員

- 会員は、会員 ID（UUID）、IdP のアカウント ID（token の subject）、登録日時を持つ。
- カート・注文手続き・注文が持つのは会員 ID。IdP を替える・アカウントを移すときは、この対応だけを書き換える。
- メールアドレスと氏名は持たない（IdP が正本で、必要なときに token から読む）。注文には注文時点のメールアドレスを写す。
- 届け先などの会員の情報は、将来ここに追加する。

## 会員を求める

- 会員の token で初めて API を呼んだときに作る。IdP の登録を EC に知らせる仕組みは作らない。
- 「IdP のアカウント ID から会員 ID を求める（なければ作る）」を API で公開する。
- 同じアカウントの初回の要求が同時に来ても、会員は 1 人だけ作る ※1。
- 会員を求める処理は、ログインした全ての要求で動く。会員を探す操作（参照の service、読み取り専用のトランザクション）と、会員を作る操作（更新の service）に分け、API はまず探し、いなければ作る。会員がいるとき（初回より後の要求）は、読み取り専用のトランザクションだけで済む。

※1：アカウント ID の一意制約で守り、作れなければ（先に作られた）再読み込みする。作る処理は、呼び出し元のトランザクションを壊さない挿入で行う。

## token から会員を取り出す

presentation が token から会員の情報（アカウント ID、メールアドレス、確認済みか、姓、名、生年月日、性別）を取り出すクラスは `common/security` に置く（Spring Security の型をモジュールに出さないため）。

- 生年月日（claim `birthdate`）と性別（claim `gender`）は、会員が IdP の会員登録とアカウントの画面で入れる任意の属性。会員モジュールは持たず、注文が成立のときに token から読んで、年齢と性別を記録する（[注文モジュール](order.md)「注文時の年齢と性別」）。
- token の値は文字列のまま渡し、形と範囲は注文が確認する。

| 店舗 API の操作 | token がないとき |
|-----------------|------------------|
| 会員の操作 | filter で 401 |
| 任意の操作（カート） | ログインしていない人として扱う |

## 構成

```
member/
├── api/                    # 会員 ID を求める（探して、いなければ作る）
├── application/            # アカウントから会員 ID を探す（参照）、会員を作る（更新）
│   └── port/               # リポジトリ
├── domain/                 # 会員
└── infrastructure/
    └── persistence/        # リポジトリの実装
```
