# Spec 134：管理画面と共有のパッケージを整える

ステータス：確定

## 1. 背景と目的

MVP 019 の全体のレビュー（2026-10-21）で、管理画面と共有のパッケージに、必須 5 件と推奨 17 件の指摘が残った。1→10 で機能を追加する前に整える。

追跡の issue は [#134](https://github.com/roger88106/ec-site/issues/134)、扱う issue は #82（必須 5 件）と #88（推奨 17 件）、作業ブランチは `134-admin-tidy` である。

2026-10-22 に、全ての指摘が今のコードでも当てはまることを確認した（もう修正されているものはない）。確認の結果、指摘の一部は次のとおり事実と違っていた。

- 「すべて」を先頭に付けた選択肢の作り方は、3 通りでなく 2 通りである（同じ形の 2 か所と、共有の関数 1 か所）。
- グラフの吹き出しの値の整形は、画面のファイルでなく、shadcn/ui の生成物の既定である。
- 基本情報の保存の成功時の知らせは、更新の競合（409）のテストの最後で、一部確認している。

並行して spec 135（店舗画面を整える）が進む。管理画面と店舗画面で重複している整形と表示は、本 spec が共有のパッケージに移す。店舗画面の使う箇所も本 spec で修正する（利用者の決定、2026-10-22）。共有のパッケージを変える決定と、店舗画面への影響は plan に書く。

指摘のうち 4 件は、運営者・消費者に見える振る舞いを変える。整理の spec は通常、見える振る舞いを変えないが、[開発の進め方](../../rules/workflow.md) 第 1.5 節に沿い、レビューで見つけた不具合の修正として、非機能要件の例外に挙げる（利用者の決定、2026-10-22）。AC は追加も変更もしない。

本 spec は整理の spec である（[文書の記号と番号](../../rules/notation.md)）。

## 2. 用語

| 用語 | 意味 |
|------|------|
| 自分の権限の一覧 | 管理 API が返す、ログインしている運営者の権限の一覧。画面はこれで、権限が必要な画面とメニューの表示を切り替える |
| 取得の失敗 | 応答がない（通信の失敗）か、サーバーのエラー（5xx）で、再試行しても取得できないこと。権限がないこと（403）とは別 |
| リンクの見た目のボタン | 画面の移動のリンクを、ボタンの見た目で表示するコンポーネント |
| 409 の後の再読み込み | 更新の競合（409）を示した後に、最新の値でフォームを再作成する操作 |
| ログインの戻り先 | ログインの後に戻る画面のパス |

用語集に追加する語は、plan で決める。

## 4. 目的と完了条件

### DS-134-1 共有のパッケージ（D / P1）

- **DC-134-1** 日付の形の判定は、管理画面の、画面に依存しない関数の置き場所（[フロントの書き方](../../rules/frontend-coding.md) 第 1.1 節）にあり、共有のパッケージにない。テストも同じ場所に移っている。理由：管理画面だけが使うため。
- **DC-134-2** 注文の状態、配送状態、配送業者の表示名を引く処理は、共有のパッケージに 1 つだけあり、管理画面と店舗画面がそれを使う。
- **DC-134-3** 金額の内訳（商品の合計、送料、総額、税率ごとの消費税）を表示するコンポーネントが共有のパッケージに 1 つあり、管理画面と店舗画面がそれを使う。
- **DC-134-4** 金額の内訳を共有にした後も、両画面の表示は移す前と同じである。管理画面はカードの中で右に寄せ、店舗画面は総額の前に区切り線を置く。
- **DC-134-5** 日本時間の年・月・日・時・分の書式の指定は、共有のパッケージの 1 か所にある。
- **DC-134-6** リンクの見た目のボタンを表示するコンポーネントが共有のパッケージに 1 つあり、管理画面の 8 か所と店舗画面の 2 か所がそれを使う。
- **DC-134-7** テストのファイルが 0 件のとき、共有のパッケージのテストの実行が失敗する。
- **DC-134-8** 共有のパッケージのテストのファイルは、テストする実装のファイル 1 つにつき 1 つである。例：カテゴリの木の処理のテストは 1 つのファイルにある。

### DS-134-2 権限の取得の失敗（D / P1）

表示の変更を含む。非機能要件 DN-134-1 の例外である。

- **DC-134-9** 自分の権限の一覧の取得に失敗したとき、権限が必要な画面（今はレポートの 3 つ）は、「権限がない」でなく取得の失敗を示す。
- **DC-134-10** 取得の失敗の表示から、取得を再試行できる。
- **DC-134-11** 取得に失敗したとき、メニューはレポートの入口を表示する。理由：権限の有無が分からないので隠さず、開いた画面が取得の失敗を示して再試行できるようにするため（利用者の決定、2026-10-22）。
- **DC-134-12** 自分の権限の一覧の取得中は、権限が必要な画面は何も表示せず、メニューにレポートを表示しない。
- **DC-134-13** 自分の権限の一覧の取得が、サーバーのエラー（5xx）になる場合と通信の失敗になる場合の結合テストがある。

### DS-134-3 ログインの戻り先（D / P1）

判定の変更を含む。非機能要件 DN-134-1 の例外である。

- **DC-134-14** ログインの戻り先の判定は、URL の解析で取り除かれる文字（TAB、改行）を含む入力を受け付けず、トップを戻り先にする。
- **DC-134-15** 受け付ける入力と、受け付けない入力（TAB・改行を含むもの）を確認する、ログインの戻り先の判定の単体テストがある。
- **DC-134-16** 戻り先の条件の記述が、DC-134-14 の判定の条件と一致する。対象は [管理画面の構成](../../design/apps/admin.md) 第 10.1 節と、[店舗画面の構成](../../design/apps/store.md) 第 9.2 節である。

### DS-134-4 表示と文言（D / P1）

- **DC-134-17** バリアントの売れ行きの表示名は、在庫の画面と注文の明細と同じく、「名前：値」を、文言ファイルの区切りの文字で並べる。例：「色：黒、サイズ：M」。表示の変更を含み、DN-134-1 の例外である。
- **DC-134-18** バリアントの売れ行きの CSV の表示名も、DC-134-17 と同じ形になる。
- **DC-134-19** バリアントの売れ行きの表示名を組み立てる関数が、画面のファイルの外にあり、単体テストがある。
- **DC-134-20** レポートの条件のフォームは、コンポーネントの中で文言を引く方法（[フロントの書き方](../../rules/frontend-coding.md) 第 7.1 節）で、全ての文言を引く。
- **DC-134-21** レポートのグラフの吹き出しの値は、[フロントの書き方](../../rules/frontend-coding.md) 第 7.3 節のロケールの定数で整形する。金額は表と同じ円の整形、数量は既定のロケールの数の整形である。表示の変更を含み、DN-134-1 の例外である。
- **DC-134-22** 入力欄の制約は、その操作の契約のスキーマから引く。例：カテゴリの名称の変更は名称の変更の要求、商品の登録は登録の要求。

### DS-134-5 管理画面の複製（D / P1）

- **DC-134-23** 409 の後の再読み込みの処理（今は 4 か所）が、1 か所にある。
- **DC-134-24** 「すべて」を先頭に付けた選択肢の作り方が、1 か所にある。
- **DC-134-25** レポートの 3 つの画面に共通の処理が、1 か所にある。共通の処理は、見出し、レポートの設定の取得、条件を URL から読む・URL に書く処理、条件のフォームの再作成である。
- **DC-134-26** メニューの項目の表示（機能の群とレポートの群）が、1 か所にある。

### DS-134-6 テスト（D / P1）

- **DC-134-27** 公開する・非公開にする操作で、送る要求と表示の変化を確認する、商品の編集の結合テストがある。
- **DC-134-28** 基本情報の保存の成功で、送る本文（税区分の変更を含む）と保存の知らせを確認する、商品の編集の結合テストがある。
- **DC-134-29** 軸のある商品へのバリアントの追加で、送る軸の値を確認する、商品の編集の結合テストがある。
- **DC-134-30** 送った品番が大文字になっていることを確認する、バリアントの追加の結合テストがある。
- **DC-134-31** 送る要求に添えるバージョンを確認する、バリアントの並べ替えと削除の結合テストがある。
- **DC-134-32** 送る要求に添えるバージョンを確認する、画像の並べ替えと削除の結合テストがある。
- **DC-134-33** カテゴリの名称の変更で 409 になった後の再読み込みの結合テストがある。
- **DC-134-34** バリアントの売れ行きと、地域・年齢層・性別の画面の CSV（見出しと、地域・年齢層・性別の 3 つの表を 1 つの CSV にまとめたときの行）の結合テストがある。
- **DC-134-35** 税率の表示の整形と、URL のページ番号の読み取り（0、小数、空を含む）に、横に置いた単体テストがある。
- **DC-134-36** 上の結合テストのうち AC を確認するものは、テスト名に AC の番号を入れる。AC 一覧のテストの列にも、そのテストを反映する。対応する AC は plan で決める。

## 5. 非機能要件

- **DN-134-1** 運営者・消費者に見える振る舞いを変えない。例外は次の表の 4 件とする。理由：レビューで見つけた不具合の修正のため（[開発の進め方](../../rules/workflow.md) 第 1.5 節）。

  | 修正 | 今 | 修正した後 |
  |------|----|----------|
  | 権限の取得の失敗 | 「権限がない」を示し、メニューにレポートが表示されない | 取得の失敗を示し、再試行できる |
  | ログインの戻り先 | TAB・改行を含むパスを受け付ける | 受け付けず、トップを戻り先にする |
  | バリアントの売れ行きの表示名 | 値だけを「 / 」で並べる。区切りの文字がコードに直接書かれている | 「名前：値」を区切りの文言で並べる |
  | グラフの吹き出しの値 | ブラウザの既定の数の整形で表示し、円の単位が付かない | 金額は表と同じ円の整形、数量は既定のロケールの数の整形 |

- **DN-134-2** 例外の 4 件は、テストを先に書いて失敗（レッド）を確認してから修正する。
- **DN-134-3** API の契約とデータベースの構造を変えない。
- **DN-134-4** AC を追加・変更しない。
- **DN-134-5** 共有のパッケージを変えた後も、店舗画面のテストが全て通る。
- **DN-134-6** shadcn/ui の生成物は修正しない。外側のコンポーネントでラップする（[管理画面の構成](../../design/apps/admin.md) 第 2 節）。
- **DN-134-7** 並行の spec 135 と同じファイルを変更する箇所は、plan に挙げ、spec 135 に知らせる。
