# テストの書き方

原則（テストの種類、置き場所、テスト先行）は [constitution](../constitution.md) 第 12 節。本書は、今のテストで守っている書き方を書く。テストの流し方は README の「起動とテスト」。

## 1. テスト名

### 1.1 AC 番号を入れる

- **規則**：AC を確かめるテストは、名前（Java は `@DisplayName`、Vitest・Playwright は `test`・`it` の第 1 引数）の先頭に AC 番号を入れ、その後に確かめる振る舞いを日本語で書く（例：`AC-43 調整後に負になる調整は拒否される`）。
- **理由**：AC からテストを、テストから AC を引けるようにするため（constitution 12.1）。
- **確かめ方**：人手（見直し）。AC とテストの対応の自動の検査は、spec 004 の段階 3 で足す。

### 1.2 名前は振る舞いを書く

- **規則**：テスト名は「〜すると〜になる」の形で、画面や API に起きることを書く。メソッド名やクラス名を写さない。Java のテストは、すべての `@Test`・`@ParameterizedTest` に `@DisplayName` を付ける。
- **理由**：失敗したときに、どの振る舞いが壊れたかが名前だけで分かるようにするため。
- **確かめ方**：人手（見直し）。

## 2. バックエンド

### 2.1 統合テストの土台

- **規則**：統合テストは `@IntegrationTest`（Spring と、Testcontainers の PostgreSQL・SeaweedFS・imgproxy。IdP は起動せず、`TestSecurityConfig` が署名の鍵を `TestTokens` の鍵に差し替える）を付ける。Keycloak は、それを確かめるテストだけが自分で起動する。API のテストは `@AutoConfigureMockMvc` と MockMvc で呼び、時刻は `TestClockConfig` で固定する。データを残さないテストは `@Transactional` で巻き戻す。
- **理由**：テストごとにコンテナを起動し直さず、データが他のテストに漏れないようにするため。
- **確かめ方**：人手（見直し）。

### 2.2 テストデータは補助のクラスで作る

- **規則**：複数のテストで使うデータの作り方は、`CatalogTestData`・`OrderTestData` などの補助に置く。token は `TestTokens`、画像は `TestImages` から取る。
- **理由**：テストの本文に、確かめる項目だけを残すため。
- **確かめ方**：人手（見直し）。

### 2.3 テストの置き場所

- **規則**：テストは main と同じパッケージに置く。Spring を起動しないものは `src/test`、起動するものは `src/integrationTest`。
- **理由**：constitution 12.1。
- **確かめ方**：自動（Gradle のソースセット）。

## 3. フロント

### 3.1 画面に見えるもので探す

- **規則**：結合テストと E2E は、要素を役割と名前（`getByRole('button', { name: '保存' })`、`getByLabel('名称')`）で探す。CSS のクラス、`data-testid`、内部の状態は使わない。
- **理由**：作り直しても振る舞いが同じなら、テストが壊れないようにするため（constitution 12.1）。
- **確かめ方**：人手（見直し）。

### 3.2 API の差し替えは型付きの MSW

- **規則**：管理画面の結合テストは、`src/test/` の `http`（openapi-msw）で、OpenAPI の型に合ったハンドラーを作る。既定のハンドラーは置かず、テストごとに `server.use(...)` で渡す。
- **理由**：契約にない応答をテストで作らないため（[管理画面の構成](../frontend/admin.md) 第 10 節）。
- **確かめ方**：自動（型チェック。ハンドラーのない API が呼ばれるとテストが失敗する）。

### 3.3 E2E のデータには実行ごとの印

- **規則**：E2E で作るデータの品番・名称には、実行ごとの印（`E2E-<印>-…`）を付ける（`e2e/src/data.ts`）。
- **理由**：前の実行や手で作ったデータと混ざらないようにするため。
- **確かめ方**：人手（見直し）。

## 4. 待ち方

- **規則**：時間で待たない（`Thread.sleep`、`waitForTimeout`）。条件で待つ（Playwright の `expect(...).toBeVisible()` などの自動の再試行、状態を直接確かめる）。
- **理由**：遅い環境で失敗し、速い環境で時間を無駄にするため。
- **確かめ方**：人手（見直し）。今は `MediaApiTest` と `S3ObjectStorageTest` に `Thread.sleep` が残っている（spec 004 の段階 3 で直す）。
