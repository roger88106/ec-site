# Spec 276：整理の第 1 段の振り返りの 4 件を skill と規則に入れる

ステータス：確認待ち

## 1. 背景と目的

milestone「整理の段階」の spec である。追跡の issue は [#276](https://github.com/roger88106/ec-site/issues/276) で、sub-issue は次の 4 つである。作業ブランチは `276-retro-rules` である。整理の spec なので、AC、API、データベースは変えない。規模は M で、2026-10-29 に利用者が承認した。変えるファイルが `.claude/` と `docs/rules/` の下にあるので、経路の判定で危険度は高になる（マージは利用者の許可が必要）。

| issue | 内容 |
|-------|------|
| [#271](https://github.com/roger88106/ec-site/issues/271) | 判定器や検査に止められる形と避け方を skill にまとめる |
| [#272](https://github.com/roger88106/ec-site/issues/272) | 作業ツリーのセッションが設定・定義・skill を読む場所と効く時点を、動かして確認して skill に書く |
| [#273](https://github.com/roger88106/ec-site/issues/273) | 高の pull request のマージの許可を求めるとき、hook の確認の画面と遠隔の操作での扱いを書き添える |
| [#274](https://github.com/roger88106/ec-site/issues/274) | 同じ種類の指摘が続く審査で、禁止の一覧から許可の一覧へ前提を変える案を出す規則を加える |

整理の第 1 段の振り返り（spec 245、246、247 と issue 担当のセッション）で、2 つ以上のセッションに出た問題である。どれも振る舞いを変えない skill と規則の修正で、触る文書が重なるので、1 つの spec で扱う。第 2 段の文書の棚卸しの前に済ませる。

### 本 spec の用語

| 用語 | 意味 |
|------|------|
| 判定器 | エージェントのコマンドを実行の前に止める仕組み。Claude Code の自動の許可の判定、`settings.json` と `settings.local.json` の hook（agent-guard、backslash-guard）、git の hook（commit-msg、pre-commit の日本語と中国語の混入の検査） |
| メインの作業ツリー | clone した元のディレクトリ（`git worktree add` で作った作業ツリーでないもの） |
| アプリの作業ツリー | Claude のデスクトップアプリがセッションのために作った作業ツリー |
| 手動の作業ツリー | セッションが `git worktree add` で作り、絶対パスで作業する作業ツリー（セッションはメインの作業ツリーで起動している） |
| 護り | 不注意の誤り（うっかり書いた形）を止める判定。意図して作った回避は止めることを求めない |
| 境界 | 意図して作った回避も止める判定 |

### 今の記述と振り返りの事実

| 止めたもの | 形 | 出たセッション | 今の skill の記述 |

#### #272 作業ツリーのセッションが読むもの（今の記述）

| 対象 | 今の記述 | 記述の根拠 |
|------|----------|------------|
| `.claude/settings.json` | AGENTS.md の環境の節：「作業ツリーのブランチに commit されたものが読まれる」 | spec 246 の調べ（文書の記述）。246 では、確認のために起動したセッションが主の作業ツリーで動き、作業ブランチのものを読まなかった |
| `.claude/settings.local.json` | エージェントの作業フロー 第 4 節：アプリの作業ツリーのセッションはメインの作業ツリーのものを読む。手動の作業ツリーは未確認 | spec 247 で動かして確認した（アプリの作業ツリー、2026-10-29） |
| `.claude/agents/` | skill `sessions`「マージの後」：主のチェックアウトから読まれる | spec 245 の振り返り（手動の作業ツリーで作った定義が使えなかった） |
| `.claude/skills/` | 同上 | 同上 |
| 効く時点 | AGENTS.md の環境の節：設定はセッションの開始のときに読まれる | issue 担当の振り返り（動いているセッションに hook が効かなかった） |

- 確認していない組がある：アプリの作業ツリーの `settings.json`・`agents/`・`skills/`、手動の作業ツリーの全て、`claude -p` を作業ツリーで起動したとき。
- 作業ツリーのセッションと `claude -p` は、起動のディレクトリで読むものが変わりうる。アプリの作業ツリーのセッションと、メインの作業ツリーで起動したセッションは、新しいセッションを起動しないと確認できない。利用者が遠隔操作のときは、新しいセッションを起動できないことがある。

#### #273 マージの許可の箇所（今の記述）

- AGENTS.md の Git の表は、許可が必要なマージで hook が確認の画面を出すことを書いている。許可を求めるときに、それを利用者に伝えることは書いていない。
- [開発の進め方](../../rules/workflow.md) 第 5.7 節は、許可を求める時点（アーカイブの許可と一緒に）だけを書いている。
- 遠隔の操作（Remote Control）では、確認の画面とアプリの「次の一歩」の箱が見えないことがある。PR #269 のマージで、利用者は確認の画面を hook の誤りと思って拒否した。

#### #274 収束の規則（今の記述）

- skill `review` の convergence.md は、上限（3 回）と同じ種類の指摘（まとめて検索して直す）を書いている。修正の前提を変える案を出す時点は書いていない。
- 判定の script（hook、CI の検査）を作る spec の書き方の規則はない。plan の型のファイルもない。
- PR #268 の審査は 6 回になり、高の数は 4→2→2→1→1→0 だった。禁止する形の一覧に回避の形を 1 つずつ加え、最後に許可する形の一覧に替えて止まった。

## 3. 目的と完了条件

完了条件は、第 6 節の推奨の案で書いた。

### DS-276-1 判定器に止められる形と避け方を skill に書く（D / P1）

- **DC-276-1** skill `local-dev` の「シェルと Git の落とし穴」が、第 1 節の #271 の表の全ての形について、止めるもの（判定器の名前）と避け方を書いている。避け方は少なくとも次を含む。
  - Markdown の表（`\|`）を含む追記は、Edit で書く。
  - 外へ出す `gh` の操作（pull request の編集・ready・マージ、issue の編集）は、1 つのコマンドに 1 つにする。
  - `cd` で作業ディレクトリを移さず、`git -C` と絶対パスを使う。
- **DC-276-2** skill `sessions` のツールの注が、`claude -p` の起動の形（`--permission-mode default` と `--allowedTools` で許すツールを渡す）と、`bypassPermissions` を使わないことを書いている。
- **DC-276-3** skill `zh-mixing` が、コミットメッセージと spec で止まりやすい語の参照先（層 1 の `scripts/ci/ja-text.json`）と、利用者の中国語の言葉は日本語に訳して書くことを書いている。skill `local-dev` の DC-276-1 の該当の行から、この箇所を指す。

### DS-276-2 作業ツリーのセッションが読む場所と効く時点を、動かして確認して表にする（D / P1）

- **DC-276-4** skill `sessions` のツールの注に、次の表がある。行は起動の形（アプリの作業ツリーのセッション、メインの作業ツリーで起動して手動の作業ツリーで作業するセッション、作業ツリーで起動した `claude -p`）、列は `.claude/settings.json`・`settings.local.json`・`.claude/agents/`・`.claude/skills/` の読む場所と、変更が効く時点である。
- **DC-276-5** DC-276-4 の表の各欄は、動かして確認した結果（確認した日と方法）である。確認していない欄は「未確認」と書き、第 7 節の T276-01-07 で利用者が戻った後に確認する。
- **DC-276-6** 定義・skill・hook を変える spec が、マージの前に変更を確認する手順（その作業ツリーで新しいセッションか `claude -p` を起動する）が、DC-276-4 の表の後にある。
- **DC-276-7** AGENTS.md の環境の節、[エージェントの作業フロー](../../rules/subagents.md) 第 4 節、skill `sessions` の「マージの後」、skill `local-dev` の「手元の hook の設定」の、作業ツリーのセッションが読むものの記述が、DC-276-4 の表と食い違わない。重なる記述は表を指す形にする。
- **DC-276-8** skill `review` の docs-review.md の照合の項目に、「spec の第 1 節の環境の前提が、文書の記述によるか、動かして確認したものかを書き分けているか」がある。

### DS-276-3 高の pull request のマージの許可を求めるときの書き添えを決める（D / P2）

- **DC-276-9** [開発の進め方](../../rules/workflow.md) 第 5.7 節が、利用者の許可が必要なマージの許可を求めるときに、許可の後に hook の確認の画面が出ることを書き添える、と書いている。
- **DC-276-10** 同じ箇所が、利用者が遠隔の操作のときは、許可の質問と選択肢を返答の文章に書く（確認の画面と「次の一歩」の箱だけに頼らない）、と書いている。
- **DC-276-11** skill `sessions` のツールの注が、確認の画面を出す hook（agent-guard）と、遠隔の操作では確認の画面が見えないことがあることを書いている。

### DS-276-4 同じ種類の指摘が続くときに前提を変える規則と、判定の spec の書き方を加える（D / P2）

- **DC-276-12** skill `review` の convergence.md に、「同じ種類の指摘（同じ判定の別の書き方）が 2 回続いたら、修正の前提を、禁止の一覧から許可の一覧へ、または対象の外（既知の制限）へ変える案を出す」行がある。
- **DC-276-13** [開発の進め方](../../rules/workflow.md) 第 1.4 節に、入力の形を判定する script（hook、CI の検査）を作る spec の書き方として、次の 2 つがある。
  - 入力の形の判定は、許可する形の一覧で書く。
  - 判定が護りか境界かを、DC で先に決める。
- **DC-276-14** skill `review` の prompts.md の指示のひな形に、護りの spec では、意図して作った回避の形を高にしないことがある。

## 4. 守る制約

- **DN-276-1** 振る舞い、API、データベース、AC、script を変えない。変えるのは、文書と skill だけである。
- **DN-276-2** 確認のために、メインの作業ツリーの `.claude/`（設定、定義、skill）と `/.local/` を変えない。確認は、本 spec の作業ツリーか、スクラッチパッドに作った確認用の Git のリポジトリで行う。理由：メインの作業ツリーは issue 担当と他のセッションが使うため。
- **DN-276-3** 確認のための一時の設定・定義・skill は、確認の後に消し、commit しない。
- **DN-276-4** `scripts/ci/check-all.sh` と CI が通る。

## 5. Non-goals

| 項目 | 理由 |
|------|------|
| 判定器（agent-guard、backslash-guard、ja-text、zh-mixing）の判定を変える | 本 spec は避け方を書くだけで、振る舞いを変えない（DN-276-1） |
| 既存の判定の script を許可の一覧に書き直す | DC-276-13 は今後の spec の書き方。既存の script を変えるなら別の issue にする |
| Claude Code の文書の記述の誤りを報告する | 本 spec の範囲の外 |
| plan の型のファイルを作る | 型のファイルはなく、規則は開発の進め方 第 1.4 節に置く（決めたこと 3） |
