# Spec 454：文書を書く skill と校閲の手順を調整する

種類：整理　規模：M　ステータス：草案

## 背景と目的

#406〜#418 の修正では、文書の書き方の試み（観測の結果を書かない、追記でなく書き直す など）を、担当のセッションを起動する指示に書いて続けた。規則と skill には入れていないので、指示に書き忘れると同じ問題が再発する。利用者がレビューで指摘した問題（pull request #428、#431、#432、#434）の多くは、文書のレビューと校閲を通過していた。原因は次の 3 つである。

- 各フォルダーの `template.md` の「置くもの」「置かないもの」を、skill `docs`、文書のレビューの指示（`docs-review.md`）、校閲のどれも指さない。
- 文書のレビューは差分の追加行を見るので、変えた後の節の全体の形を見ない。
- 実装の後の `docs/02-設計/`・`docs/03-機能仕様/` の更新を「数行」と見なしてセッションが書き、実装の詳細や確認した結果が入る（#409 は 40 行前後、#410 は 20 行前後）。

日本語の規則は安定したので、差分の量によらず校閲の 2 役（検出役と確認役）を呼ぶ今の形は費用がかかる（利用者の判断、2026-11-09）。書き方の規則、skill、文書のレビューの指示、校閲の級、文書の形の検査を調整する。消費者・運営者に見える振る舞いとコードは変えない。追跡の issue は #454。

## スコープ

| 含める | 含めない |
|--------|----------|
| 書き方の規則（`writing.md`、`doc-structure.md`、`docs/02-設計/template.md`、`docs/03-機能仕様/template.md`） | push の時点の変更と、コミットメッセージを書き換える script（#455） |
| skill `docs` の進め方 | warning が出る今の図・表の修正 |
| 文書のレビューの指示のひな形（skill `review` の `docs-review.md`） | 新しい校閲の手順を、この spec の中で使うこと（この spec は今の手順で校閲する） |
| 校閲の級と、単独の校閲役の定義、評価の一覧による採点 | 追記かどうかを機械で判定すること |
| 文書の形の検査（warning）の script | |
| `docs/02-設計/payment.md` に残る観測の語の修正 | |

決定：

1. 値の正本の指し方：設計と機能仕様には、正本の値（件数、時間、上限など）を写さない。業務の値は、機能仕様の「今有効な AC」の節を指す（AC の番号は書かない）。設定と実装の値は、設定のキーやクラスを、表の識別子の列かコードブロックで示す。
2. 書き手のサブエージェントを使う条件：1 つの文書で追加が 5 行以上（`git diff --numstat`）のとき、または節・段落を加える・組み替えるとき。実装の後の `docs/02-設計/`・`docs/03-機能仕様/` の更新も同じ条件にする。この 5 行は、校閲の 1 級と 2 級を分ける 20 行とは別の値である。2 つを並べて書き、混同しないようにする。
3. 校閲の級：`docs-review.md` に次の表を置き、セッションが表で級を決める（機械の検査にはしない）。
   - 1 級：利用者が確認する前の spec・plan・tasks の全文と、`docs/`・skill・AGENTS.md の差分で追加が 20 行以上のもの。校閲する役は検出役と確認役（今のまま）。
   - 2 級：`docs/`・skill の 20 行未満の差分、コードのコメントとテスト名の追加行、pull request と issue の本文、コミットメッセージ。校閲する役は新しい単独の校閲役（汎用）で、明らかな問題だけを理由を付けて挙げる。
   - 3 級：tasks の結果、レビューの記録、issue の開始と完了のコメント。校閲する役は単独の校閲役（軽量）。
   - 1 回に渡すものに級が混ざるときは、番号が最も小さい級で 1 回だけ呼ぶ。
   - 修正の後の再校閲は、1 級の規則の文書の本文を変えたときだけ行う。
   - 20 行は試行中の値で、効果を見て変える。
4. 単独の校閲役：定義を新しく作る（名前は実装で決める）。検出役の定義は「多めに挙げる」ので流用しない。使い始める前に、評価の一覧（`.claude/skills/review/evals/ja-proofread.md`）で汎用と軽量を、一覧の規則どおり各 2 回採点し、採用の基準で採否を決める。結果は `docs/07-記録/subagents-results.md` の「校閲の評価の結果」に書く。採用の基準に届かなかったモデルの級（汎用なら 2 級、軽量なら 3 級）は、今の 2 役のままにし、`docs-review.md` の級の表にその旨を書いて、issue 担当のセッションに知らせる。級の表は、採否によらず置く。
5. コミットメッセージを校閲する時点：最初の push の前に、push していない全ての commit のメッセージを 1 回で渡す。pull request の後に足した commit も、push の前にまとめて渡す。
6. 文書のレビューのひな形：対象の文書の種類に対応する `template.md` のパスを渡す。観点に、置き場所（`template.md` の「置くもの」「置かないもの」）と、変えた後の節の全体（最初から書いたらこの形になるか）の 2 つを加える。
7. Mermaid の図の描画を GitHub で確認する手順は、skill `docs` の進め方の確認の手順に置く（blob を head の SHA で開き、図の右上の展開ボタンで全体を見る）。
8. 文書の形の検査は、新しい script（`scripts/ci/doc-shape.mjs`）にまとめる。warning だけを出し、終了コードは 0 で、CI を止めない。`check-all.sh` から実行し、`docs/06-手順書/ci-checks.md` に節を 1 つ加える。`ja-text.mjs` は語の検査で、文書の種類ごとの対象と、表・図の構造を扱わないため、別の script にする。検査するものは次の 4 つ。
   - 表のセルが 300 バイトを超える。
   - `docs/02-設計/`・`docs/03-機能仕様/` に観測の語（「sandbox で確認」など）がある。
   - `docs/03-機能仕様/` に Stripe の語（`PaymentIntent` など）がある。
   - Mermaid の sequenceDiagram で、参加者が 6 以上、自分への矢印のラベルが 21 字以上、他の矢印のラベルが 26 字以上。今の図に当てはめると、参加者は 1 図、自分への矢印は約 9 図、他の矢印は 3 図に当たる。warning の値は、決定 9 の目安（12 字、20 字）より緩くしてある。当たる図はどれも目安を超えており、今は直さない。

   この検査は文の形から推定するので、検出すべき例と検出してはいけない例の表を、最初の `[テスト]` の前に作る（例の内容は着手のときに決める）。表を spec の文脈を持たないレビュー役に読ませ、例を追加させる（[文書の構成](../../05-開発規則/doc-structure.md)の「形を判定する検査」）。表はスコープの「検査の例」に置く。
9. 書き方の規則に加えるもの：
   - 書く前に、文書の種類の `template.md` を読む（skill `docs`）。
   - 追記でなく書き直す。変えた後の節の全体を読み、最初から書いたらこの形になるかを見る（skill `docs`、`writing.md`）。
   - 設計と機能仕様に、観測の結果、決定の理由、正本から写した値を書かない（各 `template.md` の「置かないもの」）。
   - 箇条書きの途中に表を挟まない。表は箇条書きの後の注に置く（`writing.md` の「表と注」）。
   - AC に見た目の細部（px など）を書かない。画面の見た目は、後でデザイン案に置き換える（利用者の判断、#449。[文書の構成](../../05-開発規則/doc-structure.md)の「spec と plan の書き方」）。
   - Mermaid の図は、字数を削るのでなく、広い図は分ける、参加者を減らす、細部を図の下の文に移す。ラベルの字数の目安は、自分への矢印で 12 字、他で 20 字（`docs/02-設計/template.md` の処理の流れの節）。
   - pull request の本文に、文書の追加と削除の行数を書く（skill `docs`）。

### 検査の例

`doc-shape.mjs` のテストは、次の表の全ての例を確認する。対象は、Git が管理する Markdown のうち、`docs/08-spec/archive/` と `.claude/skills/review/evals/` を除いたもの。判定の決まりは、表の下の箇条に書く。

| 種類 | 例 | 判定 |
|------|----|------|
| 表のセル | 301 バイトのセル | 検出する |
| 表のセル | 全角 101 字（303 バイト）のセル | 検出する |
| 表のセル | 箇条書きの中に字下げした表の、301 バイトのセル | 検出する |
| 表のセル | 300 バイトのセル。全角 100 字のセル | 検出しない |
| 表のセル | 前後の空白を含めると 301 バイトで、中身は 299 バイトのセル | 検出しない |
| 表のセル | コードブロック（` ``` `、4 個以上のバッククォート、`~~~`）の中の表の行 | 検出しない |
| 表のセル | 区切りの行。`\|` で書いた縦線 | 検出しない |
| 表のセル | `<!-- generated:… -->` の組の中の表 | 検出しない |
| 観測の語 | 設計の「（売上確定済みは sandbox で確認した）」「sandbox で確認した応答」 | 検出する |
| 観測の語 | 設計の「sandbox で動かして確認した」 | 検出する |
| 観測の語 | 機能仕様の「実測では 3 秒かかった」「試したところ、409 が返った」 | 検出する |
| 観測の語 | 機能仕様の「検証したところ」「確認したところ、」「計測では」「動かしたところ」 | 検出する |
| 観測の語 | 「消費者が確認の画面で確認した注文」「確認していない注文」 | 検出しない |
| 観測の語 | 「署名を確認し、確認できないものは処理しない」 | 検出しない |
| 観測の語 | 「Stripe の sandbox で動かす設定」「Stripe の sandbox の設定ファイルが入らない」 | 検出しない |
| 観測の語 | 図の `Note over U: 確認の画面へ` | 検出しない |
| 観測の語 | 設計と機能仕様の外の「sandbox で確認した」 | 検出しない |
| 観測の語 | `template.md` の「置かないもの」の見本 | 検出しない |
| Stripe の語 | 機能仕様の `PaymentIntent`、`Checkout Session`、`capture_before` | 検出する |
| Stripe の語 | 機能仕様の `payment_intent`、`payment_intent_unexpected_state` | 検出する |
| Stripe の語 | 機能仕様の `checkout.session.completed`、`checkout.session.expired` | 検出する |
| Stripe の語 | 機能仕様の `Refund`、「Refunds API」 | 検出する |
| Stripe の語 | 機能仕様の「Stripe」「Stripe Checkout」（サービスと機能の名前） | 検出しない |
| Stripe の語 | 機能仕様の `RefundRequested`、`PaymentGateway`、`PaymentPage`（プロジェクトの識別子） | 検出しない |
| Stripe の語 | 機能仕様の小文字の `refund` | 検出しない |
| Stripe の語 | 機能仕様のリンクの先のパスにある語 | 検出しない |
| Stripe の語 | `template.md` の見本。設計の `PaymentIntent` | 検出しない |
| Mermaid の参加者 | `participant ID as 名前`、`actor`、`create participant` の宣言が合わせて 6 の図 | 検出する |
| Mermaid の参加者 | 宣言 5 と、矢印にだけ出る参加者 1 の図 | 検出する |
| Mermaid の参加者 | 参加者が 5 の図。同じ ID を 2 回宣言して 5 の図 | 検出しない |
| Mermaid の参加者 | `Note over` にだけ出る ID を数えると 6 になる図 | 検出しない |
| Mermaid の参加者 | 参加者が 3 の図を 2 つ置いた文書 | 検出しない |
| Mermaid の参加者 | ノードが 6 以上の flowchart。`text` の囲みの中の sequenceDiagram | 検出しない |
| 自分への矢印 | ラベルが 21 字（全角の記号を 1 字と数える） | 検出する |
| 自分への矢印 | 活性化の印の付いた `P->>+P:` で 21 字 | 検出する |
| 自分への矢印 | ラベルが 20 字 | 検出しない |
| 自分への矢印 | `<br>`・`<br/>`・`<br />` で分けた各行が 20 字以下で、全体は 21 字以上 | 検出しない |
| 自分への矢印 | ID の違う矢印で 21 字 | 検出しない |
| 他の矢印 | ラベルが 26 字（矢印は `->`、`-->`、`->>`、`-->>`、`-x`、`--x`、`-)`、`--)`、`<<->>`、`<<-->>`） | 検出する |
| 他の矢印 | `+`・`-` の印が付いた矢印で 26 字 | 検出する |
| 他の矢印 | ラベルが 25 字 | 検出しない |
| 他の矢印 | `Note over`・`Note right of`・`Note left of` の文 | 検出しない |
| 他の矢印 | `alt`・`else`・`loop`・`opt` の見出し | 検出しない |
| 他の矢印 | ラベルが空の矢印（エラーにもしない） | 検出しない |

- 表のセルは、前後の空白を除いた中身を UTF-8 のバイトで数える。
- ラベルは、矢印に続く最初の `:` から行末までを、前後の空白を除いてコードポイントで数える。`<br>` の 3 つの書き方で分けた各行の最大で判定する。
- 参加者は図ごとに、宣言と矢印の両端の ID を重複なく数える。
- 改行（CRLF と LF）と BOM で、判定の結果は変わらない。
- 1 行が 2 つの種類に当たるときは、種類ごとに 1 件ずつ warning を出力する。

## 目的と完了条件

### DS-454-1 文書を書くセッションが、置き場所と書き方の規則を、起動の指示によらず規則と skill から読める（D / P1）

- **DC-454-1** skill `docs` の進め方に、書く前に文書の種類の `template.md` を読む手順がある。
- **DC-454-2** skill `docs` と `writing.md` に、変えた後の節の全体を読み、書き直す規則がある。
- **DC-454-3** `docs/02-設計/template.md` と `docs/03-機能仕様/template.md` の置かないものの節に、観測の結果、決定の理由、正本から写した値があり、`writing.md` に値の正本の指し方がある。
- **DC-454-4** `writing.md` と skill `docs` に、書き手を使う条件（追加 5 行以上、または節・段落を加える・組み替える）がある。
- **DC-454-5** `writing.md` に、箇条書きの途中に表を挟まない規則がある。
- **DC-454-6** `doc-structure.md` に、AC に見た目の細部を書かない規則がある。
- **DC-454-7** `docs/02-設計/template.md` に、Mermaid の図を分ける方法と、ラベルの字数の目安がある。
- **DC-454-8** skill `docs` に、図の描画を GitHub で確認する手順と、pull request の本文に文書の追加と削除の行数を書く手順がある。

### DS-454-2 文書のレビューが、置き場所と、変えた後の節の全体を見る（D / P1）

- **DC-454-9** `docs-review.md` の文書のレビューのひな形に、`template.md` のパスと、置き場所の観点と、節の全体の観点がある。

### DS-454-3 校閲の役を、対象の級で選べる（D / P1）

- **DC-454-10** `docs-review.md` に、級の表と、級が混ざるとき・再校閲・20 行が試行中の値であることの規則がある。
- **DC-454-11** コミットメッセージを校閲する時点が、最初の push の前に push していない全ての commit を 1 回で渡す形になっている。
- **DC-454-12** 単独の校閲役の定義があり、`docs-review.md` と `subagents.md` の校閲役の行が、その定義を指す。
- **DC-454-13** 評価の一覧で汎用と軽量を各 2 回採点した結果が、`subagents-results.md` の「校閲の評価の結果」にある。

### DS-454-4 文書の形の検査が warning を出力する（D / P1）

- **DC-454-14** `doc-shape.mjs` が、決定 8 の 4 種の warning を出し、終了コードが 0 である。
- **DC-454-15** `doc-shape.mjs` のテストが、「検査の例」の表の全ての例を確認する。
- **DC-454-16** `check-all.sh` が `doc-shape.mjs` を実行し、`ci-checks.md` に節がある。
- **DC-454-17** 今の文書に当てはめた warning の件数を、種類ごとに tasks の結果に書いている。誤検出（規則に反しない箇所への warning）は 0 にするか、残すものに理由を付けている。

### DS-454-5 設計の文書から観測の語を除く（D / P2）

- **DC-454-18** `docs/02-設計/payment.md` に、観測の語の warning がない。
