# Spec 555：集約の不変条件と同一性の判定を整える

種類：整理　規模：L　ステータス：確定

## 背景と目的

追跡の issue は #555（#544 の一部）で、sub-issue は #475 と #516。#475 は、不変条件を検査する場所がそろっていない問題である。ファクトリーメソッドだけで検査する型は、公開のコンストラクターで作ると検査を通らない。DB からの復元で検査しない集約と値があり、不変条件に違反する行を読み込みで検出できない。条件を検査していない型もある。#516 は、同一性の判定の問題である。集約と集約の中の entity が `equals` と `hashCode` を上書きしておらず、同じ識別子の集約を 2 回読むと別のものとして扱われる（class は参照で、record は全ての項目で比べる）。規則（バックエンドの書き方の「entity と集約の同一性」。#538 で決めた）に合わせる。消費者・運営者に見える振る舞いも、正しい値に対する振る舞いも変えない。

## スコープ

| 含める | 含めない |
|--------|----------|
| 不変条件の置き場所の規則を、バックエンドの書き方の文書に書く | レベル B のモジュールの、まだ値を検査していない型への検査の追加（#475 の対象外） |
| #475 の対象の型の検査を、コンストラクターに移す・加える（「変える範囲」の表） | 業務の規則の追加・変更、API の契約と DB の構造の変更 |
| 復元で不変条件の違反を検出し、復元のエラーにする | 集約の操作の戻り値と保存の形（#493 で扱う） |
| 対象の entity と集約の `equals` と `hashCode` を、識別子で比べる形にする | |
| 参照の同一性か、record の全項目の等価に頼る所を調べ、対応する | |
| テストで entity と集約を等価で比べない規則（バックエンドのテストの書き方の文書）と、その検査 | |

## 目的と完了条件

### DS-555-1 不変条件を、作るときと復元するときに同じ所で検査する（D / P1）

- **DC-555-1** 不変条件の置き場所の規則が、バックエンドの書き方の文書にある。規則は次の 3 つである。
  - 値オブジェクト・entity・集約ルートの不変条件は、作るときと復元するときに共通のコンストラクターで検査する。
  - ファクトリーメソッドに残すのは、コンストラクターを呼ぶ前の前処理（正規化、計算、解析）と、作り方によって違う規則だけにする。例：在庫の調整の「運営者は注文に由来する理由を選べない」「理由が『その他』ならメモが必須」は、運営者の調整だけの規則なので、ファクトリーメソッドに残す。
  - 復元で不変条件に違反したときは、復元のエラーにする。例外のメッセージとログに DB の値を含めない。
- **DC-555-2** 対象の型（「変える範囲」の表）は、コンストラクターを直接呼んでも、条件に違反する値のインスタンスを作れない。
- **DC-555-3** 対象の型のファクトリーメソッドには、前処理と、作り方によって違う規則だけが残っている。
- **DC-555-4** 対象の型を DB から復元するとき、条件に違反する行を読むと復元のエラーになり、例外のメッセージとログに DB の値が出ない。
- **DC-555-5** 加えた条件ごとに、違反を拒むことと境界の値を受け付けることを、コンストラクターを直接呼ぶ単体テストで確認している。
- **DC-555-6** ローカルの seed と E2E のデータに、条件に違反する行がない。

### DS-555-2 entity と集約を、識別子で比べる（D / P1）

- **DC-555-7** 対象の entity と集約（jMolecules の注釈の付いた 10 個と、注釈を付けるレベル B の 4 個）の `equals` と `hashCode` が、識別子だけで比べる。
- **DC-555-8** 参照の同一性か、record の全項目の等価に頼る所の一覧と、それぞれへの対応（振る舞いが同じか、意図して変えたか）が、pull request に書いてある。
- **DC-555-9** テストで entity と集約を等価（`isEqualTo`、`containsExactly` など）で比べない規則が、バックエンドのテストの書き方の文書にある。値を比べるときは、項目ごとか `usingRecursiveComparison` で比べる。
- **DC-555-10** DC-555-9 の規則に反するテストを、自動の検査が見つける（検査の方法は plan で決める）。

### DS-555-3 振る舞いを変えず、既存のテストと CI の検査が通る（D / P1）

- **DC-555-11** `./gradlew check` が通る。
- **DC-555-12** ローカルの seed で起動して、店舗画面と管理画面が開ける。

### 検査を変える型（DC-555-2 の対象）

| モジュール | 業務の名前 | 型 | 今 | 変えること |
|------------|------------|----|----|------------|
| order | 配送先 | `ShippingAddress` | ファクトリーメソッドだけで検査と正規化をする。復元はコンストラクターを直接呼び、検査を通らない | 検査と、郵便番号・電話番号のハイフンを除く正規化を、コンストラクターに移す |
| inventory | 在庫の調整 | `StockAdjustment` | ファクトリーメソッドで検査する。注文 ID と注文番号が両方あるか両方ないかは検査しない | 増減が 0 でないこと、メモの長さ、注文 ID と注文番号の有無の一致を、コンストラクターで検査する ※1 |
| tax | 税率の一覧 | `TaxRates` | 期間の連続を、税率の置き換えのときだけ検査する | 期間の連続を、コンストラクターで検査する（復元でも有効になる） |
| shipping | 追跡番号 | `TrackingNumber` | ファクトリーメソッドだけで検査する。復元は検査を通らない | 検査をコンストラクターに移す |
| reporting | 集計の期間 | `ReportPeriod` | ファクトリーメソッドだけで検査する。永続化しない | 検査をコンストラクターに移す |
| order | 注文の明細 | `OrderLine` | 検査なし | 数量と行番号が 1 以上、小計が単価（税込）と数量の積 |
| order | 金額 | `Amounts` | 検査なし | 合計が商品の合計と送料の和 |
| order | 見積もりの品目 | `QuoteItem` | 検査なし | 数量が 1 以上 |
| order | 取消の申請 | `CancellationRequest` | 検査なし | 未決なら決定の日時と決定者がない、決定済みならある |
| order | 購入者の属性 | `BuyerProfile` | 年齢の計算だけ | 年齢が 0〜120（年齢がないときは対象外） |
| payment | 承認の期間 | `AuthorizationTerm` | 検査なし。設定から作る | 有効期間が正、警告までの時間が有効期間より短い |
| catalog | バリアント、商品の画像 | `Variant`、`ProductImage` | 検査なし | 表示順が 0 以上 |
| order | 注文（集約ルート） | `Order` | メールアドレスの検査が、注文の作成だけにある。状態と取消の情報の整合は検査しない | メールアドレスの検査をコンストラクターに移す。状態と取消の情報（取消の申請、取消）の整合を検査する |
| payment | 支払（集約ルート） | `Payment` | 状態と項目の整合を検査しない | 状態と、状態ごとに必要な項目（承認済みなら承認の参照番号と承認の日時など）の整合を検査する |
| order | 注文手続き（record の集約ルート） | `Checkout` | 検査なし | 引当の期限が作成の日時より後 |
| catalog | 商品（集約ルート） | `Product` | 名前・説明・軸はコンストラクターで検査する。他の 4 つの条件は、状態を変えるメソッドでだけ検査する | 4 つの条件をコンストラクターで検査する。状態を変えるメソッドの検査は、操作の前の判定として残す |

※1：運営者の調整だけの規則は、ファクトリーメソッドに残す。在庫の調整は復元しない（読み取りは別の型）。

### 復元の経路の調査の結果（DC-555-4 の対象）

次の型は、復元の補助（例外を復元のエラーに変える）を通さずに復元している。違反を復元のエラーにするため、この補助を通して復元する。

| モジュール | 型 |
|------------|----|
| order | `ShippingAddress`、`OrderLine`、`Amounts`、`CancellationRequest`、`BuyerProfile`、`Order`（一部の項目だけ個別に補助を通している）、`Checkout` |
| tax | `TaxRate` |
| catalog | `Variant`、`ProductImage` |
| shipping | `TrackingNumber`、出荷 |
| payment | `Payment`（全体） |

既存の、復元の失敗のテスト（列挙にない値などで、例外の出力に DB の値が出ないことを確認する）は 9 つある。不変条件の違反を復元のエラーとして確認するテストはない。

### 同一性の判定の調査の結果（DS-555-2 の対象）

- jMolecules の注釈で entity・集約を示すクラスは 10 個ある。catalog の `Category`・`Product`・`ProductImage`・`Variant`、inventory の `StockAdjustment`、order の `Checkout`・`Order`、payment の `Payment`、tax の `TaxCategory`・`TaxRate`。
- 注釈のない entity は 4 個あり、対象にして注釈を付ける。レベル B の cart の `Cart`、shipping の `Shipment`（どちらも class で識別子を持つ）、media の `Asset`、member の `Member`（どちらも識別子を持つ record）。
- 本番のコードには、参照の同一性に頼る所がない。集約・entity を Set・Map のキー、`remove`・`contains`、`==` で使う所はない。
- record の全項目の等価に頼るテストは、6 ファイル、9 件程度ある。対象は次の 6 つの型である：商品の画像、バリアント、税率、注文手続き、画像の資産、支払のスナップショット。
- これらのテストは、識別子で比べる形に変えると確認が弱くなる。項目ごとか `usingRecursiveComparison` で比べる形に書き換える。
- class の集約（商品、注文など）をそのまま `isEqualTo` で比べるテストは、見つかっていない。

## 非機能要件

- **DN-555-1** 正しい値に対する振る舞い（API の応答、画面、イベント）を変えない。今、作るメソッドで返している業務のエラー（エラーコード）は、検査をコンストラクターに移しても同じエラーを返す。
- **DN-555-2** API の契約、DB の構造、AC を変えない。
- **DN-555-3** アーカイブした spec を変えない。
- **DN-555-4** 例外のメッセージとログに、DB の値と個人の情報を含めない。
