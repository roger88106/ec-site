## バリアントの販売停止（AC-28）

- 完了条件：AC-28 のテストが通り、管理画面で販売停止・解除ができ、店舗画面で販売停止のバリアントが選べない状態で出る。
- 参照：spec AC-28、[catalog.md](../../../modules/catalog.md)「状態の切り替え」、`admin.yaml`（suspendVariant、resumeVariant）
- 決めたこと：販売終了の商品のバリアントも、販売停止・解除できる（販売終了の商品も基本情報を編集できるのと揃える。C 側には出ないので影響はない）。イベントは登録しない（catalog.md のイベントの表にないため）。

- [x] **T1001** [テスト] 商品（集約）の単体テスト：バリアントの販売停止・解除（AC-28）、同じ状態への切り替えは何もしない（冪等）、存在しないバリアントは 404。
- [x] **T1002** 商品（集約）、アプリケーションサービス、Controller（suspendVariant、resumeVariant）を実装する。T1001 を通し、API の統合テスト（停止・解除、冪等、404、店舗 API の詳細で販売停止のバリアントが salesSuspended になる）を書く。catalog.md の「後の段階で実装する endpoint」から販売停止・解除を外す。
- [x] **T1003** 管理画面：バリアントの行に「販売停止」「販売を再開」のボタンを置く。結合テスト（押すと API を呼び、表示が「販売停止」に変わる）を書く。
- [x] **T1004** E2E：管理画面でバリアントを販売停止にすると、店舗画面の詳細で、そのバリアントの値が選べない状態になる（AC-28、62）。

## 公開日時の予約（US-6）

- 完了条件：AC-34〜36 のテストが通り、AC-33 の予約の取り消しのテストが通り、管理画面で公開期間を設定でき、店舗画面がその時刻で切り替わる。
- 参照：spec US-6、AC-33、[catalog.md](../../../modules/catalog.md)「初回表示日時」、`admin.yaml`（setPublicationPeriod）
- 決めたこと：公開期間は、どの状態の商品にも設定できる。初回表示日時を計算し直すのは、公開中に変えたときだけ（catalog.md のとおり）。イベントは登録しない。

- [x] **T1005** [テスト] 商品（集約）の単体テスト。
  - 公開開始・終了日時を設定できる。どちらも空でよい（AC-34）。終了は開始より後（AC-36）
  - 公開中に期間を変えると、初回表示日時を「公開した時刻と開始日時の遅いほう」で計算し直す。未来の間だけで、過去になって確定した値は変わらない。開始が終了以降なら空にする
  - 非公開の商品の期間を変えても、初回表示日時は空のまま
  - 開始日時の前に非公開にした（予約を取り消した）商品は、表示されていないものとして削除できる（AC-33）
  - 期間の外では C 側に表示されない（AC-35。`isVisibleAt`）
- [x] **T1006** 商品（集約）を実装する。T1005 を通す。
- [x] **T1007** アプリケーションサービスと Controller（setPublicationPeriod）を実装する。API の統合テスト（設定、AC-36 の 400、バージョン不一致の 409、時計を進めると店舗 API の一覧・詳細が開始日時で出て終了日時で消える（AC-35）、新着順が開始日時で並ぶ（AC-54））を書く。catalog.md の「後の段階で実装する endpoint」の節を消す。
- [x] **T1008** 管理画面：状態のカードに公開期間の入力（開始・終了。日本時間）を置く。バージョン付きのフォーム（管理画面の構成 第 5 節）にする。結合テスト（保存、AC-36 のエラーの表示、入力中の 409 と再読み込み）を書く。
- [x] **T1009** E2E：開始日時を数秒後にして公開すると、開始前は店舗画面の詳細が「見つかりません」で、開始後に表示される（AC-35）。
- [x] **T1010** P2 の 2 項目の完了確認：AC-28、33〜36 のテストがあること、catalog.md・管理画面の構成が実装と合っていること。README の進捗を更新する。

## 商品画像（US-7）

- 完了条件：AC-37〜40 のテストが通り、管理画面で画像を登録・並び替え・削除し、バリアントに画像を指定でき、店舗画面に出る。
- 参照：spec US-7、[plan 001](../plan.md) 第 7 節、[catalog.md](../../../modules/catalog.md)「商品画像」
- 画像のファイルは、US-13 まではアップロードされた形式のまま配信する（メタデータも残る。spec US-7 の注記）。

### 基盤

- [x] **T1011** compose に SeaweedFS を足し、初期化で受付・配信のバケット、CORS（管理画面のオリジンからの PUT）、配信のバケットの公開、受付のバケットのライフサイクル規則を作る。local profile の接続設定と、README の起動手順を足す。
- [x] **T1012** `admin.yaml`・`store.yaml` に画像の endpoint とスキーマを足す（plan 第 2 節。受付の要求と応答、画像の登録・並び替え・削除、バリアントの画像の指定、商品の詳細の画像の一覧、バリアントの画像 ID）。実装するまで endpoint は 501 を返す。管理画面の結合テストのデータを新しい型に合わせる。
- [x] **T1013** マイグレーション：商品画像のテーブルと、バリアントの画像 ID。catalog.md のデータモデルにリンクする。
