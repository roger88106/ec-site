# Spec 012：テストの安全網

ステータス：確定

## 1. 背景と目的

spec 013・014 で、振る舞いを変えずにコードを書き方の規則にそろえる。その完了の条件は「既存のテストを変えずに全て通る」で（[MVP の完成までの一覧](../../../mvp.md) 第 2 節）、テストが通ることを「振る舞いが変わっていない」の証拠にする。今のテストには、その証拠にするには次の問題がある。

- 「起きないこと」を、固定の時間（0.5〜1 秒）だけ見て確認するテストがある。遅い環境では、処理の前に見終わって誤って通る。時間で待つことの検査は、この書き方を検出しない。
- E2E の公開の開始のテストは、実時間で 8 秒以内に準備を終える前提で、遅い環境で誤って失敗する。支払いの期限のテストは、実際に 30 秒あまり待つ。
- E2E の一部が、画面の構造（xpath、タグと文字、DOM の id、先頭の要素）で要素を選ぶ。画面の書き方をそろえると、振る舞いが同じでも失敗する。
- AC-90 にテストがない（spec 011 で分かった）。テスト名の規則の一部（全てのテストに名前を付ける）を、機械で確認していない。管理画面のテストの 1 つが、続けて実行するとタイムアウトで失敗することがある。
- テストの補助（注文までの準備、配送先、待機のタイムアウト、E2E の会員の登録など）が、テストごとに重複して書かれている。書き方の統一で API の形を変えると、多くのテストを修正することになる。spec 013・014 ではテストを変えないので、重複は本 spec で解消する。
- 書き方の統一で触る所に、テストが薄い所がある。Stripe の実装と通知のエンドポイント、管理画面のログインのガード、店舗画面のコンポーネントの多く（行のカバレッジ 63%、コンポーネントの多くが 0%）。税込価格の計算は Java と SQL の 2 か所にあり、同じ結果になることを確認していない。
- カバレッジの報告は合計だけで、薄い所が分からない。

本 spec は**整理の spec**（[文書の記号と番号](../../../../rules/notation.md)）。消費者・運営者に見える振る舞いを変えない。

## 4. 目的と完了の条件

### DS-29 テストが時間で待たず、壁の時計の速さに頼らない（D / P1）

- **DC-97** 「起きないこと」（再送しない、2 通目のメールを送らない など）を確認するテストは、処理が終わったことを条件で待ってから、起きた数を確認する。条件で待てない所だけ、固定の時間で見る共通の補助を使い、使う所に理由を書く。
- **DC-98** 時間で待つことの検査が、固定の時間を見る書き方（決まった時間の間、条件が変わらないことを見る、決まった時間だけ待ってからレビューする）も検出する。DC-97 の共通の補助は除く。
- **DC-99** E2E の公開の開始のテストは、準備にかかる時間によらず、公開の前と後を確認する。支払いの期限のテストの待ち時間が、今の半分以下になる。
- **DC-100** 条件で待つときのタイムアウトは、バックエンドのテストと E2E でそれぞれ 1 か所に定める。長く待つ必要がある所だけ、理由を書いて別の値を使う。

### DS-30 E2E が、画面の要素を利用者に見える役割と名前で選ぶ（D / P1）

- **DC-101** E2E は、店舗画面・管理画面の要素を、xpath、タグの名前と文字の組み合わせ、DOM の id や属性、先頭の要素（並びの 1 つ目）で選ばない。役割と名前、ラベル、見える文字で選ぶ（[テストの書き方](../../../../rules/test-writing.md) 第 4.1 節）。例外：詳細の項目の値（`dd`）は、Biome の検査が名前の属性を認めないので、項目名の次の値を選ぶ書き方を E2E の補助 1 か所にまとめる（[plan](plan.md) 第 5.1 節）。
- **DC-102** DC-101 のために画面に追加するのは、支援技術向けの属性（名前、役割、ラベルとの関連）だけにする。見た目は変わらず、画面のテストは変えずに通る。
- **DC-103** IdP の画面（自分たちで作っていない画面）の要素の選び方は、E2E の補助の 1 か所にまとめる。

### DS-31 全ての AC にテストがあり、テスト名の規則を機械で確認する（D / P1）

- **DC-104** AC-90 の「注文番号を振る」に、テストがある。「カートを空にする」が spec 007 の AC-147 で置き換わったことが、spec 002 の AC-90 に書いてある。AC とテストの対応の検査の除外の一覧に、AC-90 がない。
- **DC-105** バックエンドの全てのテストに表示の名前があることを、検査で確認する。
- **DC-106** IdP の設定ファイルの検査だけで確認する AC と、その理由が、テストの書き方の文書にある。
- **DC-107** 管理画面の商品の登録のテスト（AC-15）が、店舗画面・管理画面のテストを続けて実行しても、タイムアウトで失敗しない。原因を修正し、既定のタイムアウトを延ばして隠さない。

### DS-32 テストの補助が重ならず、API の形が変わっても修正する所が 1 か所にまとまる（D / P1）

- **DC-108** バックエンドの統合テストで、商品の作成、注文までの準備（カート、注文の手続きの開始、注文）、配送先は、共通の補助で作る。テストに残るのは、そのテストで変える値だけになる。郵便番号の書き方は 1 つにそろえ、別の書き方を確認するテストはそう書く。
- **DC-109** E2E で、会員の登録、カートを空にする、画面を再読み込みして条件を待つ処理は、共通の補助を使う。
- **DC-110** データをコミットする（ロールバックできない）統合テストのクリーンアップの規則が、テストの書き方の文書にあり、該当するテストが従う。

### DS-33 書き方の統一で触る所のテストが、振る舞いの変化を見つけられる（D / P1）

- **DC-111** Stripe の実装の支払いの画面の作成（リクエストの内容）、画面を閉じる、与信の取り消し（取り消し済みを成功とみなす場合を含む）と、通知のエンドポイント（署名の確認の後の受け渡し）にテストがある。外部のサービスに接続しない。
- **DC-112** 支払いの port の共通の振る舞い（同じ要求の繰り返し、完了した後の要求）を、mock と Stripe の実装の両方で同じテストで確認する。mock の支払いの画面にテストがある。
- **DC-113** 管理画面のログインのガード（ログインしていなければ中身を出さずにログインへリダイレクトする、リダイレクトは 1 回、認証の失敗が続いても繰り返さない）にテストがある。AC-132 のテストは、この振る舞いを確認する。
- **DC-114** 店舗画面のコンポーネント、server action、API の呼び出しの補助は、全てテストで 1 行以上通る。対象外はページ（E2E で確認する）と Next.js の入り口のファイルで、一覧を plan に書く。在庫がない商品の表示（AC-56）と価格の表示（AC-55）は、画面のテストでも確認する。
- **DC-115** 管理画面の、ロジックを持つコンポーネントとページは、全てテストで 1 行以上通る（今 0% のログインのガードを含む）。税区分の一覧と登録の画面に、直接のテストがある。
- **DC-116** 税込価格を Java で計算した結果と SQL で計算した結果が、同じ入力（端数の出る値を含む）で同じになることを、テストで確認する。

### DS-34 カバレッジの報告から、テストの薄い所が分かる（D / P2）

- **DC-117** CI のカバレッジの報告に、合計に加えて、行のカバレッジが低い順にパッケージ（バックエンド）・ファイル（画面）を表示する。基準の値で失敗させない。

## 5. 業務ルール

なし（本 spec は業務の規則を変えない）。

## 6. 非機能要件

- **DN-12** 追加する・修正するテストは、今のコードで通り、コードをわざと壊すと失敗する（[MVP の完成までの一覧](../../../mvp.md) 第 2 節の 3）。壊して確認したことを、段階の記録に残す。
- **DN-13** API の応答、画面の見た目、データベースの構造とデータを変えない。画面のコードの変更は DC-102 の属性だけ。テストの設定の値（E2E の支払いの期限の長さなど）は変えてよい。
- **DN-14** CI の全体が 10 分以内のまま終わる（spec 011 の DC-85）。

## 7. Non-goals

| 項目 | 扱う場所 |
|------|----------|
| 新しい振る舞いのテスト | 振る舞いを作る spec（015〜017）が TDD で書く |
| 店舗画面のページ（`app/` の下）の画面のテスト | 行わない。E2E で確認する |
| IdP の振る舞い（アカウントのロック、重複のメールなど）の実機のテスト | 行わない。DC-106 で、設定ファイルの検査で確認することを明記する |
| カバレッジの基準の値で CI を失敗させる | 行わない |
| テストのコードを書き方の規則にそろえること（本 spec で触る所を除く） | 013・014 では触らないので、MVP の後 |
