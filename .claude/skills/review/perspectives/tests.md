# テストの観点

テスト（バックエンド、フロント、E2E）を書く・変えたときに、結果を返す前の自己確認とレビューの両方で読む。規則の文は、表の「規則の正本」で読む。

| 観点 | 見る問い | 過去の見落としの例 | 規則の正本 |
|------|----------|--------------------|------------|
| 層ごとのテストの置き方 | 層ごとに、どのテストで確認するかの決まりどおりに置いたか。置かない層の理由が分かるか。 | application の正常の流れのテストがなく、統合テストに任せた意図がどこにも書かれていなかった | [テストの書き方](../../../../docs/05-開発規則/test-writing.md)の「テストの種類」 |
| 入口ごとの 3 つの結果 | 入口ごとに、正常、エラーコードごとの業務の例外、500 系があるか。本番で投げるエラーコードの全てに、それを起こすテストがあるか。 | 支払画面の期限切れの通知が、application より上のテストで一度も実行されていなかった | [テストの書き方](../../../../docs/05-開発規則/test-writing.md)の「テストの観点」 |
| 境界の両側 | 上限・下限・期間ごとに、「ちょうど」（通る）と「1 つ外」の両方があるか。 | 数量の上限で、ちょうどと 2 つ外だけを確認し、1 つ外がなかった。集計の期間の初日と末日を確認していなかった | [テストの書き方](../../../../docs/05-開発規則/test-writing.md)の「テストの観点」、[CI の検査の追加](../../../../docs/06-手順書/ci-adding-checks.md)の「テストの観点」 |
| 参照するものの変化 | 参照する商品の取り下げ・削除・販売の停止、税率の失効の後の操作を確認しているか。 | 注文の手続きを始めた後に商品が非公開になってから注文する場合が、どの層でも確認されていなかった | [テストの書き方](../../../../docs/05-開発規則/test-writing.md)の「テストの観点」 |
| domain の単体での網羅 | domain は、単体テストだけで C0・C1 を満たすか。複合の条件の各項を単独で変えるテストがあるか。 | 空の注文は domain で確認したが、商品の取り下げは後の層に任せて domain では確認していなかった | [テストの書き方](../../../../docs/05-開発規則/test-writing.md)の「テストの種類」「カバレッジと mutation score の基準」 |
| 状態の遷移 | 全ての状態と全ての操作の表を作り、許す遷移と拒否する遷移の全てにテストがあるか。 | 出荷済みの注文に支払の期限切れが届いたときに、何もしないことが確認されていなかった | [テストの書き方](../../../../docs/05-開発規則/test-writing.md)の「テストの観点」 |
| 拒否のときの副作用 | 業務の例外・500 のときに、DB・イベント・外部の呼び出しが変わらないことを確認しているか。 | 注文を拒否したテストが、エラーコードだけを見て、注文・在庫・引当が変わらないことを見ていなかった | [テストの書き方](../../../../docs/05-開発規則/test-writing.md)の「テストの観点」 |
| 並行と冪等 | 楽観ロックの衝突、二重の送信、再送と順の入れ替わり、ジョブの重複を確認しているか。 | 並行の要求に負けた支払画面を閉じる処理が、一度も実行されていなかった | [テストの書き方](../../../../docs/05-開発規則/test-writing.md)の「テストの観点」 |
| 外部の失敗 | 外部サービスのタイムアウト・5xx・不正な応答・再試行の回数を確認しているか。 | 画像の変換が 200 で空の本文を返す場合と、決済の再試行の回数が確認されていなかった | [テストの書き方](../../../../docs/05-開発規則/test-writing.md)の「テストの観点」 |
| 権限 | 操作ごとに、ログインなし、他の会員、権限の足りない管理者を確認しているか。token の対象（audience）の違いを確認しているか。 | audience のない token と、別の audience の token が確認されていなかった | [テストの書き方](../../../../docs/05-開発規則/test-writing.md)の「テストの観点」 |
| 時刻 | 開始・終了のちょうど、日の境目、期限の直前・直後を確認しているか。 | イベントの再送の間隔と、記録の削除の日数の「ちょうど」がなかった | [テストの書き方](../../../../docs/05-開発規則/test-writing.md)の「テストの観点」 |
| 金額 | 端数、0 円、大きな金額、税・送料の組み合わせを確認しているか。外部の上限を超えないか。 | 注文の総額に上限がなく、決済サービスの 1 回の上限を超えうることに気づいていなかった | [テストの書き方](../../../../docs/05-開発規則/test-writing.md)の「テストの観点」 |
| DB の制約の違反 | 一意・外部キー・CHECK の違反が業務の例外になるか、500 になるか。 | 引当の数量に 0 や負の数を渡すと、CHECK の違反で 500 になった | [テストの書き方](../../../../docs/05-開発規則/test-writing.md)の「テストの観点」、[バックエンドの書き方](../../../../docs/05-開発規則/backend-coding.md)の「DB の制約の違反は業務のエラーに変えるか、重複を吸収する」 |
| 確認の強さ | 状態コードだけ、件数だけ、例外がないことだけで、本番が壊れても通る確認になっていないか。テストの土台のせいで対象が実行されないことはないか。 | 返金のテストが、テストのトランザクションのため返金を一度も呼ばず、何も確認していなかった | [テストの書き方](../../../../docs/05-開発規則/test-writing.md)の「テストの観点」 |
| テストの独立と待ち方 | 自分のデータだけを確認しているか。差し替えた外部サービスの呼び出しの記録を毎回戻しているか。1 回だけ読んだ値で判定せず、条件で待っているか。 | 差し替えた決済サービスの呼び出しの記録を戻し忘れ、他のテストの呼び出しまで数えていた。E2E で 1 回だけ読んだ値で判定していた | [バックエンドのテストの書き方](../../../../docs/05-開発規則/test-writing-backend.md)の「統合テストの土台」、[テストの書き方](../../../../docs/05-開発規則/test-writing.md)の「待ち方」、[フロントのテストの書き方](../../../../docs/05-開発規則/test-writing-frontend.md)の「E2E のステップと別の利用者」 |
| 流れのテスト | 正常の流れと、標準の流れの中で起きる例外が、通しで確認されているか。 | 支払の確定の後の取消の申請、出荷の拒否、承認、返金の流れが、通しで確認されていなかった | [テストの書き方](../../../../docs/05-開発規則/test-writing.md)の「テストの種類」 |
| テストの補助の置き場所 | テストのルートパッケージにテストだけを置き、補助とモックを子のパッケージに置いているか。 | テストのルートパッケージに、テストでない補助が多く並んでいた | [バックエンドのテストの書き方](../../../../docs/05-開発規則/test-writing-backend.md)の「統合テストの土台」「単体テストの補助」 |
| 整理で振る舞いと判定を変えない | 整理の変更が、振る舞い・契約・URL・遷移の先・テストの判定を変えていないか。消した確認が、同じか狭い確認に替わっているか。 | 画面の取得を並行にしたら失敗のときの遷移の先が変わり、URL の書き方を変えたら共有の URL が変わったので、元に戻した | [開発の進め方](../../../../docs/05-開発規則/workflow.md)の「中断して質問する条件」 |
