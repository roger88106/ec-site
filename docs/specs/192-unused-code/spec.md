# Spec 192：使われていないコードを削除し、静的解析の検査を広げる

ステータス：確定

## 1. 背景と目的

MVP 019 の全体レビューで、使われていないコードの指摘（8 件）が残った。spec 18 で Error Prone と NullAway を入れたときに範囲を絞った検査と、バックエンドの書き方に null の基準を補う作業も残っている。spec 155 では、パッケージの移動を伴わない DC と、使われていないコードと範囲の近い DC を、本 spec に移した。どれもバックエンドの `src/main` を変え、削除の対象と静的解析の設定が重なるので、1 つの spec で扱う。

追跡の issue は [#192](https://github.com/roger88106/ec-site/issues/192) で、扱う issue は #85、#148 である。作業ブランチは `192-unused-code` である。規模は L を提案する。理由：注文、地域、商品カタログ、媒体、出荷、支払、共通コード、店舗画面、管理画面にまたがるため。

本 spec は整理の spec である（[文書の記号と番号](../../rules/notation.md)）。

### 1.1 使われていないコードの再調査

#85 の「ほか 4 件」は、MVP 019 のレビュー結果のファイルが残っていない。そこで 2026-10-26 に、今の `develop`（f8f2b29a）を同じ観点で再調査した。観点は、本番から呼ばれずテストか tools だけが使う操作、どこからも使われない型・export・ファイル・依存、使われていない import と並びの乱れた import である。汎用のモデルで 1 回調査し、spec 担当のセッションが、各項目の置き場所と呼び出し元をコードで確認した。

- #85 で名前を挙げた項目は、全て今のコードに残っていた。`cn` は依存そのものは使われていて、使われていないのは管理画面で `cn` を再び export するファイルだった。
- 「ほか 4 件」に当たるものとして、商品の代表画像を返す操作、地域 API の郵便番号検索、税率キャッシュの破棄、ファイル保存設定の複製が見つかった。税率キャッシュの破棄とファイル保存設定の複製は、spec 155 から移した DC-155-27 と同じである。
- spec 155 から移した DC の項目は、全て今のコードに残っていた。例外は、レベル A のモジュール一覧の複製（DC-155-32）である。spec 186 の DC-186-10 が同じ内容を済ませ、一覧は構成検査の補助クラス 1 か所にある。2026-10-26 に、spec 186 のマージ後の `develop` で確認した。そこで本 spec の範囲から外す。
- spec 181 と spec 186 のマージ後の `develop`（821af1a5）で、上の項目が残っていることを確認し直した。
- 使われていない import は `src/main` と統合テストに 1 件ずつ、並びの乱れた import は全体で約 50 ファイルある。

## 4. 目的と完了条件

### DS-192-1 テスト専用の操作をなくす（D / P1）

- **DC-192-1** 次の操作が、本番コードにない。テストは、本番コードが使う操作で確認する（※1）。#85 の項目である。

| 操作 | 今の呼び出し元 |
|------|----------------|
| 注文がキャンセル済みかを返す操作 | 注文の単体テストだけ |
| レポートの集計基準が注文の状態を数えるかを返す操作 | 集計基準の単体テストだけ |
| 商品の代表画像を返す操作 | 商品の単体テストだけ |
| 地域 API の郵便番号検索 | 地域 API の統合テストだけ。店舗 API は、地域モジュールの中から直接引く |

※1：削除する操作の AC のテスト（郵便番号検索の AC-253、AC-254）は、店舗 API のテストで同じ条件を確認しているかを plan で確認し、足りなければ店舗 API のテストに移す。

- **DC-192-2** 郵便番号の CSV を読む処理（対象の郵便番号を絞る処理を含む）は、`src/main` になく、マイグレーションを作る tools の側にある。tools は削除しない。`src/main` から外す理由：本番で動かず、tools とテストだけが使うため。tools を残す理由：DB の再作成はマイグレーションで足りるが、郵便番号のデータを更新するときに、tools でマイグレーションを再生成するため。#85 の項目である。
- **DC-192-3** 次のテスト専用の操作が、本番コードにない。DC-155-27 の項目である。
  - ファイル保存設定の複製 2 つ（アップロード URL の期限を替えるものと、接続先を替えるもの）
  - ファイル保存のクライアントを作る static の操作
  - mock の画面だけが使う、最近の出荷を一覧する問い合わせ。出荷の Repository の port から外し、mock の側に置く。
  - 例外：税率キャッシュを破棄する操作は残す。ただし public にせず、統合テストの補助クラスだけが呼ぶ。キャッシュのクラスの public も外す。理由：テストは共通の時計を使い、多くのテストが同じ時刻に設定するので、時計を進めても有効期間が切れず、操作を本番から消すと本番の振る舞いか規模に影響があるため（利用者の決定、2026-10-26。plan 第 10 節の 1）。
- **DC-192-4** テストのために可視性を広げた本番のクラスがない。例：決済の期限切れジョブの public。他のパッケージのテストが呼ぶ必要があるときは、公開 API か、テストの補助クラスを通す。DC-155-28 の項目である。

### DS-192-2 同じ処理を 1 か所に（D / P1）

- **DC-192-5** 出荷の mock の画面は、通知モジュールの文言のキーを使わない。DC-155-20 の項目である。
- **DC-192-6** 画像変換は、ファイル保存設定の型に依存しない。理由：外部サービスの知識を 1 か所に限るため。DC-155-24 の項目である。
- **DC-192-7** イベント記録の表を読み書きする処理は、本番コードの 1 つのクラスにある。片付けのジョブも、そのクラスを使う。DC-155-30 の項目である。
- **DC-192-8** 認証情報から token を取り出し、なければ未認証のエラーにする処理は、1 か所にある。今は会員、運営者、ログイン中の利用者の情報を返す API の 3 か所にある。DC-155-31 の項目である。

### DS-192-3 フロントの使われていないもの（D / P1）

- **DC-192-9** 店舗画面と管理画面の API 型の別名のうち、どこからも使われないものがない。テストだけが使う別名は、plan で残すか決める。#85 の項目である。
- **DC-192-10** 店舗画面、管理画面、共有パッケージに、`cn` を再び export するだけのファイルがない。`cn` は、shadcn/ui の生成物と同じく `cn` の依存から直接 import する。#85 の項目である。
- **DC-192-11** 店舗画面、管理画面、共有パッケージ、E2E に、使われていない export とファイルがない。定義したファイルの中だけで使うものは、export を外す。
- **DC-192-12** 使われていない export、ファイル、依存を、CI の検査が見つける。openapi-typescript などで生成したコードと shadcn/ui の生成物は、理由を付けて対象外にできる。#85 のコメント（spec 135 第 8 節）の項目である。

### DS-192-4 Java の import（D / P1）

- **DC-192-13** 全てのソースセットの Java のファイルに、使われていない import がない。
- **DC-192-14** 全てのソースセットの Java のファイルの import は、決めた順に並ぶ。順は plan で決め、[バックエンドの書き方](../../rules/backend-coding.md)に書く。
- **DC-192-15** DC-192-13、14 の違反を、CI の検査が見つける。

### DS-192-5 NullAway と規則の検査（D / P1）

- **DC-192-16** NullAway の `AcknowledgeRestrictiveAnnotations` が有効で、`./gradlew check` が通る。目的は、生成した interface の `@Nullable` の引数を、実装側が注釈なしで上書きした箇所を検出することである。#148 の項目である。
- **DC-192-17** 必須でないリクエストのヘッダー・パラメータを受ける引数に `@Nullable` がある。今は、決済と配送業者の通知を受ける 2 つの Controller にある。#148 の項目である。
- **DC-192-18** 全てのソースセットで、`@SuppressWarnings` の直前に理由のコメントがある。今は `unchecked` の 12 か所に理由がない。理由のない `@SuppressWarnings` を、規則の検査が見つける。#148 の項目である。
- **DC-192-19** JSpecify 以外の `Nullable` を含むパッケージのワイルドカード import（`import javax.annotation.*;` など）を、規則の検査が見つける。#148 の項目である。
- **DC-192-20** [バックエンドの書き方](../../rules/backend-coding.md) 第 7 節に、次がある。#148 の項目である。
  - getter を `Optional` で返すか `@Nullable` で返すかの基準
  - `Objects.requireNonNull` のメッセージの書き方と、今のコードがその書き方にそろうこと（今は「〜がある」の形と「〜がない」の形などが混ざる）
  - [テストの実行方法](../../guides/running-tests.md)のコンパイル失敗の読み方から、バックエンドの書き方 第 7.2 節へのリンク

## 6. 非機能要件

- **DN-192-1** 消費者・運営者に見える振る舞いを変えない。
- **DN-192-2** API の契約とデータベースの構造を変えない。地域のマイグレーションを作る tools の出力も変えない。
- **DN-192-3** AC を追加・変更しない。削除する操作の AC のテストは、同じ条件を別の公開の操作で確認する形に移し、テストを弱めない。
- **DN-192-4** 追加した検査は、違反する例で違反を検出できることを確認する。
- **DN-192-5** カバレッジと mutation score が基準を下回らず、`./gradlew check` と `check-all.sh` が通る。

## 9. Open questions

なし。次は利用者が 2026-10-26 に決めた。

1. shadcn/ui の生成物のうち、管理画面で使われていない小部品（約 50）は削除しない。検査の対象外にし、理由を除外の一覧に書く。理由：生成物なので、部品を再取り込みすると削除したものが戻り、差分が増えるため。
2. 規模は L にする。理由：開発の進め方 第 4.2 節の「2 つ以上のモジュールにまたがる」に当たるため。
3. 郵便番号の CSV を読む処理は、tools に移して残す（DC-192-2）。利用者が判断を spec 担当のセッションに任せた。
