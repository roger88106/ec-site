# Spec 104：手元の環境の並行化

ステータス：確定

## 1. 背景と目的

1→10 の段階では、複数のセッションが作業ツリーを分けて並行に開発する（[spec 7](../archive/1to10/7-dev-process/spec.md)）。最初の並行は spec 104 と spec 131 である。

今の手元の環境は 1 つだけである。compose のポート（5432、9411、8333、8081、8180、8181、2525、8025）、バックエンド（8080、運用 9080）、店舗画面（3000）、管理画面（5173）、データベースの名前（ec_site）、画像のバケットが固定されている。そのため、負荷の高い作業（compose の起動、バックエンドの起動、E2E、バックエンドの全テスト）を、同時に 1 つのセッションだけで実行する決まりにしている。他のセッションは待つ。

compose のプロジェクト名とコンテナ名も固定されている。作業ツリーで compose を起動すると、共有のコンテナが、その作業ツリーのファイル（Keycloak の realm の定義、seed の画像など）を指す形で再作成される。

方針は spec 7 の検討で決めた。基盤（PostgreSQL のサーバー、Keycloak、SeaweedFS、imgproxy、Mailpit、Zipkin）は 1 つを共有し、作業ツリーごとにデータベース、画像のバケット、ポートを分ける。マシンは RAM 32 GB、Docker に 16 GB、CPU 16 スレッドである。

追跡の issue は [#104](https://github.com/roger88106/ec-site/issues/104)、作業ブランチは `104-parallel-local-env`、規模は L（利用者が 2026-10-22 に承認）である。

本 spec は整理の spec である（[文書の記号と番号](../../rules/notation.md)）。

## 2. 用語

| 用語 | 意味 |
|------|------|
| 共有の基盤 | compose で動かすミドルウェア（PostgreSQL のサーバー、Keycloak、SeaweedFS、imgproxy、Mailpit、Zipkin）。全ての作業ツリーで 1 つを使う |
| メインの作業ツリー | 作業ツリーのうち、リポジトリを clone したもの。本書で単に「作業ツリー」と書くときは、メインの作業ツリー以外の作業ツリーを指す |
| スロット | 作業ツリーに割り当てる番号。0 はメインの作業ツリー、1〜3 は作業ツリー。番号ごとにデータベース、画像のバケット、ポートが決まる |
| スロットの環境 | 1 つのスロットのデータベース、画像のバケット、バックエンド、店舗画面、管理画面 |

用語集に追加する語と識別子は、plan で決める。

## 4. 目的と完了条件

### DS-104-1 共有の基盤を 1 つ起動し、作業ツリーごとのスロットの環境を同時に動かせる（D / P1）

- **DC-104-1** メインの作業ツリーはスロット 0 で、ポート、データベースの名前、画像のバケットが今のままである。理由：1 つだけで作業するときの手順と、既存の文書・script を変えないため。
- **DC-104-2** 作業ツリーで 1 つのコマンドを実行すると、空いているうちで最小のスロット（1〜3）が割り当てられる。
- **DC-104-3** 割り当てたスロットは作業ツリーの中の Git に入らない場所に記録され、同じ作業ツリーの後の起動と検査がそれを読む。
- **DC-104-4** スロット 1〜3 が全て使われているとき、割り当てのコマンドは空きがないことと、使っている作業ツリーを示して終了する。
- **DC-104-5** 割り当てのとき、そのスロットのデータベースと画像のバケットが新しく作られ、前に同じスロットを使った作業ツリーのデータを引き継がない。理由：ブランチごとにマイグレーションが違うため。
- **DC-104-6** 解除のコマンドがあり、スロットを空け、そのスロットのデータベースと画像のバケットを削除する。作業ツリーを削除する前に使う。
- **DC-104-7** 削除された作業ツリーが持っていたスロットは、割り当てのコマンドが空きとして扱える。解除を忘れたときのためである。
- **DC-104-8** スロットの環境でバックエンドを起動すると、そのスロットのデータベースにマイグレーションと local の seed が適用される。
- **DC-104-9** スロットの画像のバケットには、seed の画像が入っている。
- **DC-104-10** 各スロットのバックエンド（業務ポートと運用ポート）、店舗画面、管理画面のポートは、他のスロット、共有の基盤、E2E のポートと重ならない。
- **DC-104-11** 各スロットの店舗画面と管理画面で、共有の Keycloak によるログインとログアウトができる。
- **DC-104-12** 同じブラウザで 2 つのスロットの店舗画面にログインしても、セッションが混ざらない。
- **DC-104-13** 2 つのスロットのバックエンドと画面を同時に動かし、片方で変えたデータ（注文、商品、画像）が、もう片方で表示されない。
- **DC-104-14** 共有の基盤のコンテナは、メインの作業ツリーのファイルを使う。作業ツリーの script と手順は、共有の基盤を再作成しない。
- **DC-104-15** 共有の基盤が止まっているとき、作業ツリーの script は、メインの作業ツリーで起動するよう示して終了する。
- **DC-104-16** データの再作成の script を作業ツリーで実行すると、そのスロットのデータベース（と画像のバケット）だけを再作成する。IdP の再作成と全ての再作成は、メインの作業ツリーでだけ実行できる。

### DS-104-2 E2E を 1 つずつ実行する決まりを、機械で守る（D / P1）

- **DC-104-17** E2E は、どの作業ツリーからでも実行できる。テストのコードと画面は、実行した作業ツリーのものを使う。
- **DC-104-18** 他の作業ツリーで E2E が実行されている間に E2E を始めると、実行中の作業ツリーを示して終了する。
- **DC-104-19** E2E の準備は、共有の基盤のコンテナを再作成しない（E2E 用の Keycloak を除く）。
- **DC-104-20** E2E は、どのスロットのデータベース、画像のバケット、ポートも使わない。

### DS-104-3 エージェントの手順（skill、script、プレビュー）と文書が、スロットに合う（D / P1）

- **DC-104-21** 手元の環境を扱う skill に、スロットの割り当てと解除、スロットのポートでの起動、確認、停止の手順がある。
- **DC-104-22** エージェントは、スロットの店舗画面と管理画面をプレビューのツールで開ける。
- **DC-104-23** 手元の環境を扱う skill の、負荷の高い作業の制限が、新しい環境に合う。バックエンドと画面の起動はスロットごとに同時に実行してよく、E2E は 1 つずつ実行する。CPU の重い検査（バックエンドの全テスト、フロントの検査の script、E2E）を同時に実行するとタイムアウトしうるという注意は残す。
- **DC-104-24** 開発環境の起動の文書とテストの実行方法の文書に、スロットの使い方がある。
- **DC-104-25** 環境変数の文書に、追加または変更した環境変数がある。

## 6. 非機能要件

- **DN-104-1** 消費者と運営者に見える振る舞い（API の応答、画面、データベースの構造）を変えない。本番と CI で使う設定の値を変えない。変えるのは手元の既定の値と手順だけである。
- **DN-104-2** CI の定義のファイルを変えない。理由：並行する spec 131（CI の整頓）と重なるため。変える必要が出たら、利用者に相談する。
- **DN-104-3** Keycloak の realm の定義に追加するのは、手元のスロットのリダイレクト先だけである。本番に当たる設定はない。
- **DN-104-4** スロット 3 つを同時に動かしても、共有の基盤のメモリが Docker の 16 GB に収まる。
- **DN-104-5** CI と commit の前の検査が通る状態を保つ。

## 7. Non-goals

| 項目 | 扱う場所 |
|------|----------|
| E2E を複数の作業ツリーで同時に実行する（作業ツリーごとの E2E 用の Keycloak と、メールの分離が必要） | 必要になったとき（利用者が 2026-10-22 に決定） |
| スロット 4 以上 | 必要になったとき |
| Stripe の通知の転送をスロットごとに分ける（スロット 0 だけ） | 必要になったとき |
| Mailpit のメールと Zipkin のトレースをスロットごとに分ける（共有のまま） | 必要になったとき |
| CPU の重い検査を同時に実行したときのタイムアウトの解消 | spec 131 など CI とテストの spec |
| 機能紹介のページのスクリーンショットをスロットで撮る（スロット 0 だけ） | 必要になったとき |
