# 用語集

業務の用語（論理名）と、コード・DB で使う識別子（物理名）の対応表。
文書の本文では論理名だけを使い、識別子はこの表で引く（開発の進め方 第 3 節）。

## モジュール

| 用語 | 識別子 | 意味 |
|------|--------|------|
| 税モジュール | `tax` | 税区分と税率 |
| 商品カタログモジュール | `catalog` | 商品、バリアント、カテゴリ、公開、商品検索 |
| 在庫モジュール | `inventory` | 在庫数と調整履歴 |
| 店舗モジュール | `storefront` | C 側 API。複数モジュールの結果を組み合わせる |
| カートモジュール | `cart` | カートと、その品目 |
| 注文モジュール | `order` | 見積もり、注文手続き、注文、キャンセル |
| メディアモジュール | `media` | アップロードされたファイル（画像）の受け付け、検証、保存、配信 |
| 会員モジュール | `member` | 会員（IdP のアカウントと EC の会員 ID の対応） |
| 決済モジュール | `payment` | 注文の代金の支払（カードの与信）と、決済サービスとのやり取り |
| 出荷モジュール | `shipping` | 注文の出荷と配送状態、物流サービスとのやり取り |
| レポートモジュール | `reporting` | 注文と出荷のデータの写しと状態の履歴、売上のレポート |
| 地域モジュール | `region` | 都道府県・市区町村・郵便番号のマスターデータ |
| 通知モジュール | `notification` | 消費者へのメール（今は出荷通知メールだけ） |

## 共通

DB のテーブルとカラムには、ここと各節の論理名をコメントとして付ける（バックエンドのアーキテクチャ 第 6.1 節）。

| 用語 | 識別子 | 意味 |
|------|--------|------|
| バージョン | `version` | 楽観ロックのための番号。保存するたびに上がる |
| 作成日時 | `created_at` | 行を作った日時 |
| 更新日時 | `updated_at` | 行を最後に更新した日時 |
| 操作者 ID | `actor_id` | 操作した運営者の運営者 ID。認証の導入より前の行は空 |
| 操作者の氏名 | `actor_name` / `operatorName` | 操作した運営者の氏名（姓 名）の、操作の時点の写し（AC-142）。運営者の氏名が後で変わっても、記録は変わらない。記録を始める前の行は空 |
| イベント発行記録 | `event_publication` | 発行したイベントと、リスナーごとの処理の完了を記録するテーブル |
| 定期ジョブのロック | `shedlock` | 同じ定期ジョブを、同時に 1 インスタンスだけで動かすためのロック（ShedLock）のテーブル |
| 片付け | `cleanup`（`XxxCleanupJob`） | 不要になったデータ（期限切れ、処理の済んだもの）を、保存期間を過ぎたら消す定期ジョブ。データを持つモジュールに置く |
| 保存期間 | `retention` | 片付けで削除するまでに、データを残す期間。起点（期限、処理を終えた時刻）はデータごとに決める |
| 止めたイベント | `completion_attempts` が上限を超えた記録 | 再発行の上限まで処理に失敗し、再発行を止めたイベント。処理を終えていないので、片付けで消えない |
| 外部サービスのエラー | `ErrorType.EXTERNAL_SERVICE_ERROR` | 外部サービス（決済、画像の変換、ファイルの保存）が応答しない・失敗したこと。再試行できるエラーとして 502 で返す |
| マスターデータ | - | デプロイせずに、運営者の操作や外部のデータで更新される、業務が参照するデータ（税率、都道府県、市区町村、郵便番号）。データベースに持つ（バックエンドのアーキテクチャ 第 6.4 節） |
| 正となる所 | - | ある値を決めている、ただ 1 つの場所（データベース、設定、domain の定数）。他の所（画面、契約）は、そこから得るか、一致をテストで確認する |
| 業務の時間帯 | `BusinessTime.ZONE` | 業務の日付を切る時間帯（日本時間）。時刻は UTC で持ち、日付にするときだけ使う |

| 会員のカート | | 会員に結び付いたカート。会員ごとに 1 つで、どの端末からでも同じ |

## 税

| 用語 | 識別子 | 意味 |

| 置き換え後の税率 | `TaxRateDraft` | 税率の一覧の置き換えで指定する 1 件。既存の税率を残す場合は、その ID を持つ |

| 商品 | `Product` / `product` | 消費者から見た 1 つの商品ページの単位 |
| 商品品番 | `ProductCode` / `product_code` | 運営者が商品に付ける業務上の番号。英大文字・数字とハイフン。一意だが、付け替えられることがある |
| バリアント | `Variant` / `variant` | 商品の中で、実際に販売・在庫管理する単位（例：「白 / M」） |

| 軸の値 | `AxisValue` / `variant_axis_value` | バリアントが各軸で持つ値（例：白、M） |

| カテゴリ | `Category` / `category` | 商品の分類。最大 3 階層 |
| 階層の深さ | `depth` | カテゴリの階層。最上位が 1、最大 3 |
| 表示順 | `displayOrder` / `display_order` | 兄弟カテゴリの中の並び順。小さいほど先 |

| 税込価格 | `priceInclTax` | 税抜価格に、その時点の税率を適用した価格 |
| 金額 | `Money` | 円単位の整数を表す値オブジェクト |
| 公開状態 | `PublicationStatus` / `status` | 非公開（`UNPUBLISHED`）、公開（`PUBLISHED`）、販売終了（`DISCONTINUED`） |
| 公開期間 | `PublicationPeriod` / `publish_start`、`publish_end` | 公開状態でも、C 側に表示する期間を限る |

| 商品画像 | `ProductImage` / `product_image` | 商品の画像。メディアモジュールのアセット ID と並び順を持つ |
| 代表画像 | `representativeImage` | 商品の画像の並びの先頭。一覧に表示する |
| 商品検索 | `ProductSearch` | キーワード検索の port |
| 商品照会 | `ProductQueryRepository` | カテゴリ・価格帯などの条件による一覧 |

## 注文

| 用語 | 識別子 | 意味 |
|------|--------|------|
| 注文に使うバリアントの情報 | `OrderableVariant` | 商品カタログがカートと注文に渡す、品番・商品名・軸の値・価格・税区分・表示されるか・販売停止か |
| 見積もり | `Quote` | 品目と時点から、金額と購入できるかを求めたもの。カートの表示、注文手続き、注文で同じ計算をする |
| 注文手続き | `Checkout` / `checkout` | カートから注文に進んだ 1 回の手続き。引当の持ち主 |
| 注文 | `Order` / `sales_order` | 成立した注文 |
| 注文番号 | `OrderNumber` / `order_number` | 人が使う注文の番号（例：20261010-482915）。識別子ではなく属性 |
| 注文明細 | `OrderLine` / `sales_order_line` | 注文時点の品番・商品名・価格・税率の写しと数量 |
| 注文の状態 | `OrderStatus` / `status` | 支払待ち（`PENDING_PAYMENT`）、受付（`ACCEPTED`）、キャンセル申請中（`CANCELLATION_REQUESTED`）、キャンセル（`CANCELLED`）、出荷済み（`SHIPPED`） |
| キャンセルの申請 | `CancellationRequest` | 消費者によるキャンセルの申請。1 つの注文に 1 回だけ。結果は承認・却下 |
| 運営者のキャンセル | `cancel` | 申請の承認によらない、運営者の判断によるキャンセル。理由が必須 |
| キャンセルの種類 | `CancellationKind` / `cancellation_kind` | 申請の承認（`REQUEST_APPROVED`）、運営者の判断（`OPERATOR`）、支払期限切れ（`PAYMENT_EXPIRED`） |
| 判断した運営者 | `decidedBy` / `cancellation_decided_by_id`・`_name` | キャンセルの申請を承認・却下した運営者の ID と氏名の写し（AC-142） |
| キャンセルした運営者 | `cancelledBy` / `cancelled_by_id`・`_name` | 注文をキャンセルした運営者の ID と氏名の写し（AC-142）。申請の承認なら承認した運営者 |
| 購入できない理由 | `UnpurchasableReason` | 見積もりで、品目を購入できない理由（表示されない、販売停止、在庫切れ、在庫不足）。その品目は合計に含めない |
| 小計 | `subtotal` | 品目ごとの、税込単価 × 数量 |
| 商品の合計 | `itemsTotal` / `items_total` | 購入できる品目の小計の合計 |
| 送料 | `shippingFee` / `shipping_fee` | 1 注文にかかる送料（税込） |
| 総額 | `total` / `total_amount` | 商品の合計と送料の合計 |
| 確認した総額 | `expectedTotal` | 注文手続きの画面で表示し、消費者が確認した総額。注文の時点の総額と違えば注文しない |
| 消費税額 | `taxAmount` / `sales_order_tax` | 税率ごとに、税込金額の合計から 1 回だけ計算した消費税 |
| お届け先 | `ShippingAddress` | 氏名、郵便番号、都道府県、市区町村、住所、電話番号。都道府県と市区町村は、注文の時点のコードと名前の写し（`AddressArea`） |
| 注文時の年齢 | `age` / `buyer_age` | 注文日（日本時間）の時点の、会員の満年齢。会員の生年月日から求めて記録し、生年月日は持たない。分からなければ空 |
| 性別 | `Gender` / `buyer_gender` | 会員が IdP で選ぶ任意の属性。男性（`MALE`）、女性（`FEMALE`）、その他（`OTHER`）、回答しない（`UNDISCLOSED`）。注文には成立の時点の値を記録する |
| 生年月日 | `birthdate` | 会員が IdP で入れる任意の属性。EC は持たず、token から読んで注文時の年齢を求める |

## 決済

| 用語 | 識別子 | 意味 |
|------|--------|------|
| 決済サービス | `PaymentGateway` | 支払画面と与信を提供する外部のサービス（Stripe）。テストと既定は mock |
| 支払 | `Payment` / `payment` | 1 つの注文の代金の支払。注文に 1 つ |
| 支払の状態 | `PaymentStatus` / `status` | 未払い（`UNPAID`）、与信済み（`AUTHORIZED`）、与信の取消待ち（`VOID_PENDING`）、与信の取消済み（`VOIDED`）、支払なし（`NOT_PAID`）、売上確定済み（`CAPTURED`）、与信期限切れ（`AUTHORIZATION_EXPIRED`）、返金待ち（`REFUND_PENDING`）、返金済み（`REFUNDED`） |
| 与信 | `authorization` | カードの利用枠のうち、総額分を確保すること（オーソリ）。売上の確定（出荷の時）までは代金を受け取らない |
| 与信の取消 | `void` | 確保した与信を解くこと。売上の確定の前なので、返金ではない |
| 与信の参照 | `authorizationRef` / `authorization_ref` | 決済サービスでの与信の ID。与信を取り消すときに使う |
| 支払画面 | `PaymentPage` / `page_id`・`page_url` | 消費者がカード番号を入力する、決済サービスの画面（Stripe Checkout） |
| 支払の期限 | `deadline` | 注文日時 ＋ 30 分。過ぎても与信がなければ、注文はキャンセル（支払期限切れ）になる |
| 通知を待つ支払 | `awaiting_authorization_since` | 期限を過ぎた未払いの支払のうち、決済サービスで支払が済んでいて期限切れにできなかったもの。与信の成功の通知を待つ。識別子は待ち始めた時刻 |

## メディア

## 出荷

| 用語 | 識別子 | 意味 |
|------|--------|------|
| 出荷 | `Shipment` / `shipment` | 注文を配送業者に渡したことの記録。注文に 1 つで、注文の全ての明細を 1 回で出荷する |
| 物流サービス | `CarrierTracking` | 配送業者の追跡の仕組みを提供する外部のサービス。配送状態の通知を送信する。テストと既定は mock |
| 配送業者 | `Carrier` / `carrier` | 荷物を届ける事業者。ヤマト運輸（`YAMATO`）、佐川急便（`SAGAWA`）、日本郵便（`JAPAN_POST`） |
| 送り状番号 | `TrackingNumber` / `tracking_number` | 配送業者が荷物に付ける追跡の番号。半角の数字とハイフン、30 文字まで。ハイフンを除いて保存する |
| 配送状態 | `DeliveryStatus` / `status` | 出荷した荷物の状態。出荷済み（`SHIPPED`）、配送中（`IN_TRANSIT`）、配達完了（`DELIVERED`）、返送（`RETURNED`）。今より高い順位にだけ進む（出荷済み 0、配送中 1、配達完了・返送 2） |
| 最後に通知を反映した日時 | `last_notified_at` | 配送状態を最後に更新した通知の反映日時 |
| 売上確定 | `capture` | 与信で確保した総額の代金の受け取りを確定すること（キャプチャ）。出荷の登録で行う |
| 与信期限 | `authorization-validity` | 与信の成功から、売上を確定できる期間（設定の名前。Stripe のカード決済は 7 日）。過ぎると売上を確定できない |
| 返金 | `refund` | 売上を確定した代金を、買い手に戻すこと。確定の前に与信を解く「与信の取消」とは別 |

### 配送業者の表示と配送状態の対応

物流サービスが通知する状態名（配送業者の追跡の表示）を、配送状態に対応づける。途中の表示は、全て「配送中」にする。表にない状態名の通知では、配送状態を変更しない。

| 配送業者 | 配送中 | 配達完了 | 返送 |
|----------|--------|----------|------|
| ヤマト運輸 | 荷物受付、発送、作業店通過、配達中、持戻、保管中 | 配達完了 | 返品 |
| 佐川急便 | 未確認 | 未確認 | 未確認 |
| 日本郵便 | 未確認 | 未確認 | 未確認 |

- ヤマト運輸は、mock が通知する名前。
- 佐川急便と日本郵便の追跡の表示は確認していない。実在の物流サービスにつなぐときに確認して、表に追加する。それまでは、この 2 社の通知は何も変えない。
