# 地域モジュール

都道府県・市区町村・郵便番号のマスターデータを持ち、参照だけを公開する。

| 項目 | 内容 |
|------|------|
| レベル | B（参照だけのマスターデータで、業務の状態を変える操作がない） |
| 依存 | なし（`common` だけ。注文・レポートから API で呼ばれる） |
| 関連 spec | [016](../../specs/archive/mvp/016-master-data)、[018](../../specs/archive/mvp/018-docs-and-tools) |

名前を「住所」にしないのは、お届け先や会員の住所録を管理するモジュールと混同しないため。

## マスターデータ

| 表 | 持つもの | コード |
|----|----------|--------|
| 都道府県 | コード、名前 | 地方公共団体コードの先頭 2 桁 |
| 市区町村 | コード、都道府県のコード、名前 | 地方公共団体コードの 5 桁（検査数字を除く） |
| 郵便番号 | 郵便番号（7 桁）、市区町村のコード、町域名、並び順 | 町域を識別するコードはない |

- 市区町村は、市・町・村と東京都の特別区。政令指定都市は区を 1 つの市区町村とし、市そのものは持たない。郡を含む町村は、名前に郡を含む（例：西多摩郡瑞穂町）。
- 1 つの郵便番号に、町域が複数あることがある。2 つの市区町村にまたがることもある。
- 町域名は、住所でない注記（「以下に掲載がない場合」、括弧の中の補足など）を除いて持つ。注記だけの町域名は空。
- 使う側は、都道府県と市区町村をコードで参照し、名前は表示にだけ使う。注文は、注文の時点のコードと名前を写す（[注文モジュール](order.md)）。
- 郵便番号の表は、他のデータから参照されない。更新するときは、表を全件置き換える ※1。

※1：郵便番号のデータには町域を識別するコードがなく、更新で町域の行が分かれる・まとまることがある。参照されなければ、差分を追跡せずに置き換えられる。

## 最初のデータ

都道府県・市区町村の全件と、郵便番号の一部を、Flyway のマイグレーションで入れる。郵便番号の全件は入れない（テストのデータベースを作るたびに読むと CI が遅くなるため）。外部から取り込んで更新する仕組みは 1 → 10 で作る。

| 項目 | 内容 |
|------|------|
| 出典 | 日本郵便の「住所の郵便番号（1 レコード 1 行、UTF-8 形式）」の CSV だけ。市区町村も同じ出典から、地方公共団体コードの重複を除いて作る ※2 |
| 変換 | `infrastructure/source` の変換（注記を除き、マスターデータの行にする）。取り込みの仕組みからも同じ変換を使う |
| 郵便番号の一覧 | `src/tools/resources/region/postal-codes.txt`。seed・テスト・E2E が使う郵便番号と、変換の確認に使う郵便番号 |
| 作り方 | 下の手順。作ったマイグレーションは手動で修正しない |
| 出典と利用の条件 | [依存とライセンス](../licenses.md) 第 3.4 節 |

1. 日本郵便の郵便番号データのページから `utf_ken_all.zip` をダウンロードし、`/.local/masterdata/utf_ken_all/utf_ken_all.csv` に展開する（Git に入れない）。
2. `./gradlew generateRegionMigration` を実行する（置き場所を変えるときは `-PpostalCodeCsv=<CSV>`）。都道府県・市区町村・郵便番号の数が出力される。一覧の郵便番号がデータになければ失敗する。
3. 郵便番号を追加するときは、一覧に追加して再実行する。適用済みのマイグレーションは修正しないので、デプロイした後は、新しいマイグレーションに書き出すようにタスクを修正する。

※2：郵便番号の市区町村は、全て一覧にある。郵便番号のデータの地方公共団体コードは総務省のコードと同じなので、市区町村を国の API から取得するようにしても、郵便番号の表とはコードで対応づけられる。

## 切り出しの前提

1 → 10 で、別のサービスに切り出せるようにする。

| 前提 | 切り出すとき |
|------|--------------|
| 業務のモジュールに依存せず、イベントを出さない | そのまま移せる |
| 使う側は腐敗防止層（`RegionDirectory`）で包む | 腐敗防止層の実装を、HTTP の呼び出しに替える |
| 他のモジュールの表から外部キーを張らない | 表をそのまま移せる |
| API は参照だけで、EC に固有の判断を持たない | 他の用途からも使える |

## 店舗 API

店舗 API（`store.yaml` のタグ `region`）の 3 つの操作は、このモジュールの presentation が受ける（`storefront` を通さない）。3 つとも token なしで使える。

| 操作 | 応答 |
|------|------|
| 都道府県の一覧 | コードの順の、コードと名前 |
| 都道府県の市区町村の一覧 | コードの順の、コードと名前。都道府県がなければ 404 |
| 郵便番号で検索する | 住所の一覧（都道府県、市区町村、町域）。ないときは 200 で空の一覧 |

## 行わないこと

- 管理 API に地域の操作を追加しない。管理画面は、注文とレポートの応答にある名前を表示する。
- 地域の API の応答のキャッシュを、バックエンドに持たない。店舗画面が再取得する間隔で取る。

## 構成

```
region/
├── api/                    # 都道府県・市区町村・郵便番号の取得
├── application/            # 参照のサービス
│   └── port/               # リポジトリ
├── domain/                 # 都道府県、市区町村、郵便番号の住所
├── infrastructure/
│   ├── persistence/        # リポジトリの実装
│   └── source/             # 郵便番号のデータの変換
└── presentation/           # 店舗 API
```
