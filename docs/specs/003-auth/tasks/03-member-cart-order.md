## カート

- [ ] **T3306** マイグレーション：カートに会員 ID（任意。会員ごとに一意）を足す。
- [ ] **T3307** [テスト] カートを移す処理の単体テスト：同じバリアントの合算、10 での切り詰め、30 品目を超える分を移さない（移すカートの後ろから）、切り詰めた品目と移せなかった品目の結果（AC-122、123）。
- [ ] **T3308** [テスト] 会員のカートの統合テスト。
  - `/me/cart`：初めてなら作り、2 回目は同じカート（AC-121）
  - 会員のカートを、持ち主でない会員やログインしていない人が読み書きすると 404。店舗のカートの表示も同じ（AC-121）
  - 会員を持たないカートは、今までどおり ID で使える（AC-120）
  - `/me/cart/merge`：品目が移り、元のカートが空になる。2 回目は何も変わらない。商品・在庫は確かめない。会員のカートの変更のイベントが出る（AC-122〜124）
  - 会員のカートを、移す元には指定できない
- [ ] **T3309** 会員のカートとカートを移す処理を実装する（カートモジュールと、店舗モジュールのカートの表示）。T3307、T3308 を通す。cart.md のデータモデルを直す。

## 注文

- [ ] **T3310** マイグレーション：ログインせずに作った注文・注文手続きと、その引当を消し、注文手続きと注文に会員 ID（必須）を足す（plan 第 3.4 節）。在庫の調整履歴とカートは残す。
- [ ] **T3311** [テスト] 会員の注文の統合テスト。
  - 注文手続き：認証がないと 401。会員のカートでないカートからは始められない。持ち主でない会員には 404（AC-125、126）
  - 注文：持ち主でない会員には 404。メールアドレスは token から取り、注文の写しに残る。token の「確認済み」が偽なら拒否する（AC-127、128）
  - 注文の参照とキャンセルの申請：持ち主でない会員には 404。ログインしていなければ 401（plan 第 5.1 節。AC-130、131、137）
  - `/me/orders`：自分の注文だけが、注文日時の新しい順に、ページ単位で返る（AC-129）
- [ ] **T3312** 注文の会員化を実装する。既存の注文の統合テストに会員の token を付ける（テストの意図は変えない）。T3311 を通す。order.md のデータモデルを直す。
- [ ] **T3313** [テスト] IdP の設定の統合テスト（T3208）に店舗の側を足す：会員の token で `/me/cart` を使え、運営者の token では 401（AC-138）。
