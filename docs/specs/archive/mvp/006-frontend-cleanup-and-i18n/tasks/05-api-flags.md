### T6501 の結果：出し分けの一覧とフラグ

画面が業務の規則で操作を出し分けている所（admin・store の `src` を、状態の比較と判定の関数で探した）。
フラグは応答に `actions`（できる操作の真偽）としてまとめて追加する。名前は利用者の指示で、エージェントが決めた（spec 006 の確認 C）。

| 画面 | 今の判定 | 応答 | フラグ | 値（集約の規則） |
|------|----------|------|----|------------------|
| 管理・商品の状態 | `status === 'UNPUBLISHED'` で公開のボタン | admin `ProductDetail` | `actions.publish` | 非公開 |
| 〃 | `status === 'PUBLISHED'` で非公開のボタン | 〃 | `actions.unpublish` | 公開 |
| 〃 | `status !== 'DISCONTINUED'` で販売終了のボタン | 〃 | `actions.discontinue` | 販売終了でない |
| 〃 | `isNeverShown`（AC-71）で商品の削除 | 〃 | `actions.delete` | C 側に表示されたことがない |
| 管理・バリアント | `isNeverShown`（AC-71）でバリアントの削除 | 〃 | `actions.deleteVariants` | 〃 |
| 〃 | `canAdd`（AC-24）でバリアントの追加の欄 | 〃 | `actions.addVariant` | 軸がある、またはバリアントがない |
| 管理・注文 | `availableActions`（AC-101〜103）で承認・却下・キャンセル | admin `OrderDetail` | `actions.approveCancellation`・`rejectCancellation`・`cancel` | 承認・却下は申請中、キャンセルはキャンセル済みでない |
| 店舗・注文 | `cancellationState` の「申請できる」（AC-95） | store `OrderDetail` | `actions.requestCancellation` | 受付で、まだ申請していない |

- 値は、今の画面の出し分けと同じにする（DN-7）。集約が冪等に受け付ける操作（公開中の公開、キャンセル済みのキャンセル）は、今と同じく出さない。
- 集約が別の理由で拒む操作（バリアントのない商品の公開、公開中の商品の最後のバリアントの削除）は、今と同じく出し、押したときの業務のエラーで知らせる。
- 出し分けでないもの（状態のバッジの色、税率の状態の表示、キャンセルの状況の文言）は、表示の変換なので対象にしない。在庫の調整は、状態による出し分けがない。
