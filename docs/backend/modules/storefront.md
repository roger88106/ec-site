# 店舗モジュール

C 側 API。複数のモジュールの結果を組み合わせて返す。

| 項目 | 内容 |
|------|------|
| レベル | B（ドメインもテーブルも持たない参照専用の層） |
| 依存 | 商品カタログ・在庫・注文（API）、会員（API。presentation だけ） |
| 関連 spec | [001](../../specs/001-catalog-and-inventory)、[002](../../specs/002-cart-and-order)、[003](../../specs/003-auth) |

## 置く理由

C 側の画面は、商品の情報と在庫の有無を同時に必要とする。在庫は商品カタログのイベントを購読しているので、商品カタログが在庫を呼ぶと依存が循環する。両方を呼んで組み合わせる層をここに置く。

## 構成

```
storefront/
├── presentation/           # store.yaml から生成したインターフェースを実装
├── application/            # 組み合わせ、表示の型、店舗の情報の設定
│   └── port/               # 腐敗防止層の口と、その型
└── infrastructure/
    └── directory/          # 商品カタログ・在庫・注文の API を自分の型に変える腐敗防止層
```

## 組み合わせ方

| 画面 | 組み合わせ |
|------|------------|
| 商品一覧・検索 | 商品カタログから 1 ページ分の商品を受け取り、バリアントの在庫の有無を在庫からまとめて受け取る。全バリアントが在庫なしなら「在庫なし」 |
| 商品詳細 | 商品カタログから商品を受け取り、全バリアントに在庫の有無を付ける |
| カート | 注文の見積もり API に、品目の取得から金額と購入できるかの判定までを任せ、表示の形に変える ※1 |

- 在庫がまだないバリアントは「在庫なし」（[inventory.md](inventory.md)）。
- 組み合わせの結果は application の表示の型（view）にし、presentation はそれを API の型に変えるだけにする。腐敗防止層の型をそのまま presentation に渡さないのは、在庫の有無と、軸ごとの値の一覧（選べない値を含む）を組み立てる加工が application にあるため。
- 会員のカートは持ち主だけに見せ、他の人には 404。要求した会員 ID（ログインしていなければなし）を見積もり API に渡し、注文モジュールがカートの持ち主と照らす。

※1：注文手続き中なら、注文モジュールがその引当を販売可能数から除いて見積もる。

## 店舗の情報

- 問い合わせ先のメールアドレスを設定に持ち、店舗 API で返す。キャンセルの申請が却下された注文の画面に出す。
- 問い合わせ先は必須。なければ起動しない。
