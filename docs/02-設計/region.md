# 地域の設計

地域モジュールは、都道府県・市区町村・郵便番号のマスターデータを持ち、参照だけを公開する。業務規則は [地域モジュール](../03-機能仕様/region.md) にある。

## 境界

依存は写さず、[全体構成](overview.md) の「モジュールの依存とイベント」を指す。地域は `common` だけに依存し、業務のモジュールに依存せず、イベントを出さない。

### 他のモジュールへの公開

| 種類 | 内容 | 利用者 |
|------|------|--------|
| API | 都道府県の一覧、都道府県の市区町村の一覧、都道府県をコードで取得する、市区町村をコードで取得する | 注文、レポート |

### 切り出しの前提

別のサービスに切り出せるように、次の前提を守る。

| 前提 | 切り出すとき |
|------|--------------|
| 業務のモジュールに依存せず、イベントを出さない | そのまま移せる |
| 使う側は、地域を呼ぶ腐敗防止層で包む | 腐敗防止層の実装を、HTTP の呼び出しに替える |
| 他のモジュールの表から外部キーを張らない（規則は[地域モジュール](../03-機能仕様/region.md)の「データモデル」） | 表をそのまま移せる |
| API は参照だけで、EC に固有の判断を持たない | 他の用途からも使える |

## 処理の流れ

なし。地域は参照だけを公開し、モジュールをまたぐ処理の手順を持たない。

## API

リクエストとレスポンスの項目、エラーコード、状態コードは OpenAPI（[店舗 API](../../api/openapi/store.yaml)）が正本である。管理 API に地域の操作はない。3 つの操作は、地域の presentation が受ける（`storefront` を通さない）。

| 画面 | 操作 | メソッドとパス | operationId |
|------|------|----------------|-------------|
| 店舗 | 都道府県の一覧 | `GET /prefectures` | `listPrefectures` |
| 店舗 | 都道府県の市区町村の一覧 | `GET /prefectures/{prefectureCode}/municipalities` | `listMunicipalities` |
| 店舗 | 郵便番号の住所 | `GET /postal-codes/{postalCode}` | `findPostalCodeAddresses` |

## パッケージの構成

クラスの名前と設定の値は書かない（正本はコード）。

```
region/
├── api/                    # 他モジュールへの参照の公開
├── application/            # 参照のサービス
│   └── port/               # リポジトリの port
├── domain/                 # 都道府県、市区町村、住所
├── infrastructure/
│   └── persistence/        # リポジトリの実装
└── presentation/           # 店舗 API の実装
```
