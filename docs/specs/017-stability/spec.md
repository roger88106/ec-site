# Spec 017：安定性

ステータス：確定

## 1. 背景と目的

spec 010 の後の全体のレビューで、データが減らずに増え続ける所と、外部サービスが止まったり遅くなったりしたときに、分かりにくい失敗や待ち続けになる所が見つかった。**古いデータは期限で片付け、外部サービスの失敗は分類して返し、待つ時間に上限を置き、失敗をログで追えるようにする**。

- 定期ジョブは、イベントの再発行と支払の期限切れの 2 つだけで、データを削除するジョブがない。処理の済んだイベント、期限切れの引当・注文手続き・カートが残り続ける。処理の済んだイベントには、購入者のメールアドレスが入っている。
- 処理に失敗し続けるイベントは、1 分ごとに限りなく再発行され、誰にも知らされない。
- 外部サービスに接続できないとき、決済の売上確定だけが「再試行できる」エラー（502）を返す。支払画面を作るときの決済サービスの失敗、画像の変換と保存のサービスの失敗は、予期しないエラー（500）や、ファイルが壊れているというエラー（400）になる。
- 決済サービスとファイル保存の呼び出し、店舗画面のサーバー側からバックエンドと IdP への呼び出しに、待つ時間の上限がない（または外部ライブラリの既定の長い値のまま）。
- 画像の確定は、データベースのトランザクションの中で画像の変換（最長 30 秒）と保存を呼ぶ。その間データベースの接続を持ち続け、トランザクションが失敗すると、公開の保存先にファイルだけが残る。
- 店舗画面のサーバーアクションは、失敗をすべて「接続できない」に変え、ログに何も残さない。
- 支払の期限切れのジョブは、決済サービスで支払済みのまま通知を待つ支払が先頭の 100 件にたまると、それより新しい期限切れの支払を処理できない。一部の例外で、1 回の処理が途中で止まる。

マスターデータ（spec 016）でデータの構造が落ち着いたので、その上で新しい仕組み（片付けのジョブ、タイムアウト）を追加する。

AC・US・BR・NFR の番号は、spec 016 から続けて振る。

## 2. 用語

| 用語 | 意味 |
|------|------|
| 片付け | 保存期間を過ぎたデータを、定期ジョブで削除すること |
| 保存期間 | データが不要になってから（期限切れ、処理の完了）削除するまでの時間 |
| 処理の済んだイベント | すべてのリスナーが処理を終えたイベント |
| 止めたイベント | 再発行の回数の上限を超え、自動では再発行しなくなったイベント |
| 外部サービスのエラー | 外部サービス（決済、画像の変換、ファイル保存）に接続できない、時間内に応答がない、外部サービスの側の故障で処理できないこと。再試行すれば通ることがある |

用語集には plan で追加する。

## 4. User stories と受け入れ条件

### US-61 古いデータを保存期間で片付ける（B / P1）

運営者は、不要になったデータと、購入者の個人情報を、決めた期間より長く持たない。

- **AC-284** 片付けの定期ジョブが、次のデータを保存期間を過ぎたら削除する。

  | データ | 保存期間の起点 | 既定の保存期間 |
  |--------|----------------|----------------|
  | 処理の済んだイベント | 処理を終えた時刻 | 7 日 |
  | 引当 | 期限 | 1 日 |
  | 注文手続き | 期限 | 1 日 |
  | カート | 期限（最後の変更から 30 日） | 0 日（期限で削除する） |

- **AC-285** 保存期間と、片付けのジョブの間隔は、設定で変えられる。
- **AC-286** 片付けは、注文・支払・出荷と、未完了のイベント・止めたイベントを削除しない。注文になった注文手続きを削除しても、注文は今までどおり表示・操作できる。
- **AC-287** 片付けのジョブは、複数のインスタンスで動かしても同時に 1 つだけが動く（[バックエンドのアーキテクチャ](../../backend/architecture.md) 第 5 節）。
- **AC-288** 片付けのジョブは、データごとに削除した件数をログに出力する。
- **AC-289** 期限切れのカート・注文手続きを削除した後に、そのカート・注文手続きを使う操作は、今の「期限切れ」と同じ結果か、見つからない（404）になり、予期しないエラーにならない。

### US-62 処理できないイベントを止めて知らせる（B / P1）

運営者は、処理に失敗し続けるイベントに気づき、限りない再発行でログとデータベースを埋めない。

- **AC-290** 再発行しても処理に失敗し続けるイベントは、決めた回数（設定で変えられる）を超えたら、自動の再発行を止める。
- **AC-291** イベントを止めたとき、イベントの種類と ID をエラーのログに出力する。イベントの中身（個人情報を含む）は出力しない。
- **AC-292** 未完了のイベントの件数と止めたイベントの件数を、運用ポートのメトリクスで公開する。
- **AC-293** 止めたイベントは、片付けで削除せずに残す。

### US-63 外部サービスのエラーを、再試行できるエラーとして返す（B・C / P1）

消費者と運営者は、外部サービスの一時的な故障を、自分の入力の誤りや予期しないエラーと区別できる。

- **AC-294** 外部サービスのエラーは、どのモジュールでも 502 と、再試行できることを示すメッセージで返す（[API の規約](../../api/conventions.md) 第 3 節）。
- **AC-295** 支払画面を作るとき、決済サービスのエラーなら 502 を返す。
- **AC-296** 画像の確定で、画像の変換のサービスに接続できない、時間内に応答がない、変換のサービスの側の故障のときは 502 を返す。
- **AC-297** 画像の確定で、変換のサービスがファイルを読めない（ファイルの側の問題）ときだけ、画像を変換できないエラー（400）を返す。
- **AC-298** 画像の確定で、ファイル保存のサービスのエラーなら 502 を返す（受付は署名付き URL を手元で作り、ファイル保存のサービスを呼ばない。実装の時に修正した、2026-10-20 利用者）。
- **AC-299** 店舗画面と管理画面は、外部サービスのエラーを受けたら、再試行できることを示すメッセージを表示する。
- **AC-300** API の規約に、外部サービスのエラーの扱いと、OpenAPI の外のエンドポイント（決済・物流の通知、mock の画面）の応答をまとめて書く。OpenAPI の各操作には、外部サービスを呼ぶものに 502 を書く。

### US-64 外部サービスとバックエンドを、限りなく待たない（B・C / P1）

消費者と運営者は、外部サービスやバックエンドが応答しないとき、画面が止まったまま待たされない。

- **AC-301** バックエンドから決済サービスとファイル保存のサービスへの呼び出しに、接続と応答の待つ時間の上限がある。上限は設定で変えられる。
- **AC-302** 店舗画面のサーバー側から、バックエンドと IdP への呼び出しに、待つ時間の上限がある。上限は設定で変えられる。
- **AC-303** 上限を超えたら、バックエンドは外部サービスのエラー（502）として返し、店舗画面は今の「接続できない」と同じ扱いにする。

### US-65 外部サービスの呼び出しで、データベースの接続を持ち続けず、ファイルを残さない（B / P1）

運営者は、画像の変換が遅いときにも、他の操作がデータベースの接続を待たされない。

- **AC-304** 画像の確定は、画像の変換と保存のサービスを、データベースのトランザクションの外で呼ぶ。トランザクションは、画像の登録と、商品への画像の追加だけを包む。
- **AC-305** 画像を公開の保存先に置いた後に、画像の登録か商品への追加が失敗したら、置いたファイルを削除する。削除するのに失敗したら、警告のログに保存先のキーを出力し、元の失敗を返す。
- **AC-306** 他のモジュールの、外部サービスを呼ぶ処理も、データベースのトランザクションの外で呼ぶ。外で呼べない所があれば、plan で理由を書く。

### US-66 店舗画面の失敗を、ログで追える（B / P1）

運営者は、消費者が「接続できない」を見たとき、その原因を店舗画面のログで追える。

- **AC-307** 店舗画面のサーバーアクションが例外で失敗したら、例外の内容をエラーのログに出力してから、今の「接続できない」の結果を返す。画面の移動と not found の例外は、今までどおりログに出力せずに通す。
- **AC-308** 店舗画面のサーバー側で、バックエンドから 5xx を受けたら、警告のログに状態コードとエラーコードを出力する。
- **AC-309** 店舗画面のログは、トレース ID を持ち、バックエンドのログと照合できる（[フロントの書き方](../../frontend/coding.md) 第 8.2 節）。token、メールアドレスなどの秘密情報と個人情報は出力しない。

### US-67 支払の期限切れの処理を、処理できない支払で止めない（B / P2）

運営者は、一部の支払を処理できなくても、他の期限切れの支払を期限どおりに取り消せる。

- **AC-310** 支払の期限切れのジョブは、1 件の支払で例外（種類を問わない）が起きても、その支払 ID をログに出力して、残りの支払を処理する。
- **AC-311** 決済サービスで支払済みのまま与信の通知を待つ支払が 1 回の処理の件数を超えてたまっても、それより新しい期限切れの支払を処理する。
- **AC-312** 与信の通知を待つ支払が、待ち始めてから決めた時間（設定で変えられる）を過ぎても残っていたら、警告のログに件数を出力する。

## 5. 業務ルール

- **BR-38** 不要になったデータは、保存期間を過ぎたら削除する。保存期間は、データを使う業務の期限と、個人情報を長く持たないことから決める。
- **BR-39** 外部サービスのエラーは、利用者の入力の誤りと分けて、再試行できるエラーとして返す。外部サービスがファイルや入力を読めないと答えたときだけ、入力の誤りにする。
- **BR-40** 外部サービスとの通信は、待つ時間に上限を置き、データベースのトランザクションの外で行う。

## 6. 非機能要件

- **NFR-24** 片付けは、一度に削除する件数に上限を置き、他の操作のデータベースの行ロックを長く止めない。
- **NFR-25** 会員の確認（token の subject から会員を探す処理）は、会員がいるときは読み取り専用のトランザクションで行う。理由：ログインしたすべてのリクエストで動くため。
- **NFR-26** 本 spec の AC に関わらない既存のテスト（バックエンド、フロント、E2E）は、期待値を変えずに通る。
- **NFR-27** ローカルの起動、E2E、CI は、今と同じコマンドで動く。
- **NFR-28** CI の全体が 10 分以内のまま終わる（spec 011 の DC-85）。

## 7. Non-goals

| 項目 | 扱う場所 |
|------|----------|
| 匿名のカートの作成の回数の制限 | 1 → 10（デプロイのときに、リバースプロキシなどの入口で行う） |
| 止めたイベントを、画面から見る・再発行する操作 | 1 → 10。MVP は、ログとメトリクスで気づき、データベースで扱う |
| 公開の保存先にある、登録のないファイルを定期的に探して削除する | 行わない（AC-305 でその場で削除する） |
| 確定していないアップロードの、受付の保存先での期限（ローカルは 1 日） | 1 → 10（デプロイの構成で設定する） |
| メトリクスによる警報（通知の送り先） | 1 → 10（デプロイの監視の構成で行う） |
| 外部サービスの呼び出しの自動の再試行（決済サービスの SDK が持つものを除く）、サーキットブレーカー | 行わない（MVP の規模では、画面からの再試行で足りる） |
| 商品の検索の性能 | MVP の後（検索エンジンへの置き換えと合わせて決める） |
