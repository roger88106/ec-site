# 店舗モジュール

C 側 API。複数のモジュールの結果を組み合わせて返す。

- レベル：B（ドメインもテーブルも持たない参照専用の層）
- 依存：商品カタログモジュール（API）、在庫モジュール（API）、注文モジュール（API）
- 関連 spec：001（US-10〜12）、002（US-15 のカートの表示、AC-96 の問い合わせ先）
- 用語と識別子：[用語集](../glossary.md)

## 置く理由

C 側の画面は、商品の情報と在庫の有無を同時に必要とする。しかし在庫モジュールは商品カタログのイベントを購読しているため、商品カタログが在庫を呼ぶと依存が循環する。両方を呼んで組み合わせる層をここに置く（constitution 4.1）。

## 構成

```
storefront/
├── catalogdir/   # 商品カタログの API を自分の型に変換する腐敗防止層
├── stockdir/     # 在庫の API を自分の型に変換する腐敗防止層
├── orderdir/     # 注文の API（見積もり）を自分の型に変換する腐敗防止層
├── service/      # 組み合わせ、店舗の情報の設定
└── controller/   # OpenAPI（store.yaml）から生成したインターフェースを実装
```

## 組み合わせ方

- 商品一覧・検索：商品カタログから 1 ページ分の商品を受け取り、それらのバリアントの在庫の有無を在庫モジュールからまとめて受け取る。全バリアントが在庫なしの商品に「在庫なし」を付ける。
- 商品詳細：商品カタログから商品を受け取り、全バリアントに在庫の有無を付ける。
- 在庫がまだ作られていないバリアントは「在庫なし」とする（[inventory.md](inventory.md)）。
- カートの表示（spec 002）：注文モジュールの見積もりの API に、カートの品目の取得から金額と購入できるかの判定までを任せ、表示の形に変換する。注文手続き中なら、注文モジュールがその引当を販売可能数から除いて見積もる。

## 店舗の情報

- 店舗の情報（問い合わせ先のメールアドレス）は、設定に持ち、店舗 API で返す（[plan 002](../specs/002-cart-and-order/plan.md) 第 4 節）。キャンセルの申請が却下された注文の画面に示す（AC-96）。
- 問い合わせ先は必須。設定がなければ起動しない（環境ごとに必ず決めるため）。
