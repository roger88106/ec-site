## 見直しの結果

### 直したこと

- 固定の時間で「起きないこと」を見るテスト（15 か所）を、イベントの発行の記録で待つ形にした（段階 2）。CI でその 1 つが、等しいイベントを重ねて発行したときの Spring Modulith の振る舞いで落ちたので、前の処理を待ってから重ねる形に直し、テストの書き方に書いた（T012-02-09）。
- E2E の支払の期限を 30 秒から 12 秒にし、期限切れのテストを 32.6 秒から 16.4 秒にした（T012-02-05）。
- AC-90 を除外の一覧から消した（T012-03-01）。管理画面の商品の登録のテストの時間切れを直した（T012-06-01）。
- E2E の要素の選び方を、役割と名前にした。IdP の画面と詳細の項目の値の選び方は、補助 1 か所ずつに置いた（段階 5）。
- カバレッジ（行）：Stripe の実装 43.3% → 83.6%、バックエンド 96.2% → 97.8%、管理画面 89.7% → 94.2%、店舗画面 62.8% → 80.2%。

### 直さずに残したこと

| 項目 | 理由 |
|------|------|
| 詳細の項目の値（`dd`）に名前の属性を付けない | Biome の検査（`useAriaPropsSupportedByRole`）が認めない。利用者の判断で、項目名の次の値を選ぶ xpath を `e2e/src/detail.ts` だけに置いた（spec の DC-101 の例外） |
| カートを空にする補助（`emptyCart`）の、並びの 1 つ目の削除のボタンを押す書き方 | 同じ名前のボタンを 1 つずつ消すので、どれを押しても同じ。テスト（`e2e/tests`）の外の補助にだけある |
| 機能紹介・流れの撮影（`e2e/flow`）の要素の選び方 | 撮影の script で、plan の対象の外 |
| 公開の開始の E2E の待ち方 | 画面の表示でなく応答の状態を見るので、`reopenUntil` を使わない |
| 管理画面・店舗画面の、表示の切り替えだけの分岐（画面の幅、読み込み中）と、届かない守り | ロジックがなく、テストを足しても振る舞いの証拠にならない |

### 後の spec に回したもの

- Stripe の支払の画面の作成に冪等のキーがない（T012-04-01）。送り直しで Checkout Session が 2 つでき、両方で支払えるおそれがある。本番のコードを変えるので、本 spec（DN-13）の外。書き方の統一か、支払いの次の spec で扱う。
