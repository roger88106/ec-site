# メディアモジュール

利用者がアップロードするファイル（いまは画像だけ）の受け付け、検証、保存、配信の URL、削除を担う。
ファイルが何に使われるか（どの商品の何枚目か、代表画像はどれか）は知らない。それは使う側のモジュール（商品カタログなど）が持つ。

- レベル：B（業務の不変条件はなく、ストレージとの連携が中心。3 層：api / service / infrastructure）
- 依存：なし（使う側から api で呼ばれる）
- 関連 spec：001（US-7、US-13）
- 用語と識別子：[用語集](../glossary.md)
- 範囲の外：サイトそのものの静的なファイル（ロゴ、CSS、JavaScript）。フロントのビルドの成果物として、フロントの配信（CDN）が出す。

## アセット

アセットは、検証して配信の場所に置いた 1 つのファイル。ID、形式（JPEG など。種類はここから分かる）、配信のキーを持つ。

- 使う側は、アセット ID だけを持つ（モジュールをまたぐので外部キーは張らない。constitution 6）。配信のキーや URL の形は、このモジュールの外に出さない。
- 配信のキーはアセット ID で作り（`assets/{assetId}.{拡張子}`）、上書きしない。そのため長くキャッシュさせる。
- アセットは使う側が持ち主として扱い、要らなくなったら手放す（後述）。複数の持ち主で 1 つのアセットを共有しない。

## アップロードの流れ

ファイルは、ブラウザから受付のバケットへ直接送る（署名付き URL）。バックエンドはファイルを中継しない。置き場所（バケット）の構成は [plan 001](../specs/001-catalog-and-inventory/plan.md) 第 7 節。

1. **受付**（`requestImageUpload`）：形式と大きさを確かめ、受付のバケットへの署名付き URL を返す。受付は DB に記録しない。
   - 使う側は、持ち主を表す「範囲」（例：商品 ID）を渡す。受付のキーは `{範囲}/{uploadId}` になり、別の範囲の受付を確定できないようにする。
   - 枚数の上限など、使う側の規則は、受付を頼む前に使う側が確かめる。
2. **確定**（`confirmImage`）：受付のファイルの大きさと、先頭のバイトで判定した形式を確かめ（申告は信用しない）、配信のバケットへ置いてアセットを記録する。アセット ID を返す。
   - 使う側のトランザクションの中で呼ぶ。使う側の保存が失敗すると、アセットの記録も取り消される（配信のファイルは残るが、だれからも参照されない）。
   - US-13 では、ここで WebP に変換し、メタデータを除いてから配信のバケットへ置く（同期。AC-68〜70）。変換に失敗したら、その場でエラーにし、アセットを記録しない。変換の方法は [plan 001](../specs/001-catalog-and-inventory/plan.md) 第 7.5 節。
3. 受付だけで確定しなかったファイルは、受付のバケットのライフサイクル規則で 1 日後に消える（定期ジョブを作らない）。

### 受け付ける画像

| 項目 | 決まり |
|------|--------|
| 形式 | JPEG、PNG、WebP（AC-39）。US-13 で BMP、HEIC / HEIF、AVIF を足す（AC-67）。確定のときに、先頭のバイトで判定する |
| 大きさ | 1 バイト以上、10MB まで（AC-39） |
| 配信の形式 | US-13 から、すべて WebP（AC-68）。それより前に確定したアセットは、受け付けた形式のまま |

使う側によって決まりを変える必要が出たら、受付・確定に決まり（形式、大きさ）を渡せるようにする。

## アセットを手放す

使う側は、アセットが要らなくなったら（画像の削除、商品の削除）、自分のトランザクションの中で `release` を呼ぶ。

- アセットの記録を消し、内部のイベント（アセット解放）を登録する。配信のファイルは、コミットの後にそのイベントで消す。使う側の保存が失敗すれば、解放も取り消される。
- ファイルの削除は何度行っても同じ結果になるので、イベントが重ねて届いてもよい（constitution 5-7）。
- すでにない（解放済みの）アセットを手放しても成功とする。

## 他モジュールへの公開

| 種類 | 内容 | 利用者 |
|------|------|--------|
| API | 画像のアップロードの受付、確定、アセットの解放、配信の URL の取得（まとめて） | 商品カタログ |

イベントは外に公開しない（アセット解放はモジュールの中だけで使う）。

## ストレージ

ストレージの操作は、ポート（`ObjectStorage`）の背後に置く。操作は、AWS（S3）と GCP（GCS）の両方にあるものだけにする（署名付きの PUT の URL、ファイルの情報、先頭の読み取り、配信のバケットへの書き込み、削除）。
画像の変換は、ポート（`ImageConverter`）の背後に置く。実装は、別のコンテナの imgproxy を HTTP で呼ぶ（plan 001 第 7.5 節）。設定は `ecsite.media.converter`。
実装は S3（AWS SDK v2）で、ローカルと CI は SeaweedFS で動かす。設定は `ecsite.media.storage`（環境変数で上書き。README の「環境変数」）。
