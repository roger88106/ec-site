# Spec 406：同じカートの支払待ちの注文を重ねない

種類：機能　規模：L　ステータス：草案

危険度：高

## 背景と目的

同じカートから、先の注文の与信の通知が届く前に、2 件目の注文を成立させられる。カートは注文の成立で変わらない（AC-144）。重複の防止は注文手続きごとである（AC-91）。このため、注文手続きを再作成すると 2 件目の注文が成立する。この spec では、支払待ちの注文があるカートで新しい注文を作らず、既存の注文の画面へ案内するようにする。

追跡の issue は #406。関わる文書は、[注文モジュール](../../03-機能仕様/order.md)、[カートモジュール](../../03-機能仕様/cart.md)、[注文の設計](../../02-設計/order.md)。

### 確認した範囲と限界

issue #406 の統合テストで、次を確認した。店舗画面は操作していない。

| 操作 | 結果 |
|------|------|
| 順に 2 回注文する | 別の注文が 2 件できる。在庫は 10 から 6 になる。両方を支払うと両方が受付になり、両方を出荷すると売上の確定が 2 件になる |
| 2 つのタブで注文手続き A、B を始め、A、B の順に注文する | 両方が成立する。在庫は 10 から 6 になる |
| 先の注文の与信の後に、先に始めていた注文手続きと新しい注文手続きから注文する | 先に始めていた手続きは 409、新しい手続きは 400（カートが空）になり、二重にならない |
| 支払の期限切れの後に、同じカートで注文する | 再び注文できる。これは意図した仕様である（[カートモジュール](../../03-機能仕様/cart.md)の「カート」） |

利用者は 2026-11-06 に、issue のコメントで次を決めた。同じカートの支払待ちの注文があるときは、注文手続きを開始したときに既存の注文の画面へ案内し、新しい注文を作らない。同じ商品を続けて注文する消費者は、先の注文を支払うか、期限切れを待つ。

## スコープ

| 含める | 含めない |
|--------|----------|
| 注文手続きの開始の拒否と案内 | 会員ごとの支払待ちの上限（#411） |

| 店舗画面の遷移と案内の文 | 支払待ちの注文のキャンセル |
| 機能仕様と設計の文書の更新 | |

## User stories

| US | 誰が | 何をできる | なぜ |
|----|------|------------|------|
| US-406-1 | 消費者 | 支払待ちの注文があるカートで注文に進もうとしたとき、その注文の画面へ案内される | 同じ内容を二重に注文し、二重に支払うことを防ぐため |

## 受け入れ条件

### US-406-1 支払待ちの注文の画面への案内（C / P1）

- **AC-406-1** カートに支払待ちの注文があるとき、注文手続きの開始は拒否され、新しい注文手続きを作らない。応答で、どの注文かを返す。
- **AC-406-2** AC-406-1 の拒否では、在庫の引当を変えない。前の注文手続きの引当も解かない。
- **AC-406-3** AC-406-1 の判定は、カートの品目が変わっていても、空でも同じ結果にする。購入の可否の判定より先に行う。
- **AC-406-4** 店舗画面は、AC-406-1 の拒否を受けたら、その注文の画面へ遷移する。支払待ちの注文があるので新しく注文できないことと、支払うか期限切れを待つことを示す。
- **AC-406-5** 注文手続きを始めた後に同じカートの注文が支払待ちになったときは、その注文手続きからの注文は拒否される。在庫を減らさず、応答で、どの注文かを返す。
- **AC-406-6** 店舗画面は、AC-406-5 の拒否を受けたら、AC-406-4 と同じくその注文の画面へ遷移し、同じ内容を示す。
- **AC-406-7** 同じカートの別の注文手続きから同時に注文しても、支払待ちの注文は 1 件だけ成立し、在庫は 1 件分だけ減る。他方は AC-406-5 と同じ結果になる。
  - Given：同じカートに支払待ちの注文がなく、2 つの注文手続きを始めてある。
  - When：2 つの注文手続きから同時に注文する。
  - Then：一方だけが成立して支払待ちの注文ができ、在庫が 1 件分だけ減る。他方は拒否され、応答で、成立した注文を返す。
- **AC-406-8** 同じ注文手続きの再送は、従来どおり作成済みの注文を返す（AC-91 を変えない）。注文が支払待ちかによらない。
- **AC-406-9** カートの注文が支払待ちでなくなった後は、同じカートで注文手続きを開始し、注文できる。支払待ちでなくなるのは、支払の期限切れによるキャンセルと、与信の成功による受付である。
- **AC-406-10** カートの持ち主でない会員の開始は、従来どおり 404 で、注文を返さない。注文手続きの持ち主でない会員の注文も同じ。
- **AC-406-11** 変更を適用した時点ですでに支払待ちの注文も、判定の対象にする。

## 業務ルール

- **BR-406-1** 「支払待ちの注文がある」は、注文の状態で判定する。支払の期限を過ぎ、期限切れのキャンセルが行われる前の注文も、支払待ちとして扱う。理由：キャンセルまで在庫が戻らず、2 件目を作ると在庫が二重に減るため。この間は、注文の画面に支払の操作が表示されない（支払えるのは期限の前だけである。AC-151）。消費者は期限切れのキャンセルを待つ。
- **BR-406-2** 判定の対象は、同じカートの注文だけにする。別のカートの注文は含めない。会員のカートは会員ごとに 1 つである（[カートモジュール](../../03-機能仕様/cart.md)の「会員のカート」）。

## 非機能要件

- **NFR-406-1** 同時の注文の防止は DB で保証する。複数のインスタンスで動かしても成り立つように、JVM 内のロックを使わない（constitution の「水平スケール」）。
- **NFR-406-2** 変更を適用する時点で同じカートに支払待ちの注文がすでに複数あっても、DB の移行を失敗させず、既存の注文を変えない。それらの注文は、支払いも期限切れも従来どおり処理する。

## Non-goals

| 項目 | 理由 |
|------|------|
| 会員ごとの支払待ちの注文の上限 | 別の問題（在庫の確保）で、#411 で扱う |
| 警告だけで新しい注文を許す | 利用者が、案内して新しい注文を作らない方針に決めた（2026-11-06） |
| 注文の成立でカートの品目を除く | AC-144 とカートの規則を変えることになり、期限切れの後に再び注文できなくなる |
| 支払待ちの注文のキャンセル | AC-158 を変えない。消費者は期限切れを待つ（利用者の決定） |
| 同じカートで同じ商品を続けて注文する別の手段 | 利用者が、先の注文を支払うか期限切れを待つ方針に決めた |
