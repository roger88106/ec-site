# エージェント用の振り返り

外から取り込んだ skill `retro`（`../retro/SKILL.md`）の、エージェント用の入口。`retro` の原文は変えない。観点の意味と、提案だけをして文書や設定は変えないことは `retro` に従う。観点の名前は訳さず、そのまま使う。

観点：Navigation、Automated checks、Coding standards、Global AGENTS.md、Tool economy、No-ops、Information access。

## 使う場面

| 場面 | 行うセッション |
|------|----------------|
| spec の後片付け（マージの後）。アーカイブの許可の有無によらず必ず行う | spec 担当のセッション |
| ステップと段の終わり | issue 担当のセッション |

## 手順

1. `retro` の手順 2「セッションの記録を読む」は使わない。記録（セッションの記録のファイル）は読まず、自分の文脈にある事実から書く。事実は、つまずいたこと、繰り返した作業、遅かったこと、足りなかった情報。
2. 読んでよいのは次だけ。
   - 自分の作業ツリーの tasks。
   - `/.local/retro/` にある既存の振り返りの見出し。問題の短い名前の重複を数えるために読む。本文は読まない。
3. 観点ごとに、改善点の候補を挙げる。なければ書かない。
4. 重要な順に、次の形でファイルに書く。

## 出力

- 置き場所：`/.local/retro/<yyyyMMddHHmm>-<spec の番号か issue>.md`。1 つの振り返りを 1 つのファイルにする。環境の改善点はセッションごとの記録で、Git の履歴に残す必要がないため、Git には入れない。spec 247 が `/.local/` の構成を変えたら、置き場所を合わせる。
- 1 つの問題を 1 つの節にする。節の見出しは問題の短い名前で、中身は次の 3 つ。
  - 観点：`retro` の観点の名前
  - 起きたこと
  - 提案：skill への追記、自動の確認の追加、文書の移動など。修正はしない
- 問題の短い名前は、ステップの終わりに数える（skill `sessions` の [ステップと段の終わり](../sessions/rounds.md)）。同じ問題には、既存のファイルと同じ名前を使う。
