# plan・tasks の照合と文書のレビュー

skill `review` の手順 7・8 の詳細とひな形。

## 手順

1. plan と tasks を照合する。plan と tasks を、それぞれ書き終えたときに行う。日本語だけのサブエージェント（汎用）に、spec の各 AC・DC と plan の決定（tasks のときは、各段階の完了の条件と各タスク）を 1 件ずつ照合させる。tasks では、次の 4 点も見させる。(1) 完了の条件が spec の AC・DC・DN より厳しい・緩いもの。(2) 前のタスクが後のタスクで作るものを使う順序。(3) 共有する部品（共通の関数、生成するファイル、共通の設定、AC 一覧など）を変えるタスクと、それを使うタスクの間の、書いていない依存。(4) 並行する spec との変えるファイルの重なりと実装の順序が、plan（規模 M は spec の tasks）に書いてあるか。結果は表（AC・DC、plan の節またはタスク、合っている・抜けている・食い違う、説明）で受け取る。抜けと食い違いは、確認の前に修正する。
   完了の条件：全ての AC・DC が表にある。
2. 文書をレビューする。日本語だけのサブエージェント（汎用）に、書き方の見本（[エージェントの作業フロー](../../../docs/rules/subagents.md)、[spec 018 の plan](../../../docs/specs/archive/mvp/018-docs-and-tools/plan.md)）と [文書の言い回しと論理の規則](../docs/tech-writing.md) を渡し、不自然な言い回しを候補として挙げさせる。結果は表（ファイル、行、今の書き方、修正案、理由）で受け取り、spec 担当のセッションが採否を判定する。spec・plan・tasks を書き終えたときと、spec の最後に行う。
   完了の条件：全ての候補の採否が決まっている。

## 指示のひな形（plan・tasks の照合）

手順 7 で使う。日本語だけで書く。tasks の照合では、＜tasks のとき＞の行を加える。

```
あなたは、spec と plan（＜tasks のとき＞と tasks）を照合する担当です。実装の過程は知らされていません。

## 対象
- spec：<パス>
- plan：<パス>
- ＜tasks のとき＞tasks：<パス>

## 観点
spec の各 AC・DC と、plan の決定を 1 件ずつ照合する。
＜tasks のとき＞spec の各 AC・DC・DN と plan の決定が、どのタスクで行われるかを照合する。各段階の完了の条件と各タスクの条件が、spec より厳しくないか・緩くないかを見る。前のタスクが後のタスクで作るものを使っていないかを見る。共有する部品（検査の script の共通の関数、生成するファイル、共通の設定、AC 一覧などの共有の文書）を変えるタスクと、それを使う・前提にするタスクの間に、依存に書いていない順序の制約がないかを見る（特に `[P]` のタスクの間）。

## 結果
<結果の書き先> に、次の表で書く。AC・DC を全て載せる。
| AC・DC | plan の節（＜tasks のとき＞タスク） | 判定（合っている・抜けている・食い違う） | 説明 |

- 判定の根拠は、spec と plan の本文に置き、出典（ファイル:行）を書く。出典のない理由は書かない。
- 他のファイルは変更しない。返すのは件数（合っている、抜けている、食い違う）だけ。
```

## 指示のひな形（文書のレビュー）

手順 8 で使う。日本語だけで書く。

```
あなたは、日本語の技術文書のレビュー担当です。実装の過程は知らされていません。

## 対象
<新しく書いた、または変えた文書のパス>

## 見本
目指す書き方の見本：<見本のパス>
言い回しと論理の規則：.claude/skills/docs/tech-writing.md（1〜5 の表を当てはめる）

## 観点
技術文書として不自然な言い回しを、候補として挙げる。見本の書き方に近づける。次の 2 つを両方見る。
- 和語の言い換え：技術文書で一般的な語に替える（規則の「用語」の表）。
- 論理、読む人の負担、中身のない言い回し、翻訳調の比喩と擬人化、冗長さ（規則のその他の表）。

## 守ること
- 意味、番号、節の番号、表の構成を変えない。
- 識別子、文書の題名、節の名前を変えない。
- プロジェクトの用語集の語を一般の語に替えない。
- 理由には出典（規則のファイル:行）を書く。出典のない理由は書かない。

## 結果
<結果の書き先> に、次の表で書く。
| ファイル | 行 | 今の書き方 | 修正案 | 理由 |

- 対象のファイルは変更しない。返すのは候補の件数だけ。
```
