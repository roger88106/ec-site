# Spec 566：文書の検査の script の、参照と言い換えの一覧の漏れと誤検出を修正する

種類：整理　規模：M　ステータス：確定

危険度：高

## 背景と目的

文書の検査の script のうち、参照の検査（`scripts/ci/docs/doc-refs.mjs`）と日本語の文の検査（`scripts/ci/ja/ja-text.mjs` と言い換えの一覧 `scripts/ci/ja/ja-text.json`）に、検出の漏れと誤検出がある。spec 283（pull request #285）のレビューの推奨として挙がった。今の文書に該当する違反は少ないが、書き方によって将来の誤りを見逃す。消費者・運営者に見える振る舞いは変えない。

追跡の issue は #566。sub-issue は #290、#291、#241 で、全体の issue #544 の一部である。

issue の後に状態が変わったものがある（全体のブランチの commit 7a915267f で確認）。

- #290 の 4 か所の「決済の設計書「Stripe」」の形と、`docs/06-手順書/ci.md` の `ac-check` の行の「の」のない参照は、既に「の」のある形に書き換わっている。修正する対象がない。
- #241 は、commit 232ad437d で、依存とライセンスの方針の表が識別子を写さず、`policy.json` の一覧のキー（`conditional.licenses`）と主な例だけを書く形になった。`policy.json` の `$comment` に「文書には写さない」とある。照合する写しがない。

決定：

- 判定の区分（[文書の構成](../../05-開発規則/doc-structure.md)の「形を判定する検査」）は、どの検査も誤りの防止とする。誤って書いたものを見つけ、意図して作った回避は対象にしない。
- 新しい検査の script は作らない。既存の 2 つの検査（参照の検査、日本語の文の検査）と commit の前の hook を広げる。
- 存在しないパスは Markdown だけを対象にする。理由：コードとコメントの存在しないパスは、テストの入力例とパスの置き換え例が多く、誤検出になるため（コードとコメントは 600 件を超え、Markdown は 39 件だった）。issue 担当のセッションが、利用者の代わりに確認した。
- 存在しないパスの対象は、`docs/`・`scripts/`・`backend/`・`frontend/`・`e2e/`・`api/`・`docker/`・`showcase/`・`.claude/`・`.github/` で始まり、直前が `/`・英数字でない語とする。`api/` は `api/openapi/` で始まるものだけにする。理由：フロントの `api/cart.ts` のような相対のパスと、`db/seed/e2e/` の `e2e/` のように語の途中の `/` の後にあるものを区別するため。末尾が `/` のものは、フォルダーがあるかを見る（実在するファイルの末尾に `/` を付けた形は検出する）。
- Markdown の存在しないパスは、コードブロックの外を読み、インラインコードの中を含める。見出しの参照が続かないパスも対象にする。パスの終わりは、インラインコードの中は空白か「まで、外は空白・全角の句読点・括弧・かぎ括弧までとする。末尾の `:<行>`・`:<行>-<行>`・`#<見出し>` は、除いてから確認する。理由：フォルダーの名前に漢字があり、字の種類では終わりを決められないため。
- パスがあるかは、Git が追跡するファイルとそのフォルダーの一覧と、大文字と小文字を区別して照合する。理由：Windows では大文字と小文字を区別せずに通り、CI だけで失敗するのを防ぐため。
- 追跡していないが参照してよい場所は、script の一覧で除く：`.claude/settings.local.json`、`.claude/worktrees/`、`.local/`、`docker/.env`、パスの中に `build/`・`node_modules/`・`.next/`・`dist/`・`generated/` を含むもの。`.gitignore` の判定は使わない。理由：`.claude/` の下は許可した名前以外を全て無視するので、綴りの誤りを見逃すため。
- 次の文書は、存在しないパスの検査から除く（当時のパスを書く記録と、まだないファイルを書く文書）：`docs/07-記録/`、`.claude/skills/review/evals/`（当時の commit のパスで、直せない）、`docs/08-spec/`（進行中の spec と tasks は、まだないファイルのパスを書く）。
- 拡張子がなく 1 行目が `#!` で始まるファイルは、Git が追跡するものを、コードとして読む。今は `scripts/dev/hooks/pre-commit` と `commit-msg` が当たる。
- 節の番号の参照は、漢数字は「第」のある形（`第三節`、`第三・四節`、`第三〜五節`、`第十二節`）だけを読む。「第」のない漢数字（`一節`、`三節に分ける`）と、節でない語（`第三章`、`第三段`、`第三条`）は読まない。`§` は、「第」のない `N 節` と同じく、参照先の文書が直前で決まるとき（文書の名前、パス、リンク、`この文書の`、`本書の`）だけ失敗にする。全角の数字、`§§3-4`、`§3〜5` も読む。外の規格（`RFC 9457 §3.1`）と外のリンクの後の `§` は、参照先の文書が決まらないので通す。
- `の『…』` は、見出しの参照として読む。ただし、『』の中に文字列の連結・埋め込み（`"`、`+`、`${`）を含むものは読まない（実例：`ModuleDiagramTest.java` の文字列）。文書の名前の後の閉じる印に「』」を加える（`『見本の文書』の「ない」` を読む）。
- 太字（`**名前**`、`__名前__`、太字のリンク、太字の後の空白）は、印を除いて文書の名前として読む。
- 文書の名前・リンクの直後の「」と、パスの後に半角・全角の空白を挟んだ「」は、最初の「」が参照先の文書の見出しに当たるときだけ失敗にし、「の」を入れるよう示す（続く `の「」` も確認する）。当たらないときは、語の引用として通す。理由：語の引用（`用語集「写し」`）と見分けるため。空白を挟まないパスの直後の「」は、今のとおり見出しの参照として読む（見出しがなければ失敗にする）。理由：[文書の構成](../../05-開発規則/doc-structure.md)の「参照」が、コメント以外のパスの直後に見出しを書く形を許すため。今のテスト「「の」のない「」は、文書の名前の直後…では読まない」と、パスの後の空白・改行を挟んだ「ない」を読まないテストは、見出しに当たらない例として残す。
- 行をまたぐ形は、行が文書の名前・リンク・パス（とその後の「の」）で終わり、次の行（コメントの印 `//`・`#`・`*`・`--` と前の空白を除く）が「」か `の「` で始まるときだけ、2 行をつないで読む。つないだ形にも、上の「の」のない「」の規則を当てる。Markdown は、同じ段落の続きの行だけをつなぐ（見出し、表、リストの項目の始め、コードブロックの境目ではつながない）。
- 見出しの参照の後に、`と`・`、`・`・`・`や` か区切りなしで続く「」は、3 つ目以降も含めて、同じ文書の見出しとして確認する。
- 「第」のない `N 節` は、参照先の文書が直前で決まるとき（文書の名前、パス、リンク、`この文書の`、`本書の`）と、点を含む番号（`4.2 節`）のときだけ失敗にする。個数を表す `3 節に分ける` と `全 5 節` は通す。行の始め、リストの印・表のセル・`。`・開き括弧の後（`- 3 節に分ける`、表のセルの `3 節`、`（3 節）`）も通す。`第 3 節` は今のとおり検出する。
- 活用の形は、語を pattern に替えて書く。`足す` は `足し`・`足さ`・`足す`・`足せ`・`足そ`（漢字の直後は除く。`付け足す`・`足し忘れ`・`足します`・`足そう` も検出する）、`要る` は `要ら`・`要り`・`要る`・`要れ` とする。`要る` は、`要` の直前が `必`・`重`・`不`・`主`・`概`・`需` のとき（`必要`・`重要`・`不要`・`主要`・`概要` などの語の一部）だけ除く。`設定要らない` は検出する。漢字の直後の `不足して`、`必要らしい`、`重要らしい` は検出しない。`足し算` は、言い換えの説明で使う普通の語なので許容用語にする。
- 語ごとの除き方：`worktree` は大文字と小文字を区別しない（`Worktree`・`WORKTREE`・`WorkTree`）が、直前が英数字・`_` のもの（識別子の一部。`listWorktrees`）は当てない。カタカナの `ワークツリー` も error にする。`判定機` は `判定機能` に当てない。漢字・カタカナの直後の `箱の`（`ゴミ箱の`、`道具箱の`）は当てない。`資料を集める役` は `役割` が続く形に当てない。`口頭で伝える` は当てず、`口頭語` だけを当てる。
- インラインコードの中の error の語は、かな・漢字を含むインラインコードの中だけを検査する。「かな」はひらがなとカタカナの両方とする。英字だけのインラインコード（`git worktree`、`.claude/worktrees/`）は今のとおり見ない。コミットメッセージにも同じ規則を当てる。
- 使わない語の例として書く場所は、`ja-text.json` に、ファイル・見出し・理由の一覧で許可する。見出しの許可は、その見出しの下の、次の同じレベル以上の見出しまで（子の見出しを含む）とする。使われなくなった許可は失敗にする（許容用語と同じ）。場所はあるが、その中から error の語がなくなった許可も同じである。日本語を含むインラインコードの中の許容用語は、使われているとみる。
- 許可の一覧は、今の文書の 2 か所を載せる。[文書の書き方](../../05-開発規則/writing.md)の「用語の選び方」（造語の例。`判定器`・`口頭の語`・`書面語`・`無記憶のレビュー役`・`指令`・`効く`）と、[エージェントの作業フローの調べた仕組みと実績](../../07-記録/subagents-results.md)の「校閲の評価の結果」（`護り` を評価の例として挙げる）。
- この spec の例と DC は、かな・漢字を含むインラインコードに使わない語を書く。T566-01-05 で、許可の一覧にこの spec のファイルを加え（見出しを書かない許可は、ファイルの全体を許可する）、T566-01-11 でアーカイブに移すときに外す。理由：アーカイブは日本語の文の検査から除かれており、外さないと、使われなくなった許可として失敗になるため。許可の一覧はファイルにだけ書けるので、この spec の commit のメッセージには、使わない語をインラインコードで書かない（語の種類を言葉で書く）。
- warning の `[高低]の|高・必須` の pattern が「重要度（高・必須・推奨）」に当たるので、`・推奨` が続く列挙（`（高・必須・推奨）`、`重要度：高・必須・推奨`）だけを当てない形に絞る。`（高・必須の指摘を直す）` は検出する。
- 読点を数えない「参照だけの項目」のうち、空白のない語 ＋ `の「…」` の形は、語が文書の名前（参照の検査と同じ文書の名前の一覧。空白を含む名前も、一覧に一致すれば）と、パス（`.md` で終わる語）のときだけ参照と見る。一致は語の全体の一致で、末尾の一致にしない。
- commit の前の hook は、検査の段で ja-text の全体を実行し、続く warning の段（`ja-text --warning --added`）で再び全てのファイルを読む。warning の段は、追加行のあるファイルだけを読み、error の語は数えない。理由：error の語は検査の段で数え済みのため。
- 既存の文書とコードに新しい違反が見つかったら、本当の誤りは同じタスクで修正し、件数を結果に書く。誤検出なら判定を再検討する。判定を変える必要が決定の範囲を超えるときは、修正の前に issue 担当のセッションに知らせる。

検出すべき例と検出してはいけない例を、検査ごとの表に示す。最初の `[テスト]` の前に、spec の文脈を持たないレビュー役に表を読ませ、例を追加させる（[文書の構成](../../05-開発規則/doc-structure.md)の「形を判定する検査」）。

## 目的と完了条件

### DS-566-1 参照の検査が、書き方によって見逃していた誤りを見つけ、誤って失敗にしない（D / P1）

- **DC-566-1** 「第」のある漢数字の節の番号（`第三節`、`第三・四節`）と `§3` を、節の番号の参照として失敗にする。「第」のない漢数字と、外の規格の `§` は通す。
- **DC-566-2** `の節「…」` と `の『…』` を、見出しの参照として読む。『』の中に文字列の連結・埋め込みを含むものは読まない。
- **DC-566-3** 文書の名前・リンクの直後の「」（空白を挟んでもよい）と、パスの後に空白を挟んだ「」は、最初の「」が参照先の文書の見出しに当たるときだけ失敗にし、「の」を入れるよう示す。見出しに当たらないときは、語の引用として通す。
- **DC-566-4** 行が文書の名前・リンク・パス（とその後の「の」）で終わり、次の行（コメントの印と前の空白を除く）が「」か `の「` で始まるときだけ、2 行をつないで読む。Markdown は、同じ段落の続きの行だけをつなぐ。
- **DC-566-5** Markdown（コードブロックの外。インラインコードの中を含む）に書いた、リポジトリのルートからのパスの先が、Git が追跡するファイルとフォルダーの一覧に（大文字と小文字を区別して）なければ失敗にする。見出しの参照が続かないパスも対象にする。末尾の `:<行>` と `#<見出し>` は除いて確認する。
- **DC-566-6** 存在しないパスの検査は、対象の始まりの一覧（決定のとおり）に当たる語だけを見る。追跡しない参照してよい場所（決定の一覧）、プレースホルダー・glob・`…` を含むもの、URL の中のもの、`docs/07-記録/`・`.claude/skills/review/evals/`・`docs/08-spec/` の中のものは見ない。
- **DC-566-7** 太字（`**開発の進め方**`、`__…__`、太字のリンク、太字の後の空白）の文書の名前を、印を除いて文書の名前として読む。
- **DC-566-8** Git が追跡する、拡張子がなく 1 行目が `#!` で始まるファイルを、コードとして読む。
- **DC-566-9** 見出しの参照の後に `と`・`、`・`・`・`や` か区切りなしで続く「」は、3 つ目以降も含めて、同じ文書の見出しとして確認する。
- **DC-566-10** 「第」のない `N 節` は、参照先の文書が直前で決まるときと、点を含む番号のときだけ失敗にする。`3 節に分ける`、`全 5 節`、行の始め・リストの印・表のセル・`。`・開き括弧の後の `N 節` は通す。
