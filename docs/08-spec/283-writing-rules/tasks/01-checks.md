## タスク

実装は実装役のサブエージェントに任せる。`[リスク]` のタスクは高性能の区分のモデルで行う。

- 組：`[テスト]` のタスクと、その次の実装のタスクは組である。同じ実装役が続けて行い、同じ commit にする（[開発の進め方](../../../05-開発規則/workflow.md) 第 2.1 節）。

- [x] **T283-01-01** 表のセルごとに、文の字数の合計を測る。`--stats` に、その合計の分布（40、60、80 字以上）を加え、アーカイブの外の文書で測る。直近の 5 つの pull request で、追加行のうち警告が出る見込みの数も測る（字数 100、読点 5、セルの閾値の案）。差分の測定は、スクラッチパッドの script で行う。結果を書き、セルの閾値を決める（DC-283-22、24）。
  - 依存：なし
  - 範囲：`scripts/ci/ja-text.mjs`（`--stats` だけ）、`scripts/ci/ja-text.test.mjs`
  - 確認方法：結果の数。1 つの pull request で警告が 10 を超えるなら、利用者に閾値を確認する。
  - 結果：アーカイブの外の文書には、表のセルが 3143 ある。セルごとの文の字数の合計は、 40 字以上が 800、60 字以上が 346、80 字以上が 196 だった。直近の 5 つの pull request の追加行で、警告が出る見込みの数は次の表のとおり。#280 は名前の変更を検出せずに測ったので、移したファイルを全て追加行として数えた。

    | pull request | 追加行の文 | 文の警告（字数 100 か読点 5 以上） | 文の警告とセル 60 字以上 | 文の警告とセル 80 字以上 |
    |--------------|------------|------------------------------------|--------------------------|--------------------------|
    | #280 | 604 | 7 | 13 | 11 |
    | #278 | 610 | 13 | 23 | 17 |
    | #275 | 143 | 4 | 6 | 6 |
    | #269 | 744 | 22 | 33 | 26 |
    | #268 | 1206 | 30 | 54 | 47 |

  - 決定：セルの閾値は 80 字にする。字数 100、読点 5 は変えない（利用者、2026-10-30）。理由：警告だけで失敗にしないので、大きな pull request で 10 を超えても、pull request の前のレビューで 1 件ずつ読めば足りる。#268 でも、追加行の文の約 4% である。名前を変えたファイルの扱いは T283-01-04 で決める。
