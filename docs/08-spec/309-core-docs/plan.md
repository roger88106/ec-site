「正本を 1 つにする」から「本 spec の文書の完了の条件」までの表の DC の列は、`DC-309-` の後の番号だけを書く（`1` は DC-309-1）。本文では `DC-309-` を付けて書く。

共通の決定：

- 危険度は高である（spec の冒頭）。理由：`AGENTS.md`、constitution、`docs/05-開発規則/`、`.claude/` を変え、`scripts/ci/risk.json` の「エージェントの規則と設定」の経路に当たるため。マージは利用者が許可する。
- レビューの profile は「節約」とする（issue 担当が決めた）。理由：週の使用量が約 89% であるため。利用者は今の期間に限り「週の使用量を使い切ってよい」とした。危険度が高いので、段階の最後の重要な観点のレビューは profile によらず高性能で行う（[エージェントの作業フロー](../../05-開発規則/subagents.md)の「レビューの時点と profile」）。
- hook、CI の検査の script、認証・支払・権限の経路は変えない。そのため、pull request の前の文脈を持たない高性能のレビュー役は加えず、セキュリティのレビューも行わない。
- 実装は実装役（汎用）に 1 タスクずつ任せる。文書の本文は、spec 担当が日本語の要点を書き、実装役が書く。
- 1 タスクを 1 commit にする。
- push は段階の最後に行う。draft の pull request は、spec・plan・tasks を利用者に見せるときに作る（issue 担当の指示）。作ったら、追跡の issue にリンクを書く。
- 並行する #307・#308 との重なりは、[spec](spec.md)の「依存」のとおりである。#310 が加える検査が本 spec の文書を失敗にしないかは、実装を始める前の照合で `develop` を取り込んだ後の `check-all.sh` で確認する。
- 段階は番号の順に進める。段階 1 と 2 は同じ文書（`subagents.md`、`AGENTS.md`、constitution）を変えるため。
