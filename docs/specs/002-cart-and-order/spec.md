# Spec 002：カートと注文

ステータス：確定

## 1. 背景と目的

コアフローの「カート → 注文」を作る。**消費者が商品をカートに入れて注文し、運営者がその注文を管理できる状態**にする。

- 消費者が、ログインせずに（ゲストとして）カートを使い、お届け先を入力して注文できる。
- 注文手続きに進んだ時点で在庫を一定時間引き当て、入力している間に売り切れないようにする。在庫数を超えて注文を受け付けない。
- 金額と消費税額を、カート・注文手続き・注文のどこでも同じ方法で計算する。注文には、注文時点の価格と税率の写しを残す。
- 消費者が注文のキャンセルを申請し、運営者が承認するとキャンセルになり、在庫が戻る。
- 運営者が、注文を一覧・参照できる。

決済は扱わない（決済の spec）。本 spec の注文は、成立した時点で「受付」となる。決済を加えるときは、その前に「支払待ち」の段階を足す。

AC・US・BR・NFR の番号は、spec 001 から続けて振る（テスト名で番号が重ならないようにするため）。

## 4. User stories と受け入れ条件

### US-14 商品をカートに入れる（C / P1）

- **AC-72** C 側に表示される商品（BR-2）の、選べるバリアント（販売停止でなく、在庫あり）を、数量を指定してカートに入れられる。選べないバリアントは入れられない。
- **AC-73** カートを持っていなければ、最初に商品を入れたときに作られる。カートはそのブラウザーでだけ使え、別の端末やブラウザーとは共有されない（ログインがないため）。（ログインしている間は spec 003 の AC-121 で変更）
- **AC-74** カートにあるバリアントをもう一度入れると、数量を合算する。
- **AC-75** 1 品目の数量は 1〜10。1 つのカートに入れられるのは 30 品目まで。超える場合は拒否される。
- **AC-76** 入れた後の数量が、その時点の販売可能数（BR-11）を超える場合は拒否される。数量そのものは示さない（AC-64）。カートに入れても在庫は引き当てない。

### US-15 カートを見る・変更する（C / P1）

- **AC-77** 品目ごとに商品名、軸の値、画像、単価（BR-4）、数量、小計を表示し、あわせて商品の合計、送料（BR-6）、総額、税率ごとの消費税額（BR-8）を表示する。
- **AC-78** 品目の数量を変更（AC-75、76 の範囲で）・削除できる。
- **AC-79** 単価は常に現在の価格で表示する。カートに入れた時点の価格は保持しない。
- **AC-80** 購入できなくなった品目は、理由とともに「購入できません」と示し、合計に含めない。理由は次のいずれか。
  - 商品が C 側に表示されなくなった（BR-2）
  - バリアントが販売停止になった
  - 販売可能数がない、またはカートの数量より少ない
- **AC-81** 最後に変更してから 30 日たったカートは、空のカートとして扱う。

### US-16 注文する（C / P1）

- **AC-82** カートから注文手続きに進むと、全品目をカートの数量だけ 15 分間引き当てる（BR-11）。1 品目でも引き当てられなければ、どれも引き当てず、引き当てられなかった品目を示す。
- **AC-83** 同じ在庫に同時に引当が来ても、在庫数を超えて引き当てない。
  - Given：在庫数 1 のバリアントを、2 人がそれぞれ 1 個ずつカートに入れている
  - When：2 人が同時に注文手続きに進む
  - Then：1 人だけ引き当てられ、もう 1 人には在庫不足と示す
- **AC-84** 引当は次のときに解かれる。注文手続きに進み直すと、その時点のカートで引き当て直す（期限も 15 分に戻る）。
  - 注文が成立した（在庫の減算に置き換わる）
  - カートを変更した
  - 15 分たった
- **AC-85** 注文手続きでは、カートの内容、送料、総額、税率ごとの消費税額を確認し、メールアドレスとお届け先（氏名、郵便番号、都道府県、住所、電話番号）を入力して注文できる。（メールアドレスは spec 003 の AC-127 で変更）
- **AC-86** 入力の形式。
  - 郵便番号：数字 7 桁（ハイフンは任意）
  - 都道府県：47 都道府県のいずれか
  - 電話番号：数字 10〜11 桁（ハイフンは任意）
  - 氏名・住所：空白不可、長さの上限は plan で決める
- **AC-87** 注文が成立すると、全品目の在庫数を注文数だけ減らし、引当を解く。引当の期限が切れていた場合は、注文の時点で引き当て直し、1 品目でも足りなければ注文全体が拒否され、どの在庫も減らない。
- **AC-88** 空のカート、または購入できない品目（AC-80）を含むカートは注文できない。
- **AC-89** 確認した総額と、注文時点で計算した総額が異なる場合（その間に価格や税率が変わった）は、注文を拒否し、変わったことを示す。
- **AC-90** 注文が成立すると注文番号を振り、カートを空にする。（カートを空にする所は、[spec 007](../007-payment/spec.md) の AC-147 で置き換えた。与信の成功で、注文した品目をカートから除く）
- **AC-91** 同じ注文の送信が繰り返されても（二度押し、通信の再送）、注文は 1 件だけ作られる。
- **AC-92** 注文には、注文時点の商品品番、バリアント品番、商品名、軸の値、税抜単価、税率、税込単価を写しとして残す。その後に商品や税率が変わっても、注文の内容と金額は変わらない（BR-5、constitution 7.1）。
- **AC-107** 注文による在庫数の減算と、キャンセルによる戻しは、在庫の調整履歴（AC-45）に、理由「注文」「注文のキャンセル」と注文番号とともに残る。運営者の在庫調整では、これらの理由を選べない。

### US-17 注文を確認する（C / P1）

- **AC-93** 注文の直後に、注文番号、注文日時、明細、金額の内訳（BR-7、8）、お届け先、状態を表示する。
- **AC-94** 注文の URL を知っていれば、後から同じ内容を見られる。URL は注文番号から推測できない。（spec 003 の AC-131 で変更）

### US-18 注文のキャンセルを申請する（C / P1）

- **AC-95** 注文の URL の画面から、「受付」の注文のキャンセルを申請できる。理由（任意、500 文字まで）を添えられる。申請すると「キャンセル申請中」になり、在庫はまだ戻らない。（申請できるのは注文した会員だけ：spec 003 の AC-131）
- **AC-96** キャンセルの申請は、1 つの注文につき 1 回だけ。申請中の注文にもう一度申請しても、成功し、何も変わらない。却下された注文は、もう一度申請できず、画面で申請が承認されなかったことと、問い合わせ先を示す（その後のキャンセルは、問い合わせを受けた運営者が AC-103 で行う）。

### US-19 注文を一覧・絞り込みする（B / P1）

権限：`order:read`

- **AC-97** すべての注文を、注文日時の新しい順に一覧できる。注文番号、注文日時、氏名、総額、状態を表示する。
- **AC-98** 注文番号の前方一致、状態、注文日の範囲（BR-3）で絞り込める。
- **AC-99** ページ単位で取得できる。

### US-20 注文の詳細を見る（B / P1）

権限：`order:read`

- **AC-100** 注文番号、注文日時、状態、明細（AC-92 の写しと数量、小計）、金額の内訳（BR-7、8）、メールアドレス、お届け先、キャンセルの申請（日時、理由、結果）、運営者の判断によるキャンセルの理由を表示する。

### US-21 注文をキャンセルする（B / P1）

権限：`order:write`

- **AC-101** 「キャンセル申請中」の注文の申請を承認すると、キャンセルになり、明細の数量だけ在庫数を戻す。
- **AC-102** 申請を却下すると「受付」に戻る。
- **AC-103** 運営者の判断で、「受付」または「キャンセル申請中」の注文を、申請の承認によらずにキャンセルできる。理由（必須、500 文字まで）を記録する。在庫の戻しは AC-101 と同じ。
- **AC-104** キャンセルと在庫の戻しは、両方が行われるか、どちらも行われないかのどちらか。
- **AC-105** キャンセル済みの注文へのキャンセル・承認は、成功し、在庫は戻さない（constitution 9 の状態の切り替え）。キャンセル済みの注文の申請は却下できない。
- **AC-106** キャンセル済みの注文も、一覧・詳細に表示される。

## 5. 業務ルール

spec 001 の BR-1〜5 に加える。

- **BR-6 送料**：全国一律 1,000 円（税込）。1 注文に 1 回かかり、商品の合計によらない。標準税率（10%）の対象。金額は設定で変えられる（運営者の画面はない）。
- **BR-7 金額**：カート、注文手続き、注文で同じ計算をする。
  - 小計 ＝ 税込単価 × 数量。税込単価は BR-1 で計算する。
  - 総額 ＝ 小計の合計 ＋ 送料。
  - 価格と税率を判定する時点は、カート・注文手続きでは表示の時点、注文では注文日時。
- **BR-8 消費税額**：税率ごとに、その税率の対象の税込金額（小計と送料）を合計し、合計 × 率 ÷（100 ＋ 率）で 1 回だけ計算する。1 円未満は切り捨て。品目ごとには端数処理しない（適格請求書の端数処理のルール）。
  - 例：10% の対象が 2,970 円 ＋ 送料 1,000 円 ＝ 3,970 円 → 消費税額 360 円。8% の対象が 1,332 円 → 消費税額 98 円
- **BR-9 注文の状態**：
  - 「受付」→「キャンセル申請中」（消費者の申請）→「キャンセル」（承認）または「受付」（却下）
  - 「受付」→「キャンセル」（運営者の判断）
  - 「キャンセル」からは、どの状態にも戻せない。
- **BR-10 注文番号**：注文ごとに一意で、人が読み上げられる番号。識別子ではなく属性（BR-5）。形式は plan で決める。
- **BR-11 引当と販売可能数**：
  - 販売可能数 ＝ 在庫数 − 有効な引当の数量の合計。期限の切れた引当は数えない。
  - 引当は在庫数を減らさない。在庫数を減らすのは注文の成立だけ。
  - C 側の在庫の有無（AC-56、62〜64）とカートへの追加（AC-76）は、販売可能数で判定する。
  - 運営者の在庫調整（AC-42、43）は引当を考えない。販売可能数より多く減らす調整も受け付け、その場合は引当中の注文が在庫不足で成立しないことがある。

## 6. 非機能要件

- **NFR-2** 引当、注文の成立と在庫の減算、キャンセルと在庫の戻しは、強い一貫性で行う（constitution 6）。結果整合にしない。
