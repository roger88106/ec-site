- tag と Release のタスク（順 6）とブランチの削除のタスク（順 7）のチェックは、それらを行った後に、チェックと結果だけを書く小さな pull request（3 回目）で付ける。tag は 2 回目のマージの commit に付けたまま、3 回目の後に付け直さない。理由：2 回目の pull request で先にチェックを付けると、記録が実際の作業より先になるため（2026-10-21 利用者）。
- DC-214 の「tasks が全て完了」は、3 回目のマージで満たす。

## 7. 用語集

- 「受け入れ確認」を[用語集](../../design/glossary.md)の「開発」の節に追加する（skill `review` の「全体のレビュー」と同じ意味）。
- 「事前知識なしのエージェント」は本 spec の中だけで使うので、追加しない。
- 「アーカイブ」は既にある。パスの記述を確認するだけ。
