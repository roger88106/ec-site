# Spec 566：文書の検査の script の、参照と言い換えの一覧の漏れと誤検出を修正する

種類：整理　規模：M　ステータス：確定

危険度：高

## 背景と目的

文書の検査の script のうち、参照の検査（`scripts/ci/docs/doc-refs.mjs`）と日本語の文の検査（`scripts/ci/ja/ja-text.mjs` と言い換えの一覧 `scripts/ci/ja/ja-text.json`）に、検出の漏れと誤検出がある。spec 283（pull request #285）のレビューの推奨として挙がった。今の文書に該当する違反は少ないが、書き方によって将来の誤りを見逃す。消費者・運営者に見える振る舞いは変えない。

追跡の issue は #566。sub-issue は #290、#291、#241 で、全体の issue #544 の一部である。

issue の後に状態が変わったものがある（全体のブランチの commit 7a915267f で確認）。

- #290 の 4 か所の「決済の設計書「Stripe」」の形と、`docs/06-手順書/ci.md` の `ac-check` の行の「の」のない参照は、既に「の」のある形に書き換わっている。修正する対象がない。
- #241 は、commit 232ad437d で、依存とライセンスの方針の表が識別子を写さず、`policy.json` の一覧のキー（`conditional.licenses`）と主な例だけを書く形になった。`policy.json` の `$comment` に「文書には写さない」とある。照合する写しがない。

決定：

- 判定の区分（[文書の構成](../../05-開発規則/doc-structure.md)の「形を判定する検査」）は、どの検査も誤りの防止とする。誤って書いたものを見つけ、意図して作った回避は対象にしない。
- 新しい検査の script は作らない。既存の 2 つの検査（参照の検査、日本語の文の検査）と commit の前の hook を広げる。
- 存在しないパスは Markdown だけを対象にする。理由：コードとコメントの存在しないパスは、テストの入力例とパスの置き換え例が多く、誤検出になるため（コードとコメントは 600 件を超え、Markdown は 39 件だった）。issue 担当のセッションが、利用者の代わりに確認した。
- 存在しないパスの対象は、`docs/`・`scripts/`・`backend/`・`frontend/`・`e2e/`・`api/`・`docker/`・`showcase/`・`.claude/`・`.github/` で始まる語とする。`api/` は `api/openapi/` で始まるものだけにする。理由：フロントの `api/cart.ts` などの相対のパスと区別するため。末尾が `/` のものは、フォルダーがあるかを見る。
- Markdown の存在しないパスは、コードブロックの外を読み、インラインコードの中を含める。見出しの参照が続かないパスも対象にする。
- 拡張子がなく 1 行目が `#!` で始まるファイルは、Git が追跡するものを、コードとして読む。今は `scripts/dev/hooks/pre-commit` と `commit-msg` が当たる。
- 文書の名前・リンクの直後の「」は、見出しに当たるときだけ失敗にし、「の」を入れるよう示す。見出しに当たらないときは、語の引用として通す。理由：語の引用（`用語集「写し」`）と見分けるため。今のテスト「「の」のない「」は、文書の名前の直後…では読まない」は、見出しに当たらない例として残す。
- 行をまたぐ形は、行が文書の名前・リンク・パス（とその後の「の」）で終わり、次の行（コメントの印と前の空白を除く）が「」で始まるときだけ、2 行をつないで読む。Markdown の段落の折り返しも同じ条件にする。
- 「第」のない `N 節` は、参照先の文書が直前で決まるとき（文書の名前、パス、リンク、`この文書の`、`本書の`）と、点を含む番号（`4.2 節`）のときだけ失敗にする。個数を表す `3 節に分ける` と `全 5 節` は通す。
- 活用の形は、語を pattern に替えて書く。漢字の直後の語（`不足して`、`必要らしい`、`重要らしい`）は検出しない。`要る` の活用は `要ら`・`要り`・`要る`・`要れ` とする。
- インラインコードの中の error の語は、かな・漢字を含むインラインコードの中だけを検査する。英字だけのインラインコード（`git worktree`、`.claude/worktrees/`）は今のとおり見ない。コミットメッセージにも同じ規則を当てる。
- 使わない語の例として書く場所は、`ja-text.json` に、ファイル・見出し・理由の一覧で許可する。使われなくなった許可は失敗にする（許容用語と同じ）。日本語を含むインラインコードの中の許容用語は、使われているとみる。
- 許可の一覧は、今の文書の 2 か所を載せる。[文書の書き方](../../05-開発規則/writing.md)の「用語の選び方」（造語の例。`判定器`・`口頭の語`・`書面語`・`無記憶のレビュー役`・`指令`・`効く`）と、[エージェントの作業フローの調べた仕組みと実績](../../07-記録/subagents-results.md)の「校閲の評価の結果」（`護り` を評価の例として挙げる）。
- この spec の例と DC は、かな・漢字を含むインラインコードに使わない語を書く。T566-01-05 で、許可の一覧にこの spec のファイルを加え（見出しを書かない許可は、ファイルの全体を許可する）、T566-01-11 でアーカイブに移すときに外す。理由：アーカイブは日本語の文の検査から除かれており、外さないと、使われなくなった許可として失敗になるため。
- warning の `[高低]の|高・必須` の pattern が「重要度（高・必須・推奨）」に当たるので、直前が開き括弧（`（`、`(`）の `高・必須` は当てない形に絞る。
- 読点を数えない「参照だけの項目」のうち、空白のない語 ＋ `の「…」` の形は、語が文書の名前（参照の検査と同じ文書の名前の一覧）に一致するときだけ参照と見る。
- commit の前の hook は、検査の段で ja-text の全体を実行し、続く warning の段（`ja-text --warning --added`）で再び全てのファイルを読む。warning の段は、追加行のあるファイルだけを読み、error の語は数えない。理由：error の語は検査の段で数え済みのため。
- 既存の文書とコードに新しい違反が見つかったら、本当の誤りは同じタスクで修正し、件数を結果に書く。誤検出なら判定を再検討する。判定を変える必要が決定の範囲を超えるときは、修正の前に issue 担当のセッションに知らせる。

検出すべき例と検出してはいけない例を、検査ごとの表に示す。最初の `[テスト]` の前に、spec の文脈を持たないレビュー役に表を読ませ、例を追加させる（[文書の構成](../../05-開発規則/doc-structure.md)の「形を判定する検査」）。

## 目的と完了条件

### DS-566-1 参照の検査が、書き方によって見逃していた誤りを見つけ、誤って失敗にしない（D / P1）

- **DC-566-1** 漢数字の節の番号（`第三節`）と `§3` を、節の番号の参照として失敗にする。
- **DC-566-2** `の節「…」` と `の『…』` を、見出しの参照として読む。
- **DC-566-3** 文書の名前・リンクの直後の「」は、「」の中が参照先の文書の見出しに当たるときだけ失敗にし、「の」を入れるよう示す。見出しに当たらないときは、語の引用として通す。
- **DC-566-4** 行が文書の名前・リンク・パス（とその後の「の」）で終わり、次の行（コメントの印と前の空白を除く）が「」で始まるときだけ、2 行をつないで読む。Markdown の段落の折り返しも同じ条件にする。
- **DC-566-5** Markdown（コードブロックの外。インラインコードの中を含む）に書いた、リポジトリのルートからのパスの先がなければ失敗にする。見出しの参照が続かないパスも対象にする。
- **DC-566-6** 存在しないパスの検査は、対象の始まりの一覧（決定のとおり）に当たる語だけを見る。Git が無視するパス、プレースホルダー・glob・`…` を含むもの、URL の中のものは見ない。
- **DC-566-7** 太字の文書の名前（`**開発の進め方**の「…」`）を、太字の印を除いて文書の名前として読む。
- **DC-566-8** Git が追跡する、拡張子がなく 1 行目が `#!` で始まるファイルを、コードとして読む。
- **DC-566-9** `の「A」と「B」`、`の「A」、「B」`、`の「A」・「B」` の B も、同じ文書の見出しとして確認する。
- **DC-566-10** 「第」のない `N 節` は、参照先の文書が直前で決まるときと、点を含む番号のときだけ失敗にする。`3 節に分ける` と `全 5 節` は通す。

### DS-566-2 言い換えの一覧と日本語の文の検査・hook が、活用と語を取りこぼさず、誤って失敗にしない（D / P1）

- **DC-566-11** `足す`・`要る`・`見直す` の活用（`足して`・`足さない`・`足せば`、`要らない`・`要ります`、`見直さ`・`見直せ`）と、`Worktree`・`WORKTREE` を error にする。漢字の直後の語（`不足して`、`必要らしい`、`重要らしい`）は検出しない。
- **DC-566-12** `口頭語`、`箱の大きさ` など「箱の」、`主の checkout`・`主の worktree`、`判定機`、`資料を集める役` を error にする。
- **DC-566-13** かな・漢字を含むインラインコードの中も error の語を検査する。英字だけのインラインコードは今のとおり見ない。コミットメッセージにも同じ規則を当てる。
- **DC-566-14** 使わない語の例として書く場所を、`ja-text.json` にファイル・見出し・理由の一覧で許可でき、使われなくなった許可は失敗にする。許可の一覧に、今の文書の 2 か所とこの spec（決定のとおり）を載せる。
- **DC-566-15** warning の `高・必須` は、直前が開き括弧のとき当てない。
- **DC-566-16** 読点を数えない「参照だけの項目」のうち、空白のない語 ＋ `の「…」` の形は、語が文書の名前に一致するときだけ参照と見る。
- **DC-566-17** commit の前の hook は、warning の段で追加行のあるファイルだけを読み、error の語を数えない。

### DS-566-3 例の表をテストで確認し、既存の検査が通る（D / P1）

- **DC-566-18** 「検出すべき例」の全てで、テストの失敗を確認する。「検出してはいけない例」の全てで、テストの成功を確認する。
- **DC-566-19** 変えた検査の script の先頭のコメント（判定の範囲、失敗したとき）が、変えた後の動きに合う。`docs/06-手順書/ci-checks.md` の `doc-refs` の行に、存在しないパスが加わっている。
- **DC-566-20** `scripts/ci/check-all.sh` が成功する。今の文書とコードに、新しい違反が残らない。
