## 1. 振る舞いを変えないことの確認（DN-18、DN-19）

### 1.1 テストの差分の検査を、ファイルをまたぐ移動に対応させる

spec 013 の `scripts/ci/review/test-diff.mjs`（テストの実行方法 第 4 節）を次のように修正する。

| 項目 | 今 | 修正した後 |
|------|----|----------|
| 削除した行の照合先 | 同じファイルの追加した行 | 全てのテストのファイル（新しく追加したファイルを含む）の追加した行 |
| 照合して残った追加した行 | 違反 | 既存のファイルなら違反。新しく追加したファイルなら見ない ※1 |
| 行の比べ方 | そのまま | 前後の空白を除いて比べる（テストを `describe` に入れるとインデントが変わるため） |
| import の行 | `import` で始まる行 | 加えて、複数行の `import {` から `} from` までの行 |
| 削除したファイル | 見ない | 削除した行を照合する（ファイルを分けて元を削除する場合） |

※1：移した先の import と `describe` の枠の行のため。新しく追加したテストの中身は、今と同じく見ない。移したテストの行を変えると、元の削除された行が照合できずに違反になる。

- 名前の対応のファイルは `tasks/renames.txt`。モジュールのパス（`@/lib/orderDisplay=@/features/order/orderState` など）も書き、`vi.mock` の文字列のパスにも当たるようにする。
- 各段階の最後とレビューの段階で、spec の最初の commit の 1 つ前を元に実行する。

## 3. 共有の整形と文言（DS-42）

### 3.1 整形の関数

共有パッケージに `lib/format.ts` を作り、2 つの画面の同じ整形を移す。

| 関数 | 今 | 決定 |
|------|----|------|
| 金額 | 管理画面と店舗画面の注文の表示に 1 つずつ、店舗画面の価格に書式だけ | 共有の 1 つにする |
| 価格（税込と税抜） | 管理画面は 2 つの数（税込は null がある）、店舗画面は価格の型を受ける | 共有の 1 つにし、`{ inclTax?: number \| null; exclTax: number }` を受ける。税込が null のときの文（管理画面だけが使う）も共有の文言に移す |
| 日時 | 管理画面は UTC に 9 時間を追加して組み立て、店舗画面は `Intl.DateTimeFormat` | 店舗画面の実装（ロケールとタイムゾーンを共有の設定から取得する）にする。null は空文字（管理画面の今の扱い） |
| 税額 | 2 つの画面に同じものが 1 つずつ | 共有の 1 つにする |
| 郵便番号 | 同上 | 同上 |
| 軸の値の並び（DC-144） | 店舗画面は全角の空白、管理画面は「、」や別の区切りで並べる | 1 つの軸の文（`{name}：{value}`）は共有の文言、並べる関数は共有にし、区切りは呼ぶ側の文言から渡す（区切りの違いを残す） |

- 共有パッケージは、共有の文言だけで作った文言の関数（`lib/translate.ts`、`use-intl` の `createTranslator`）を持ち、整形の関数はこれを使う。`use-intl` を共有パッケージの依存に追加する（管理画面がすでに使い、店舗画面の `next-intl` も内部で使う。ライセンスは MIT）。
- 片方の画面だけが使う整形は、その画面に残す：管理画面の日時の入力欄との変換、レポートの金額の短い表示、店舗画面の価格をコンポーネントで分けて表示する書式。
- 管理画面の日時の入力欄との変換と、レポートの期間の日付は、日本時間のオフセット（9 時間、`+09:00`）とロケール（`sv-SE`）を直接書かず、共有のタイムゾーンから `Intl.DateTimeFormat` の `formatToParts` で求める（DC-145）。
- 整形のテストは、関数と一緒に共有パッケージへ移す（第 1.1 節）。2 つの画面の同じ関数のテストは、同じファイルに並べて残す（中身を変えないため、重なりは削除しない）。

### 3.2 共有の文言（DC-146）

| 区分 | 決定 |
|------|------|
| 2 つの画面で同じ役割の文言 | 共有の文言に移す。現時点で判明しているもの：注文の詳細の項目（注文番号、注文日時、〒と都道府県、配送業者、送り状番号）、金額の内訳（商品の合計、送料、総額、税率ごとの消費税）、カテゴリの選択の「全て」とインデント、軸の値の文 |

| 偶然同じ文 | 移動しない（第 2 節の 7.1 の基準） |

- どのキーをどちらの画面が使うかは、段階 2 の最初のタスクで、キーを生成する箇所（`` `common.orderStatus.${status}` `` など）と `useTranslations('common')` の名前空間を含めて調べ、一覧を tasks に書いてから移す。
- 文言の文は変えない（DN-19）。DC-159 の空白の修正だけは、この段階で行う。
