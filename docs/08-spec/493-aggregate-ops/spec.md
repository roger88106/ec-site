# Spec 493：集約の操作と照会の構造を整える

種類：整理　規模：L　ステータス：確定

## 背景と目的

追跡の issue は #493（#544 の一部）である。#458 の全体のレビューで、集約と照会の構造に 4 つの問題が見つかった。

1. 注文と支払の集約で、状態を変える操作が「変えたか」を返すものと、何も返さず、状態によっては何も変えないものが混ざる。service は、何も変わらなくても保存し、バージョンと更新日時だけが進む。
2. 商品の集約（約 850 行）は、公開状態・公開期間・初回表示日時が 1 組の状態の規則なのに、別々の項目とメソッドに散っている。バリアントと画像は専用の型を持たない一覧で、「ID で探す」「1 件を置き換えた一覧を作る」処理が繰り返し出てくる。
3. 商品の詳細と税区分の照会で、クエリリポジトリが一部の項目を null にした view を返し、service が後から埋める。null が「値がない」のか「まだ計算していない」のかを、型で区別できない。
4. 店舗の商品の一覧と検索で、同じ問い合わせの骨組みを 2 回書いている。売上の集計は、商品・税抜き・送料除外を位置の引数の真偽値で渡し、「商品を選んだら送料を除く」の規則が service とリポジトリに分かれている。

消費者・運営者に見える振る舞い（API の応答、画面、イベント）を変えない。#555 で入った集約の不変条件と同一性の形（コンストラクターの検査、復元の補助、識別子で比べる `equals`）の上で行う。

## スコープ

| 含める | 含めない |
|--------|----------|
| 状態によって何もしないことがある操作の戻り値と保存の規則を、バックエンドの書き方の文書に書く | 運営者の編集（商品の更新・公開期間の変更・並べ替え、カテゴリの名前の変更、税率の置き換え）で、同じ値なら保存しないこと |
| 注文と支払の、状態によって何もしないことがある操作を、変えたかを返す形にし、service は変えたときだけ保存する | 商品の保存で、変わった行だけを書く仕組み（変更の追跡） |
| 商品の公開状態の規則を値の型に、バリアントと画像の一覧を一覧の型に分ける | API の契約と DB の構造の変更、業務の規則の変更 |
| クエリリポジトリが保存されている値だけの型を返す規則を書き、商品の詳細と税区分の照会を、service が完成した view を作る形にする | レベル B のモジュール（カートなど）の書き方の変更 |
| 店舗の商品の一覧と検索の骨組みを、共通のクラスにまとめる | 運営者の商品の一覧（列・条件・並べ替えが違う） |
| 売上の集計の範囲（商品、税抜き、送料除外）を値の型にし、「商品を選んだら送料を除く」の規則をその型に置く | |

## 目的と完了条件

### DS-493-1 状態を変える操作の結果で、保存するかを決める（D / P1）

- **DC-493-1** 規則がバックエンドの書き方の文書にある。規則は次の 2 つである。
  - 集約の状態を変える操作のうち、状態によって何もしないことがある操作は、変えたかを真偽値で返す。
  - service は、変えたときだけ保存する。
- **DC-493-2** 対象の操作（「変える範囲」の「戻り値を変える操作」の表）が、変えたかを真偽値で返す。
- **DC-493-3** 対象の操作を呼ぶ service が、変えたときだけ保存する。何も変わらない操作の後に、注文と支払のバージョンと更新日時が進まない。
- **DC-493-4** DC-493-3 を、何も変わらない場合（重ねて届いた通知、申請中の注文への再度の申請など）にバージョンが進まないことを調べるテストで確認している。

### DS-493-2 商品の集約を、役割ごとの型に分ける（D / P1）

- **DC-493-5** 公開状態・公開期間・初回表示日時が、1 つの値の型にある。その遷移の規則（公開・非公開・販売終了・期間の変更）と、一度でも表示したかの判定も、同じ型にある。商品の集約は、その型に処理を任せる。
- **DC-493-6** バリアントの一覧と画像の一覧が、それぞれ一覧の型（税率の一覧と同じ形）になる。「ID で探す」「1 件を置き換えた一覧を作る」「追加」「削除」「並べ替え」が、その型の操作として 1 か所にある。
- **DC-493-7** 切り出した型の不変条件は、#555 の規則のとおりコンストラクターで検査する。DB からの復元で違反したときは、復元のエラーになる。
- **DC-493-8** 切り出した型ごとに、単体テストがある。

### DS-493-3 照会は、保存されている値と計算した値を型で分ける（D / P1）

- **DC-493-9** 規則がバックエンドの書き方の文書にある。クエリリポジトリは保存されている値だけの型を返し、後から埋める null の項目を持つ view を返さない。現在時刻や他のモジュールの値で決まる項目は、service が加えて view を作る。
- **DC-493-10** 商品の詳細と税区分の照会で、リポジトリが保存されている値だけの型を返し、service が完成した view を作る。null を後から埋める処理がない。

### DS-493-4 同じ問い合わせの骨組みを 1 か所にする（D / P2）

- **DC-493-11** 店舗の商品の一覧と検索が、骨組みを共通のクラスで共有する。違いは絞り込みの条件と並べ替えだけである。骨組みは次の 5 つである。
  - 税率がないときの空の結果
  - 税込価格の計算
  - 表示の条件
  - ページング
  - 件数
- **DC-493-12** 売上の集計の範囲（商品、税抜き、送料除外）が 1 つの値の型で、presentation から repository まで渡る。位置の引数の真偽値で渡す所がない。
- **DC-493-13** 「商品を選んだら送料を除く」の規則が、集計の範囲の型の 1 か所にある。
- **DC-493-14** 売上の集計で、商品で絞る結合と条件が 1 か所にある。

### DS-493-5 振る舞いを変えず、既存のテストと検査が通る（D / P1）

- **DC-493-15** `./gradlew check` が通る。
- **DC-493-16** ローカルの seed で起動して、店舗画面と管理画面の商品・注文・税区分・売上の集計の画面が開ける。

### 戻り値を変える操作（DC-493-2 の対象）

| モジュール | 業務の名前 | 今 | 変えること |
|------------|------------|----|------------|
| order | 取消の申請 | 申請中なら何も変えない。service は常に保存する | 変えたかを返し、変えたときだけ保存する |
| payment | 売上の確定の反映 | 与信済みと与信の取消待ち以外では何も変えない。常に保存する | 同上 |
| payment | 与信の期限切れの反映 | 与信済みでなければ何も変えない。常に保存する | 同上 |
| payment | 注文の取消に合わせた取消 | 取消待ち・取消済み・支払なしなどでは何も変えない。常に保存する | 同上 |
| payment | 与信の取消済みの反映 | 与信の取消待ちでなければ何も変えない。常に保存する | 同上 |
| payment | 返金済みの反映 | 返金待ちでなければ何も変えない。常に保存する | 同上 |
| payment | 与信の反映 | 与信済みにしたかを返すが、支払なしの取消待ちへの変更では偽。service は常に保存する | 変えたかを返し、変えたときだけ保存する ※1 |

※1：与信の反映の service が返す「与信済みにしたか」は、変えた後の状態から判定する。呼び出し元（ログ）とテストの結果は今と同じ。

### 調べた結果

- 注文と支払の保存は、毎回バージョンを 1 進め、更新日時を現在時刻にする。注文と支払のバージョンと更新日時は API の応答にない（`api/openapi/` で確認）。画面に見える項目は変わらない。
- 状態によって何もしない操作のうち、次は今も戻り値で保存を分けている。
  - 注文：支払の受付、支払の期限切れ、取消の承認、運営者の取消。
  - 支払：支払の期限切れ、与信の反映を待つ支払。
  - 出荷：配送状況。
  - カート。
  - 商品：公開、非公開、販売終了、バリアントの販売の停止と再開。
- 商品の保存は、すでに差分の書き方である（消えた子の行だけを削除し、残りの行を upsert する）。どの変更でも、全ての子の行を削除して入れ替える処理は、今のコードにない。
- 後から null を埋める view は、商品の詳細（税込価格と、今できる操作）と、税区分（今の税率）の 2 か所だけである。他のモジュールにはない。
- 店舗の商品の一覧と検索で、骨組みを 2 回書いている。3 回目以降はない。
- 売上の集計で、「商品を選んだら送料を除く」は、service（応答の送料除外の表示）と repository（商品で絞るときは明細の金額だけを合計する）に分かれている。商品で絞る結合と条件は 3 回書かれている。

## 非機能要件

- **DN-493-1** 消費者・運営者に見える振る舞い（API の応答、画面、イベント）を変えない。変わるのは、状態が変わらない操作の後に、注文と支払のバージョンと更新日時が進まなくなる点だけである。この 2 項目は API の応答にない。
- **DN-493-2** API の契約、DB の構造、AC を変えない。
- **DN-493-3** アーカイブした spec を変えない。
- **DN-493-4** 例外のメッセージとログに、DB の値と個人の情報を含めない（#555 の復元のエラーの規則と同じ）。

## Non-goals

| 項目 | 理由 |
|------|------|
| 運営者の編集で、同じ値なら保存しないこと | 運営者がバージョンを付けて明示的に送る操作で、状態によっては何も変えない操作ではないため。値の比較を各操作に加えると、変える操作が増える |
| 商品の保存で、変わった行だけを書く仕組み | 今も差分の書き方で、画像は 20 件まで、バリアントも少数なので、変更の追跡を入れる手間に見合わないため |
| カートなどレベル B のモジュールの書き方 | カートはすでに変わったときだけ保存している。issue の対象外 |
| 運営者の商品の一覧の骨組み | 列・条件・並べ替えが店舗の一覧と違い、共有する部分が少ないため |
