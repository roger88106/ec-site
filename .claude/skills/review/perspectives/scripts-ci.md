# script と CI の観点

検査の script、hook、CI を書く・変えたときに、結果を返す前の自己確認とレビューの両方で読む。規則の文は、表の「規則の正本」で読む。

| 観点 | 見る問い | 過去の見落としの例 | 規則の正本 |
|------|----------|--------------------|------------|
| 検査の必要性 | この検査がなくなると何が起きるか。既製のツールや設定で値を 1 か所にすれば不要にならないか。止めた実績と、直した回数のどちらが多いか。 | 2 か所の値の一致を比べる検査が、設定の既定値を 1 つ消せば不要だった。導入のときに直したのは改名だけで、不具合を止めていない検査があった | [CI の検査の追加](../../../../docs/06-手順書/ci-adding-checks.md)の「検査にするかの基準」 |
| 検出の正しさ | 名前と先頭のコメントのとおりに検出するか。抜けられる書き方（漏れ）と、正しい書き方を止める形（誤検出）がないか。 | hook が、正しい形の git の呼び出しを誤って止めた。ファイルを分けた後、新しいサブフォルダーを走査しなくなった検査があった | [文書の構成](../../../../docs/05-開発規則/doc-structure.md)の「形を判定する検査」、[書き方の規則とレビュー](../../../../docs/05-開発規則/review.md)の「レビューの収束」 |
| 検査を動かす範囲 | commit の前の hook で、変えたファイルに関係する検査とテストが漏れずに選ばれるか。 | 他の script を走査するテストが選ばれず、hook は通って CI で失敗した | [CI の検査の script](../../../../docs/06-手順書/ci-checks.md)の「commit の前の hook」 |
| 検査の速さ | 行ごと・語ごとに同じ計算や正規表現の作成を繰り返していないか。commit のたびに重い処理をしていないか。 | 日本語の検査が行ごとに同じ正規表現を再作成し、commit のたびに数秒を余計に使っていた | [CI の検査の追加](../../../../docs/06-手順書/ci-adding-checks.md)の「script の書き方」 |
| 閾値の根拠 | 閾値（カバレッジ、mutation score など）を、CI の実測から決めた手順どおりに設定したか。 | mutation score の基準を手元の値から決めたので、CI の値より低かった | [テストの実行方法](../../../../docs/06-手順書/running-tests.md)の「カバレッジと mutation score の基準の検査」 |
| 実装と値の重複 | 同じ関数や設定の値を、複数の所に持っていないか。 | 正規表現の文字を逃がす関数が複数の script に別々にあり、見出しを読む関数の 2 つは結果が違った | [CI の検査の追加](../../../../docs/06-手順書/ci-adding-checks.md)の「補助の script の置き場所」 |
| script のテスト | 失敗の条件ごとに通る例と失敗する例があるか。閾値の両側、出力の `ファイル:行` と規則の名前まで確認するか。一時のフォルダーで動かすか。 | 本体の入口だけを確認、規則の中身を何も確認ないテストがあった | [CI の検査の追加](../../../../docs/06-手順書/ci-adding-checks.md)の「テストの観点」 |
| 終了コードと失敗の文 | 終了コードが通過・違反・使い方の誤りで分かれているか。失敗の文に `ファイル:行` と直し方があるか。 | 検査によって終了コードと要約の行の形がそろっていなかった | [CI の検査の追加](../../../../docs/06-手順書/ci-adding-checks.md)の「検査を追加する手順」 |
| 外部のコマンドと環境の差 | 外部のコマンドに引数の配列を渡しているか。パスの区切り・改行・大文字と小文字・列挙の順・時刻に依存しないか。 | なし（審査の観点として挙げた） | [CI の検査の追加](../../../../docs/06-手順書/ci-adding-checks.md)の「script の書き方」 |
