## タスク

- [x] **T013-05-01** [テスト] ArchUnit：レベル A のモジュールの presentation は、集約（`@AggregateRoot`）に依存しない（plan 第 2.2 節）。段階 4 で order は直したので、今のコードで通るなら `break-check.mjs` で order の mapper に仮に集約の参照を足して失敗することを確かめ、戻す。バックエンドの書き方の規則の一覧の確かめ方を「自動（ArchUnit）」にする。
  - 今のコードで通った。order の管理の mapper に集約を引数に取るメソッドを仮に足すと失敗し、戻した。payment には presentation がないので、対象がなくても通す。参照の service が view を返すことは型の名前で決められないので、規則の一覧では presentation の側だけを自動とした。
- [x] **T013-05-02** payment の更新の service の読み取り専用のメソッド 5 つ（支払える支払、支払、期限切れの支払、取り消す与信、返金の要求）を、参照の service に移す。使う側が要る項目の view か、外部への要求の型を返す（plan 第 5.2 節）。
- [x] **T013-05-03** 参照の service の支払の期限の判定を、支払の集約の判定のメソッドを呼ぶ形にする（DC-138）。
  - 対象は与信期限の一覧（`findAuthorizationDeadlines`）。支払の集約をまとめて読み（リポジトリに `findByOrderIds` を足す）、集約の与信期限と期限が近いかの判定を呼ぶ。使われなくなったクエリと view（`AuthorizationView`）は消した。
  - 見直しで確かめること：order の参照の service（`OrderQueryService.findPayments`）が、支払の要約の状態と期限から「支払える」を自分で判定している（集約の `isPayable` と同じ式）。モジュールの境界を越えるので、このタスクでは変えていない。
- [x] **T013-05-04** 期限切れにする処理を、更新の service の 1 つのメソッドにまとめ、通知の受け口と定期の処理から呼ぶ（DC-138）。
- [ ] **T013-05-05** 支払の期限の間隔を、支払の設定の型の `Duration` の項目にする。キーと既定値（1 分）は今と同じ。`@Scheduled` は SpEL で設定の型の Bean を参照する。決済モジュールの設計書の「支払の期限」と、環境変数の文書を照らし、違えば直す。
