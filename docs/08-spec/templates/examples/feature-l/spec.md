# Spec 900：管理画面で注文の出荷を登録する

種類：機能　規模：L　ステータス：確定

見本。実在の spec ではない。番号 900 は見本用で、題材は注文モジュールの出荷の登録である。

## 背景と目的

運営者が、受付の注文の出荷を管理画面で登録できるようにする。登録では、決済サービスで売上を確定してから、注文を出荷済みにして出荷を作る。業務規則は [注文モジュール](../../../../03-機能仕様/order.md)の「出荷の登録」、処理の流れは [注文の設計](../../../../02-設計/order.md)の「出荷の登録」にある。

## スコープ

| 含める | 含めない |
|--------|----------|
| 管理画面の注文詳細で、配送業者と送り状番号を入力して出荷を登録する | 与信期限切れの注文の自動キャンセル |
| 売上確定の失敗と重複した登録での、注文・支払・出荷の状態 | 出荷での在庫の変更 |

## User stories

| US | 誰が | 何をできる | なぜ |
|----|------|------------|------|
| US-900-1 | 運営者 | 受付の注文の出荷を登録する | 出荷した注文を出荷済みにするため |
| US-900-2 | 運営者 | 失敗や重複があっても、売上と出荷を食い違わせずに登録を繰り返す | 売上が確定していないのに出荷済みになる注文を作らないため |

## 受け入れ条件

### US-900-1 受付の注文の出荷を登録する（B / P1）

- **AC-900-1** 運営者は、受付の注文の詳細で、配送業者と送り状番号を入力して出荷を登録できる。
- **AC-900-2** 出荷を登録すると、売上を確定した後に注文が出荷済みになり、出荷が作られる。

### US-900-2 失敗や重複があっても、売上と出荷を食い違わせずに登録を繰り返す（B / P1）

- **AC-900-3** 売上確定に失敗したときは、出荷を作らず、注文は受付のままである。
- **AC-900-4** 受付以外の注文は、売上を確定せずに、出荷の登録を拒否する。
- **AC-900-5** 売上確定の後に登録に失敗した注文に再び登録しても、決済サービスを呼ばずに進む。理由：決済の API が売上確定済みなら、決済サービスを呼ばずに成功を返すため。

## 業務ルール

- **BR-900-1** 売上確定は、注文を出荷済みにする前に行う。理由：[出荷の登録で、注文を出荷済みにする前に売上を確定する](../../../../04-決定記録/order-capture-before-shipment.md)のとおり、売上が確定していない注文を出荷済みにしないため。
- **BR-900-2** 送り状番号は、数字とハイフンで、数字が 1 つ以上、30 文字までとする。売上確定の前に、リクエストの検証で確認する。

## 非機能要件

- **NFR-900-1** 売上確定は、注文 ID を冪等キーにして決済サービスに求める。

## 依存

| 対象 | 関係 |
|------|------|
| 決済 | 売上確定の API を使う |
| 出荷 | 出荷を作る API を使う |
| 通知 | イベント「注文の出荷」を受けて、出荷通知メールを送る |

## Non-goals

| 項目 | 理由 |
|------|------|
| 与信期限切れの注文の自動キャンセル | 期限が近い注文は一覧で絞り込めるので、運営者が確認し、キャンセルするかを判断するため |
| 出荷での在庫の変更 | 在庫数は注文の成立で減らしているため |
