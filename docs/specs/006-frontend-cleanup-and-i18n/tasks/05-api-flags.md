# 段階 5：業務の出し分けを API の旗に

- 前提：段階 4 と、**spec 005 の段階 2**（バックエンドの構成の移動）の完了
- 完了条件：DC-61。バックエンドの旗の値のテストと、画面の結合テストが通る。画面に業務の判定の関数がない。
- 参照：[plan](../plan.md) 第 3.5 節

## タスク

- [ ] **T6501** 画面が業務の規則で出し分けている所を、admin・store で洗い出す（今わかっているもの：商品の削除 `isNeverShown`（AC-71）、バリアントの追加 `canAdd`（AC-24）。ほかに注文のキャンセルの申請・承認・却下、在庫の調整など）。旗の名前と、どの応答に足すかの案を作り、利用者に確かめる。
- [ ] **T6502** `admin.yaml`・`store.yaml` に旗を足す。モジュールの設計書の API の欄を直す。
- [ ] **T6503** [テスト] 旗の値のバックエンドのテスト（集約の規則と同じ結果になる。境界の値を含む）。
- [ ] **T6504** バックエンドで旗を作って返す（値は集約の規則から）。T6503 を通す。
- [ ] **T6505** 画面を旗で出し分けるように直し、判定の関数（`isNeverShown`、`canAdd` など）を消す。結合テストの MSW の応答に旗を足す。
