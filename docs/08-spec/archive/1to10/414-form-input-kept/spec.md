# Spec 414：店舗画面のフォームの送信が失敗しても、入力した値を残す

種類：機能　規模：M　ステータス：確定

## 背景と目的

キャンセルの申請のフォームは、理由（任意、500 文字まで）を入力して送る。申請が失敗すると、エラーメッセージと一緒に、入力した理由が空になり、再入力が必要になる。接続の失敗、5xx、400 のときに起こる。409（キャンセルを申請できない状態）は、再送しても通らないので、実害は小さい。

原因は、フォームの action にサーバーアクションを渡して送る形にある。この形では、React は送信の結果を待たず、成否に関係なくフォームを初期値に戻す。店舗画面のサーバーアクションは、失敗を例外にせず結果で返す。そのため、エラーメッセージと空の欄が同時に出る。「カートに入れる」のフォームも同じ原因で、選んだ数量が失敗の後に 1 に戻る。

注文のフォームは、この動きを避けるため、送信の処理から送っている。店舗画面の構成は、入力の誤りでは入力を削除しないと定めている。この spec は、キャンセルの申請と「カートに入れる」の 2 つのフォームで、失敗の後も入力した値を残す。

追跡の issue は #414。関わる文書は、[店舗モジュール](../../../../03-機能仕様/storefront.md)、[店舗画面の構成](../../../../02-設計/apps/store.md)。

### 確認した範囲と限界

| 確認した内容 | 方法と出典 |
|--------------|------------|
| キャンセルの申請で、理由を入れて失敗させると、送った値は入力した文字列と一致し、エラーが表示され、欄は空になる。確認の画面でやめたときは値が残る | jsdom の一時的なテスト（実際の React を使い、サーバーアクションだけを差し替えた）。実行後に削除した |
| 「カートに入れる」で、数量 3 を選んで失敗させると、送った値は 3、失敗の後の欄は 1 | 同上（2026-11-09） |
| フォームの action で送ると、React が結果を待たずにフォームを初期値に戻す | react-dom の `requestFormReset`（結果の成否を確認しない） |
| 注文のフォームが送信の処理から送っている | `frontend/store/src/features/checkout/components/OrderForm.tsx:73-79` のコメント |

実際のサーバーアクションの通信、ブラウザーでの操作、通信そのものが失敗して結果が返らないときは、確認していない。

## スコープ

| 含める | 含めない |
|--------|----------|
| キャンセルの申請のフォーム | 「カートの数量の変更」のフォーム |
| 「カートに入れる」のフォーム | 結果のない送信の失敗の経路 |
| テストの追加 | 他の画面（管理画面） |
| AC 一覧と店舗画面の構成の更新 | |

含めないものの理由は Non-goals に書く。

決定：

1. 規模は M にする。理由：AC を追加するが、API の契約と DB の構造を変えず、店舗画面だけを変えるため。
2. 2 つのフォームは、注文のフォームと同じく、送信の処理で既定の送信を無効にする。フォームの値を集め、トランジションの中でサーバーアクションを呼ぶ。キャンセルの申請では、確認の画面で「はい」のときだけ呼ぶ。フォームの action にもサーバーアクションを渡したままにする。送信の処理で既定の送信を無効にすると、React は action を呼ばない。理由：JavaScript の読み込み前に送ったときも、従来と同じくサーバーアクションで処理するため。

   | 論理名 | 識別子 |
   |--------|--------|
   | 送信の処理 | `onSubmit` |
   | トランジション | `startTransition` |
   | フォームの action | `action` |
   | キャンセルの申請のフォーム | `CancellationRequestForm` |
   | 「カートに入れる」のフォーム | `AddToCartForm` |

3. キャンセルの申請が成功した後は、申請の状態の表示に切り替わるので、欄を空にする処理は加えない。
4. 「カートに入れる」が成功した後も、選んだ数量は 1 に戻さず残す（今は成功でも 1 に戻る）。理由：成功の知らせとカートへのリンクを表示するだけで、続けて同じ数を入れる操作にも支障がないため。
5. 「カートの数量の変更」のフォームは変えない。理由：失敗の後に、カートにある今の数量へ戻るのが正しい表示であるため。
6. 店舗画面の構成の「サーバーアクション」の節に、次の 2 点を書く。失敗の後も入力した値を残すフォームは、送信の処理から送る。カートの数量の変更は、action で送る。

### US-414-1 失敗の後も入力が残る（C / P1）

- **AC-414-1** キャンセルの申請が失敗したとき、理由の欄に入力した文字列が残る。
- **AC-414-2** キャンセルの申請の確認でやめたとき、申請せず、理由の欄に入力した文字列が残る。
- **AC-414-3** 「カートに入れる」が失敗したとき、選んだ数量が残る。
- **AC-414-4** 「カートに入れる」が成功したとき、選んだ数量が残る。
