- [ ] **T0202** 用語集に、レポート、状態の履歴、売上の数え方（注文基準・出荷基準）、集計の粒度、会計年度、年齢層、性別、管理職、営業、全国地方公共団体コードと、3 つの権限を足す。

## 写しと履歴

- [ ] **T0203** [テスト] 単体テスト：都道府県の名前から全国地方公共団体コードへの読み替え（47 件、知らない名前）。
- [ ] **T0204** マイグレーションで、schema `reporting` に写し（注文、明細）と状態の履歴の表を作る。都道府県のコードの表を実装する。T0203 を通す。
- [ ] **T0205** [テスト] 統合テスト（AC-223〜225）：
  - 「注文の状態の変化」「配送状態の変化」を受けると、注文の API から写しを作り直す
  - 支払待ちのまま期限切れでキャンセルになった注文も、写しと履歴に入る（plan 第 5.2 節「集める範囲」）
  - キャンセルが受付より先に届く、同じイベントが重ねて届く、でも同じ写しになる
  - 履歴はイベントごとに 1 行で、重ねて届いても足さない
  - 失敗したイベントは再発行で処理し直される
- [ ] **T0206** イベントのリスナー、写しの上書き、履歴の追記を実装する。T0205 を通す。

- [ ] **T0208** 区切りと年齢層を実装する。設定 `ecsite.reporting.fiscal-year-start-month` を足す。T0207 を通す。

- [ ] **T0210** 売上の推移の集計を実装する。T0209 を通す。
- [ ] **T0211** [テスト] バリエーションの売れ行きの統合テスト（AC-202〜204）：売れなかったバリエーションの 0、販売数量の多い順、消費税を除く。
- [ ] **T0212** バリエーションの売れ行きを実装する（商品カタログの API でバリエーションの一覧を受ける）。T0211 を通す。
