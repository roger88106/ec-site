# 規則の文書

コードの書き方と、プロジェクトの習慣を主題ごとにまとめる。コードを書く前と、見直しのときに読む。

| 文書 | 主題 |
|------|------|
| [backend.md](backend.md) | バックエンドの層とパッケージ、エラーの変換、入力の検証、トランザクション、時刻、命名 |
| [frontend.md](frontend.md) | フロントの部品の置き場所、API の呼び出し、店舗画面のサーバーアクション、整形と lint、画面の URL、文言とロケール、店舗画面のサーバーの設定とログ、依存の足し方 |
| [testing.md](testing.md) | テストの種類と置き場所、テスト名、テストデータ、待ち方 |
| [comments.md](comments.md) | コメント（Javadoc・TSDoc、型の項目、複雑な処理の前） |
| [review.md](review.md) | 見直しで読む規則の一覧 |

## constitution との分担

- [constitution](../constitution.md) は原則（何を守るか、なぜ）を、本フォルダーは具体的な書き方（どう書くか、例）を書く。食い違ったら constitution が正しい。
- 規則の文書は constitution の節を引いてよいが、同じ文を写さない。
- アプリごとの構成（ディレクトリ、画面の追加手順）は [docs/frontend/](../frontend)、モジュールごとの設計は [docs/modules/](../modules) にあり、本フォルダーからは引くだけにする。

## 規則の書き方

1 つの規則を 1 つの項目にし、次の 3 つを書く。

- **規則**：何をどう書くか。
- **理由**：なぜそうするか。
- **確かめ方**：自動（ArchUnit・Modulith のテスト、Biome、テスト、CI の script）か、人手（見直しで読む）か。自動のものは、設定かテストへのリンクを付ける。人手のものは [review.md](review.md) の一覧にも載せる。

新しい習慣が決まったら、その spec の plan か tasks で本フォルダーに足す。
