# Spec 553：設定の型の登録を 1 か所にまとめ、時間の値に下限を置く

種類：整理　規模：M　ステータス：確定

## 背景と目的

設定の型（設定ファイルの値を受ける record）を登録するために、今はモジュールごとに設定のクラスを置き、登録の注釈を書いている。登録の注釈を持つ本番のクラスは 14 個あり、そのうち 9 個は登録のほかに処理を持たない。#464 の本文は 21 個と書いているが、2026-11-18 に全体のブランチで数えた結果は 14 個と 9 個だった。登録した Bean はアプリ全体で 1 つの DI コンテナーが管理するので、モジュールごとに登録のクラスを置く必要はない。

時間と間隔の設定の値の多くに下限がなく、0 や負の値でも起動できる。期限が即時に切れるなどの誤った設定に、気づかないまま動くおそれがある（#521）。

この spec は、設定の型の登録を 1 か所にまとめ、時間と間隔の値に下限を置く。消費者・運営者に見える振る舞いを変えない。今の設定ファイル（`application*.yml`）の値は、全て新しい下限を満たす。追跡の issue は #553（組の issue）。sub-issue は #464（設定の型の登録をまとめる）と #521（時間と間隔の設定の値に下限がない）。#544（リリースの前の整理）の段階 2 の 1 番目である。

## スコープ

| 含める | 含めない |
|--------|----------|
| 設定の型の登録を、アプリのクラスでの 1 回のスキャンにまとめ、登録だけの設定のクラスを削除すること | 設定の値の上限と、値どうしの関係（例：与信の期限が近いと判定する長さ < 与信の有効期間）の検査 |
| 条件で切り替える実装（決済の mock と Stripe）の設定の型を、同じ条件で登録すること | 設定の検証のテストの書き方を 1 つにそろえること（テストの補助を集約する issue で扱う） |
| 時間と間隔の設定の値に下限を置き、許す範囲の外の値で起動できないことをテストで確認すること | 時間でない値（件数、品質など。既に下限がある） |
| 規則（バックエンドの書き方の「設定の値の型」）と環境変数の一覧の修正 | |

決定：

- 規模：M とする。判定の表では、2 つ以上のモジュールにまたがるので L の条件に当たる。しかし、API・DB・モジュールの境界を変えず、plan に書く決定がないため、M とした（[開発の進め方](../../05-開発規則/workflow.md)の「規模」の特例。issue 担当のセッションが 2026-11-18 に確認した）。
- 決定 1（登録の場所）：アプリのクラスに、設定の型のスキャンを 1 回だけ付ける。スキャンするパッケージは、共通の設定とモジュールの 2 つに限る。全ての設定の型を共通の 1 つのクラスに列挙する方法は採らない。
  - 理由（パッケージを 2 つに限る）：統合テストのクラスパスに単体テストのクラスが入り、構成の検査の見本の型までスキャンされるため。
  - 理由（共通の 1 つのクラスに並べない）：共通のモジュールが各モジュールに依存することになるため（#464 の本文）。
- 決定 2（登録だけのクラス）：登録だけの設定のクラス 9 個を削除する。他の Bean も作る設定のクラス 5 個は残し、登録の注釈だけを外す。
- 決定 3（条件付きの設定の型）：決済の mock と Stripe の設定の型には、今の設定のクラスと同じ条件の注釈を、設定の型に直接付ける。スキャンは条件を評価し、成り立たないときは登録しない。条件がスキャンで評価されないと分かったら、実装を止めて issue 担当のセッションに報告する。
- 決定 4（Bean の名前）：スキャンで登録した Bean の名前は、今と同じ「接頭辞-完全修飾名」である（Spring Boot の文書「Externalized Configuration」）。
  - 定期ジョブの間隔を指定する式（SpEL）は変えない。
  - 式の横のコメントの「登録の注釈の決まり」は、「設定の型の登録の決まり」に修正する。
- 決定 5（構成の検査）：今の「登録の注釈を付けるクラスは設定のクラス」の検査を、「本番のクラスは登録の注釈を使わない」に替える。「本番の設定の型は、決定 1 の 2 つのパッケージにある」の検査を加える。
- 決定 6（下限の分け方）：時間と間隔の値を、「正の値だけ」と「0 以上」に分ける（下の表）。
  - 保存期間は 0 を許す。カートの保存期間の既定は 0 で、期限を過ぎたらすぐ削除する意味のため。
  - 与信の期限が近いと判定する長さも 0 を許す。0 は「期限が近い」と判定しない意味のため。
  - 他の値は、正の値だけを許す。
  - 全ての値に、null を許さない制約を付ける。今、この制約がない値がある。
- 決定 7（規則と環境変数の一覧）：
  - バックエンドの書き方の「設定の値の型」で、登録の注釈をモジュールの設定のクラスに付けるという項目を、決定 1〜3 の形に書き換える。
  - 同じ節に、時間の値には下限を制約で付けることを 1 文で加える。
  - 名前の形の表にある設定のクラスの例を、残るクラスに差し替える。
  - 確認方法の行も修正する。
  - 環境変数の一覧に、時間の値が許す範囲の外だと起動に失敗することを書く。今は支払の期限の上限だけを書いている。

決定に出るコードの名前は、次の表のとおり。

| 決定 | 識別子 | 指すもの |
|------|--------|----------|
| 1 | `@ConfigurationPropertiesScan`、`EcSiteApplication` | 設定の型のスキャン、アプリのクラス |
| 1 | `com.ecsite.config`、`com.ecsite.module`、`com.ecsite.architecture.sample` | 共通の設定用、モジュール用、構成の検査の見本用のパッケージ |
| 1、5 | `@EnableConfigurationProperties` | 登録の注釈 |
| 2 | `EventConfig`、`CartConfig`、`InventoryConfig`、`NotificationConfig`、`OrderConfig`、`PaymentConfig`、`MockPaymentConfig`、`ReportingConfig`、`StorefrontConfig` | 削除する 9 個 |
| 2 | `SecurityConfig`、`ImgproxyConfig`、`MediaStorageConfig`、`StripeConfig`、`ShippingConfig` | 注釈だけを外す 5 個 |
| 3 | `@ConditionalOnPaymentMock`、`@ConditionalOnPaymentStripe`、`MockPaymentProperties`、`StripeProperties` | 条件と、条件付きの設定の型 |
| 6 | `@DurationMin`、`@NotNull` | 下限と null の制約 |

決定 6 の、設定の型と値ごとの許す範囲は、次の表のとおり。

| 設定の型 | 値 | 許す範囲 |
|----------|-----|----------|
| `PaymentProperties` | `deadline`（上限は今のまま） | 正の値 |
| `PaymentProperties` | `expiryInterval` | 正の値 |
| `PaymentProperties` | `awaitingAuthorizationWarning` | 正の値 |
| `PaymentProperties` | `authorizationValidity` | 正の値 |
| `PaymentProperties` | `authorizationWarning` | 0 以上 |
| `StripeProperties` | `connectTimeout`、`readTimeout` | 正の値 |
| `ImgproxyProperties` | `timeout` | 正の値 |
| `MediaStorageProperties` | `uploadUrlTtl`、`attemptTimeout`、`callTimeout` | 正の値 |
| `OrderProperties` | `reservationTtl` | 正の値 |
| `CartCleanupProperties`、`StockReservationCleanupProperties`、`CheckoutCleanupProperties`、イベントの片付けの設定 | `interval` | 正の値 |
| 同上 | `retention` | 0 以上 |
| イベントの再発行の設定 | `interval`、`minAge` | 正の値 |

イベントの再発行の `minAge` は #521 の表にないが、同じ時間の値なので含める。

## 目的と完了条件

### DS-553-1 設定の型の登録が 1 か所にまとまっている（D / P1）

- **DC-553-1** 登録だけの設定のクラスは 0 個で、本番のコードは登録の注釈を使わない。
- **DC-553-2** 本番の全ての設定の型が、1 回のスキャンの範囲にある。
- **DC-553-3** 決済の mock と Stripe の設定の型は、それぞれの条件が成り立つときだけ登録される。
- **DC-553-4** 定期ジョブの間隔を指定する式が参照する Bean の名前が変わらず、アプリが起動する。
- **DC-553-5** バックエンドの書き方の「設定の値の型」と環境変数の一覧が、決定 7 の形になっている。

### DS-553-2 時間と間隔の設定の値に下限がある（D / P1）

- **DC-553-6** 決定 6 の表の全ての値に、許す範囲の下限の制約がある。
- **DC-553-7** 許す範囲の外の値（正の値だけの値は 0、0 以上の値は負の値）で、設定の検証が失敗することを、値ごとのテストで確認している。
- **DC-553-8** 0 以上の値は、0 で検証が通ることをテストで確認している。

### DS-553-3 検査が通る（D / P1）

- **DC-553-9** `./gradlew check` が通る。

## 変える範囲

パスは、バックエンドのコードを `backend/ecsite/src/main/java/com/ecsite/` からの相対で書く。

| まとまり | ファイル |
|----------|----------|
| アプリのクラス | `EcSiteApplication.java` |
| 削除する設定のクラス | 決定 2 の 9 個（`config/event/`、各モジュールの `infrastructure/`、`payment/infrastructure/mock/`） |
| 注釈を外す設定のクラス | 決定 2 の 5 個 |
| 設定の型 | 決定 6 の表の型、`MockPaymentProperties` |
| 定期ジョブのコメント | `EventCleanupJob`、`EventResubmissionJob`、`CartCleanupJob`、`StockReservationCleanupJob`、`CheckoutCleanupJob`、`PaymentExpiryJob` |
| テスト | `backend/ecsite/src/test/java/com/ecsite/architecture/ConfigurationPropertiesTest.java`、`backend/ecsite/src/test/java/com/ecsite/config/ExternalServiceSelectionTest.java`、設定の型ごとの設定のテスト（既存のものに加えるか、新しく作る） |
| 規則と手順書 | `docs/05-開発規則/backend-coding.md`、`docs/06-手順書/environment.md` |

## 非機能要件

- **DN-553-1** 消費者・運営者に見える振る舞いを変えない。設定ファイル（`application*.yml`）の値と、設定の名前を変えない。
- **DN-553-2** Bean の名前を変えない（DC-553-4）。
- **DN-553-3** アーカイブした spec を変えない。
