# 毎回読む文書と固定の文脈の大きさ

毎回読む文書の大きさと、セッションの固定の文脈の大きさを置く。文書を整理した後に、効果を比べるときに読む。spec 309 で作った。

## 1. 測り方

- 文書の大きさは、`wc -c` のバイト数で測る。
- 固定の文脈は、新しいメインのセッションを起動した直後に、デスクトップアプリの使用量の表示（文脈の内訳）で読む。
- 本 spec が変える文書のうち、固定の文脈に自動で入るのは `AGENTS.md` だけである。内訳の「Memory files」に含まれる。
- `/.local/agent/environment.md` は、メインのセッションでは SessionStart の hook で最初のメッセージに入る。サブエージェントには入らない。
- constitution や開発の進め方などは、セッションが読んだときに文脈に入る。会話の中のファイルの読み取りとして数える。
- token の概算は、日本語の文書で約 2.5 文字が 1 token である。バイトでは、およそ 5 バイトが 1 token になる。基準の記録の概算で、正確な数は数えていない。

## 2. 基準（整理の前）

出典は、issue 担当のセッションが作った基準の記録（`/.local/refactor/baseline.md`、Git の管理外）である。整理を始める前の最後のステップ（spec 222〜227）で、2026-10 に測った。

固定の文脈は約 10 万 token だった。内訳は次のとおり。

| 項目 | token |
|------|-------|
| ツールの定義 | 3.9 万 |
| MCP のツール | 2 万 |
| system prompt | 1.2 万 |
| skill の説明 | 0.7 万 |
| Memory files | 0.25 万 |
| 最初のメッセージ（`/.local/agent/environment.md` と指示を含む） | 2 万 |

毎回読む文書の大きさは次のとおり。

| 文書 | いつ読むか | バイト |
|------|------------|--------|
| `AGENTS.md` | 全てのセッションとサブエージェント | 11,400 |
| `/.local/agent/environment.md` | メインのセッションの始めと圧縮の後 | 13,677 |
| constitution | 最初に読む | 16,323 |
| 開発の進め方（`workflow.md`）※1 | 最初に読む | 22,292 |
| エージェントの作業フロー（`subagents.md`）※1 | spec 担当 | 18,975 |

※1：当時のパスは `docs/rules/` の下だった。

spec 担当の最初の読みは、約 1.6 万 token と概算した。上の表の 5 つの文書である。

固定の文脈（約 10 万 token）のほうが、最初に読む文書より大きい。固定の文脈のうち、MCP のツールの定義が 2 万 token を占める。使わないときも文脈に入る。
