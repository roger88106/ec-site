# Spec 511：AC-126・AC-5 の文を、実装の振る舞いに合わせる

種類：整理　規模：M　ステータス：確定

## 背景と目的

テストを観点ごとに書き換えたとき（#498）、AC の文が実装と食い違う所が 2 つ見つかった。どちらも実装とテストは設計どおりで、AC の文だけが古いか、言い方が合っていない。AC の文を実装に合わせ、テストの名前と AC の文がそろうようにする。消費者・運営者に見える振る舞いと、本番のコードは変えない。追跡の issue は #511。

| AC | 今の文 | 実装とテストの振る舞い | 出典 |
|----|--------|------------------------|------|
| AC-126（order） | 他の会員やログインしていない人には「見つからない」と示す。 | 他の会員には 404、ログインしていない人には 401。AC-125・AC-131・AC-232 と同じ扱い | `docs/03-機能仕様/order.md:21`、`backend/ecsite/src/integrationTest/java/com/ecsite/module/order/presentation/MemberOrderApiTest.java:217` |
| AC-5（tax） | 現在より前の日時を、開始・終了として新たに設定できない | 現在ちょうどの日時も拒否する。税モジュールの規則の文「新しく設定する開始・終了は、空か現在より後。」と同じ | `docs/03-機能仕様/tax.md:26`、`backend/ecsite/src/main/java/com/ecsite/module/tax/domain/taxcategory/TaxCategory.java:234` |

## スコープ

| 含める | 含めない |
|--------|----------|
| AC 一覧（`docs/03-機能仕様/acceptance-criteria.md`）の AC-126・AC-5 の行 | 本番のコードの変更 |
| `order.md`・`tax.md` の「今有効な AC」の表（AC 一覧から生成する） | 他の AC の文 |
| AC-5 の、現在ちょうどの境界のテストの追加 | 既存のテストの名前の変更 |

決定：

- AC-126 の今の内容は、「注文手続きは、それを始めた会員だけが操作・参照できる。他の会員には「見つからない」と示す（ログインしていなければ、ログインを求める）。」にする。根拠として、[注文モジュール](../../03-機能仕様/order.md)の「注文手続き」を指す文を添える。
- AC-5 の今の内容は、「現在より前の日時を」を「現在以前の日時を」に替える。残りの文は変えない。根拠として、[税モジュール](../../03-機能仕様/tax.md)の「税率は一覧ごと置き換える」を指す文を添える。
- 2 つの行の状態は「変更」、変えた spec は `511` にする。[起票と記録の操作](../../05-開発規則/issues.md)の「AC 一覧の操作」にある、前の spec の AC を変えるときの手順に従う。
- 「今有効な AC」の表は、AC 一覧を修正した後に `node scripts/ci/spec/ac-check.mjs --write` で再作成する。
- AC-5 の境界のテストは、税区分の domain の単体テスト（`TaxCategoryTest`）に、開始と終了の 2 つを加える。名前は「AC-5 現在ちょうどの日時を、新しい税率の開始として設定できない」と「AC-5 現在ちょうどの日時を、新しい税率の終了として設定できない」にする。
  - 実装は既に拒否するので、テストは最初から通る。一時的にコードを変えて、失敗しうることを確認する（[開発の進め方](../../05-開発規則/workflow.md)の「循環」の、今の振る舞いを固定するテスト）。
